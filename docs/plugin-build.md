# 插件构建与发布资源

安装用户直接使用仓库内的产物，无须安装 Node 或自行编译。开发者统一执行：

```sh
npm run build
npm run check
```

`build` 先通过统一 lint 和类型检查，再生成并验证全部目标后替换产物；`check` 执行同一套检查，在暂存区重建并逐字节比较已安装产物，再运行全部测试、离线运行时验收与 Node 18 兼容验证，不修改已安装产物。构建工具使用依赖要求的现代 Node；服务端安装包保持 Node 18 / CommonJS 契约。根 `lint`、`test` 仅用于定位问题，不存在模块专属命令。

统一 lint 检查所有自有 JS、MJS、CJS、TS、MTS、CTS、Vue 及 HTML 内脚本，以零警告为通过条件。Node 环境和各语言解析规则集中在根 ESLint 配置，严格类型选项只在根 `tsconfig.json` 定义。自有源码与第三方库、生成物的区分由 `.eslintignore` 定义，类型检查、测试及页面发现复用它和 `.gitignore`，不维护模块名单。新目录的 TS/Vue 与 `*.test.js/mjs/cjs/ts/mts/cts` 自动纳入检查；生成物由总检查重建验证。对已核实的规则误报仅允许在具体位置说明安全依据，不能按文件关闭安全规则。

## 唯一入口与所有权

- `scripts/build/targets.mjs` 登记必要的输入生成和 Node 目标。服务端、Agent、绘图、联网运行时、vendor、形象、图标与助手索引都由总命令管理，无须手工记顺序。
- `scripts/build/browser-entries.mjs` 只登记浏览器独立执行入口；原生页面和模板自动发现。宿主、酒馆、助手、阅读器、总结、OS、OS Agent、地图投影、原生页面模块脚本及动态桥接脚本参加同一次构建。
- OS 的应用和游戏继续由现有应用目录及动态 import 登记，不维护第二份游戏列表。
- `vite.plugin.config.mjs` 负责共享依赖、Vue、样式和宿主边界。只有插件根目录以外的 SillyTavern 代码 external；跨出 OS 目录的插件代码仍参与构建。
- 功能拥有业务源码、模型、纹理、字体与许可证；构建层仅拥有入口登记、资源映射和生成物，不拥有业务数据或存档。

浏览器源码互相引用源码，不引用生成的旧 bundle。TypeScript 的 `.js` import 由构建器解析到对应 `.ts`，不再在源码旁保留转译 JS。第三方浏览器库与 npm 源码不得在同一图重复打包。

添加内置 OS APP 时，仍按 OS 的 APP 注册规则接入；不在构建层再登记一份 APP 名单。只有新增独立执行入口才修改 `browser-entries.mjs`，引用现有入口的新页面无须登记。修改后执行同一套构建与检查，不手工编辑 `dist`。构建清单只索引本次随包产物，不是 OS 开放 APP 注册的准入名单；外部 APP 的注册契约不应依赖内部哈希块。

## 输出和加载

```text
dist/
  host/plugin.js          SillyTavern 固定装载入口
  apps/                   带内容哈希的独立页面入口
  runtime/                带内容哈希的延迟公共入口
  shared/                 从真实依赖图提取的公共块
  assets/                 CSS、小型资源及构建器生成的 Worker
  manifest.json           入口、CSS、依赖与确定性 buildId
  THIRD-PARTY-LICENSES.md  浏览器依赖许可证
```

根 `manifest.json` 指向 `dist/host/plugin.js`。`core/build-assets.js` 根据实际安装目录解析资源，从重新验证的构建清单取得入口和完整静态 CSS 依赖，先等待 CSS，再启动页面。清单请求失败会向上报错，下次显式调用可重试；不回退旧包、不重发业务请求。

页面中的清单快照只保留在内存，刷新后重新获取。共享块和 CSS 使用内容哈希；运行中的旧构建若已不属于当前清单，拒绝继续混装并要求刷新。没有新增 Service Worker、IndexedDB 缓存或安装步骤，正常 HTTP 缓存由浏览器管理。

iframe 保持执行隔离与原有消息协议；共享文件不意味着共享运行状态。地图投影仍在 ShadowRoot 内挂载，它从清单获取所需 CSS 并注入 ShadowRoot，而非误装到宿主 head。经典脚本和被 fetch 后插入的模板保留原执行语义；独立模块脚本通过清单启动。

模型及外置纹理仍只保存在功能资产目录。`scripts/vite-source-assets.mjs` 将 `?url&no-inline` 转为插件根目录下的唯一资源地址，内容摘要用于版本查询；不依赖 chunk 深度，不复制到 dist。保留现有 Meshopt、外置纹理、延迟场景加载及释放逻辑。SVG 等小型资源由构建器内联或管理。Worker 由构建器独立编译，输出引用参加检查。

## 暂存、检查和恢复

全部目标先写入忽略目录 `output/plugin-build-*/stage`。浏览器和 Node 编译均读取本次生成输入。类型检查、资源闭合与模块归属通过后，才逐个替换构建明确拥有的输出；旧版本保存在该次构建的 `previous` 目录。中途替换失败会逆序恢复整组产物，不先删除可用版本。

内部生成器只接受总构建提供的暂存目录，缺失上下文或目录位于 `output/` 之外时直接失败；不能回退到仓库根目录。Vite 同样只写本次暂存区。只有 `scripts/build.mjs` 调用发布器更新安装产物，内部步骤不再拥有独立发布或独立比对流程。

`scripts/check-project.mjs` 在总命令起点检查结构：模块自带的质量命令、构建/类型/lint 配置、模块 `dist`、绕过统一入口的原生模块脚本、页面引用不存在的构建入口都会失败。OS APP 的业务注册不受这项工程检查限制。

`scripts/build/validate.mjs` 检查入口、CSS、共享依赖、真实输出 import、HTML 引用、Worker 和资源文件；未解析的裸 import 或缺失本地资源阻止发布。`output/browser-build-audit.json` 记录实际模块归属，任何模块重复归属阻止发布。审计、暂存、测试数据与缓存只留本地。

删除功能时，删除其功能目录和独立入口注册，重建并检查无反向引用；不保留旧 dist 或旧构建命令作为兼容壳。用户数据由功能自己的删除策略处理，构建不清理聊天或存档。回退须成套恢复源码接线、构建规则和对应产物。

## 验收契约

| 情况 | 必须结果 | 出错代价 |
| --- | --- | --- |
| 新增任一种自有源码或 HTML 内脚本 | 自动进入总 lint，警告阻止构建和整体验收 | 漏检危险代码 |
| 在新目录新增 TS、Vue 或测试 | 自动检查，类型错误或失败测试使整体验收失败 | 漏检功能错误 |
| 新增独立模块流水线或遗漏页面入口 | 总检查拒绝通过 | 隐性版本分叉 |
| 单独执行内部生成器且没有合法暂存区 | 失败且已安装产物不变 | 安装损坏 |
| 页面显示外部文本或收到窗口消息 | 文本不能执行代码，只有同源父窗口可驱动页面 | 凭据泄露或数据被篡改 |
| 完整重建与产物检查 | 覆盖所有登记目标，发现过期和多余输出 | 隐性版本分叉 |
| 页面、动态入口或 Worker 加载 | 引用闭合，错误可见，可显式重试 | 功能不可用 |
| 打开某个应用 | 不启动其他应用，游戏和专属资源保持按需加载 | 重复下载及意外副作用 |
| 资源或清单更新 | 不混装旧共享块与新清单，刷新获得新构建 | 难复现运行错误 |
| CSS 失败及地图重新挂载 | 不在无样式状态启动，正确注入隔离边界 | 界面不可用 |
| 多目标发布中途失败 | 恢复全部原产物 | 安装损坏 |
| 进入荒岛和余火 | 模型、外置纹理及解码正常，退出重进不丢存档 | 黑屏或数据损坏 |
| SillyTavern 1.14/1.18 与 Node 18 | 保持宿主接口和服务端契约 | 插件整体不可用 |

构建测试覆盖稳定规则；协议、工具续轮、取消、同步 Markdown 过滤、聊天与游戏数据继续由现有功能测试验证。交付还需在隔离数据下验证真实宿主、原生页面、游戏与 ShadowRoot，不以构建成功代替运行成功，不擅自调用付费模型。
