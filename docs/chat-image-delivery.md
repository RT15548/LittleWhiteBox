# 聊天绘图接管与交付设计

本文拥有主聊天图位、原生生成接管、显示和取消边界。场景理解与计划见 [Scene Planner](./scene-planner-design.md)，后台执行与恢复见 [Image Job](./image-backend-batch-jobs.md)及 [Draw Run](./backend-draw-runs.md)。三家 Provider 各自拥有请求、编译与供应商结果。

## 所有权与身份

- [chat-image-session.js](../modules/draw/shared/chat-image-session.js)：生成期间的接管与图位任务身份。
- [chat-message-images.js](../modules/draw/shared/chat-message-images.js)：消息展示与订阅；DOM 被重绘后按现有任务事实恢复。
- [chat-image-placement.js](../modules/draw/shared/chat-image-placement.js)：正文替换、删除及位置映射。
- [image-card-view.js](../modules/draw/shared/image-card-view.js)：已有卡片的局部投影、图片加载和编辑器节点保留；不写正文、不提交绘图。
- [image-card-target.js](../modules/draw/shared/image-card-target.js)：编辑与重绘的精确版本读取和运行期目标校验；不选择展示回退版本、不写图库。

任务身份依赖聊天消息对象、分支、生成范围和标签位置，不依赖 DOM、可见性或不会变化的楼层下标。接管与显示观察仅在运行期存在，不另建持久化缓存、锁或任务副本。

## 原生生成与保存

接管完成边界先恢复已提交图位，再允许 DICE 同楼处理，最后解析剩余标签。多次续写准备交错只能恢复已提交图位；其他图位删除或前楼移动后重新定位，真正编辑或目标变化使过期接管失效。

正常原生回复的交付顺序为：图片输入落图库 → 同步替换正文及当前 swipe → 交还宿主原生保存。不等待供应商完成，也不额外保存/读回整聊天。历史标签、编辑保存与重挂载只提供展示或手动入口，不重新自动购买图片。后台提交与接回需要的确认保存另遵守后台协议，不混入普通原生生成。

正文中的图位是排版事实，DOM 是可重建视图。宿主重绘后按原任务恢复卡片，不重买；写前重新核对消息、分支和存活图位。迟到结果可留图库，但不能写到另一消息或复活用户已删除的图位。删除标记归既有任务记录，随其结算/清理释放。

## 卡片投影与旧图保留

普通进度、结果、图库通知只投影正文与宿主 DOM 都存在的图位，不因隐藏或过滤图位而重建整楼。只有明确提交的正文结构变化才调用宿主格式化及必要的 `MESSAGE_UPDATED` 通知；标签接管已经同步挂好卡片时不重复格式化。酒馆助手仍可收到真正正文重写的通知。

重绘等待、失败或取消时保留旧图片，当前尝试的状态、身份和 TAG 仍独立显示，不以旧图冒充成功。旧图在状态展示期间不带保存、删除或版本导航动作，返回已有图片使用原恢复入口。作为背景的旧图加载失败时，仅隐藏不可用的图片，任务状态和恢复操作立即以无图布局显示，不等解码、不自动重载，也不用资源错误覆盖当前任务。状态装饰不改变可用图片布局；不通过设置滚动位置或锁定卡片高度掩盖重建。

单项进度只刷新变化图位；整楼通知也不替换未变化的卡片、图片或打开的编辑器。草稿及编辑目标只活在 DOM 内，选择改变后不能把旧草稿保存到新版本。新图片解码完成后才替换资源，过期聊天、分支、内容租约或视图投影无权完成交换；解码不阻塞图片交付或 ACK。解码期间视图仍未完成加载，正文续写后由当前图位重新读取事实并接手，不能只丢弃旧回调而永久保留旧图。

展示回退不授予编辑或重绘权限：操作在首次异步读取前捕获卡片版本、消息及分支，只读该版本或同身份的聊天保存引用；记录丢失且引用不匹配则报错，不能借用其他版本的 TAG、角色或负面词。打开编辑器只读；保存时才归档对应 saved-only 版本。只有无版本 ID 的新占位卡可首次创建输入记录，自己的首次保存投影可以绑定该新 ID，不能放宽已有目标的版本校验。

图库读取失败与图片资源加载失败属于视图错误：保留现有图片及输入，提供重新加载，不伪造空参数的绘图失败，也不触发新绘图请求。首次挂载保留浏览器懒加载，监听实际图片节点的失败并识别已缓存的加载失败；没有可见旧图时错误提示不能依赖图片高度。首次读取失败也必须结束自动加载，错误提示的 DOM 更新不能触发循环读取；重试核对仍挂载的消息、分支与存活图位，并读取当前正文。

saved-only 聊天引用由 `draw-common.js` 的共享适配器转成现有图库版本，编辑、重绘准备和后台接回共用；普通显示不写图库。重绘购买前必须保住该版本，归档写失败则不购买、不清聊天引用。异步归档同时核对原消息、存活图位（含非当前分支）及引用，不能把删除后残留的 saved 元数据当作写入授权；删除不被迟到写入复活。版本沿用现有图库清理与图位删除生命周期，不新增持久化模型。

## 任务状态与取消

Provider 任务登记统一服务胶囊、自动配图、原生标签及重绘批次。批次独立取消，按聊天/消息/当前分支聚合；已结算兄弟批次保留到聚合结束。胶囊挂载直接读取当前汇总，不依赖此前通知是否被接到；后台 handoff 不冒充全部完成，排队项不显示为正在生成。

已有图位按槽位接受重绘：不同图片可连续点击，原批次已交付的图片也可再次重绘，不等待兄弟图位。提交准备及保存确认只校验原消息、分支和图位存活，不因无关正文续写失败，也不把冻结正文写回。相同槽位的准备、排队、生成和未确认交付仍防重复提交；结构性场景规划保留整楼约束。实际执行沿用 Provider 直连队列和后台用户队列，不改变并发、公平调度或冷却策略。

后台单项交付的唯一完成事实是现有 journal item 的 `deliveryCommitted`：图片及选择持久化 → 同租约确认交付 → 释放图位 → 后端 ACK。确认失败保留占用和后端副本，不将画廊里出现图片当作交付证明；刷新或清缓存不能撤销已确认事实。该字段由交付租约持有者维护，随 journal 删除，不另建持久队列。新任务入日志时在同一事务检查槽位冲突，不能只靠按钮或先读后写防重复购买。

首次交付、接回和失败/取消/失踪收尾共用单项交付门禁；确认过的旧项不能再改图、选择、失败状态或删除新结果，只继续 ACK 和批次清理。运行期图位活动仍按操作所有者清理，旧批次的结束不能清掉新重绘的排队状态。升级不清除活跃日志，尚无交付确认的项继续按未完成处理。

取消先捕获目标及运行任务身份，整组意图持久化后经同一个后端请求确认；不能先逐项取消运行中的任务而让它唤起同组排队项。运行页、另一标签页及刷新接回共用 [整组取消契约](./image-backend-batch-jobs.md#整组取消)，不重写聊天正文来记录取消。停止文字生成不等于取消早前已提交的图片批；图片取消从对应绘图入口发起。

取消失败不能停留在不可操作的“取消中”：楼层与悬浮入口恢复可重试状态，后台已接受任务的投影不能覆盖取消失败事件。即使读取任务或保存取消意图失败、没有可恢复的持久记录，点击入口也必须自行恢复；过期操作不能改写新聊天、分支或已经推进的界面状态。

提交前取消、明确拒绝、已知成功、提交后未知必须区分。已解码成功不被后续取消抹掉；未知请求不自动重发，保留再计费风险，不让胶囊永久显示确认中。

NovelAI 电子书、Tavern 与普通文本入口不依赖聊天楼层，仍遵守各调用方取消信号与图库归属。共享绘图 facade、宿主内容挂载和 DICE 检定规则各由原功能拥有。

## 检查与限制

共享测试位于 `modules/draw/shared/tests/`，三家 Provider 测试位于各自 `tests/`。浏览器夹具中的 `provider-browser-host.mjs`与 `provider-browser-*.mjs`使用真实宿主生成/事件/保存链路和隔离供应商，不能用于真实用户聊天或计费验收。

重点保护：续写/swipe/重生成交错、无 DOM 与宿主重绘、DICE 同楼位置映射、切聊/切分支、输入落库失败、聊天保存失败、逐项取消、未知结果和显式删除。隔离测试证明交付链路，不证明真实供应商图片质量、系统冻结后台页、Tauri/移动 WebView 或正式宿主可部署性；后两者还要求对应构建与运行检查。
