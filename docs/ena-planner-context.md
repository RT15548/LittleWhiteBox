# 剧情规划上下文

剧情规划拥有规划指令、规划 API、输出处理及运行状态。SillyTavern 拥有世界书扫描与提示词组装；提示词模板扩展拥有原生 EJS 处理；剧情总结拥有召回及记忆注入。

## 同一次生成

用户消息正常入楼。剧情总结先通过生成拦截器完成本轮召回，随后剧情规划在本轮聊天副本的末条用户消息尾部设置临时回填标记。标记由空白字符组成，SillyTavern 1.14/1.18/1.19 的世界书扫描在读取消息时会 trim，因此扫描文本不变。

宿主完成组装后，规划在模板扩展之后等待：聊天补全使用 `CHAT_COMPLETION_SETTINGS_READY`，文本补全使用 `GENERATE_AFTER_DATA`。每次准备重新安排回调顺序，规划不调用独立世界书扫描，不重新执行宿主资料中的模板。

规划输入只有处理后的文字、角色和名称，作为资料交给规划自己的指令。不会复制请求配置、密钥、图片、音频或工具调用权限。剧情记忆已包含在宿主输入中，不额外读取 canonical 总结或发起向量召回。

成功结果替换本轮标记，保留宿主消息角色、非文字附件和文本补全前缀。聊天补全使用 `messages`，文本补全使用 `prompt`，NovelAI 使用 `input`；CFG 正负提示分别回填并检查预算。NovelAI 在原生模板处理事件期间将 `prompt` 临时映射到 `input`，事件结束后移除别名，不额外求值。

预算检查包含文字、工具定义和宿主媒体成本。聊天补全文字按宿主 `Message` 的逐条、非 full 模式计数；统一回复起始预留只加一次，纯媒体消息不额外计空文本封装，工具结果 ID 和签名不作为正文重复计费。文本补全使用已经扣除输出预留的输入预算，CFG 分支分别检查而不相加。未知成本或超限均阻止正文，不裁剪记忆或重新扫描。

## 预览与确认

用户原文正常保存并确认；规划完成不自动保存、不自动生成正文。剧情规划自行在 USER 的 `.mes_text` 后挂独立预览块，不引用 DICE 业务状态。预览跟随原消息对象、索引与聊天身份，宿主重绘后可重新挂载。

- 流式预览保留所选标签过滤，隐藏思考内容；预览“停止”仅中断规划模型，保留已显示内容和用户楼层。
- “重新规划”复用本轮已组装上下文，不重新发送原文，不把未确认规划加入输入，不重复执行世界书扫描或原生模板。
- “发送”才把当前预览追加到同一用户楼层，经预算检查、宿主保存及原聊天读回确认后，替换本轮请求的回填位置，继续本轮正文。
- 不操作时，本轮原生请求保持等待，预览只在内存中；不写正文、`extra` 或持久日志。切聊天、编辑/删除原楼层、关闭模块后不得再采用旧预览。

确认发送后，`saveState` 冻结本次规划和保存目标。“保存失败”和“写入后读回失败”分别处理：只有读到原文且旧写入已结算，才回滚本次内存修改；读回失败、第三方改文或尚未结算的写入，均保持未知并阻止正文。重试发送先只读确认原目标，已写成则直接恢复正文，不重复保存或调用规划模型；明确未写才可重试同一规划。保存返回本身不代表成功。

宿主整轮停止后，尚未确认的保存事务仍在本页面内存中。下一次前台生成先恢复用户此前已确认的同一份规划；恢复中取消或并发新生成不能绕过确认。若恢复改变了正文而宿主已克隆旧输入，则中止这次旧快照并提示再次生成，不把其他拦截器的结果自行改写。已明确编辑/移动原消息且旧写入已结束时，旧授权失效，不永久阻塞新内容。

规划标记只写入原生生成拦截器收到的聊天副本，不写入全局 `extension_prompts`，也不修改持久化用户消息。`quiet`、`impersonate`、已有规划、续写及其他跳过规划的原生请求，使用各自的空白关联标记；不依赖文本补全未必提供的 `data.type`，也不把“没有前台标记”当作请求归属证据。关联标记在扩展处理前清除，前台回填标记在同一请求对象上替换。聊天补全必须保留关联标记到 `CHAT_COMPLETION_SETTINGS_READY`，因为宿主会在前一个事件之后重新创建参数对象和消息数组。dry-run 不进入拦截器、不领取任何前台标记。

## 生命周期与错误

运行状态绑定当前聊天和用户消息，只有内存态。确认成功或整轮取消、关闭、卸载时清理临时提示词。预览停止与整轮宿主取消不同：前者保留待确认请求，后者使本轮预览失效并禁止迟到回填。切换聊天同时清除最近上下文和预览。可恢复的规划/预算/保存错误保留本轮请求与预览，使用预览操作恢复，不另增用户楼层。

规划错误不能只从事件回调抛出：宿主事件会捕获异常。可恢复错误不放行等待中的请求。已关联请求的回填位置无效、切聊等致命错误使本轮失效；仅附着于本次请求的序列化保护拒绝传输，防止文本流式宿主随后建立新信号而绕过停止。身份缺失或多个身份混合的未知载荷，只拒绝该载荷并报错，不猜成当前前台请求、不取消别的运行，也不消耗旧请求的撤销记录。不修改全局 fetch 或伪造宿主忙闲状态。迟到的规划结果不允许回填。规划要求独立 API 预设，不递归使用等待中的宿主连接。

宿主可能在拦截器之后提前返回而不发出请求事件；`GENERATION_ENDED` 既不携带请求身份，也可能由后台生成触发，不能用它直接清理前台。新的前台拦截允许替换旧的 `ready` 且尚未绑定载荷的准备态；旧标记保留撤销记录，晚到载荷仍被拒绝。已绑定、规划中、预览中、保存或保存恢复中的请求不能被这条规则替换。

关闭模块时，若仍有尚未到达捕获点的请求，保留只做关联与拒绝的轻量拦截器和事件守卫；新请求只绕过规划，旧请求不再执行模型或采纳。待相关请求到达后清理守卫；若宿主早退而请求永不到达，守卫可保留到页面结束，不能因超时而重新授权迟到请求。

自定义规划指令中的 EJS 由模板扩展公开 API 执行，缺失扩展或执行失败会终止规划。原生模板的执行和报错语义仍由模板扩展决定，不根据输出中是否出现 EJS 字符串猜测成功状态。

“查看本轮上下文”只显示本聊天最近捕获的文字资料，不扫描、不求值、不召回。API 测试使用固定测试输入，不读取聊天或执行用户模板。它不等同于完整生成链路验收。

## 验收契约

| 条件与结果 | 出错代价 |
| --- | --- |
| 同一次生成的原生世界书/EJS 只走宿主链路；诊断不增加执行次数 | 隐蔽状态改写 |
| sticky、cooldown、递归、概率、预算、深度和 outlet 均沿用宿主结果 | 采用错误设定 |
| 规划与正文使用同轮已发布记忆，不另行召回或重复注入 | 错用记忆、重复费用 |
| 只有文字和角色进入规划，回填保留原请求协议及附件 | 泄露或协议错误 |
| 失败、取消、超限和无效回填位置不能发出正文请求 | 意外发送或付费 |
| 重试不重复入楼；切聊天、关闭及卸载后不发布迟到结果 | 聊天损坏 |

纯数据与生命周期契约由模块测试覆盖；宿主协议及 EJS 兼容使用真实 SillyTavern 1.14、1.18、1.19 和 ST-Prompt-Template 1.17.9 验证。构建产物也必须经过加载与发送验证。

## 退出

没有新增持久化实体。删除模块目录及注册后，清理原有规划配置和日志即可退出；已保存到用户消息的规划文字仍属于聊天记录。
