# 循环任务：保存与生命周期实现规则

面向维护者。任务作者的用法见 [脚本开发指南](<README.md>)；这里只记作者看不到、但改代码时必须守住的规则。

## 1. 启停与授权

- 全局、角色和预设任务统一使用“启用循环任务”总开关和单任务启停，不弹角色任务的“允许”提示。旧允许名单和已提示记录在设置初始化时清除。
- 任务列表修改启停状态要等保存确认；失败会提示并恢复显示已保存的状态。同名任务的列表开关只修改所选条目。

## 2. 保存

### 2.1 通用规则

- 保存期间仍可操作其他任务。全局、角色任务的连续保存只合并各次修改，不用旧列表覆盖已经确认的脚本、设置或顺序；不同角色之间不互相等待。保存失败不会阻止后续保存，也不会恢复主动停止时已取消的预设启动。
- 编辑器点击“保存”后等待实际写入回执，成功才关闭；失败保留输入。保存期间可以取消、关闭或按 Escape 离开；这不会撤销已发出的请求，迟到结果不会关闭后来打开的编辑器。
- 修改名称、脚本或类型在保存完成后停止旧实例；主动停用、删除立即停止。
- 改变类型先保存目标，再移除原位置；未确认的目标不得触发源删除。编辑器记住本次尝试过的位置，重试沿用同一个任务 ID，不重复创建。

### 2.2 全局任务

- 保留原 ID、设置位置与脚本文件。编辑先写新的候选脚本，元数据的内部 `scriptId` 在宿主设置提交成功后才成为当前运行版本；没有 `scriptId` 的现有任务仍按任务 ID 读取，不批量转换。
- 相同内容的失败重试复用候选引用，改写内容使用新引用，避免覆盖可能已提交的脚本。导出包含完整脚本，不包含内部引用。
- 设置由酒馆原生 `saveSettings()` 组装；任务模块短期只读观察匹配本次任务字段的请求，要求响应 `{ result: "ok" }`，不改写宿主请求或响应。
- 正常成功不读回、不回滚；请求异常、结果未知时仅查询一次对应字段，不回填整份宿主设置。查询仍失败则保留原页面版本、候选脚本及本页重试信息；任何仍可能被引用的脚本都不删除。确认不再使用的脚本后台清理，清理失败只记日志，不影响保存结果。

角色和预设任务使用原位置的写入回执。

### 2.3 预设任务

- 任务定义随预设 JSON 保存在酒馆服务端，不另存浏览器持久化副本。
- 当前页面对同一个预设的任务保存按顺序发送；每次发送前读取最新预设并仅合入 `scheduledTasks`，保存完成只同步任务字段，不回灌整份旧提示词设置。普通提示词、开关和参数编辑不取消任务保存。
- 保存期间，删除和停用立即生效；名称和脚本继续使用已提交版本，失败不会让候选脚本参与执行。仅切换到另一预设不会取消原预设的正常保存。
- 完整预设导入在写入服务端前，等待本页面已有的同名任务保存及其队列结束，避免旧队列随后覆盖导入文件；其他预设的保存不阻塞这次导入。导入失败不撤销之前的编辑，也不停止现有实例；导入成功后才替换任务定义和运行实例。宿主替换了预设后，过期保存结果不再回填内存。
- 读取缺少 ID 的预设任务时，只在内存中补齐；读取、执行和切换预设都不自动保存预设。运行归属使用带预设范围的任务名称，不依赖补出的 ID 是否已保存。

## 3. “随预设启用”的文件格式

- 保存为旧版认识的 `triggerTiming: 'chat_changed'`，并以 `x.presetStart: true` 标记；只有预设任务且基础时机仍为 `chat_changed` 时，新版才按“随预设启用”执行。完整预设与单独任务 JSON 都使用这份格式，避免旧版把未知时机静默变成“AI 消息后”。
- 新增此模式保存时固定 `interval: 1`，仅为避免旧界面误标“手动”；两版的事件触发均不使用楼层间隔。普通旧任务的间隔不改。
- 旧版降级行为以正式线提交 `1aaf3fbf` 为验证基线。

## 4. 角色切换与聊天调度

- 角色退出时立即注销旧实例、命令执行记录和冷却；资源清理执行一次，异步收尾不再占用新聊天的执行锁。旧结果不再用于后续调度，切回同一角色也不会恢复旧实例。
- `chat_changed` 在动画帧中后台触发；`character_init` 在宿主 `CHAT_CREATED` 事件中等待本次初始化。两者之间不加等待队列，不等待旧角色清理，也不补发开场消息。
- 全局、预设及当前有效任务的执行锁与消息防重入保持原规则；占锁时跳过而不补跑。角色退出前已交给宿主的命令会请求取消，但插件不能阻止不支持取消的宿主代码继续产生副作用。
