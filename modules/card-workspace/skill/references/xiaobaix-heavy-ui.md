# 一体游玩界面：连接场景、聊天与宿主操作

玩家主要在自定义界面里读和做时读本篇。界面职责、消息与存档归属先按[前端技能](<../frontend/SKILL.md>)确定；完整接法见[解铃会成品](<../frontend/examples/jieling.md>)。

## 从入口到下一次行动

入口让玩家进入这张卡的场景。进入后，正文说明当前处境，行动与输入接住玩家选择，回应与结算结果留在同一界面里，玩家可以接着做下一件事。布局按故事与操作的主次安排；手机上可把辅助信息折成抽屉，阅读与输入仍是主体。

界面可以收起以访问酒馆设置。主界面的常用游玩流程在内部完成，辅助面板才以返回聊天为日常流程。

## 接住真实聊天

复用原生聊天时，用 `SillyTavern.getContext()` 取得当前聊天与真实楼号；显示层不另存一份会话。消息变化、生成中、编辑、swipe、删楼和换聊天时更新对应显示，保留未变化楼层的阅读位置。

发送普通玩家文本按[消息按钮](<xiaobaix-capabilities.md#message-buttons>)处理。界面草稿与酒馆输入框里的草稿都需要保留；重写、发送和停止生成按宿主的实际状态开放。卡内行动是否先结算、结果属于哪一楼，按所用变量技能确定，正文接着已确认的结果写。

<a id="host-features"></a>
## 接住变量和图片操作

界面承担的功能，其操作、状态和错误反馈也在界面内可达。按本卡使用的能力接入，而不是把全部插件功能都搬进来。

- **变量结算**：规则与回执使用 ReadSkill builtin-state3 或 builtin-state2 的入口。直接提交成功、被拒、已生效但保存未确认是不同结果；后者只重试保存。
- **界面中的经营动作**：解铃会经营版由自己的按钮调用变量 3.0 动作，处理结算回执和重试保存；具体设置随[成品示例](<../frontend/examples/jieling.md>)。其他卡是否使用更新模型、何时结算，由自己的玩法决定。
- **聊天图片**：自定义阅读器使用 `xiaobaixDraw.mountMessageImages({ element, messageId })`，传渲染该条真实消息的容器和楼号。图片版本、重画、保存、放大与菜单由插件处理；替换容器内容、删除楼层或卸载前调用返回句柄的 `destroy()`。参数、就绪条件与生命周期以插件 `docs/user/media-api.md` 的“在自己的聊天 UI 中显示图片卡”一节为准。
- **独立媒体**：自己生成的图片和语音按[媒体接口](<xiaobaix-capabilities.md#media>)处理。独立请求的结果不等于已经保存为聊天消息。

## 挂载与卸载

一个角色任务拥有一套常驻界面，DOM ID 与全局入口使用卡专属名称。任务挂载前卸载自己的旧实例，在 `onCleanup` 中释放监听、计时器、图片句柄、Blob URL 与界面节点；借用的宿主控件归还原位置。触发时机与任务停止条件见[能力参考](<xiaobaix-capabilities.md>)第 2 节。

展开状态、标签页和阅读位置属于界面状态；钱、人物关系、事件与回合结果属于玩法状态。同角色换聊天时重新读取当前聊天，不能沿用上一份玩法状态。不要为卸载本卡界面停止全部任务。

## 原卡只有文本状态栏时

读取最近消息原文中卡自有的状态标签。显示正则可以把状态块替换成与场景相符的入口，并把完整匹配保留在隐藏容器；此规则只改变显示，不改变模型输入。宿主会移除内联事件并给普通类名加 `custom-` 前缀，点击由任务里的事件委托处理，读取隐藏原文用 `textContent`。变量卡直接读当前状态，不要求模型重复输出整份状态栏。

## 布局与刷新

- 内部 flex 滚动区设置 `min-height: 0`；手机全屏使用 `100dvh` 适配地址栏。
- 状态刷新保留阅读位置、输入草稿和界面选择；只重绘变化的正文与状态。
- 动态文本用 `textContent` 或转义后放进 HTML。背景过渡可用遮罩透明度，不靠大 Data URL 的 `background-image` 动画。
- 没有素材时正文与操作正常铺开，图片区可以收起。视觉动效表达场景或结果，不代替操作反馈。

<a id="assets"></a>
## 素材与绘图

自备素材使用酒馆页面实际能访问的 URL 或用户提供的 Data URL；工作区文件路径不是图片服务器地址。图片、地点表等大块共享数据由常驻任务保留一份，各楼按需读取，不往每楼代码块里重复塞整份。

已有聊天插图按上面的图片卡接口显示。独立生成的图片需要卡自己保存时，读插件 `docs/user/media-api.md` 的“保存生成结果”；收进图库不等于已经与卡的某一回合关联。替换或卸载时释放临时 URL，取消与部分失败按媒体接口处理。

## 验收一轮完整游玩

在隔离聊天里，从进入界面开始，完成阅读、行动或输入、发送、等待回应、查看结算与图片，再继续下一步。整个过程不用退出主界面。再检查本卡使用的功能：

- 生成中、失败、取消、保存未确认时，玩家知道当前发生了什么，并有对应的下一步。
- 重写、编辑、删楼后，正文、变量操作与图片仍指向正确消息。
- 重绘与重新挂载不重复绑定；收起、重开和卸载后，借用的宿主控件仍然可用。
- 切角色时卸载，同角色换聊天时读新聊天；桌面与手机都检查滚动、输入和辅助区域。

静态预览说明布局，模拟服务验证交互分支；真实生成与历史恢复只报告实际联调过的部分。
