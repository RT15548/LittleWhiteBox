# 解铃会：一体游玩界面

这份[完整卡工程](<jieling/>)来自作者完成的《解铃会》。正文、行动、输入、经营状态以及所用的变量与图片操作在同一界面内；聊天记录、生成与 swipe 仍由酒馆管理。

## 玩家怎样走完一轮

| 过程 | 这张卡的处理 |
| --- | --- |
| 进入 | 会所的磨砂门、门牌和门铃构成入口；按铃进入现场 |
| 阅读 | 正文占主要空间，按真实聊天楼层显示；案头放在场人物、互助室、包间、档案与账本 |
| 行动 | 选择“请下一位进来”等行动标签，可以补上自己的话再发送；已经结算的行动交给正文接着写 |
| 看结果 | 规则回执更新案头，保存未确认时提供重试保存；收工结果呈现为日报 |
| 继续 | 输入、swipe、变量按钮和聊天图片操作在界面内可用，不用退出再找原聊天控件 |
| 手机上 | 正文和输入保留在主画面，案头收进可展开的辅助区域 |

这套组织方式可借鉴，门、双栏、黄铜配色与经营题材则属于本卡。其他卡从自己的场景、行动与信息主次出发设计。

## 从哪里读实现

- [一体界面任务](<jieling/tasks/[解铃会] 一体界面.md>)：唯一的前端实现，包含样式和交互。先读“界面骨架”，再按需求查“行动条”“发送”“真实楼层”“插图”和“变量按钮”相关段落。
- [变量定义](<jieling/variables/definition.json>)和[规则函数](<jieling/variables/functions/>)：`club` 保存经营状态，`desk` 派生案头显示；日结、分班和接待按规则提交。它们与任务配套。
- [开场](<jieling/message/0.md>)、[角色说明](<jieling/description.md>)和[世界书](<jieling/world_book/解铃会/>)：提供现场、人物与正文约定，让按钮行动接得上故事。

宿主接口与适配边界统一见[一体界面参考](<../../references/xiaobaix-heavy-ui.md#host-features>)。本例中的变量按钮复用是对插件 DOM 的适配；图片卡使用公开 `mountMessageImages` 接口。阅读器按真实楼号挂载图片，重画正文前释放旧句柄，避免只显示一张失去操作能力的图片。

## 在独立卡里试用

这是一套 CardFiles 格式的文件，不是加载技能就会执行的插件。试用时选择一张专用卡，通过 CardFiles open 取得根目录，把本例文件按相对路径写入并保存；变量包、世界书、开场与任务成套使用，任务最后写回。已有同名世界书时，先为试用副本选择独立书名，同时调整 `card.json` 的 `world` 和 `world_book` 下的目录名，避免改到原卡共用的书。启用小白X循环任务，并把变量管理设为 3.0。全部写回后，新建该专用卡的测试聊天，触发 `chat_changed`；在这个聊天里启用规则，按提示允许卡内扩展，并核对初始状态与场景入口。

任务使用 `chat_changed` 挂载，不需玩家先寻找任务启动按钮。运行中的界面有自己的场景入口。单独复制任务到另一套变量规则上不能得到这张卡；按本卡配套数据测试后，再按作者目标修改。

`modules/variables/state3/skill/references/examples/jieling/` 是另一份按周经营的结算教学卡；本例按日经营，人物、动作和状态结构均以本目录为准。

## 改作其他卡时

先替换场景、正文和行动，使每次操作能接回故事；再确定哪些状态、图片与宿主操作需要显示。保留的每项功能都验证一条完整路径，包括失败与重新进入。具体交互验收见[一体界面参考](<../../references/xiaobaix-heavy-ui.md>)。
