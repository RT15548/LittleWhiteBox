# Vibe 检查与修改记录（2026-10-23）

## 一、问题反馈

用户（第三方 NAI 端点）反馈：

1. 切到其他画图预设后，Vibe 勾选被取消；切回原预设后，原本绿色「已编码」的 Vibe 变回「生成时编码」。
2. 跑图时，这些显示为「生成时编码」的图仍提示要消耗 anlas。用户认为已编码的 Vibe 不应重复支付编码费。

## 二、排查结论

静态审查保存 / 加载链路，未发现必现 bug。关键事实：

- 编码按表单当前模型存 key（`v4curated` / `v4full` / `v4-5curated` / `v4-5full`），徽标与跑图按「预设里保存的模型」取 key。
- 切到别的预设后勾选消失是**设计行为**：Vibe 勾选按预设各自保存，Vibe 本体与编码为全局共享。
- 改动编码缺失时的「自动补编回写」逻辑（见下），是「跑图仍扣 anlas」的直接来源。

未完全复现，暂不能排除第三方代理对 cached encoding 的计费行为与官方不一致。需用户进一步提供 console 信息或请求日志才能定性。

## 三、本批修改

核心原则：**编码只允许用户手动发起，杜绝生成时偷偷扣费。**

### 1. 取消生成时自动编码（根因修复）

`novel-draw.js` → `ensurePresetVibeReady`

- 原逻辑：生成前发现当前模型缺编码，会用库里原图即时补编并回写库（此时扣 anlas）。
- 新逻辑：缺编码的项直接跳过，不发起请求、不扣编码费，弹提示「以下 Vibe 尚未编码，本次未应用（不扣编码费）」。

### 2. 编码改为手动按钮

`novel-draw.html` → Vibe 渲染主块

- 未编码：显示紫色「点击编码」按钮，点击才调用 `/ai/encode-vibe`。
- 已编码：显示绿色「✓ 已编码」，点击可重新编码（带二次确认，避免误扣点数）。
- 上传参考图入库后**不再自动编码**，仅入库并勾选。

### 3. 两个参数对齐官方

`novel-draw.html` / `novel-draw.js` / `cloud-presets.js`

- **信息提取**（`information_extracted`）：由二元下拉「高·构图 / 低·色彩」改为 0–1 连续滑杆（默认 1，step 0.05）。
  修改旧编码失效，需手动重新编码（消耗点数）。
- **强度**（`reference_strength`）：修复数字框无法输入的问题（原 input 事件会即时回写覆盖正在输入的内容），改为输入过程只同步滑杆、`change` / 回车才提交重渲染。
  - 说明：调强度**不**需要重新编码，生成时随请求发送；只有改「信息提取」才需要重新编码。

### 4. 文档同步

`Vibe使用指南.md` 相应章节已更新（上传不自动编码、信息提取滑杆、调强度不需重编码、未编码降级规则）。
