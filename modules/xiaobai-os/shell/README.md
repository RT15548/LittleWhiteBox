# Shell 布局边界

## 窗口与应用

电脑上直接打开横向平板窗口；空间不足时铺满可用屏幕。切换 APP 不改变窗口形态，不提供另一套展开入口，也不保存设备模式。

窗口几何、全屏条件、状态栏占位和桌面网格只在 `app-src/styles/index.css` 定义。APP 消费 `--os-status-height`，不再自行判断宿主是不是手机。`XiaobaiOsDevice` 提供 `os-stage` 命名容器；各 APP 按实际可用宽度安排内容，不按电脑型号或指针类型判断布局。

APP 拥有自己的分栏及内容尺度：聊天的列表与会话、业务页面的导航与正文、阅读的材料与语伴、游戏的棋盘与操作。宽屏不等于拉伸文字或强制双栏；专注阅读和填写的详情仍可保持适宜行长。断点和列宽在对应 APP 的 UI 样式中定义，Shell 不保存逐 APP 布局表。

## 生命周期与弹层

窗口变化只改变布局，不触发 `app/activate`、切换 APP key 或重启后台工作。纯布局使用 CSS；确实需要切换语义或卸载不可见重内容时，由 APP 观察自身空间，并保留运行内草稿和阅读位置。

`useAppLayer` 分开管理返回栈与模态隔离。普通弹层默认模态；停靠详情通过响应式 `modal` 参数释放相邻内容的 `inert`，但保留原组件、内容和返回入口。弹层按打开顺序注册，布局变化不重新排序；背景隔离和焦点恢复使用同一个最上层模态面板，不能让先打开的详情遮断后打开的确认框。管理员详情的停靠条件由其 CSS 自定义属性提供，组件只读取这个事实，不复制另一份宽度阈值。

这里不新增存储、Host 协议、模型请求或运行依赖。APP 的 UI 随所属目录和 catalog 注册删除；Shell 只保留被现有 APP 使用的通用窗口与导航能力。

## 验证边界

布局检查必须包含 `xiaobai-os.html` 的完整 Shell、Device 和实际 APP。独立挂载 APP 能验证局部组件，不能证明用户能从酒馆入口到达宽屏布局。

使用有内容的页面检查主操作、列表与详情、滚动、返回、宽窄切换、深浅主题和短窗口。隔离数据可验证布局与交互；真实 Provider 质量、持久化和实体设备性能不由此推定。
