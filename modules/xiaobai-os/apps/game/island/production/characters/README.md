# 荒岛人物制作

这是荒岛自有的离线资产制作工具，不是游戏运行模块。当前只制作叶芮这一名成年女性，并将已认可样模作为她的游戏资产源；其余五名 NPC 的正式美术尚未制作。

## 制作顺序

1. **无遮盖人体灰模**：正、侧、背使用相同正交尺度，先验收头身比、颈肩、胸廓、腰胯、四肢与手脚。不以衣物或内层遮挡替代人体验收。
2. **人物定型**：调整脸型、身体轮廓与自然站姿；完成成熟、漂亮、舒展的外观要求。当前第一名角色的脸、体型与自然站姿已经主人认可，作为后续衣发制作基准，不借衣发制作重新改动人体。
3. **人体变形**：检查抬臂、屈肘、弯腰、屈膝的关节体积、拉伸与穿插。导出带骨骼只证明数据结构，不证明变形质量。
4. **头发与独立服装**：只在前三步通过后继续制作，并分别验收穿脱和穿插。

`clay_review.py` 直接从同一人体数据生成无遮挡灰模；不载入头发、衣物、内层或肤色。其输出独立于先前的穿衣实验。使用与下文相同的 Blender 参数，将脚本换为 `clay_review.py`、输出目录设为独立灰模目录，省略 `--render`。用 `--portraits` 附加正面、四十五度、侧面脸部近景。灰模使用可关闭的细分曲面预览，不改写原始拓扑，也不代表游戏面数预算。人体轮廓检查后，用 `--deformation` 附加四个关节检视姿态，不把动作表生成当成人体已经定型。

主人的身高、体重、罩杯和年龄要求集中在 `ye_design.py` 的 `BRIEF`。身高驱动几何尺度；体重与罩杯是造型要求，不宣称网格具有测定体重，也不在缺少下胸围及尺码体系时伪造精确胸围。艺术形态参数必须经过灰模视觉复核。人体定型前，旧头发、衣物及贴色坐标均不得当作适配完成的资产重新发布。

单独修脸使用 `clay_review.py --portraits-only`，只渲染正面、四十五度、侧面，保存相机对准头部的 `head-clay.blend`。修前、修后使用独立输出目录和相同相机、光照，不覆盖前稿。此模式不与 `--deformation` 同用。只修脸时应比较修前修后原始人体网格及身体骨骼，不能只核对身高：修改头顶的目标会通过全身高度归一化改变身体，有些来源面部目标也夹带头部之外的顶点位移，均需实际核对。眉形参数同样归 `ye_design.py` 所有；上下唇着色分别跟随各自目标的顶点支持域，不以两者混合后的中心裁剪唇色。

胸廓与乳房体积、骨盆横宽与臀部后向轮廓、臀峰高度与臀腿交界、大小腿围必须分别塑形；不能用全身减脂或整体缩放代替。对比使用相同尺度、站姿、相机及光照，不通过扭腰、骨盆前倾或透视美化掩盖底胚问题。当前角色的参数仅属于她，不作为另外两名女性的默认身材。后续角色可以共享拓扑和工具，但需独立的体型设计；去掉衣发、换成相同灰材质与站姿后，仍须有可辨认的轮廓差异。

当前角色的整体方向是娇小、优雅、舒展，不是强调肩臂力量感的体型。胸部横向分布与体积分别调整，不能以减小体积代替纠正外扩。`ye_design.py` 的 `STANDING_POSE` 集中定义她的肩臂、手腕和拇指放松姿态，由灰模检视、站立和行走片段共同消费；绑定姿势不冒充日常站姿。收拢手臂后要检查手掌、拇指与身体及衣物的接触，不以重新架开上臂掩盖手腕内偏或穿插。

## 边界

- 制作参数由 `ye_design.py` 所有；人体数据解析、造型、衣物、动作、构建分别由相邻 Python 模块所有。
- `build.py` 生成可编辑的 `.blend`、包含独立网格与动作的 `.glb`、实渲图片及网格统计。输出写入明确指定的目录，不改变存档、人物设定、GM 或现有场景。
- 输出 `.blend` 是生成物。手工雕刻前另存为工作文件，不能把需要保留的手工编辑放在下次构建将覆盖的输出文件里。
- 本地照片仅供人工观察，不读入脚本、不做脸部贴图、不上传、不打包；样模是虚构人物，不是人体扫描或对真人身体的重建。
- 预览页只显示资产，不具备库存语义。衣物显示开关不是已完成的游戏穿脱；站立/原地行走样本也不等于完整动作系统。
- 四件衣物均为独立网格；各自导出 `garment_id`，检视页据此生成开关，人体没有强制保留的遮挡层。眉毛位置由眼部几何推导，唇色跟随唇部造型顶点，衣物裁剪跟随关节位置；头发使用头顶包络与分层发束，不读取参考照片。
- 头发引导线在头侧到肩部保持切向连续，衣物避让沿发束平滑分摊，不把逐点射线推开当作最终形态。发束使用显式 RGBA 发丝裁切、法线贴图和 glTF `MASK`；必须检查保存重开后的实际透明通道，不能只检查材质声明。头发仍需视觉验收，不因导出契约通过而视为美术完成。
- 动作导出包含自然站姿的颈部和手指基础姿态，不能仅导出摆动的四肢。`motion.py` 同时提供四个关节检查姿态；静态衣物贴合不等于走动或大幅动作下无穿插。
- 不需要运行时依赖、新持久状态、数据迁移或注册入口。删除本目录和指定的本地输出目录即可撤下制作工具；不会影响游戏数据。

## 输入与许可

人体、形态目标、默认骨骼/权重、眼睛来自 [MakeHuman](https://github.com/makehumancommunity/makehuman)。唯一固定版本在 `makehuman_data.py` 的 `SOURCE_COMMIT`；构建会检查本地 checkout 的版本。

本工具只消费其 CC0 图形数据，未复制或导入 AGPL 应用代码。许可原文见来源仓库的 `LICENSE.ASSETS.md`。眼睛、目标和骨架文件也有各自的 CC0 声明。原始数据权利声明包括 Manuel Bastioni、Data Collection AB、Joel Palmius、Jonas Hauquier，具体以输入文件为准。

实际消费的路径：

- `makehuman/data/3dobjs/base.obj`，仅取人体和明确使用的拟合/眼睑辅助网格。
- `makehuman/data/targets/` 下由 `ye_design.py` 的 `MORPHS` 指定的目标。
- `makehuman/data/rigs/default.mhskel`、`default_weights.mhw`。
- `makehuman/data/eyes/low-poly/low-poly.obj`、`low-poly.mhclo`、`eyes/materials/brown_eye.png`。

长发网格、发丝贴图、局部肤色、衣物剪裁及样本动作在本项目本地生成。未把来源的关节辅助立方体作为可见人物网格导出。未使用许可不明的社区头发或服装。

## 制作与检视

从工作区根目录运行；来源缓存和输出不进入游戏包。

```powershell
& 'D:/Blender/blender.exe' -b --factory-startup -t 6 --python-exit-code 1 `
  --python modules/xiaobai-os/apps/game/island/production/characters/build.py -- `
  --source output/island-makehuman-source --output output/island-characters/ye `
  --render all --samples 24

node modules/xiaobai-os/apps/game/island/production/characters/review-server.mjs `
  --asset output/island-characters/ye/ye-sample.glb
```

本地检视入口由服务打印，仅监听回环地址。它使用项目已有 Three.js/GLTFLoader，支持转动、全身/面部/俯视、动作播放、独立衣物显示。所有操作只活在当前页面，没有持久化。找不到文件或解析失败会明确报错，不静默回到方块人。

`tests/test_hair_export.py` 用 Blender 自带 Python 运行：`blender -b --factory-startup --python-exit-code 1 --python <脚本路径>`。它在临时目录保存并重开 `.blend`，再检查导出 GLB 内的实际贴图是否同时包含透明和不透明区域，保护发梢裁切在打包后丢失的边界；不比较文案或源码结构。

## 游戏资产与运行边界

[游戏导出器](gameplay_export.py)直接打开已经认可的本地样模，导出[叶芮游戏资产](../../assets/characters/ye.glb)，不重新运行人体造型或覆盖源样模。原人体、脸、头发、四件衣物与站走曲线保持；新增救生衣、鞋、足部包裹以及休息、劳动、建造、饮用、清洁、递出、拖行、死亡动作。[导出复核](gameplay_check.py)检查保存重开后的骨架、动作、接地和世界根不动；预览图片不能替代实际场景检查。

[资产适配器](../../presentation/character-asset.ts)由场景加载生命周期持有。角色实例拥有自己的骨架和衣物材质，几何与贴图共享到场景退出时释放；离身衣物由同一蒙皮网格烘焙，保持款式与尺寸。GLTFLoader 会清理骨名，挂点按同一规则查找，不建立另一套骨名猜测。手持物跟随右手，标签跟随头，死亡使用骨内卧姿，不再叠加整体下沉。

衣物是否出现、款式、湿度和去向只取真实物件；[衣物目录](../../clothing.ts)集中定义款式、穿戴层、线性色和游戏接触高度，不把款式放在穿衣者身上。场景只回放已经确认的位置和活动；站走的足底校准仅作用于临时视觉组，不缩放人体、不改变世界坐标或时间。外部观察只补充可见劳动种类，以及正在使用的本人随身饮食物件外形、湿度和手持份数，不携带物件 ID、容量、其他库存、任务目标、私有身体状态或剩余工时。

原样模预览仍是独立美术检视工具，衣物开关没有库存语义。游戏加载失败明确显示重试入口，不回退成旧占位模型；退出时取消尚未完成的加载。另一五名 NPC 与玩家仍使用原程序化人物。本接入不等于六人美术或完整章节制作完成，也没有逐物件握持、布料仿真或精细工序动作。

从工作区根目录导出和复核；添加 `-- --render` 可附加坐姿和递出姿态图片：

```powershell
& 'D:/Blender/blender.exe' -b --factory-startup -t 6 --python-exit-code 1 `
  --python modules/xiaobai-os/apps/game/island/production/characters/gameplay_export.py
& 'D:/Blender/blender.exe' -b --factory-startup -t 6 --python-exit-code 1 `
  --python modules/xiaobai-os/apps/game/island/production/characters/gameplay_check.py
```
