# 普通小白 OS 世界 APP：施工与验收记录

## 1. 当前决定与范围

记录日期：2026-09-06。产品定位见 [世界 APP 设计](./world-app-target-design.md)。

原生 ↑Char 加载事件的请求隔离验证失败后，用户明确改为 **System @D4**，并要求继续施工。本版已接入世界 APP、桌面图标与 D4 短背景；没有把失败的世界书临时条目方案留作运行分支。历史证据见 [↑Char 验证记录](./world-app-native-injection-verification.md)。

世界是镜头外的轻背景阅读 APP，不是任务、剧情导演或百科。首版后用户确认：将已保存的世界新闻直接加入任务、地图现有素材包，本次已接通。信息联动、ENA、小白板迁移与退场不在本轮范围。不自动提交或推送。

### 1.1 已确认行为

- 玩家订阅并阅读当前新闻；作者设定约束创作，新闻不必等玩家亲历才出现。
- 维护同一组见闻：延续、保持、退出与加入均可，不要求每轮制造新事件。
- 主剧情只收到概况与独立摘要；文章正文供玩家阅读，不等同于角色已经知情。
- 不建设人工纠正环境、历史档案、逐条编辑、点赞或已读系统。

### 1.2 首版运行参数

| 项目 | 已采用规则 |
| --- | --- |
| 初始偏好 | 全局自动新闻关闭；全局「作为剧情背景」开启；不从某个旧聊天推定全局意愿 |
| 订阅 | 保存意愿后申请首批；之后每个有效接受轮参与维护，可能使用模型但内容不变 |
| 无开场正文 | 保存订阅意愿，等待开场；打开页面本身不生成 |
| 取消订阅 | 停止自动维护并使未提交的所属运行失效；保留新闻和背景偏好 |
| 手动刷新 | 无需已订阅，沿用当前新闻 |
| 容量 | 最多 8 条；ID／标题／摘要／正文／概况分别最多 64／64／120／800／320 Unicode 码点 |
| 投影预算 | 初始资料安全格式化后不超过 16,000 码点，超出时省略正文并说明；主剧情短背景含说明不超过 2,000 码点，超出时选取完整概况／摘要，不影响原文保存 |
| 历史分支 | 开关仍读全局设置；清空概况与新闻，在子线重新建立 |
| 完整复制、改名 | 保留当前内容，后续各聊天独立维护 |

## 2. 所有权与终态结构

```text
domains/world/              当前模型、字段校验、原子编辑、纯数据读视图
apps/world/
  descriptor / partition / module / production-module
  prompt-data               后台资料包装与注入预算
  application/              分区服务、内容并发比较
  settings                  全局偏好规范化，通过 OS settings repository 保存
  storage/                  正式线历史文件的入口升级
  maintenance/              领域 Prompt、工具契约、运行内候选
  host/                     控制器、维护注册、D4 投影与生命周期、分支处理
  ui/                       刊物首页、独立文章页、本地图标与样式
```

- 唯一事实来源：内容为当前聊天 sidecar 的 `world` 分区；开关为用户级 `xiaobaiOs.apps.world` 设置。卡片、激活世界书、近期剧情及既有有界总结为只读背景，不再建世界书副本。
- 持久态：两个开关是跨聊天、跨重启的用户意愿，由既有 settings repository 串行保存，失败恢复旧值；概况／新闻是各聊天长期事实，由分区服务拥有写入和删除生命周期。请求及队列不持久化。
- 临时态：候选、未解决的工具错误、请求 token、注入快照、文章快照、滚动与焦点。不新增持久化版本号、运行日志、缓存或世界时钟。
- 外部依赖：既有 ScopedChatStore／文件恢复、maintenance／Provider、宿主生成生命周期与浏览器 SVG／CSS；无新增运行依赖。
- 注册：Host／Shell catalog、Shell 懒加载、生产组合、World module 的分区／维护／Prompt 接口；可选资料通过 World 自有只读 context capability 提供。核心维护层不识别 World 业务。
- 删除：先停止并注销 World 运行和监听，清除 `world` 分区、`xiaobaiOs.apps.world` 全局设置及其注入键，再删功能目录、注册、任务与维护素材包中的只读接入，重建产物。无需修改聊天正文、作者世界书或其他 APP 数据。
- 兼容：依赖现行 SillyTavern、浏览器、Provider 与 sidecar 协议。正式线 World v1 文件在分区解析入口一次性转换，保留内容，不把旧聊天开关推广到全局；运行时只认当前模型。不迁移正式线小白板数据。

## 3. 数据、工具与保存边界

内容格式为 `{version:2,overview,news}`；`{subscribed,injectToStory}` 只存全局设置。旧 v1 文件只读打开时不重写，下次内容提交使用 v2。每条新闻仅含 `{id,title,summary,body}`。未知字段、重复 ID、空标题／摘要／正文和超限字段在领域入口拒绝，不自动截断或丢条目。存档合法性不依赖注入说明文字或安全转义后的长度；领域不依赖提示词格式化。

模型初始数据与 `WorldRead` 共用 `{overview,news}` 投影，不外露偏好、存储版本或宿主对象。初始资料通常完整；安全格式化后超过 16,000 码点时，仅在输出副本中将所有正文置空，并明确说明正文省略、其余字段完整。当前字段上限保证摘要视图在最坏转义情况下也能放下。`WorldRead` 参数为空，始终返回完整投影，可补读省略的正文或核对编辑后的候选，不返回 Edit 的状态包装。工具读取不受初始资料预算截断。

`WorldEdit` 接收可选 `overview`、完整条目 `upsert`、ID 列表 `remove`：

- 省略概况保留，空字符串清空；省略新闻原样保留。没有 null 或局部新闻合并语义。
- 同一 ID 延续原条目，原条目保留顺序；新条目按输入次序置于前面。
- 删除不存在的 ID 是成功但无变化；同批重复或增删冲突拒绝。
- 整批校验后才替换候选；任何错误不产生部分删除、部分概况或残缺文章。
- 返回 `{ok,status,changed,data:{overview,news},errors:[{path,message}]}`；`status` 为 updated／unchanged／failed。unchanged 是成功，不要求重试。
- 失败批次按受影响概况／文章记录运行内未解决项。后续无关编辑不能抹掉失败；成功调用的 errors 仍说明此前待修正项，解决后才能提交。无法识别有效条目的坏调用可用合法的具体编辑纠正。
- 放弃失败的新稿可 `remove` 其 ID；已有文章的 `remove` 是真实删除。若只放弃对已有文章的修改，先从 `WorldRead` 取原值再完整 `upsert`；概况同样可重交原值。合法的 unchanged 修正会解除对应错误，不要求制造新变化。

提交比较原 `{overview,news}`、聊天身份和维护 guard，不以另一 APP 的写入或全局开关改变作为正文冲突，无额外持久化 revision。

只有确认保存的内容进入界面和注入。World 声明 `complete-run` 提交策略：工具循环完整结束且本领域没有未解决错误后，才发布整期候选。网络中断、空返回、轮数耗尽或未解决的工具错误均保留旧刊物，不保存中途删除或替换的结果。共享执行器不认识领域名；未声明此策略的地图等领域继续保留合法的部分结果。

保存失败保留旧内容；未确认的候选交给现有文件恢复，UI 提供「核实保存」，不会再生成一份覆盖它。

## 4. Prompt 分层与内容标准

实现遵循 `writing-model-prompts`，原型为助手的 `system-prompt.js` 与 `tooling.js`。

| 层 | 归属与事实依据 |
| --- | --- |
| 共享说明 | `capabilities/maintenance/provider-tool-loop.ts`：身份、背景资料、跨领域流程和唯一收尾，World 不重复 |
| 领域判断 | `apps/world/maintenance/prompt.ts`：镜头外新闻、具体看点、依时间延续、公开消息与传闻／私密知识边界 |
| 工具契约 | `apps/world/maintenance/tool-contract.ts`、`domains/world/edit.ts`：原子批次、返回形状、顺序、失败修正和字段语义 |
| 初始资料 | `maintenance/session.ts`、`apps/world/prompt-data.ts`：复用纯数据投影，包装完整或省略正文的资料说明并控制预算 |
| 主剧情资料 | `apps/world/host/story-projection.ts`：已确认概况与摘要、镜头外背景定位，安全格式化并选择放得下的完整段落 |

模型说明默认使用英文，新闻语言随当前故事。主剧情背景说明也保留英文，不因相邻块使用中文而额外改写。无运行提示词写入持久化文档。领域块点名实际资料标签与缺少正文时的读取入口；首刊以资料能否支持符合场所、时代或生活方式的具体镜头外事件为判据。工具保留字段限额，不要求模型计算转义后长度；共享层按各工具实际应用／拒绝结果指导修正，不暗示失败原子批次会保留部分修改。

真实生成评审看：是否有具体而独立的看点、是否体现世界的文化和生活、是否不依赖玩家参与、是否依据经过的时间延续、传闻和事实是否保持各自确定性。轻背景不等于每条鸡毛蒜皮，也不等于每条危机。明确剧情能纠正旧背景；私人内容不会自动变成公开报道。

这些是产品质量标准，不另加评分 Agent、喜好画像或自动评分存档。手写测试数据不证明模型能写好。

## 5. 订阅与维护生命周期

自动维护沿用现有有效接受轮；全局自动新闻开启时，当前聊天直接参与，不需要先打开 APP。首次开启和手动刷新使用 `startRebuild('world')` 的有界历史输入，但 World 候选仍从旧内容开始，不清空重建。

首次开启先检查 Agent，保存全局偏好后仅在当前聊天内容可写时启动。内容保存待核实不锁住全局开关。空聊天保存意愿后等待；API 配置不足给出 API 应用入口。打开、阅读、返回、重进只读本地。

全局设置保存失败保留旧开关，不生成、不取消进行中的更新；保存成功后已获准的首次更新不依赖页面停留。控制器以运行内取消代次覆盖保存等待期：切聊天、停用或明确取消后，这次首次更新永久失效，即使回到原聊天或重启后台也不续跑；不撤销已保存的全局意愿，不影响之后的新请求。新闻文件的核实／恢复只处理内容，永不触发首次生成，不另存续跑标记。

确认关闭自动新闻时使 World 的 requested／automatic token 失效，重新开启不会复活旧请求。切聊天、停用 OS、修改／删除本次捕获依据使未提交运行失效；切换 APP、关闭 OS 窗口和追加新消息不取消更新。手动与自动采用相同来源守卫，只要求已捕获依据保持有效，不冻结未来消息数量。取消只针对 World，不停止队列里其他领域。

历史分支在 clone 边界清新闻，父线不受影响。`host/production-composition.ts` 分别组合 Messages 和 World 自有分支处理器，不把 World 逻辑放进 Messages。

## 6. System @D4 接入

`host/sillytavern-runtime-adapters.ts` 的现有 `setSillyTavernPrompt` 增加可选 depth，默认仍为 1。World 明确使用 4；Map 按后续确认的空间背景定位明确使用 3，Tasks／Shop 默认 D1 不变。

- 原生位置为 IN_CHAT、SYSTEM、depth 4，`scan=false`。不再注册世界书加载监听，不读取或写入作者条目，也不受 ↑Char 区块开关和世界书条目预算支配；最终请求仍遵守宿主的上下文组装。
- 本次主生成拦截时，从当前聊天已确认内容取一次快照。维护后到的新内容从后续请求生效，不等待维护。
- 支持 normal／regenerate／swipe／continue；quiet、impersonate、dry-run 不经 World 注入入口。
- 请求已组装、结束、取消、切聊天或停用时清除所属注入键。关闭背景也清除待组装投影。
- 只投概况与摘要，不带正文、内部 ID 或偏好。文本经过安全格式化；宿主宏与标签不从新闻内容逃逸执行。
- 超过 2,000 码点时先计入说明开销，再按原顺序选择放得下的完整概况／摘要，标明有省略。过长概况可跳过，继续选择摘要；一段也放不下则不注入。不截半句话或转义序列，不更改存档和阅读内容。

### 6.1 真实宿主验证证据

在独立数据目录启动 SillyTavern 1.18，未读取或修改用户聊天，未请求 Provider：

- 实际运行时适配器设置 SYSTEM／IN_CHAT／depth 4／scan false，原 D1 对照不变。
- 原生 `prepareOpenAIMessages` 组装结果中，World 后恰有四条历史消息。
- 文本补全 `Generate(..., dryRun=true)` 搭配固定 D4 扩展提示，也保留四条历史消息；此探针证明宿主文本组装位置，不冒充生产 dry-run 会注入 World。
- 主扫描与后台 dry-run 扫描交错时，World 文本没有激活关键词测试条目；实际 OS PromptContext 捕获也未混入新闻。
- 覆盖 normal／regenerate／swipe／continue 的生命周期清理、取消、dry-run／quiet 排除、切聊天和卸载。

聊天补全／适配器探针有 21 条实际断言；另有文本补全组装探针。脚本与隔离数据位于忽略目录 `output/playwright/world-native-gate/`，不随产品打包。

尚未覆盖真实群聊完整生成、用户复杂预设组合与 WebView；不将这些标为已通过。

## 7. 世界窗口 UI

用户确认替换初版复古小刊风格。继承 OS 字体，近白底、墨色正文与浅蓝远景，深色中性炭黑/柔白与夜色。主标题 22px、新闻标题 16px、摘要 13px，保留触控热区，不同时放大所有元素。本地 SVG 仅是抽象品牌远景，不代表世界内真实地貌；没有远程字体、素材服务、模型配图或新依赖。

首页只有一个「世界」标题；开篇图与概况分离，概况最多预览两行，主动展开才看完整内容。下方直接排列同级新闻，不再加栏目眉题、计数和逐条箭头；标题与摘要分别最多预览两行。内容区宽度达到 640px 时两列，其余单列，不改 Shell 窗口尺寸。删除首篇特大排版、编号、印章与口号。文章页展示完整标题和纯文本分段正文，不重复摘要、不执行 HTML。

空态主操作为「开启自动新闻」，说明会使用模型。已有内容后顶部可刷新，自动新闻和背景开关进入右上菜单，注明全局生效。更新中旧文章可读；失败就地提示，提供重试或保存核实，不反复弹通知。

阅读文章持有临时快照；后台修改时提供「阅读新版」，删除后仍能读完当前快照。返回恢复原列表滚动和条目焦点，条目已移除时聚焦首页标题；打开或显式读取新版后聚焦文章标题。菜单支持 Escape 和点击外部关闭。没有虚构发布时间、未读红点、热搜或往期档案。

所有权：`WorldApp.vue` 编排页面与现有操作，`WorldOpening.vue` 只负责视觉开篇和概况展开，`NewsArticle.vue` 负责正文阅读；SVG 与样式留在 `apps/world/ui/`。唯一内容来源仍是现有确认状态，展开状态和阅读快照不持久化。移除世界 APP 时随目录退场，没有共享层新注册、新字段或迁移。

## 9. 项目检查与交付

### 9.5 世界 APP 误报聊天切换修复

- 根因：宿主运行时身份以角色列表编号组成，sidecar 身份以角色文件名组成；世界 APP 把两者直接比较，导致单角色聊天打开失败，也会阻止维护会话及背景资料读取。
- `WorldView` 明确区分临时的运行时 `chatIdentity` 与存储 `identityKey`：UI、维护来源与资料消费者比较前者；偏好和新闻提交仍使用后者。读取仅来自当前聊天的 scoped store，没有修改宿主身份规则、存档字段或数据版本。
- 偏好操作在异步预检前捕获存储身份，保留现有页面 guard 和事务 guard；真正切聊天仍拒绝旧操作。没有迁移、清空新闻或增加自动模型请求。
- 回归覆盖两种身份不同的打开／订阅／生成保存／状态推送／重开，以及背景开关、D4 确认快照、任务／地图资料读取和切聊天隔离。测试通过真实服务、维护队列和事务存储链路运行，Provider 与宿主事件由测试提供；不等同于真实浏览器或真实模型验收。
