# DICE：D100 属性鉴定与全局人物属性

本文定义当前 D100 属性鉴定的面板、请求、裁定与数据边界。

## 1. 终态与范围

玩家拥有一份全局面板：属性与通用技能的完整清单见[能力目录](../apps/dice/domain/coc7-catalog.ts)。用户直接加点或一键随机后手调；AI 选择一个能力和难度，程序查值、掷百分骰、记录裁定，再由 AI 续写。

对外名称为“D100 属性鉴定”，设置与结果卡共用界面文案中的规则名称。提示词以 `CoC 7 (modified)` 说明机制来源：这是适配酒馆 RP 的改良百分骰规则，不是原版 1920 年代调查员建卡。能力范围跨时代，具体用途由目录统一定义。没有独立 NPC 面板，也没有职业、年龄、装备或战斗资源管理。内部 `coc7` 标识不因产品命名变更而调整。

不维护体型、幸运、HP、SAN、MP、伤害、护甲与衍生加值。不增加双方对抗、奖惩骰、战斗轮、成长或孤注一掷。

D20 的规则和频率、随机遭遇及共用运行生命周期统一见 [Dice 总设计](./dice-app-target-design.md)。

## 2. 能力与加点规则

### 2.1 唯一事实来源

[能力目录](../apps/dice/domain/coc7-catalog.ts)拥有稳定 ID、能力名称、结构化用途词和属性／技能分类；用途说明由词表派生，请求解析、查值、UI 和模型清单都引用同一份数据。本文不复制完整技能目录。

属性与技能是独立的检定入口，不相加、无派生修正；按目录用途选择最贴近主要不确定性的一项，不额外拆出衍生能力。

[CoC 请求契约](../apps/dice/protocol/coc7-contract.ts)与面板直接引用目录的同一份中文名称和用途，保留用户定义的分类术语；不另维护翻译版用途清单。别名匹配读取用途词表，不反向拆分界面说明，也不以界面文案作为内部查值键。

### 2.2 独立点数池

[面板领域规则](../apps/dice/domain/coc7-sheet.ts)集中定义每项上下限、调整步长和两组随机档位；每组预算由档位之和派生，UI、生成与保存校验引用同一份事实。

属性与技能各有单项下限，共用上限和步长；具体数值与两组预算见领域规则。两池不能挪用，允许留点，合计不超过各自预算即可保存。以上是酒馆改良规则，不冒称官方快速建卡法。

[建卡操作](../apps/dice/domain/coc7-creation.ts)负责：

- 空草稿直接包含所有能力，初值为每项最低值；最低值已计入预算。
- 手调通过增减操作遵守上下限及剩余预算，不允许全加满。
- 一键随机在各组内打乱固定档位，得到完整合法草稿；随后可按点数规则自由调整，不限于档位交换。
- 草稿操作不修改已保存面板，只有显式保存才生效。

保存模型仅含 `attributes` 和 `skills` 两个数表。严格检查字段、能力 ID、整数、步长、范围及各组预算上限；不强转、不截断、不补项。最低值或未花满的面板合法，即使绕过 UI，也无法保存超预算或其他非法加点。

### 2.3 全局与损坏隔离

面板存于当前 SillyTavern 用户的全局文件 `dice` 分区，不绑定角色卡、聊天或用户角色。切聊、换卡、关闭功能、切回 D20 和刷新均保留；事务与保存恢复见[经济平台设计](./economy-platform-target-design.md)。行动检定开关仍由全局设置保存。

分区加载保留面板原文，由 Dice 临时投影为未建立／可用／无效。旧格式或损坏面板只暂停新 CoC 检定，不能阻断 OS 或无关设置写入。明确保存新分配或确认重置前，原数据不变；不补旧测试版缺失的能力、不自动分配新点数。保存新分配不收费；只有明确重置才按重置规则收费。

## 3. 人物属性弹窗

设置页选中属性鉴定后提供“人物属性”入口，不直接铺满整张表。打开即看到所有能力、属性与技能剩余点数；无需先随机。底部一键随机、取消修改、保存与顶部预算固定可见，中间内容独立滚动。

| 状态 | 行为 |
| --- | --- |
| 尚未建卡 | 所有项从各组最低值开始，可直接保存、手工分配或一键随机 |
| 编辑中 | 显示未保存，增减立即更新剩余点数；无需花满即可保存 |
| 保存成功 | 清除草稿，正式面板更新，后续新回复使用新值 |
| 保存失败 | 保留原面板和草稿，错误就地显示，可重试而不重新随机 |
| 无效面板 | 即使关闭行动检定或选 D20，仍提供修复入口；保存替换前保留原文 |
| 重置 | 二次确认，费用由[重置规则](../apps/dice/domain/coc7-reset.ts)定义，扣款和清空面板属于同一事务；保留聊天、骰子历史与规则偏好；失败保留原文 |

弹层复用 AppDialog、焦点管理和 OS 返回栈，背景不可操作。关闭按钮、遮罩、Esc 或一次 OS 返回只关闭弹窗；同一 Dice 页面重新打开保留草稿，取消修改才还原正式面板。退出 Dice 后草稿释放，不另加持久化状态。保存期间禁用修改及关闭。

不要求姓名、职业或背景，不增加 NPC 管理、自定义技能编辑器或第二个角色页面。

## 4. 模型请求与提示词

### 4.1 最小请求

仍使用现有 Tagged JSON、末尾暂停、Markdown 保护与正文骰子标记，不增加模型调用或原生工具。

| 字段 | 含义 |
| --- | --- |
| `action` | 本次尝试及目标 |
| `stat` | 能力字符串，模型优先使用当前能力目录中的稳定 ID |
| `difficulty` | 难度标识；可用值与对应阈值规则见 [CoC 难度配置](../apps/dice/domain/coc7-request.ts) |

三个字段均必填。请求契约与解析器共用字段定义及能力目录；模型多写的 KEY 在请求入口忽略，非法难度或缺失／非字符串／空白／超长的必需字段仍拒绝，不修补 JSON。额外字段不参与查值、裁定或保存，历史记录校验不放宽。可执行示例唯一放在模型契约中，并由正式解析、查值与执行测试验证。

能力字符串由[能力解析器](../apps/dice/domain/coc7-stat.ts)统一处理：

1. Unicode NFKC 规范化（含全角转半角）、去括号字符与首尾空白，英文 ID 忽略大小写。
2. 精确匹配当前 ID 或能力名称。
3. 精确匹配目录用途词。
4. 匹配字符串中包含的能力名称或用途词；同一能力命中多个词仍只算一项。
5. 各层只有唯一命中才取面板值；某层命中多项即判为歧义，不按目录顺序选取。没有命中或存在歧义时使用解析器定义的固定未受训基数。

命中已有项时使用其真实数值，即使低于未受训基数也不抬高。此兜底只处理能力名称，不能绕过缺少／无效面板、非法难度或次数上限。随后全部共用现有百分骰算法，无第二套判定，也不新增模型调用或随机基数。

### 4.2 提示词的职责顺序

1. 说明改良规则的机制来源，并明确面板仅属于用户扮演的角色，每次请求判定该角色的行动或应对；模型仅选择能力与难度，程序查值。注入从目录派生的 `ID=名称（用途）` 紧凑清单，不注入面板数值。
2. 玩家目标结果不确定且失败有实际后果时检定；同一目标覆盖其组成动作，不逐个动作重复掷骰。
3. 选与主要不确定性相符的一项属性或技能；难度表达障碍与做法，不因能力低再加一次难度。
4. 叙述尝试后请求检定，在结果之前暂停当前消息；收到确认结果后承接同一消息。

NPC 自身不发起检定，其阻力通过用户角色行动或应对的难度表达，不维护或临时编造 NPC 面板。检定对象由提示词指导模型选择，解析器不推断 `action` 自然语言中的角色身份。属性鉴定不受 D20 标准／积极设置影响，也不规定每回合必掷次数。

本功能不额外规定外表的叙事含义或角色塑造，也不增加世界观、装备或能力来源设定。骰子机制与叙事分离、既定结果承接以及额外收益或挫折的尺度遵循共用结果提示。

继续写作时是接续同一消息，而非新楼层。结果回注说明跳过新消息的开场标记（含 `<-begin-response->`）、引导语与书面思考；该说明不禁止完成消息时输出预设的结束格式。发起检定时则是中途暂停，暂不输出结束格式。两者职责不同。

### 4.3 没有可用面板

不注入发起新 CoC 检定的契约，也不执行新 CoC 请求；普通聊天不受阻。界面说明需要分配并保存，不让模型追问或编造数值、不回退到 D20。

历史卡片及已掷结果续写不依赖当前面板。结果回注使用 `result.verdict` 表示是否达成目标，`result.level` 表示成功等级；混合 D20／CoC 历史按各自已记录结果解释。

## 5. 裁定与历史记录

各难度的阈值规则统一定义于 [CoC 难度配置](../apps/dice/domain/coc7-request.ts)，由[CoC 裁定](../apps/dice/domain/coc7.ts)执行；百分骰阈值按规则计算并向下取整。程序采样个位与十位，组合为 1–100；临界结果优先，成功等级与本次难度是否达成分别记录。

校验请求、面板、历史、目标消息与次数上限后才采样；重试、动画和刷新显示不重掷。单回复总次数仍引用共用 `MAX_ACTION_CHECKS`。

当前消息记录为 schema 3。CoC 记录保存行动、**能力显示名称快照**、难度、完整检定值、阈值、骰面、等级与达成结论，不复制整张面板。正常 ID／名称没有额外说明；名称映射记录可选 `resolution`（原词），未受训记录未命中或歧义原因，原词保留在 `request.stat`。这些说明随已有检定事实保存，由 Dice 所有，生命周期及删除路径与原记录一致，不新增独立存储或补存任务。

名称快照和对齐说明只用于卡片及结果回注，不作为当前查值 ID；当前格式中的已掷结果不随面板编辑或目录变化而重新匹配、查值或裁定。卡片在能力位置直接显示原词到命中项的映射，或未受训来源与已用基数，难度折算沿用原有展示。这不意味着兼容旧测试格式。

### 5.1 读取边界

- 正式线 D20 的 schema 1 由[冻结 V1 读取器](../apps/dice/storage/records-v1.ts)直接读取为当前记录，不经过测试线中间版本；D20 数值、ID 和裁定不变。真实正式线样本见 [a32c28d0 fixture](../tests/fixtures/dice-message-a32c28d0.json)。
- 当前记录按 schema 3 校验；包括 schema 2 在内的其他版本明确拒绝，不猜测或转换旧 CoC 能力。schema 编号是实现细节，不作为兼容承诺。
- 读取生成新对象，不主动改写消息原文；新检定应用时才随正常宿主保存写入当前格式。

CoC 测试线旧目录与中间 schema 不作为受支持格式。无效面板保留原文供用户显式处置，不代表支持旧运行模型；不批量删除用户聊天。

## 6. 运行、保存与所有权

每次新回复开始时捕获已确认规则与面板。本次回复及其自动续写共用内存快照；中途保存面板或切换规则只影响下次新回复。已掷结果重试直接复用记录，不重新查面板；新楼不额外注入前楼骰点。

长期状态只有全局玩法偏好、面板及消息／候选中的检定事实。草稿、运行快照、动画、错误与取消状态均只在内存。保存失败不发布候选状态，不新增 NPC 实体、资源表、缓存或补存任务。

| 位置 | 所有职责 |
| --- | --- |
| `apps/dice/domain` | 目录、点池、草稿操作、严格校验、查值、裁定与当前记录 |
| `apps/dice/storage` | 受支持旧记录的冻结格式及读取转换 |
| `apps/dice/settings.ts`、`partition.ts` | 全局玩法偏好与用户文件面板分区 |
| `apps/dice/protocol` | 请求契约、提示词及结果投影 |
| `apps/dice/application`、`host` | 运行快照、会话与消息生命周期 |
| `apps/dice/ui` | 人物属性弹窗、设置入口、检定卡片 |

复用现有 production-module 注册、行动检定会话及宿主消息入口，不增加依赖、独立 APP、模型服务或跨业务抽象。

## 7. 删除路径

清空属性仅移除全局面板。若删除 CoC 功能，先明确其面板、规则偏好及历史数据的迁移／丢弃策略，再删除 CoC 模块与接入点；保留 D20 和随机遭遇。删除整个 Dice APP 才移除 Dice 注册与全部自有数据。

旧快速建卡的目录、派生资源、职业／兴趣分配、编辑控件和测试已按当前模型替换，不保留双套建卡入口。旧面板只作为待用户显式处置的原数据存在，不保留旧运行模型。

## 8. 最少必要验证

- 领域层：独立预算、单项边界、步长、随机覆盖、无随机手工完成、非法输入不改原数据；百分骰临界规则与等级／达成分离。
- 协议层：每个当前能力及用途词均可查值；规范化、包含匹配、歧义／未知基数与低值不抬高；提示词示例可执行且不外露面板；无效请求在采样前拒绝。
- 设置及组件：保存／清空失败保留数据，修复不阻断 OS，取消与关闭草稿语义，全局重载。
- 会话与历史：同回复快照、当前记录重试不重掷，真实正式线 D20 直接读取为当前格式，混合记录、候选及元数据不变；名称对齐及未受训依据随记录重载与回注，不重新计算；不支持的版本明确拒绝。
- 浏览器：真实组件与导航，窄屏、深浅主题、放大、触控、键盘、焦点、滚动及错误恢复。

测试保护状态、数据与事件，不以提示词措辞、函数名或源码关键词作为契约。真实模型的技能选择与叙事表现不能用模拟供应商证明。


真实模型的能力选择和叙事表现、实体 WebView 尚未验收。裁定资料参考：[Chaosium The Game System](https://cthulhuwiki.chaosium.com/rules/game-system.html)。通用技能与点数池属于产品改良设计，不冒称原版建卡规则。
