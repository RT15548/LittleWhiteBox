# Dice 随机遭遇：施工与验收方案

日期：2026-09-14～15。状态：已按用户确认收简为本地判断＋原生注入。遭遇不再独立保存整聊，不等待保存确认，也不提供保存重试。本文保留用户确认的行为与施工边界；实际通过项、证据和未验范围见 [随机遭遇验收](./random-encounter-verification.md)。

总目标见 [Dice 总设计](./dice-app-target-design.md)。行动检定及其 D20 卡片已有实现，本批次不重做其规则、动画或续写链。

第 5.4 节的原生 D1 注入、第 6 节的双开关与用户楼层轻提示均已落地；未引入额外剧情 Agent 或模型请求。

## 1. 终态与本次边界

同一个 Dice APP、两个按聊天保存且默认关闭的开关。行动检定决定行动成败；随机遭遇决定本轮有没有一个变数、影响多大。二者各自拥有领域和运行，组合在 Dice 模块，不把随机遭遇做成行动检定的一个阶段。

本批次包含：互斥抽取、用户回合幂等、冷却、用户楼层附属提示、三档各一句基础提示，以及按世界／总结开关拼接的一句弱参考。Dice 不读取或分析这两个模块的内容。不增加独立剧情 Agent、事件池、概率编辑器、素材数据库或自动更新任务。状态栏与 D100 不在本批次。

## 3. 固定行为契约

### 3.1 一次抽取与影响等级

| 结果 | 概率 | 唯一随机数 `r` 的区间 | 叙事尺度 |
| --- | --- | --- | --- |
| 高影响 | 1% | `0 <= r < 0.01` | 允许明显改变局面，但不替用户作决定、不直接结算重大后果 |
| 中影响 | 3% | `0.01 <= r < 0.04` | 提供新的可回应情况，同时保留当前互动继续进行的空间 |
| 低影响 | 5% | `0.04 <= r < 0.09` | 当前互动中的小变化，可忽略、不要求转移注意、不另起事件 |
| 不触发 | 91% | `0.09 <= r < 1` | 不发送遭遇指令，不显示触发提示 |

合格且不在冷却期的每个新用户回合只调用随机源一次。生产使用本地随机源；边界测试传入确定值。非有限值或不在 `[0, 1)` 的值是错误，不能当未触发或自动再抽一次。

三档互斥，总概率 9%。不是分别独立抽三次，也不是先抽 9% 再第二次抽等级。概率和冷却不交给模型执行，世界／总结不影响概率。

程序不判断“这个场景适合几级”，不自动改等级。低影响不是“小灾难”，高影响不是必然灾难或奖励；具体落实由主模型结合已有剧情完成。

### 3.2 用户回合与冷却

回合以宿主已入楼的真实普通用户消息为准，不以点击发送、模型请求次数或 AI 回复数为准。资格来自本次主生成流程确实新增的用户消息；仅仅尾楼是用户消息不够。

- `normal`／普通群聊生成中新建用户消息：符合当前开关与真实消息条件时才能首次决策。
- `regenerate`、`swipe`、`continue`：只读本轮已有记录；缺失不补抽。
- quiet、impersonate、dry-run、私人信息等非主 RP 投影、无新用户输入的自动群聊：不创建回合。
- 开启功能、打开页面、重载历史、消息重绘：不创建资格。已存在但从未记录的历史楼层不补抽。

任一等级在 U0 触发后：

| 用户回合 | 行为 |
| --- | --- |
| U0 | 保存触发等级，供本轮模型使用 |
| U1 | 冷却跳过，不调用随机源 |
| U2 | 冷却跳过，不调用随机源 |
| U3 | 如仍启用，恢复一次抽取 |

冷却仅从当前消息之前最近两个真实用户回合的触发记录推导。不是找最近两个“有 Dice 数据的消息”；关闭功能期间的真实用户回合也占回合位置。冷却跳过本身不产生新的冷却。

本轮已有记录永远先复用，包括未命中、冷却跳过与各触发等级。重生成不重新计算旧决策，不累计冷却。删除／分支后，下一新回合按当前实际保留的用户消息推导；不存在的未来楼层不参与。

### 3.3 群聊与行动检定续写

一条用户消息只有一个判断。遭遇指令用于本轮第一个实际主 RP AI 回复及该回复的继续；其后其他成员不各自接收一份“再制造变数”的指令，但仍可自然回应已写出的情境。

Messages 私人信息投影不计为主 RP 回复。使用所有者已有的投影分类，由宿主组合层传给 Dice；不按角色显示名猜测，也不让 Dice 直接导入 Messages 实现。

归属以本轮首个真实 AI 楼层为准；楼层尚未生成时只在运行内捕获成员，不持久化轮转游标或成员任务。该楼层重生成／新 swipe 复用用户记录；后续成员重生成不重新触发。若首回复整个失败且未留下 AI 楼，重试仍使用用户楼层已保存的同一判断。

行动检定的自动 continue、用户手动 continue 都不推进冷却。对于遭遇所属回复，续写使用同一等级的通用提示，参考方向仍按当前开关拼接。不附加续写专属要求，也不记录某个叙事事件是否已落实。

## 4. 记录、保存与失败路径

### 4.1 当前格式

Dice 分区增加 `encountersEnabled: boolean`，默认 false；原 `actionChecksEnabled` 保持独立。关闭遭遇不能取消行动检定的动画或续写，关闭行动检定不能清除本轮遭遇指令。

用户消息的 `extra.xiaobaiOsDice` 使用当前版本标识与 `encounter`；`encounter.outcome` 是 `high | medium | low | none | cooldown` 中的一个值。前三个值即影响等级，不再存一份可能矛盾的 `triggered` 布尔值或独立 `level`。用户消息不保存空 `checks`；AI 候选仍只拥有检定记录。

记录解析按消息角色区分当前模型，不把这做成旧版／新版分支。现有 AI 检定记录形状无需因新增用户记录而改变。测试线偏好格式按现行模型整理，不为自己的旧单开关格式常驻补字段逻辑；施工前核对发布范围及是否有用户点名保留的数据，未明确授权不得借此清理真实聊天。

持久化理由与删除路径：

- 正结果需要重载后恢复等级、UI、重生成一致性和冷却；负结果防止失败重试反复抽到命中。
- 记录归所属用户楼层，删除楼层自然删除；聊天导入／分支仅随宿主实际保留的 `extra` 进入。
- 不存时间戳、概率副本、原始随机数、新闻 ID 清单、Prompt、素材版本、模型是否已采用或运行状态。
- 源码移除路径沿 Dice 总设计；数据清理同时覆盖用户楼层与 AI 全部候选，保留其他插件字段和正文。

### 4.2 本地判断与原生注入

新用户消息入楼后，核验回合与开关，在拦截阶段复用结果或进行一次冷却判断／抽取。新结果直接附在当前用户消息的 `extra.xiaobaiOsDice`；命中后拼接固定基础句与弱参考，交给酒馆原本这一次请求。请求组装后清除自有临时注入。

- 遭遇不调用整聊保存、读回或额外模型 API，不阻塞等待服务器保存，不维护待确认候选或保存重试。
- 已有记录只读复用；新 `none` 与 `cooldown` 同样记在本地用户消息，防止本页重生成重复抽取。消息记录不是第二份聊天快照。
- 酒馆正常保存聊天时携带该字段；成功保存后的重载、分支和导入按实际保留的记录恢复。Dice 不接管酒馆的编辑、删除或保存队列。
- 主 API 失败后，本页原记录仍在，普通重生成沿用；若酒馆尚未保存就刷新，未保存记录可能丢失，载入的历史消息缺少记录时不补抽。不为此补存或阻塞主生成。
- 停止、切聊、删目标消息、编辑目标正文、关闭遭遇或停用 OS：撤销旧运行的注入资格；读取启用状态的迟到返回不能注入另一聊天，也不会产生写盘。
- 坏记录或参考开关读取失败时跳过本次遭遇，主回复及群成员轮转继续；只显示简短局部提示，原始异常留在日志。原生重新生成仍可尝试注入，但不重新抽取已有判断。没有保存或重抽按钮。停止、切聊或目标变化的迟到返回仍中止旧请求。

原先的遭遇保存会话、保存器、快照等价处理和专用保存等待均删除，不保留兼容壳。行动检定的骰点保存／续写和用户显式清理 Dice 数据不在本次简化范围。

## 5. 联动：固定基础句＋一句弱参考

### 5.1 三档基础提示不随模块变化

低、中、高影响各有一句固定基础提示，对应第 3.1 节的影响尺度。抽中哪档就选哪句；世界／总结开关只影响后面的参考方向，不改基础句、不改等级、不再抽取。未命中／冷却不注入遭遇提示。

完整注入块依次为：事件前缀、本档基础句、贴合当前场景与角色语气的要求、一句可选参考、遵守后续格式与文风的要求、不提及指令或触发标签的要求。基础句限定本次回复；中档明确提供用户可以回应的新意外情况，并保留当前互动继续进行的空间。

### 5.2 只按开关拼参考方向

| 方向 | 是否加入参考句 |
| --- | --- |
| 从当前场景自行寻找合适的变化来源 | 始终保留 |
| `<world_background>` 中的背景信息或相关氛围 | 世界背景开关开启时加入 |
| 记忆中发生过的事在此刻产生回响 | 当前聊天总结启用时加入 |

用户确认的中文表达示意，两者都开启时为：

> 可参考：如当前场景自行找到合适的变化来源、`<world_background>` 中的背景信息或相关氛围、记忆中发生过的事在此刻产生回响。

某模块关闭时，只从这一句中去掉对应方向；两者都关闭，仍可从当前场景找变化。参考方向是并列的可选灵感，不是来源优先级，也不要求逐项采用。可以仅借氛围，也可以完全使用当前场景；不能要求模型必须挑一条新闻或必须兑现某个旧事件。

### 5.3 启用状态与模块边界

Dice 只接收当前聊天的世界／总结启用布尔值。世界对应现有“作为剧情背景”设置，不要求页面打开或开启自动订阅；总结使用 `isStorySummaryEnabledForCurrentChat()`，不检查向量是否开启，也不检查正文、事件数量、召回结果或“可消费”状态。开关值由其所有者提供，不在 Dice 新存一套联动偏好。

世界和总结照旧负责各自的内容与原有注入。Dice 不读新闻或总结，不读取已注入的 Prompt，不查询发布回执，不补充摘要，不另设素材预算，也不触发更新或召回。即使模块开启而本次没有注入内容，参考句仍只是可选方向，模型可以从当前场景找变化；Dice 不据此阻塞主生成或重抽。

因此，联动增加的只是固定基础句之外的一句参考方向，不增加资料副本或模型请求。具体采用哪个方向，由主模型根据它本来收到的上下文决定。

### 5.4 提示词插入位置：沿用小白酒馆的 D1

小白酒馆在 `buildChanceEncounterDepthEntries` 中指定 `role: system`、`depth: 1`，组装器按距对话末尾的深度插入。已有普通新回合测试明确验证：遭遇指令在当前用户消息之前，而行动检定协议及 afterHistory 片段在其后。这里借鉴的是遭遇的 D1 位置，不迁移其整套 Prompt 排序。

普通酒馆通过现有 `setSillyTavernPrompt` 接入，固定为：

| 参数 | 本期选择 |
| --- | --- |
| 角色 | SYSTEM，作为本轮剧情要求，不伪装用户发言 |
| 位置 | IN_CHAT，聊天上下文内 |
| 深度 | D1，按宿主执行 IN_CHAT 注入时的消息序列计算；普通新回合位于最新用户消息之前 |
| 内容 | 按第 5.1 节的顺序组装事件前缀、基础句、场景要求、可选参考与收尾要求，作为同一个自有注入块 |
| 世界书扫描 | `scan=false`，这段规则不作为世界书触发扫描素材 |

普通新回合的逻辑顺序如下，省略其他预设和同深度注入：

```text
较早的聊天内容
上一条 AI 回复（如有）
[system · D1：事件前缀＋本档基础句＋场景要求＋可选参考＋收尾要求]  ← 只在发给模型的上下文中
本轮用户发言
→ 主模型生成回复
```

这不是用户界面里的楼层顺序。可见触发提示在用户正文下方，隐藏指令在新回合的用户消息之前；两者不靠向 `chat` 添加消息实现。

重生成／新 swipe 沿用本轮结果，仍使用 D1。continue 也保持原生 D1，但不能承诺始终紧邻末尾待续写 AI 正文：Chat Completion 开启 `continue_prefill` 时，宿主会先把待续写消息移出历史，再做深度注入，最后放回控制消息区；关闭时则先做深度注入，再组装待续写消息与续写引导。依据：SillyTavern `public/scripts/openai.js:1311`、`:1325`、`:898`。Dice 不改写宿主的续写／预填充顺序，不把指令接入 AI 正文，也不为了永远贴着用户楼层另算历史深度。群聊只在第 3.3 节规定的所属回复上注入。

小白酒馆私有 `order: 1_000_000_000` 不等于普通酒馆扩展 Prompt 的排序参数，不复制这个数字。宿主可能合并同深度、同角色的扩展文本；只保持 Dice 内部第 5.1 节的顺序，不保证独占一条 system 消息，不改其他扩展或用户预设的相对顺序。世界仍保留原 D4，总结仍走原有位置。

### 5.5 Prompt 生命周期

生产提示词按模型 Prompt 编写流程落地；本文保留用户确认的中文语义，不额外扩写为一套素材选择规则或新角色身份。续写沿用第 3.3 节的判断与等级复用规则，不构造专属文案。

Dice 自有遭遇 Prompt 用独立键和第 5.4 节的参数。用户楼层的本地判断确定后，在本次生成的拦截阶段设置；请求组装后清除。重生成或续写从本轮记录重新投影，不将整段提示词保存成聊天正文。

停止、切聊、关闭遭遇或停用 OS 时也只清理自己的键。行动检定、世界、总结、任务和地图的键不能被顺手清空。

## 6. UI 设计方案

本节已按用户确认的方案实现。主角仍是聊天正文：随机遭遇只提供一个可辨认的轻提示，行动检定继续使用现有 D20 结果卡，两种体验不混成同一种大卡片。

### 6.1 Dice APP：两个独立设置区

沿用现有页面的单列宽度、字体与开关样式。页面只在一处标明“当前聊天”，下面是行动检定、随机遭遇两个轻分区，以留白／细分隔线区分，不再嵌套大卡片。

- 每区首行：左侧功能名称，右侧启用开关；名称和开关有明确的可访问关联，触控热区至少 44px。
- 行动检定保留已有介绍及必要费用／自动续写／显示正则说明；这些注意事项留在行动检定区内，不挪到两个功能共用的页尾。
- 随机遭遇只用一句介绍，说明为当前剧情加入轻重不同的变数、可借世界背景与记忆寻找灵感。下面一行列“低 5% · 中 3% · 高 1%”，再用短句说明“触发后冷却 2 个用户回合”；窄屏自然换行。
- 随机遭遇不增加概率滑块、三档开关、来源开关、新闻预览、历史统计或未来功能占位。世界／总结仍按其各自开关提供参考方向。
- 开关保存期间禁用重复操作；确认后才改变有效值。失败反馈与恢复入口沿用 Dice 的文件状态机制，放在设置操作附近。

### 6.2 聊天内：细线＋居中小标签

借鉴小白酒馆现有的分隔条构图，但中文标签采用正常阅读字号，不照搬旧版 10px 大字距英文和 `aria-hidden`。聊天内使用用户确认的三档文案，保留原标点：

| 等级 | 聊天展示文案 |
| --- | --- |
| 低影响 | 命运轻轻拨了一下… |
| 中影响 | 命运悄然转动… |
| 高影响 | 命运骤然降临。 |

这些只用于聊天 UI，不替换模型收到的三档基础提示；设置页仍使用影响等级与概率说明。视觉示意：

```text
用户：我推开酒馆的门。

       ─────  ◇ 命运悄然转动…  ─────

AI：……
```

图中的 `◇` 代表小型静态骰子图标，正式实现沿用 Dice 自有图形语言，不添加三维库或图片依赖。

| 项目 | 视觉与交互约束 |
| --- | --- |
| 楼层归属 | 所属用户 `.mes` 内，正文区域之后；占这条消息内部的一小段空间，不新增楼层，不在聊天根部插兄弟节点 |
| 结构 | 两侧细线随空间伸缩，中间是骰子图标与对应命运文案，不再拼接功能名或等级后缀；横线不穿过文字，无大背景面板或投影 |
| 尺度 | 标签正常字号约 13px、相对宿主字体缩放，图标约 14px，整体高度约 28–32px；正文后留约 8–12px 间距，不撑出卡片级空白 |
| 颜色 | 继承聊天文字与表面，细线低对比；低影响偏中性，中／高影响用 Dice 紫色的不同强调程度，不用红绿表达吉凶 |
| 等级 | 三档分别使用上表文案；同一结构、不靠颜色单独传达，不因高影响扩大整块 UI；读屏补充对应影响等级 |
| 操作 | 普通标签不是按钮，不加展开、重掷或来源跳转；不依赖悬停才能理解 |
| 窄屏与放大 | 细线可缩短，标签必要时换行；320px 宽与文字放大时不横向溢出，不强制单行截断文案 |

只显示已确认触发等级对应的文案，不显示概率、随机采样值、冷却倒数或“来自某条新闻／伏笔已兑现”。文案表示本轮变化尺度，不是已确认的具体剧情事件或好坏判定。

### 6.3 出现时机、历史与错误

- 本轮本地判断确定后即显示，先于 AI 正文开始；不要求等模型明确写出一个事件，也不从正文猜触发位置。
- 不加掷骰等待或 1–3 秒揭晓动画。可仅在本次新触发时用约 160ms 的透明度淡入，不等待动效结束再发送主请求；减少动态效果时直接显示。
- 未命中／冷却回合完全不显示提示。刷新、重载、载入早期消息、切换候选或重绘只按用户记录恢复，不能重播入场或重复挂载；关闭功能仍可显示既有记录。
- 装饰图标隐藏于辅助技术，可访问文本保留完整命运文案，并补充“随机遭遇”及对应影响等级，不在画面上额外显示这些说明。本期没有新增主动播报器，避免历史重建时整批播报。
- 标签代表本轮已确定的影响等级，不代表服务器保存确认。记录损坏或注入准备失败时，所属用户楼层仅显示局部提示、不同时显示命运标签；本次主回复照常生成，不增加保存／重抽按钮。
- 删除用户楼层时提示一同消失。UI 不写入用户 `mes` 正文，不进入模型历史，不拥有第二份判断事实。

标签沿用已检查的深浅主题、窄屏、文字放大和可访问名称；本轮移除保存重试 UI，实际复测范围见报告。实体读屏软件和移动端 WebView 未实机验收。

## 8. 施工顺序与退出门槛

### E0：先证明宿主接入

在隔离酒馆＋本地模拟供应商中完成，不读取真实聊天／密钥，不调用付费模型，不改宿主源码：

1. 用户消息入楼之后、模型请求之前可本地记录遭遇并原生注入；开关开／关时宿主保存请求数量一致，没有额外保存或读回，不丢用户输入／下一条草稿。普通重生成删除旧 AI 楼不会丢本轮用户归属。
2. 双成员群聊只决策一次、仅首回复得到变数要求；流式／非流式及检定自动 continue 仍属于同一用户回合，不新增模型调用。
3. 世界／总结的四种开关组合只改变一句参考方向，三档基础句不变；向量开关不影响 Dice 行为。捕获出站请求，确认普通新回合的遭遇要求在最新用户消息之前；continue 沿用原生 D1，分别核对 Chat Completion 的 `continue_prefill` 开／关与 Text Completion 的实际组装位置，不以“必须紧邻末尾 AI”作断言；允许宿主合并同角色块。确认 Dice 没有新增素材或覆盖来源模块原有注入，切聊不串用开关状态。

只补真实边界。若必须大改宿主、总结召回或群聊调度才能通过，先报告证据与影响，不注册一个表面可启用但没有闭环的开关。

### E1：规则与消息事实

落地当前格式、互斥抽取、冷却、本地复用和随宿主消息清理。验证主 API 失败后同页复用以及未保存即刷新时不补抽的边界；不重新引入遭遇保存事务。

### E2：开关接入与生产 Prompt

接入两个启用布尔值，落实三档固定基础句、一句弱参考及独立 Prompt 生命周期。遵守生产 Prompt 编写流程，三个等级不能只是换标题、正文仍然全是“突然意外”；不把可选参考改写成指定来源或新闻／记忆优先。

### E3：双开关、用户楼层提示及整体回归

接入正式 Dice 页面与用户消息提示，核对关闭／重载／删除／分支／导入，完成行动检定与其他 OS 模块联动回归。未通过前不声称随机遭遇已经迁移完成。

## 9. 最少必要测试与验收记录

新增测试先明确要保护的用户行为／外部契约，不测函数名或文件位置，不读源码作字符串存在清单，也不按 Prompt 整句快照证明质量。

| 最低成本层 | 保护的契约与真实故障 | 为什么需这一层 |
| --- | --- | --- |
| 领域单测 | `0`、`0.01`、`0.04`、`0.09` 及两侧区间正确；只有一次随机调用；U1/U2 无调用、U3 恢复 | 边界与冷却 off-by-one 用确定输入即可发现，不做概率抽样统计 |
| 运行／消息集成 | 触发、未命中、冷却均本地记录；重生成沿用；不额外保存／读回；取消后迟到准备不注入或写盘 | 类型／构建无法证明事件顺序、请求副作用与消息结果一致 |
| 开关联动集成 | 两个模块的四种开关组合只改变参考方向；等级不变；不读内容，向量开／关不影响 Dice | 概率单测无法发现开关串聊、隐藏内容依赖或误改来源注入；用公开组合输入输出验证，不按整句措辞作快照 |
| 真实宿主＋模拟供应商 | 一次用户发送只增加原本的主请求；D1 的真实逻辑位置及块内顺序；流式／非流式、重生成、swipe、双成员群聊、检定续写、草稿保护 | 需要观察原生事件顺序、最终请求、实际消息文件和 UI |
| 正式 UI 浏览器检查 | 双开关独立且注意事项归属明确；本地判断确定后出现分隔标签、三档命运文案与等级对应正确；无动画阻塞、重绘不重复或重播、删除不残留；主题、窄屏、放大与可访问文本 | DOM 宿主行为和视觉不能靠领域测试证明 |

集成用例覆盖停止／切聊、开关关闭后重开、用户正文编辑、删除冷却中的消息、分支只保留实际消息、关闭 OS 后不继续注入。坏记录不静默当作“无记录”重新投骰。

整体回归重点：行动检定现有草稿保护／候选隔离／揭晓动画／保存失败恢复不变；遭遇开关不牵连检定开关；世界、总结、地图、任务、商店 Prompt 均不被覆盖；私人信息等消息投影不占新用户回合。

真实模型质量另验：低影响能被忽略、不另起事件；中影响提供新的可回应情况，并留有当前互动空间；高影响明显改变局面，但不越过用户决定权或直接结算重大后果。参考方向确实可选，允许仅借氛围或完全从当前场景找变化。模拟供应商只能证明 Dice 提示已送达且未干扰原有注入，不能证明这些叙事质量。付费验收须由用户明确授权配置与范围。
