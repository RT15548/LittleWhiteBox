# Roll 点：Tagged JSON + 酒馆同楼续写验证

日期：2026-09-14。范围：隔离可行性验证，不是正式功能施工。

## 结论

**关闭酒馆“自动续写”时，同楼闭环可行性已通过；完整 OS 功能尚未验收。**

酒馆主 RP 模型输出检定 JSON，插件本地处理并保存结果，再调用宿主 `generate('continue')`，流式和非流式都可以把后续正文接在原楼。没有额外 Agent API 审查每一轮聊天。普通聊天实测一次主模型请求；一次检定实测两次；同楼连续两次检定实测三次。请求数不等于 token 费用倍数，续写仍需重新发送上下文，真实费用未测。

实测发现：开启酒馆自带自动续写时，它会抢先启动，续写请求漏带骰点。用户随后明确决定：**Roll 不支持与酒馆“自动续写”同时启用，在设置说明中提醒关闭即可，不实现这项兼容，也不再将它列为施工阻塞。** 这是明确收窄支持范围，不是把原失败结果改成通过；探针仍不等于正式 OS 功能完成。

酒馆此选项默认关闭；Chat Completion API 还需单独允许自动续写（`public/scripts/power-user.js:127`）。Roll 继续借用原生 `generate('continue')`，不依赖开启这个按长度自动触发的选项。

## 环境与证据边界

- 本地 SillyTavern 1.18.0，真实浏览器、真实宿主 Generate、聊天存储和重载。
- 独立宿主端口 `8098`、独立模拟供应商端口 `8099`，只监听本机。数据根为仓库内已忽略的 `output/playwright/roll-native-gate/data`；不使用真实用户聊天、配置或密钥。
- 扩展自动加载、插件及更新关闭；浏览器外网请求被阻断。没有调用真实付费模型，也没有加载完整 OS。
- 本地供应商通过真实宿主请求链路返回固定非流式响应、分块 SSE、刻意的 HTTP 503，并记录收到的请求。
- 探针通过宿主事件、扩展提示词和原生续写接口接入，没有替换 Generate、修改宿主源码或接管主 API。
- 掷骰固定为 7，检定请求使用探针专用的 `ActionCheck { action, dc }`。这只验证协议、消息归属与保存，不验收真实随机性、现行领域 schema 或模型判断质量。
- 探针结果只写入隔离消息的 `extra.rollProbeResults` 及对应 swipe；调度、取消、请求身份仅在内存中。此字段不是新增的正式 OS 数据格式。

## 最终实测

下表的“通过”仅指对应的有限契约，不代表完整产品验收。

| 场景 | 观察结果 | 结论 |
| --- | --- | --- |
| 普通聊天无检定 | 1 次请求、0 次投点、0 次自动续写 | 无额外审查调用 |
| 非流式单次检定 | 1 次投点、2 次请求；只有一个新 assistant 楼；第二次请求含 system 结果；保存重载一致 | 同楼闭环通过 |
| 流式单次检定 | 同上；正文与 swipe 内容、结果一致；重载一致 | 同楼闭环通过 |
| 同楼连续两次检定 | 2 次投点、3 次请求；最终同一楼含两份结果，最后请求含两份结果 | 连续执行通过 |
| 错误／截断 JSON | 各 1 次请求、0 次投点、0 次续写 | 不误执行；错误展示未验收 |
| 停止尚未结束的流 | 请求断开、0 次投点、0 次续写、注入为空 | 停止后不擅自恢复 |
| 停止后切换聊天 | 目标聊天只有初始问候，无骰点及续写泄漏 | 此顺序通过；不覆盖所有并发切换时机 |
| 续写 HTTP 503 → 重载聊天 → 显式重试 | 首次共 2 次请求；重试追加 1 次；始终只有原来那份投点，结果再次进入请求，正文接在原楼 | 重试不重投通过 |
| 重复派发已处理消息的接收事件 | 投点数和请求数不增加 | 此重复事件边界通过 |
| 生成新 swipe、切回旧 swipe、保存重载 | 两个候选分别只有自己的结果；切回不请求、不重投；显式完成保存后重载一致 | 候选归属通过 |
| 流式仅在消息完成时删 JSON | 逐帧采样看到 `<tool_` 片段和 JSON；最终渲染事件仍可见 JSON | 不满足展示契约 |
| 使用宿主仅显示层正则过滤 | 拆分 `<`／`t`／后续标签及 JSON；逐帧与结束事件未见协议文本，解析与保存仍成功 | 显示过滤入口可用 |
| 酒馆 native-tools 选项开启 | JSON 路径仍为 2 次请求、同楼、保存一致 | 仅证明开关不排斥 JSON；本次没有注册或调用其他原生工具 |
| 酒馆内置自动续写开启 | 本地投点 1 次；宿主抢先发出第二次请求；探针未发续写；第二次请求没有结果注入 | **不支持的组合：漏传骰点；用户已确认不兼容、不阻塞施工** |

停止场景中，宿主最终保留的缓冲正文可能已有完整 JSON；取消标志仍阻止执行。该记录不代表停止后的文本已经有完善的产品展示。失败重试记录还观察到宿主生成时间字段出现 `1970-01-01`，没有据此宣称计时 UI 验收通过。

## 已查明的宿主差异

以下宿主路径相对 SillyTavern `public/`，均只读核对：

- `script.js:3477`、`:3696`、`:5380`：`GENERATION_ENDED` 反映 UI 解锁，流式处理器和最终存储可能还未释放。探针等待生成标志及处理器都空闲后才续写。
- `script.js:4240`：`GENERATION_STARTED` 带 `dryRun`。实测背景提示词计算也发出该事件；探针忽略 dry-run 对执行身份的变更。
- `script.js:5475`、`:6660`：非流式续写完成使用 `appendFinal`；流式完成使用 `continue`。探针同时处理，才通过第二次检定。
- `script.js:10061`：新建 swipe 只清理宿主认识的部分 extra 字段。第一次探针把旧骰点带进新候选；在新 swipe 生成入口清除探针自有字段、保留旧候选快照后重测通过。
- `script.js:3656`、`scripts/extensions/regex/engine.js:336`：显示格式化经过宿主 regex 引擎。临时 `markdownOnly` 过滤可隐藏完整标签及尚未完成的标签前缀，不改原始正文。此验证没有确定最终 UI，也没有修改用户的正式正则配置。
- `script.js:5383`、`:5519`、`:5724`：宿主在收尾时自行触发自动续写。实测它早于探针等待空闲后的续写步骤，且没有得到尚未注入的结果。
- `scripts/tool-calling.js:682`、`:887` 及 `script.js:5375`：本地原生工具路径排除 continue，工具结果另存消息并进入 normal 生成。这是源码核对，不是本次的原生工具端到端验收。

没有为兼容未上线的旧实现保留额外分支。上述差异来自真实宿主约束。

## 正式边界与下一步

终态应是：**Roll 功能拥有请求协议、检定规则、结果、提示词和展示；宿主适配负责把同一条回复的生成／续写归到一次检定流程。** 主 RP 模型判断何时请求检定；本地执行；继续使用用户的主聊天 API。不能为了 roll 让独立 OS Agent 接管所有聊天。

正式接入以酒馆“自动续写”关闭为使用前提，不再设计与它共用触发流程的协调逻辑，也不主动改写用户的酒馆全局设置。正式设置处保留一句说明：

> 使用 Roll 点时，请关闭酒馆设置中的“自动续写”。

这句目前只记录在方案中，正式设置 UI 尚未实现。后续工作回到 Roll 自身的领域、宿主适配和展示边界；本次没有修改用户设置或宿主源码。

正式施工前还需确定结果的唯一事实来源、候选归属、删除／导入边界和失败恢复。探针使用消息 extra 的实验不等于已经选定正式存储方案。移除此次探针只需注销监听、清除临时注入／显示过滤并移除隔离目录，不涉及用户数据迁移。

刻意未碰：真实模型是否稳定生成 JSON／遵守结果，完整 OS 主生成互斥、商店效果次数、其他插件、群聊、原生工具与 JSON 混用、所有取消竞态、结果卡片／错误提示／手动重试 UI、移动 WebView。现有 OS 的旧测试通过不能替代这些集成验收。
