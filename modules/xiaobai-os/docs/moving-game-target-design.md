# 小白搬家：两章终态

本文定义小白搬家的两章玩法、生成与资金恢复边界。

## 产品合同

保留真实 Three.js 小屋、圆润奶色玩具、旋转/缩放、空间清障和三件装箱搬运。七格改为“待打包暂存架”：同类三个释放位置，最后一格匹配先于判负。困难来自先搬什么、如何为后续留空位，而非增加重复物件。

- 第一章「猫咪的小屋」：五关免费、顺序解锁、难度递进；每关首次通关奖励 50 小白币，共最多 250。可撤回、重开；重玩不重复领钱。
- 第二章「魔女的厨房」：第一章全部通过后开放；独立家具布局，奶紫/浅冰蓝/薄荷绿，奇异但清透。无限随机挑战，每局报名扣 50，赢后入账 100（净赚 50），失败/主动放弃不退报名费。无撤回、免费换题/重开和付费救场。
- 仅两章；不增装修经营、装扮货币、模型调用、第三方依赖。运行时参数集中定义；解锁状态由首通事实派生。

第一章不是先送一关无失败的演示：第一关就要实际使用暂存空间，最快第五次拿取才形成第一组三件；错误顺序可塞满七格，但每种开局首选都保留通关路线，并可撤回纠错。之后提高暂存压力、收紧安全路线，最后两关即使物件数量相同也必须有布局难度差。不能只用更多物件或后期高难弥补第一关没有决策。

第二章按累计付费通关递进为高难、专家、极限三档；升档间隔先定为三次通关，最高档之后持续随机。失败、主动放弃、换聊天、重玩第一章都不降低档位；只统计已确认的付费通关收据，同一终局不重复计数。报名费用和胜利奖励不改，不加每日次数/收益上限。严格指标分档不等于真人每局体感递增，也不保证高手无法长期盈利。

档位及下一档进度从现有收据派生，不新增持久化字段；本局所属档由入局前累计通关数确定，第三/第六次获胜时不把刚完成的旧局改标为新档。报名确认显示下一局档位，棋盘显示本局档位。三个生成区间互斥；每局仍先验证可解与档位，再扣费。最高档有限次筛选失败则明确报错，不降档替代。

## 生成与难度

房间美术及实体位置为手工模板，物件组合/依赖由种子构造，不是旧三关换色。可取关系由领域模型唯一决定，画布、键盘、Host 和求解器一致；依赖必须具有可见空间表达，不能转视角绕过或靠盲猜隐藏身份。

每个随机候选必须完整求解：至少一条合法解，所有路线中的最低暂存压力严格高于第一章压轴关，并筛掉错误分支过少的宽松局。具体阈值经生成实验确定、集中定义；报告给出指标和样本，不冒充真人胜率。未验证、无解、难度不足的关卡不收费投放。计算有上限，生成失败明确报错，不静默降级。

同局关卡及种子固定。刷新、切聊天、关闭 APP、WebGL 恢复都不换题。先完成生成验证，再扣费开局。

## 资金与恢复

报名/开局同一 OS 用户文件事务提交；首通/发奖、付费终局/发奖也各自原子提交。UI 不能凭本地胜利领奖。Host 执行动作并保存，确认后才能下一步；未知写入复核原提交，不另买一次报名。

命令带操作身份和状态版本。重复操作不重扣/重奖，过期或同身份不同参数拒绝。报名费开局消费，不创造永久悬挂托管。关闭/刷新不是认输，回到任一聊天都可继续本局；换题必须明确放弃旧局。画面故障可重建，同局和资金不变。

## 开工前八项

1. 所有者：`apps/game/moving/` 包含领域、生成器、存储、Host 服务、UI/3D、文案；原三款金融领域和 GameKind 不扩成搬家兼容壳。
2. 唯一事实：规则参数、关卡及依赖、文案各自一处；展示、求解、发奖派生自同一模型。
3. 持久态：Game 注册用户级独立 Moving 分区，与全局钱包同作用域，保存首通、当前局及必要财务收据/重放身份。换聊天不能重复领首通或逃掉收费局；聊天清理不删除此分区，完整用户数据重置才与钱包一并删除。跨重启防重领和恢复收费局是持久化理由；当前局随新局替换，动作历史仅留当前局所需。声音开关偏好由 Game 的小白 OS 设置持久化；相机、动画、音频实例和弹层只存在当前运行中。
4. 依赖：已有 Three.js/Vue、PartitionStore、Economy，不改核心增加本游戏语义。
5. 注册：Game additionalPartitions、生产组合入口及原大厅一个入口。
6. 删除：删功能目录/注册并清理 Moving 分区；已发生的钱包交易是审计事实，保留，不倒扣奖励。作用域清理复用 OS 现有机制。
7. 兼容：SillyTavern、浏览器/WebView、现行用户文件与钱包协议。不支持已移除的体验关卡或纯本地会话格式。
8. 测试：规则/生成语义单测；真实事务集成测首通、费用、重复、保存失败/未知与恢复；浏览器实际五关/挑战、胜负/放弃/重进、旧三款回归、移动屏与视觉；全 OS 类型/lint/测试/构建。

## 完成门槛

展示真正逼迫规划的局面，验证错选可死路、正确路线可通关；公开生成难度下界与样本。五关及收费挑战均有实际 UI 操作、账本和恢复证据。终审逐条核对，不能以“能通关”代替好玩，也不能以构建通过代替体验验收。
