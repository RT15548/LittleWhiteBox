# 小白搬家：两章验收与终审

日期：2026-09-27。产品合同以[目标设计](./moving-game-target-design.md)为准；初审及施工见[施工文档](./moving-game-implementation-plan.md)。本报告替代旧三间免费体验房的验收，旧脚本结果不充当本轮证据。没有 commit、PR 或推送。

## 交付结构

- 功能完整归 `apps/game/moving/`：规则、求解/生成、命令、用户级分区、资金收据、Host/bridge、两章 UI、3D、声音及文案。Game 仅组合注册；没有扩大旧三款的 GameKind 或改核心业务。
- 物件采用可见实体叠垛。只能从顶部拿，下层仍可观察；相机、可访问列表、Host 都不能越过上层。三连腾空位；第七格先判断三连，再判负。
- 用户级首通与付费局同钱包事务保存；换聊天/清理聊天不能再次领首通或逃掉付费局。保存当前关卡/种子及动作，棋盘重放派生；不另外持久化解锁位、余额、相机或动画。
- 财务收据是钱包对应事实；报名即消费，没有悬挂托管。原三款 `game:` 与搬家 `moving:` 交易命名空间分别验证，共享 Game 所有者但不混用协议。
- 独立奶色猫咪小屋和奶紫魔女厨房，保留圆润玩具、镜头控制、三连抱箱搬运和手势开启的合成音效。没有第三章、AI 调用、新依赖、装修经营或付费救场。

## 难度证据

“最低暂存峰值”是遍历完整解空间后，所有通关路线中最小的峰值，按每次三连结算后的占用计算，不是挑一条较难路线充当下界。另用实际规则独立遍历，验证五关及首八个随机种子在低一格的上限下都无解。

| 关卡 | 物件数 | 最低暂存峰值 | 随机等概率选择当前垛顶的通关概率 |
| --- | ---: | ---: | ---: |
| 第一章 1 | 12 | 4 | 0.440672 |
| 第一章 2 | 15 | 4 | 0.198121 |
| 第一章 3 | 18 | 5 | 0.0868815 |
| 第一章 4 | 21 | 5 | 0.0203668 |
| 第一章 5 | 21 | 5 | 0.00689381 |

第一章按用户追加要求重新调校：旧第一关仅三类，未匹配余件上限六件，七格永远不满，是实质上没有失败可能的演示；已替换，不再计作合格入门。当前第一关遍历所有前四步，均不能提前三连；每个初始垛顶选择之后仍有解，同时存在错误顺序导致失败。新增规则测试保护这些行为，不固定某条解法或种子。后续难度逐级收紧，最后两关物件数量相同，区别在依赖排列。

第二章的每个候选都完整求解。最低暂存峰值高于第一章压轴；在此基础上，随机点选通关概率的上限逐档降低、从可解状态走入死路的分支比例下限逐档提高。三个 profile 及筛选预算唯一维护在 `apps/game/moving/policy.ts`，`difficulty.ts` 将候选归入其满足的最高档，因此出题区间互斥。七格规则的有效峰值不能无限增长，不拿增加峰值冒充无限递进。筛选耗尽明确失败，不扣费、不降档替代。

规则测试覆盖高难 128、专家 16、极限 16 个种子：各档内布局不同，复生成一致，分类与目标档相符，按真实规则执行解法且物件守恒；每档首八个种子还独立验证压力下界。

额外性能抽测每档 64 个分散的 uint32 种子，全部成功、各档内 64 种不同布局。原始数据见 `output/playwright/moving-tier-benchmark.log`，脚本为 `moving-tier-benchmark.mjs`。本机 Node 实测（包含逐批让出事件循环和最终复验，不代表手机性能）：

| 档位 | 中位 / P95 / 最慢（毫秒） | 平均 / 最多检查候选 |
| --- | ---: | ---: |
| 高难 | 9.81 / 55.47 / 166.88 | 9.56 / 36 |
| 专家 | 72.75 / 312.36 / 608.60 | 58.66 / 262 |
| 极限 | 546.57 / 2613.98 / 3970.29 | 360.64 / 1289 |

抽样没有耗尽不等于所有种子都保证成功；所有生成路径仍有硬预算，失败不收费。档位由累计已确认付费胜利收据派生，不新增持久化字段；旧局按入局前成绩归档，本次赢得升档只影响下一局。失败、放弃和免费重玩不降档也不计胜场。

**这些概率不是真人胜率。** 保证的是可解与规则下的压力下界，不保证每位玩家主观上都觉得极难，也不以算法指标代替后续真人试玩。

### 三档追加浏览器验收

本轮另起干净的隔离存储；`moving-tier-prepare.cli.js` 通过真实 Host 完成五关以准备解锁，不将这个准备步骤冒充本轮画布操作。随后 `moving-tier-round.cli.js` 经实际画布逐件拿取付费关物件，没有注入胜利状态。

- 连过高难三局、专家三局、极限一局，逐局验证费用、胜场与目标档；在两次升档后都重建 Host 并刷新页面。旧结果页保留入局档位，下一次报名和章节卡显示新档。每次都先取消一次报名，取消不收费。原始结果在 `output/playwright/moving-tier-browser.log`。
- `moving-tier-failures.cli.js` 在极限档先取消放弃，再确认放弃；再报名一局，经实际拿取至七格溢出。累计胜场与最高档均不变，隔离余额 700→600，账本恰为九次报名、七次胜利。原始结果在 `moving-tier-failures.log`。
- 败退后再次经画布完成一局极限题，累计八次胜利、最终余额 650；仍为极限，无下一档。最后一局 `challenge-extreme-13-291`，亦记录于上述 browser 日志。所有新增浏览器报名都只作用于隔离内存钱包。
- `moving-tier-layout.cli.js` 检查新结果卡、报名确认与章节入口：320/390 窄屏、844×390 横屏、深浅主题及两倍文字。初次检出横屏两倍文字的结果卡上溢；限制高度后又通过实际截图发现与房间标题叠层，最终短窗口结果独占棋盘区域并可滚动，不压小字或按钮。保留失败记录与复跑结果在 `moving-tier-layout.log`；末次仅 CSS 调整后的 Shell 构建见 `moving-tier-layout-build.log`。

## 终审修正

1. 用完整解空间下界替换旧“只增加物件”的假递进；垛顶依赖有实体托盘/叠放表达。
2. 从局部临时 session 迁到正确的用户级独立功能边界；关闭与主动放弃分离，删除旧第三房、容器规则和旧样式。
3. 首通/报名/终局与钱包原子提交；保留未知候选，已接受报名恢复不依赖旧聊天；奖额展示只对应当前结算动作。
4. Host 复查身份/版本/余额和生成忙状态；客户端缓存更新推送，防止旧回包覆盖较新状态。
5. 错误明确呈现，恢复不暗中换题。动画、音效、图形、观察器与监听器按生命周期清理。
6. 前端设计技能促使补做真实小屏/放大审视：修正短窗口裁切，极矮窗口减少非必要进度副行、侧栏可滚动。保留房间与七格架为主角，费用/不可逆后果仅在选择与确认处说清。
7. 文案/规则/关卡形状分别单点定义；旧大厅“本地玩法”命名改为独立功能视图，避免与真实 Host 保存混淆。
8. 三档只从已确认财务收据派生，不新增等级实体或旧单档兼容入口；生成与存档校验共用同一个互斥分类器。前端设计技能促使把档位移到房间名旁，并补做短窗口结果卡的可滚动和叠层检查；新增样式只作用于第二章结果，不改变第一章关卡与奖励。
