# 游戏 APP 终态设计

## 1. 定位

Game 是独立纯规则游戏领域，提供大话骰、翻牌寻金、步步登高。大厅另包含两章 3D 解谜，其所有权、费用奖励和独立 Host 协议见[小白搬家目标设计](./moving-game-target-design.md)。下文的资金/事件合同仅针对原有金融玩法。玩家进入 APP 直接玩游戏；Game 不生成剧情、不调用模型、不修改角色、不读取主聊天消息或回合。

## 2. 所有权与结构

```text
domains/game/
├─ games/             三个纯状态机
├─ types.ts           私有状态、事件、活动、公开 DTO
├─ timeline.ts        线性事件与 CAS/幂等
├─ invariants.ts      持久格式与冻结事实校验
├─ history.ts         V1 生命周期与历史连续性
├─ view.ts            私有信息裁剪
├─ money.ts
└─ random.ts

apps/game/
├─ application/       Game/Economy 原子协议
├─ host/              activation、frame、presentation
├─ catalog.ts         Host 记录与 UI 共用的游戏身份
└─ ui/
   ├─ GameApp.vue     导航与公共状态连接
   ├─ game-client.ts  请求、恢复、确认后的结算交接
   ├─ room-catalog.ts 入口图、房间按需加载、记录详情注册
   ├─ GameLobby.vue   搜索、分类、进行中的局
   ├─ GameEntry.vue   规则说明与本局筹码
   ├─ GameResult.vue  通用结算回执
   └─ rooms/<kind>/   玩法自己的动作、桌面、揭晓、记录与插图
```

Game 只拥有游戏状态。余额与资金写入属于 Economy Capability；sidecar 队列属于 Kernel；UI 不决定随机或派彩。

## 3. 持久与临时态

持久化`GameDomainV1.events`。进行中的庄家骰子、洗牌后的完整牌堆和阶梯步骤是重启必须恢复的游戏事实，因此随事件 result 保存。

客户端只获得安全投影：

- 大话骰进行中不暴露对方骰子；
- 翻牌游戏不暴露完整牌堆或下一张牌；
- 阶梯只暴露已完成步骤和下一步概率；
- 终局记录不带不需要公开的私有引用。

页面、目录筛选、筹码草稿、重试请求、动画、busy、结算揭晓和分页是临时态；不新增存档字段。

### 3.1 当前策略与历史事实

三个`games/`状态机只负责新开局和 active game 的下一次动作。已保存事件由`history.ts`按 V1 历史合同重放：

- 骰子核对骰面、叫价顺序、挑战者与输赢类别，但不重新选择庄家叫价，也不按当前赔率重算 payout；
- 翻牌游戏核对已保存下注、牌堆、抽取顺序、揭示数量与终态，不用当前固定下注或金币价值重建旧局；
- 阶梯核对已保存步骤、选择、金额连续性与终态，不用当前倍率、层数或封顶策略重算旧局。

历史层仍严格验证事件格式、ID/revision、生命周期、状态连续性、安全金额、`net = payout - amountIn`和 Economy 资金腿。产品参数变化只能影响以后接受的新动作；不能原地改变既有事件的含义。

## 4. 资金协议

开始游戏时，下注从 player 进入`escrow:game:<gameId>`。中间动作不写资金。终局时：

- 正收益由 game reserve 补足 escrow；
- payout 从 escrow 给 player；
- 亏损从 escrow 进入 sink；
- 结算后 escrow 必须为 0。

Game event 与资金腿在一次 Scoped transaction 中形成同一个 sidecar candidate，并以一个 commitId 上传。交叉不变量从 event 已冻结的下注与 payout 重建预期资金腿并拒绝孤儿交易或 escrow 偏差，不读取当前游戏参数重算旧结果。

## 5. 命令、安全与随机

每个写动作绑定 app activation token、当前 osId/binding、gameId、actionId 和`revision + eventId`。任一业务校验失败前不得读取随机数。已提交 action 重放不生成新 ID、不抽新随机、不重复保存。

同一时间最多一个 active game。Controller 串行化前台动作，主生成期间不接受新游戏动作，但允许纯幂等重放。

聊天编辑、swipe、删除或 Assistant 数量变化不会改变 Game 事件、余额或 escrow。

## 6. 打开、失败与删除

已有 Economy 时 APP 同步打开，不注册聊天内容后台任务。首次缺少 Economy 时显示`loading`并异步开户。

明确保存失败不发布 Game 与 Economy 新快照；未确认上传由 Kernel 保留同一候选并冻结当前聊天写入，确认不重新抽牌。

删除 Game 前处理 active game escrow，再删除`apps/game`、`domains/game`、Host/Shell catalog 注册和`game`分区。

最低验收：三款纯规则状态机、当前策略只约束新动作、历史冻结事实不被新策略重判、随机边界、私有投影、CAS/幂等、托管/派彩原子性、失败恢复、聊天内容无关、移动端可玩性。

## 7. 第五批 UI 与扩展边界

终态是「游戏大厅 → 玩法房间 → 结算」，不是大厅堆三份下注表单。大厅直接展示游戏插图、名称与入场金额，不设宣传海报或口号；完全由目录驱动，提供搜索、分类和当前局入口。手机两列、宽屏三列，三个或三十个游戏采用同一布局；返回大厅保留当前搜索、分类和滚动位置，切聊天清理这些临时状态。浏览不触发动作，一局没结束时其他房间仍能看说明，但只能返回当前局继续。

- 每款游戏拥有入席规则、动作 payload、桌面、揭晓与记录详情。GameApp 不列具体玩法分支；公共 client 只理解当前状态、请求与确认后结算。
- 增加 UI 需提供房间模块、入口插图和记录详情，在 catalog / room-catalog 注册。新增真正的游戏规则仍需领域状态机与现有命令、Host 入口；本批不发明插件引擎或绕过领域注册。
- 大话骰使用「对方叫四个六」和四颗六点骰面。叫数区与真实手牌分开；按合法叫数组合限制点数选择；一点百搭、双方各五颗、只能加叫与开盅规则不变。
- 翻牌寻金为七金币、三炸弹，每张金币 +50；不再用不符合规则的「翻倍」名称。步步登高展示五层阶梯与三条路的成功概率、可带走金额。
- 规则、赔率、随机、资金结算、现行持久格式均不变。不读取世界书或主剧情来决定输赢。
- 下注按钮直接写明金额；开盅和收手为明确动作。再玩一局只回入席页，不自动重复下注。
- 保存未确认时不展示候选结果。确认后由各房间播放最后一张牌/一步/开盅，动画落地才展示结算并更新顶部余额；中间动画不接受下一次操作。
- 超时重试冻结原 actionId、CAS 和 payload；迟到回复不得覆盖更新的 Host 推送，切聊与卸载隔离原请求。失败/未确认只走既有保存核实入口。
- 视觉沿用 OS 基础字体与深浅主题，白色大厅、青绿骰桌、紫色牌桌、蓝色阶梯。保留骰盅、白骰黑点/红色一点、牌面、筹码和揭晓动画，去掉仿旧纸张、棕色阴影和装饰性眉题。结果直接呈现输赢、净额与资金明细；本地 SVG/CSS，无素材网络、依赖或新持久状态。
- 删除本批 UI 不需迁移数据；旧大页面分支与旧确认弹窗直接删除，不保留双 UI。兼容边界仅现行 Host、SillyTavern、浏览器/WebView；保留 HTTP 环境缺少 randomUUID 时的操作标识生成。
- 最少自动验证：既有规则/资金/Host 测试；client 的幂等重试、保存冻结、迟到响应、余额揭晓与分页；叫数的人话表达与合法面。浏览器验证完整流程、目录扩展、小屏、深浅主题与减少动效。隔离预览不读写真实聊天和钱包。
