# Map APP 37 类物件与三维素材扩充计划

状态：A–D 已完成，E 的工程检查、浏览器验收与业务 review 已完成；实体手机 GPU/连续旋转 30 FPS 尚未实测。基线提交：`2536ac1`；本轮承接六类试接，完成用户确认的 C–E。日期：2026-09-13。

本计划承接 [三维视图升级设计](./map-3d-upgrade-design.md)。基线已有三维渲染、9 类程序化造型、默认当前场景、二维回退；本计划负责扩充物件词表与素材质量，不重做地图业务或界面。

最终覆盖为 22 类本地模型、14 类程序造型、1 类出入口标记。具体资源、授权、验收结果与未验证项见第 11 节；规划预算不等于实测性能。

## 1. 终态与产品边界

地图用于看清空间、理解位置关系。升级目标是造型更容易辨认、三维质感更精致，同时保留通道、入口、人物和区域的清晰度。

终态只有一份地图事实：

```text
AI：二维轮廓、位置、朝向、物件类型、材质、确定性
    ↓ 现有 MapSceneEdit 字段，扩充 icon 的可选值
MapDomainV1
    ├── 二维：原始轮廓 + 本地图标 / 现有平面造型
    └── 三维：类型与占地 → 本地模型 / 程序造型 / 原轮廓示意
```

- AI 从 37 类基本物件中选合适的 `icon`，仍使用现有二维构图方式。没有合适类型时保留真实轮廓和名称。
- 插件维护确定性的类型映射、素材适配和显示高度；AI 不选择资源文件，也不提供三维布局。
- 37 类是物件词表，不是 37 个新增枚举，也不要求恰好 37 个外部模型文件。
- 世界地图继续二维；当前 active 场景默认三维，没有当前场景时回到世界地图。
- 保留旋转、缩放、平移、全图、低墙、名称和二维/三维切换。默认保留墙体完整显示高度，低墙仅按需手动开启。场景不增加物件按钮、列表、点选、高亮、详情面板或编辑操作。世界地图地点导航保持原样。
- 不加入物理引擎、人物模型、走动、碰撞、开关门、粒子系统、自动旋转或持续动画。

现有地图在新版中无需迁移即可显示。新保存的 token 不保证能被旧版插件识别，因此不能把“字段结构未变”说成“新存档可以任意降级”。本次不增加降级兼容壳。

删除外部素材能力时，移除资产目录、加载/适配模块及三维注册，恢复相应程序造型或原轮廓示意并重新构建；地图数据无需清理。保留 37 类词表和二维表示，因为它们仍有独立用途，不属于旧三维实现的兼容壳。若另行删除词表本身，须单独确定一次性数据转换策略，不能让已有 `icon` 无声变成非法值。

## 3. 37 类词表与绘制方式

七个分组仅帮助阅读，不替换 `cat`，不要求模型同时提交分组和子类型。每类一个稳定 token；材质通过已有 `material` 表达，不拆成木椅、铁椅等重复类型。

绘制方式：**模型优先**表示先寻找合格的本地 GLB；**程序造型**表示直接依原始尺寸或路径生成；**位置标记**表示保持符号与锚点。模型优先的类型在资源、形状或比例不适配时按第 5 节降级。

合计 `5 + 6 + 5 + 4 + 10 + 3 + 4 = 37` 类：13 个已有 token，新增 24 个。基线完整 `icon` 枚举有 31 个值，保留方向、人物、楼梯等其他值后目标为 55 个，而不是用这 37 个替换全部枚举。

以下边界固定：

- `door-open` 是现有符号 token，不作为“门已经打开”的状态证据。它以及 door 类元素保持被动出入口标记。
- `stairs`、`elevator` 等连接标记不并入 `ladder`；新物件不新增 `kind` 或 `MapLinkKind`。
- 挂灯、吊灯、壁挂物暂不提供实体安装效果，因为现行模型没有附着对象与安装高度。
- 地毯、地面铺设、道路、水域、墙和森林继续使用区域/路径/材质，不增加物件类型。手推车不在范围内。
- 只读物件类型、几何、朝向和材质来选造型，不扫描名称猜型号、时代、品牌或支撑关系。

## 4. 选材与本地资产标准

### 4.1 选材顺序

优先审查 Kenney、Quaternius 的实际资源包，选择一个视觉语言作为主线。两者只是候选来源，本计划不预先断言授权或覆盖数量。Poly Haven、Sketchfab 不作为第一批混搭来源。

目标风格是清透、易辨认的精致低多边形：轮廓、倒角、部件层次和接地阴影优先于贴图细节。既能放进酒馆，也不会让金属观测舱看起来像同一套木屋；差异通过现有材质适配实现，不引入 AI 风格参数。

每项候选必须留下以下记录，第一阶段回填在本文“选材记录”中，之后正式授权摘要随资产发布：

| 记录项 | 必须回答的问题 |
| --- | --- |
| 来源 | 官方资源页 URL、作者、资源包名/版本、原始文件名与获取日期是什么？ |
| 授权 | 是否允许修改并随插件再分发？是否允许当前分发用途？需要什么署名？保留哪份许可证原文？ |
| 归档 | 发布文件的相对路径、校验值、转换步骤是什么？能否从合法来源复现？ |
| 适配 | 对应哪个 token，接受哪些占地形状，零度朝向、底面、比例范围、主材质部件如何确定？ |
| 体积 | 文件字节数、三角面数、draw calls、材质槽、贴图尺寸与解码内存是多少？ |
| 质量 | 缩到手机地图大小是否仍可辨认？是否夹带其他物件、背景地台、品牌、人物、摄像机或灯光？ |
| 结论 | 采用、需加工或淘汰；缺项明确由程序造型承担，不以“库里大概有”结案 |

授权不清、仅编辑用途、限制再分发或署名义务无法落实的文件不进入仓库。优先选择义务简单且与项目分发相容的资源；以逐包原始许可证为准，不把平台名称当成授权结论。

### 4.2 发布格式与预算

- 统一输出本地 GLB；仅含静态网格与必要材质。纹理使用内嵌 PNG/JPEG，第一版不引入 Draco、KTX2 或额外解码依赖。
- 不携带远程 URI、外部贴图、脚本、动画、骨骼、模型自带灯光或摄像机。构建时验证 GLB 内容，运行时只从自有清单解析 URL。
- 不把整个资源包或 DCC 工程放进发布目录；保存最终采用文件、来源/许可证和必要的转换记录。
- 初始选材预算：单个模型不超过 250 KiB、5,000 个三角面、3 个绘制批次；单张贴图边长不超过 512。全部新 GLB 合计不超过 8 MiB，单场景所需的不同资产合计不超过 2 MiB，资产侧解码后几何与纹理估算不超过 32 MiB。
- 以上是实施预算，不是已经测出的结果。超限先减面、合并材质、移除无效内容或改用程序造型；确需改变预算时附实际设备数据重新评估，不默默放宽。
- 不为凑齐外部模型牺牲统一性。程序造型也要达到相同的轮廓、材质和接地质量。

## 5. 几何、朝向与二维表现

### 5.1 适配规则

1. 先按原有语义识别墙、地形、路径与位置标记，再判断是否有适配物件的造型。单独的 `icon` 值不能把人物、出入口或无尺寸标记变成实体。
2. 所有 `shape: icon/label` 保持点标记/文字，不因为对应模型存在就猜测占地。带尺寸的出入口和人物保留原占地与标记。
3. 本地模型预先规范为 Y 向上、底面为零、占地中心为原点。沿用现有从二维映射到 XZ 平面的转换，不另起一套坐标。
4. `rotation` 仍是绕 rect/circle 中心顺时针旋转；椅背、沙发背、床头在零度时位于北侧，桥沿南北。新物件具有正面的，零度统一面向南侧；汽车车头也按此约定。对称物件不强造朝向。
5. 每个资产声明支持的占地形状和经过验证的长宽比范围。矩形模型不强套圆形；圆形树、岩石、圆桌等已有能力必须保留。
6. 优先等比适配。允许拉伸的台面/横梁用程序分段调整，腿、轮子、圆孔等保持比例。不能在原占地内可靠适配时退到程序造型或原轮廓，不越界、偏移或把家具任意压扁。
7. 模型所有部件的平面投影受原占地约束，树冠、扶手、旗面也不例外。显示高度属于渲染约定，不表示真实尺寸或层高；不更改 `viewBox`、原点或地图坐标。
8. 不规则闭合轮廓继续按原轮廓显示，不取包围盒硬套模型。开放道路、水流继续线状；围栏只对 path/curve 沿线生成，rect/circle 输入仍保留占地示意。

围栏路径和墙边界都不得填充内部、擅自连首尾或补入口缺口。`closed` 继续使用当前约定；特别是 decoration 类的三点以上路径默认闭合，开放围栏须显式给出 `closed: false`，不能在三维端根据名称或图标偷偷改变此规则。

### 5.2 造型选择与降级

按明确顺序选择：语义要求位置标记 → 位置标记；路径设施 → 对应程序绘制；有合格资产且形状/比例匹配 → 本地模型；有合格程序造型 → 程序造型；其余 → 原轮廓示意。

资产载入失败与地图事实未知是两件事。失败不修改 `certainty`、`icon` 或存档，也不因为一个模型失败就让整个三维场景不可用。基线 9 类程序造型可作为实际需要的备用，不能为每个外部模型再造一套复杂备用模型。

### 5.3 材质与标记

- 继续使用 22 个材质 token。为模型部件标明主表面与少量辅助表面，已有 `material` 驱动主表面；不把一个彩色贴图整体染色后声称完成材质适配。
- 未提供材质时使用中性预设外观，不回填材质事实。模型附带的书、餐具、商品等独立物件应在预处理时去除。
- `certainty` 只影响透明度、线型或标记状态。一个实例的材质和确定性不能污染同类其他实例或共享原型。
- 沿用现有玩家、入口优先的标签布局；名称来自 `label`，不从模型文件名补文字。关闭名称仍保留人物和出入口锚点。
- 保持明亮、清楚的材质分离；深色主题不把所有实体染暗。灯具/火焰用有限表面效果表达，不为每件物体新增实时灯光。

### 5.4 二维必须同步可读

扩充 `map-presentation.ts` 的本地图标映射和二维物件识别。新增有尺寸物件用原轮廓与对应本地符号表达；现有 9 类平面造型保留，不强制再手写 37 个复杂 SVG。

### 6.1 加载与竞态

- 仅进入三维时加载三维代码；仅请求当前场景实际需要、且占地适配的资产。世界图和纯二维路径不下载 GLB，不初始化 GLTFLoader。
- 当前显示场景拥有一个资产会话；同类物件合并请求、共享只读原型。同场景更新可复用仍被引用的原型，离开场景释放，不建跨聊天全局缓存。浏览器正常 HTTP 缓存不由应用另行持久化管理。
- 先显示可用的程序造型或原轮廓，资产完成后更新当前场景。加载不阻断地图读取、工具栏、维护或保存，也不要求等待下一轮剧情才显示模型。
- 首次取景按资产清单中从发布 GLB 提取的尺寸与水平半径，复用实例适配的缩放规则，预留模型及名称锚点的高度。该范围属于渲染边界，不抬高占位物、不写入地图，也不依赖模型请求完成后重置相机。
- 资产完成后的替换保持相机、低墙和名称设置，更新物件高度锚点及取景/灯光边界，不自动执行全图。
- 每次场景数据更新或退出使旧装配任务失效。请求能取消就取消；已进入解析而无法取消的结果在返回时检查归属并释放。晚到结果不能复活已删物件、覆盖新场景或挂回卸载后的组件。
- 单资产失败只退回该类型的可用表示，并保留有原因的诊断记录；同一资产会话不自动循环重试。WebGL 初始化、上下文或绘制整体失败仍走现有一次性二维回退。

### 6.2 资源所有权

资产会话拥有源 geometry、texture、原型 material 和解码图片资源。场景模型拥有节点实例及其单独创建的材质/几何；共享引用不重复登记为实例自有资源。

替换或退出时先移除并释放实例，再释放不再被引用的原型。纹理释放还须覆盖归其所有的 ImageBitmap、临时对象 URL 等解码资源，不能只调用 `texture.dispose()`。失败、取消、场景切换、主题更新和总卸载使用同一套所有权规则，不靠垃圾回收代替 GPU 释放。

### 6.3 打包与分发

当前 `vite.xiaobai-os.config.mjs` 使用 Vite library mode。不能假定普通 `?url` 导入会独立输出模型；当前 Vite 在库模式下默认内联资产。

模型使用显式不内联的 URL 导入（如 `?url&no-inline`），由 Vite 输出带内容哈希的本地资源，资产清单仅保留解析后的地址。构建后验证 JS 未嵌入整套 GLB、模型路径相对于插件产物可达，并在真实 OS iframe 下加载。不要改变整个 OS 的构建模式来满足 Map 资产需求。

构建产物、模型和所需授权文件一起进入发布范围；不使用需要运行时 Git LFS 拉取的指针文件。若构建配置需补充资产/许可证输出，只作用于这组 Map 资源，不改其他 APP 的入口与打包策略。

### 9.2 浏览器与负载验收

- 桌面、390px、320px，深浅主题；酒馆、溪谷、观测舱及新增代表性 fixture。

- 检查世界图/二维零 GLB 请求、同类多实例一次加载、本地地址与 iframe 分发路径、离开场景后的资源释放；重复开关和切场景后活动资源应回到同一基线，不持续增长。
- 保留 128 元素、每路径最多 64 点的现有领域上限；按高重复家具、混合不同类型、长围栏和密集标签分别检查，不提高上限掩盖问题。

- 无操作时不持续请求渲染帧，不因模型加载加入常驻循环。预算或质量未达标时优化/换材，不靠增加画质设置把问题交给用户。
