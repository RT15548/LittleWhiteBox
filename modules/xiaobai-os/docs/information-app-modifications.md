# 信息 APP：删除与重新回复

本文定义私人通讯与主聊天联动修改的权限、保存及恢复边界。产品入口见 [信息 APP](./information-app-target-design.md)。

## 结构与所有权

- `domains/messages/mutation.ts`：纯差量应用、回复引用清理、摘要失效与片段顺序。
- `application/modifications.ts`：权限、读取版本、跨文件候选与恢复；`mutation-evidence.ts` 只判断原楼/目标证据。
- `application/generate-reply.ts`：发送与重 roll 共用的现有模型、提示词、压缩和媒体生成步骤；`regenerate.ts` 排除旧回复及受污染摘要，生成期间不改历史。
- Host 通过正常 `MESSAGE_EDITED/MESSAGE_UPDATED` 或 `deleteLastMessage/MESSAGE_DELETED` 生命周期写楼，使用现有真实 HTTP 保存确认。不修改酒馆本体、共享 Agent 或总结回滚规则。
- Vue 仅发送目标 ID、联系人与读取版本。按需操作条不占常驻行；删除确认说明联动主聊天。Host 再次验证，不信任客户端禁用。

## 事实、顺序与权限

APP 长期历史属于 Messages 分区；主聊天是独立存档的投影。只有未封存、未总结、内容与回执一致的唯一尾部通讯楼层可改。历史、用户改写/删除、重复投影分别给出原因；封存永久，不因删去后续剧情解锁。联系人全部消息都可删除才允许整联系人删除，空联系人可直接移除。

删除只移除目标，不级联后续回复，清掉悬挂回复引用和受影响摘要。重 roll 保留用户输入，只替换当前联系人最新组的全部气泡，保留原组时间/位置，不改其他联系人。`messageIds` 是楼层展示顺序；`seq` 单调新分配，不复用、不重编号，确认高水位取最大序号。

## 单份待确认修改

`pendingMutation` 仅保存一次修改的 ID、类型、联系人、片段、原楼位置、原楼指纹、前序楼层指纹、删除 ID、新回复与候选摘要。没有聊天副本、旧回复副本或版本历史。新回复序号在候选保存时预留；安全撤销也不复用。

顺序固定：确认 sidecar 候选 → 修改/删除主聊天尾楼并确认保存 → 应用 APP 差量、更新回执并清候选。前两步期间原消息仍在；生成失败/取消不改原记录。候选持久化是为了刷新/重启后确认同一次跨存档操作，所有者 Messages，成功或安全撤销立即清除，删除分区时一并清理。

「检查保存」先核实 Kernel 文件候选，再读取主聊天已保存证据：

1. 目标已保存：完成 APP 提交，即使剧情后来继续，也不丢弃已发生结果；留下的片段按现状封存。
2. 原楼仍完整可写：重试同一个候选，不调用模型，不追加楼层。
3. 原楼不再可写且目标未生效：清候选、封存原段、保留原 APP 历史，不覆盖用户主聊天。
4. 目标只在宿主内存、主聊天保存尚未知：保留候选继续核实，不把可能仍在途的原生写入当成未发生。

待确认时禁止新的发送、删除、重 roll；不锁主剧情。关闭浮窗不取消已开始的保存。原图文件不删，其他分支继续可用。

## 迁移、复制与退出

Messages 分区 v2。`migrations/v1` 冻结正式线格式、验证器和投影规则；加载/导入解析入口只转换一次，不在日常写路径做兼容清洗。真实 v1 夹具来自此前隔离 SillyTavern 验收落盘文件（固定测试对话，非用户私聊），不补 v2 字段再假装旧格式。删除 v1 兼容的条件是明确停止支持正式线 v1 导入。

完整复制和历史分支先按子聊天实际楼层选取原状态或已生效候选，清掉父聊天待执行操作，再做原有历史裁剪；不执行父线修改。清 Messages 分区同时清候选；卸载保留普通可读主聊天正文。

## 验收边界

集成测试使用真实 Kernel/应用逻辑及可控存储/模型端口；Host 测试验证真实 HTTP 协议和原生事件，覆盖删除最后一条、防重复删前楼、未知 ACK、主聊天改写与身份变化。UI 用实际 Vue、Controller、Runtime、Kernel 的隔离浏览器夹具验证，不在用户聊天上删记录，不调用付费模型。

APP 首次加载 50 条、最多挂载 100 条，较早页保留阅读锚点并提供「回到最新消息」；变更后按当前范围权威重读，不把旧分页合并回去，草稿独立保留。主聊天原有折叠/限高/80 条窗口实现不回退。

历史分页发送时回到最新，Host 接手发送即可清掉 UI 临时提交态，不依赖消息恰好出现在当前分页。主聊天卡片使用协议内稳定的消息序号作阅读锚点，删除前方记录后按该标识重新定位分页窗口，不按旧数组下标错认消息。权限评估只复用单次请求的分区快照、片段成员索引和片段检查结果；不跨请求缓存，执行前仍重新验证。

## 上下文与验证边界

发送、重新回复、计量及摘要使用同一套 [通讯上下文设计](./information-app-context-design.md)。重新回复只修改候选摘要，生成失败保留原回复和原摘要。

隔离存储、模拟模型和桌面浏览器检查不能证明真实模型回复质量、实体手机 WebView 或供应商实际视觉 token 用量；这些环境需独立验收。
