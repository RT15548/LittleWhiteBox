# 普通小白 OS 世界 APP：产品设计

## 1. 文档性质

本文定义世界 APP 的产品与运行契约。它提供当前世界的镜头外新闻，不是任务大厅、剧情导演或世界书编辑器；不提供用户新闻档案、人工逐条编辑或完整世界推演。

## 2. 已确认的产品定位

**世界 APP 代表世界在活着：玩家眼前的剧情之外，也在发生有意思的事。它是轻背景。**

- 世界不围绕玩家转。玩家没有去过、没有参与，不妨碍其他地方有自己的生活。
- 上下文沿用角色卡、世界书、已有剧情及本 APP 已维护的背景，不另起一套复杂的世界理解工程。
- 它不关心当前主剧情有没有使用世界信息，不追踪采用率、参与情况或“这条背景是否完成”。
- 它不是任务 APP，没有接取、履约目标、进度、完成失败或奖励结算。
- “轻”指叙事分量与介入程度，不是内容敷衍，也不是只能写鸡毛蒜皮。题材需要时可以有战争、宗门动向或社会变化，但不强迫玩家介入。

任务与世界可以在内容上交叉：剧团到访是一条世界近况，运送演出服装可以是一份委托。背景不自动成为任务，世界也不以生产任务素材为目标；二者各自可以独立成立。

## 3. 输入与生成内容

角色卡、世界书与剧情是只读设定和事实来源；`world.news`是模型创作的世界内消息，不是联网现实新闻。不继承小白板的秘密分层、幕后大纲、行动指南或行动计数，不迁移其数据。

## 4. 内容结构

### 4.1 世界近况

一小段当前世界背景：最近的气氛、季节或社会环境，以及仍在影响生活的重要变化。

它不重抄世界书，不重新建立百科，也不复述玩家的主线经历。这里只保留理解当前见闻所需的背景。

### 4.2 各处见闻

APP 的主要阅读内容，是不同地方正在发生的具体事情。可以是地方消息、街谈巷议、人物生活片段或环境变化，不强制套现代新闻报道口吻。

例如首次出现：

> **旧剧院重新亮灯**\
> 停业多年的旧剧院最近开始修缮。傍晚经过的人能听见里面断断续续的排练声，门口还没挂出演出告示。

在合适的剧情时间后，同一件事可以更新为：

> **首演定在周末**\
> 旧剧院贴出了第一张海报。附近几家小店打算延长营业，街坊对这个新剧团的评价倒不一致。

玩家没有参与，这件事仍有意义；无需附带“建议前往调查”。

同一件事应有稳定身份，标题变化不等于新事件。内容可以交代当前情况及必要前情，但不设计成需要全部填满的固定分类、任务面板或势力经营表。

## 5. 上下文与创作原则

输入包括角色卡、宿主提供的世界书内容、已有剧情及本 APP 当前保存的世界背景。角色卡和作者设定约束题材、规则与人物；剧情帮助理解当前时间、环境及不能违背的事实；已有世界背景提供连续性。

- 作者已有设计时尊重设定；缺少细节时允许合理补全镜头之外的生活。
- 不能限制为只提取聊天里已经发生的事情，否则会失去世界 APP 的意义。
- 新生成内容不得冒充玩家的经历、决定或已知人际关系。
- 不把“某人计划做什么”直接写成“已经做完”，也不把传闻自动当作确定事实。
- 不为制造吸引力而处处设置阴谋、危机或主线伏笔；内容气质服从当前世界。
- 不擅自揭穿作者核心秘密。玩家在 APP 中读到镜头外背景，不等于其扮演的角色已经获知。

现有 OS 公共上下文提供的是宿主触发的世界书内容，不保证全书。不能把本次未读到某项设定当作作者没有设定；这里记录输入边界，不据此扩建独立的全书扫描系统。

## 6. 更新与连续性

新闻既是当前可读的见闻，也是下一轮维护的依据：每条报道同一件事的当前阶段，不另建暗线集合或状态字段。

- 先回看已有事情，再考虑补充新事。根据既有情况和经过的故事时间，判断保持、推进或退场；时间不明时不擅自跳阶段。
- 有实质变化才续写，沿用同一 ID，交代发展和当前影响，保留理解现状所需的少量前情；换标题、改措辞不算推进，没有变化就保持原文。
- 人的事情可以成功、受阻、转向或平淡结束。季节、迁徙等自然过程按阶段变化，不强套成功失败，也不依赖玩家参与。
- 结束不等于立即删除：结果和直接影响仍切合当下时可以保留，相关性消退后退出；仍塑造整体环境的长期影响才融入概况，不累积新闻档案。
- 不因主剧情没采用某条内容而催促、升级危机、判定失败或删除它。周边生活、景物、生计的改变本身就有意义。
- 新事应有独立且符合设定的看点，不为填满条数而补写；也不规定每轮必须换掉几条。
- 不把点击更新次数、现实经过时间或机械消息数量直接等同于世界时间；打开与反复刷新不是推进剧情的动作。

主入口采用「开启自动新闻」，菜单提供同一个全局开关：开启后随 OS 每个有效接受轮持续维护，换卡／换聊天无需再次开启；另有次要「刷新」入口。关闭后保留各聊天既有内容，仍可手动刷新。不增加现实时间定时器。自动新闻代表授权后续模型用量，即使检查后没有新内容也可能产生用量。

打开、阅读、展开正文等本地操作不调用模型。整轮维护成功后才发布整期新闻；生成或保存失败保留旧内容，不把中途编辑发布为部分完成。首次开启自动新闻在全局设置保存成功后申请首批；新闻保存核实不重新生成。自动与手动更新均归 Host 后台，离开 APP、关闭 OS 窗口或追加聊天消息不取消；切聊天或修改本次依据的旧消息仍阻止过期结果。等待与错误状态要在当前操作位置可见。

## 7. 给主剧情的背景投影

独立 APP 需要保留背景注入能力；这是本 APP 自身闭环，不等于现在开始设计 ENA 或其他 APP 适配。

主剧情只读取简短的当前概况和有限的有效近况，不灌入全部历史。投影的语义应是：

> 以下是世界背景，可在合适场景自然体现；无需逐条提及，无需引导玩家参与，也不代表当前角色已经获知。

这份背景不是剧情执行指令，不替玩家作决定，不强制转场。APP 不检测主模型是否采用它，不保存“已使用／未使用”标记。

位置采用 **聊天记录 System @D4**，复用 OS 的生成拦截与清理链路，`scan=false`；地图使用 D3，任务／商店的位置分别以[任务注入注册](../apps/tasks/prompt-registration.ts)和[商店注入注册](../apps/shop/prompt-registration.ts)为准，各自独立注入。不写世界书、不增临时条目，也不监听世界书加载事件。D4 只是离最新对话远一些，轻背景仍依靠简短内容和叙事语义，不是优先级保证。请求只读取当前聊天已确认内容的一次快照，新维护结果从后续请求生效。

提供一个全局「作为剧情背景」总开关，默认开启；提供当前聊天的概况及新闻标题、正文，不逐条勾选、不跨聊天共享内容。每条新闻只生成、保存一份正文，列表预览从正文派生，不另写摘要。阅读与展开不改变注入，停止订阅也不自动抹掉已经建立的背景。

主剧情预算容纳正常文本下的整期标题与正文，具体容量见本文的内容与预算边界。少数含大量特殊符号的内容在安全转义后超出时，只选择放得下的完整概况或文章并标明省略，不截半句话；预算只影响本次提供给模型的资料，不删改新闻，也不决定存档能否加载。

## 8. 阅读体验：看向世界的窗口

产品气质是开阔、鲜活、现代的“世界窗口”。打开时感到眼前之外还有世界，浏览时能轻松挑选有趣的见闻，进入文章后专注阅读。“轻背景”指剧情介入轻，不是视觉气场小。不再使用报头、印章、编号和无依据的首条头版，也不做世界监控仪表盘。

### 8.1 视觉语言

- 继承 OS 字体与操作尺度；浅色采用近白、墨色文字与干净的浅蓝远景，深色为中性炭黑、柔白与对应夜色。颜色仅属于世界 APP，不修改 OS 全局主题。主标题 22px，列表标题 16px、正文预览 13px，正文 15–16px；不通过全面放大字号和卡片制造气场。
- 本地 SVG 地平线建立视觉开篇：常规高 130px，最窄内容区 115px，宽内容区 185px；图与概况分开，文字不压在图上。没有首屏遮罩、轮播或进入动画。它是抽象品牌画面，不代表当前地图、天气或新闻现场，也不强制现代、古风或地球题材。
- 桌面图标使用明亮蓝色与白色球面经纬线，表达「世界」；地图使用道路和定位针，二者轮廓明确区分。不是在每条新闻前重复贴图标。
- 新闻用同级标题、留白和轻分隔组织；不做满屏大卡片。正文无需配图，不增加远程素材、外部字体、模型绘图工具或新数据字段。
- 新闻可以是仙侠见闻、现代地方消息、科幻社会近况，不强制现代报社、记者署名或精确日历。

### 8.2 首页与正文

- 首页只有一个「世界」标题，刷新和更多菜单与其同排。图下概况最多预览两行，主动展开才阅读完整近况；此操作只改运行内展开状态，不请求模型。
- 概况下直接进入新闻，不再加「各处见闻」和数量眉题。全部同级，无第一条特殊排版、重要性评分或机械编号；标题和正文开头分别最多预览两行，完整标题及正文进入文章页阅读。内容区达到 640px 时两列，其余单列；沿用宿主窗口，不修改 Shell 大小，现有顺序规则不变。
- 普通字号首屏应能浏览多条具体见闻，不能被宣传文案和概况挤满；放大文字优先保证可读与可滚动，不锁死卡片高度。
- 点击进入独立文章页，仅保留标题、分段正文及必要更新提示；不另列预览、刊头或口号。返回恢复列表位置和条目焦点；条目已移除时聚焦首页标题。
- 正在阅读的文章保存运行内快照；后台更新时提供轻量新版入口，不强制替换正文、跳页或滚动归零。
- 时间与地点只使用内容能支持的表达；技术更新时间不冒充世界日期，不显示虚构的“刚刚发布”。

### 8.3 操作与反馈

- 首次空态只显示无新闻状态与主按钮「开启自动新闻」，旁边保留使用模型的必要提示，不再铺功能介绍。
- 有内容后以阅读为主。「自动新闻」与「作为剧情背景」放更多菜单，注明开关对所有聊天生效、内容仍属于各自聊天。
- 刷新期间旧内容继续可读，刷新入口显示等待；错误就地说明并提供对应重试／保存核实入口，不连续弹通知。
- 不做未读红点、点赞、热搜、搜索分类、往期档案、逐条编辑、任务按钮或行动指南。
- 320px、390px 和桌面尺寸以及深浅主题均可读；长标题、文字放大、键盘焦点和点击区域属于正式验收。

阅读、订阅／刷新及少量设置先形成完整体验；不为凑“玩家能做什么”添加玩法。不把人工纠正作为前提：先通过创作质量让新闻值得读。不设置正文编辑、单条删除和纠正工作流；模型维护时删除替换旧新闻与用户删稿是两回事。

新闻采用有信息顺序的短讯，正文按事件及对象／地点、关键进展、直接影响或当前状态组织；写作容量与具体规则见本文的内容与预算边界。应有具体事情、世界辨识度和各自的看点；温暖、幽默、古怪、争议、生活变化与大事均可，题材服从世界。延续要有新信息，不只是换标题复读；不把每篇写成待玩家调查的任务预告。

## 9. 所有权与状态边界

世界 APP 自己拥有世界内容、连续性规则、生成与维护 Prompt、背景投影和 UI；按普通 OS 的 `domains/<domain>` 与 `apps/<app>` 边界组织，核心层只提供通用能力。当前领域位于 `domains/world/`，应用、工具与 UI 位于 `apps/world/`。

- **长期事实**：本聊天已建立的当前世界背景、近况及维持连续性所必需的前情。需要在重开后延续，由世界 APP 的独立 sidecar 分区拥有；不回写作者世界书。
- **外部只读来源**：角色卡、世界书和剧情记录仍归原功能，不复制出第二套可编辑来源。
- **临时状态**：页面展开、请求过程、模型草稿、加载与错误状态；不作为世界事实长期保存。
- **依赖与入口**：使用现有 OS 存储、Agent、维护及主生成生命周期；通过 APP、分区和相应运行入口注册，不添加独立后台引擎。
- **删除原则**：世界 APP 的分区、注册与自身代码可以独立退场；不删除作者设定或其他 APP 数据。具体用户数据处置须在删除前确定。

不建立第二份地图、联系人或任务数据，也不为可能的联动预建共享“世界事件系统”。

## 10. 数据、工具与保存

当前模型由 [World 领域类型](../domains/world/types.ts)唯一描述：`{version,overview,news}`，新闻只有 ID、标题和正文；开关归全局 OS 设置，不存聊天分区。写作容量、旧长正文读取容量分别引用 `WORLD_WRITE_LIMITS`和`WORLD_LIMITS`，长度按 Unicode 码点；加载或无关修改不截断旧正文。

初始数据与 WorldRead 共用 `{overview,news}`投影，不外露偏好或宿主对象。初始资料安全格式化的预算归 [prompt-data.ts](../apps/world/prompt-data.ts)；超出时仅在投影省略所有正文并说明，目录与概况完整。WorldRead 始终可补读完整正文。主剧情预算归 [story-projection.ts](../apps/world/host/story-projection.ts)，只选完整概况／文章，预算不参与存档合法性判定。

WorldEdit 的字段与返回由 [工具契约](../apps/world/tools/tool-contract.ts)拥有：省略保留、空概况清空、upsert 为完整新闻，同 ID 延续并保留顺序，新 ID 置前；同批重复或增删冲突拒绝。整批校验失败不部分应用。未解决错误在运行内跟踪，其他无关成功不能抹掉；保留旧稿、修正或放弃失败新稿必须经真实工具语义完成。

工具循环完整结束且本领域没有未解决错误后，才发布整期候选。网络中断、空返回、限额或错误保留旧刊物；保存未知只核实原候选，不重新生成。内容比较只看原内容、身份与维护 guard，不把其他 APP 写入或全局开关变化误报成新闻冲突。

全局设置保存失败保留原意愿，不生成或取消已有更新。首次授权更新在保存成功后由后台拥有，离开界面不取消；切聊天、停用或明确取消使该次未提交更新失效，回原聊天不续跑。新闻文件恢复永不触发首次生成；无开场正文时等待开场。

## 11. 联动、兼容与删除

任务与地图的现有素材包获得当前聊天已确认新闻；订阅和背景开关不限制该只读参考，同轮已有则不重复。任务生成将新闻固定为本次参考快照，在途新闻更新不丢弃任务结果；剧情和任务自身变化仍受原守卫约束。不自动转任务或扩地图，不新增请求、工具或联动状态。

历史分支清空概况和新闻，在子线重新建立，不把父线最新新闻伪装成分支点事实；完整复制和改名保留当前内容。全局开关不随分支复制。正式线 v1／v2 文件仅在 [分区解析入口](../apps/world/storage/upgrade.ts)转换，保留正文、丢弃独立摘要；只读不改文件，下次内容提交使用当前模型。

删除时停止 World 运行和监听，清所属分区、设置与注入，移除目录、catalog 和可选资料接入。保留主聊天、作者世界书及其他 APP 数据。信息联动、ENA、小白板迁移与退场需另定方案，本文件不授权删除旧数据。

## 12. 验证与限制

规则与工具通过真实领域／分区事务测试，完整发布、错误修正、设置失败、保存未知、分支和来源失效均需覆盖。UI 检查正式阅读、更新快照、返回焦点、菜单、窄屏、深浅主题及文字放大；阅读零模型请求。

真实模型的现代／奇幻／科幻新闻质量、故事时间连续性、私人知识隔离与主剧情自然使用仍需单独验收；复杂预设、真实群聊完整生成和实体 WebView 未由隔离浏览器证明。文档的判断标准是玩家能持续看见同一个世界的生活，不以 HTTP 成功或测试数量替代内容质量。
