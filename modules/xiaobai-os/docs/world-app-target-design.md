# 普通小白 OS 世界 APP：产品设计

## 1. 文档性质与讨论范围

本文记录世界 APP 已确认的产品定位与设计方向，避免后续将它做成任务大厅、剧情导演或世界书编辑器。具体实施契约、进度和验证证据见 [施工记录](./world-app-implementation-plan.md)。

2026-09-06 用户确认首版施工计划，并在原生 ↑Char 事件方案的隔离验证失败后明确改为 **System @D4**。当前已实现订阅、维护、保存、世界阅读 UI 和 D4 注入；工程检查与浏览器结果、仍未完成的真实模型质量验收见 [施工记录](./world-app-implementation-plan.md)。原 ↑Char 探针仅作为历史决策证据保留。

按已确认的三个讨论范围分别推进：

1. **世界 APP 自身**：当前范围，先想清独立产品闭环。
2. **与 OS 内其他 APP 的联动**：已确认只将现有世界新闻加入任务、地图本来就读取的素材包；不预建全 APP 联动。
3. **与 ENA、小白板的关系**：另行确定 ENA 适配、旧能力承接、数据处置与小白板退场。

下文提到小白板仅用于说明产品来历；不在本轮决定迁移或删除方案。

## 2. 已确认的产品定位

**世界 APP 代表世界在活着：玩家眼前的剧情之外，也在发生有意思的事。它是轻背景。**

- 世界不围绕玩家转。玩家没有去过、没有参与，不妨碍其他地方有自己的生活。
- 上下文沿用角色卡、世界书、已有剧情及本 APP 已维护的背景，不另起一套复杂的世界理解工程。
- 它不关心当前主剧情有没有使用世界信息，不追踪采用率、参与情况或“这条背景是否完成”。
- 它不是任务 APP，没有接取、履约目标、进度、完成失败或奖励结算。
- “轻”指叙事分量与介入程度，不是内容敷衍，也不是只能写鸡毛蒜皮。题材需要时可以有战争、宗门动向或社会变化，但不强迫玩家介入。

任务与世界可以在内容上交叉：剧团到访是一条世界近况，运送演出服装可以是一份委托。背景不自动成为任务，世界也不以生产任务素材为目标；二者各自可以独立成立。

## 3. 小白板原有能力的参考结论

需要区分两个概念：

- **输入的世界信息**：角色卡、世界书等设定，约束这个世界可以发生什么。
- **生成的世界资讯**：`world.news`，由模型创作的世界内消息，不是联网获取现实新闻。

小白板原有闭环是：依据设定、剧情和当前世界生成新闻 → 保存并展示 → 按勾选项注入主剧情。

- 世界页展示标题、时间及可展开正文，另有玩家处境与行动指南。
- 故事模式会先生成幕后大纲，再生成地图和新闻；新闻部分要求与剧情相关，也允许跟进上一条新闻。
- 辅助模式的世界推演主要更新新闻与地图，模板举例包括店家打折、节庆活动、NPC 日常小事，更接近本 APP 的轻背景方向。
- 勾选世界资讯后，新闻的标题和正文进入剧情 Prompt，不只是页面装饰。
- 现有推演以新 `world` 替换旧集合；模型能参考旧内容，但新闻本身没有稳定身份来维护同一件事的延续。
- 世界推演主要由用户操作触发，原行动计数只是提醒。界面的“只刷新新闻”请求目前没有对应宿主处理器，不能当作已完成的独立刷新能力。

继承的是背景生成、阅读与剧情注入的价值，不继承固定五层秘密、单一幕后推手、预定结局、玩家行动指南或旧行动计数。

参考：[小白板宿主](../../story-outline/story-outline.js)、[生成提示词](../../story-outline/story-outline-prompt.js)、[界面](../../story-outline/story-outline.html)。

## 4. 内容结构

### 4.1 世界近况

一小段当前世界背景：最近的气氛、季节或社会环境，以及仍在影响生活的重要变化。

它不重抄世界书，不重新建立百科，也不复述玩家的主线经历。这里只保留理解当前见闻所需的背景。

### 4.2 各处见闻

APP 的主要阅读内容，是不同地方正在发生的具体事情。可以是地方消息、街谈巷议、人物生活片段或环境变化，不强制套现代新闻报道口吻。

例如首次出现：

> **旧剧院重新亮灯**\
> 停业多年的旧剧院最近开始修缮。傍晚经过的人能听见里面断断续续的排练声，门口还没挂出演出告示。

在合适的剧情时间后，同一件事可以更新为：

> **首演定在周末**\
> 旧剧院贴出了第一张海报。附近几家小店打算延长营业，街坊对这个新剧团的评价倒不一致。

玩家没有参与，这件事仍有意义；无需附带“建议前往调查”。

同一件事应有稳定身份，标题变化不等于新事件。内容可以交代当前情况及必要前情，但不设计成需要全部填满的固定分类、任务面板或势力经营表。

## 5. 上下文与创作原则

输入包括角色卡、宿主提供的世界书内容、已有剧情及本 APP 当前保存的世界背景。角色卡和作者设定约束题材、规则与人物；剧情帮助理解当前时间、环境及不能违背的事实；已有世界背景提供连续性。

- 作者已有设计时尊重设定；缺少细节时允许合理补全镜头之外的生活。
- 不能限制为只提取聊天里已经发生的事情，否则会失去世界 APP 的意义。
- 新生成内容不得冒充玩家的经历、决定或已知人际关系。
- 不把“某人计划做什么”直接写成“已经做完”，也不把传闻自动当作确定事实。
- 不为制造吸引力而处处设置阴谋、危机或主线伏笔；内容气质服从当前世界。
- 不擅自揭穿作者核心秘密。玩家在 APP 中读到镜头外背景，不等于其扮演的角色已经获知。

现有 OS 公共上下文提供的是宿主触发的世界书内容，不保证全书。不能把本次未读到某项设定当作作者没有设定；这里记录输入边界，不据此扩建独立的全书扫描系统。

## 6. 更新与连续性

更新的目标是继续维护同一个世界，而不是每次重新生成一批互不相干的消息。

- 维护当前这一组见闻：有的延续，有的保持原样，有的删除替换，再加入少量新事。
- 根据合理的时间与条件改变近况，允许平静、缓慢发展或本次没有变化；不规定每次必须换掉几条。
- 不再重要的旧事可以自然退出展示；仍影响当下的结果应留在当前背景或必要前情中。
- 不因主剧情没采用某条内容而催促、升级危机、判定失败或删除它。
- 不把点击更新次数、现实经过时间或机械消息数量直接等同于世界时间；打开与反复刷新不是推进剧情的动作。
- 不以保存全部旧新闻为目标，也不引入无限历史档案；继续有影响的结果留在当前概况或必要前情中。

主入口采用「开启自动新闻」，菜单提供同一个全局开关：开启后随 OS 每个有效接受轮持续维护，换卡／换聊天无需再次开启；另有次要「刷新」入口。关闭后保留各聊天既有内容，仍可手动刷新。不增加现实时间定时器。自动新闻代表授权后续模型用量，即使检查后没有新内容也可能产生用量。

打开、阅读、展开正文等本地操作不调用模型。整轮维护成功后才发布整期新闻；生成或保存失败保留旧内容，不把中途编辑发布为部分完成。首次开启自动新闻在全局设置保存成功后申请首批；新闻保存核实不重新生成。自动与手动更新均归 Host 后台，离开 APP、关闭 OS 窗口或追加聊天消息不取消；切聊天或修改本次依据的旧消息仍阻止过期结果。等待与错误状态要在当前操作位置可见。

## 7. 给主剧情的背景投影

独立 APP 需要保留背景注入能力；这是本 APP 自身闭环，不等于现在开始设计 ENA 或其他 APP 适配。

主剧情只读取简短的当前概况和有限的有效近况，不灌入全部历史。投影的语义应是：

> 以下是世界背景，可在合适场景自然体现；无需逐条提及，无需引导玩家参与，也不代表当前角色已经获知。

这份背景不是剧情执行指令，不替玩家作决定，不强制转场。APP 不检测主模型是否采用它，不保存“已使用／未使用”标记。

位置采用 **聊天记录 System @D4**，复用 OS 的生成拦截与清理链路，`scan=false`；地图使用 D3，任务／商店仍使用 D1，各自独立注入。不写世界书、不增临时条目，也不监听世界书加载事件。D4 只是离最新对话远一些，轻背景仍依靠简短内容和叙事语义，不是优先级保证。请求只读取当前聊天已确认内容的一次快照，新维护结果从后续请求生效。

提供一个全局「作为剧情背景」总开关，默认开启；仅提供当前聊天自己的新闻短摘要，不逐条勾选、不跨聊天共享内容。阅读与展开不改变注入，停止订阅也不自动抹掉已经建立的背景。

主剧情背景在安全格式化后最多 2,000 码点。少数含大量特殊符号的内容超出时，只选择放得下的完整概况或摘要，不截半句话；预算只影响本次提供给模型的资料，不删改新闻，也不决定存档能否加载。

## 8. 阅读体验：看向世界的窗口

产品气质是开阔、鲜活、现代的“世界窗口”。打开时感到眼前之外还有世界，浏览时能轻松挑选有趣的见闻，进入文章后专注阅读。“轻背景”指剧情介入轻，不是视觉气场小。用户确认替换原复古小刊方向：不再使用报头、印章、编号和无依据的首条头版，也不做世界监控仪表盘。

### 8.1 视觉语言

- 继承 OS 字体与操作尺度；浅色采用近白、墨色文字与干净的浅蓝远景，深色为中性炭黑、柔白与对应夜色。颜色仅属于世界 APP，不修改 OS 全局主题。主标题 22px，列表标题 16px、摘要 13px，正文 15–16px；不通过全面放大字号和卡片制造气场。
- 本地 SVG 地平线建立视觉开篇：常规高 130px，最窄内容区 115px，宽内容区 185px；图与概况分开，文字不压在图上。没有首屏遮罩、轮播或进入动画。它是抽象品牌画面，不代表当前地图、天气或新闻现场，也不强制现代、古风或地球题材。
- 桌面图标使用明亮蓝色与白色球面经纬线，表达「世界」；地图使用道路和定位针，二者轮廓明确区分。不是在每条新闻前重复贴图标。
- 新闻用同级标题、留白和轻分隔组织；不做满屏大卡片。正文无需配图，不增加远程素材、外部字体、模型绘图工具或新数据字段。
- 新闻可以是仙侠见闻、现代地方消息、科幻社会近况，不强制现代报社、记者署名或精确日历。

### 8.2 首页与正文

- 首页只有一个「世界」标题，刷新和更多菜单与其同排。图下概况最多预览两行，主动展开才阅读完整近况；此操作只改运行内展开状态，不请求模型。
- 概况下直接进入新闻，不再加「各处见闻」和数量眉题。全部同级，无第一条特殊排版、重要性评分或机械编号；标题和摘要分别最多预览两行，完整标题及正文进入文章页阅读。内容区达到 640px 时两列，其余单列；沿用宿主窗口，不修改 Shell 大小，现有顺序规则不变。
- 普通字号首屏应能浏览多条具体见闻，不能被宣传文案和概况挤满；放大文字优先保证可读与可滚动，不锁死卡片高度。
- 点击进入独立文章页，仅保留标题、分段正文及必要更新提示；不重复列表摘要、刊头或口号。返回恢复列表位置和条目焦点；条目已移除时聚焦首页标题。
- 正在阅读的文章保存运行内快照；后台更新时提供轻量新版入口，不强制替换正文、跳页或滚动归零。
- 时间与地点只使用内容能支持的表达；技术更新时间不冒充世界日期，不显示虚构的“刚刚发布”。

### 8.3 操作与反馈

- 首次空态只显示无新闻状态与主按钮「开启自动新闻」，旁边保留使用模型的必要提示，不再铺功能介绍。
- 有内容后以阅读为主。「自动新闻」与「作为剧情背景」放更多菜单，注明开关对所有聊天生效、内容仍属于各自聊天。
- 刷新期间旧内容继续可读，刷新入口显示等待；错误就地说明并提供对应重试／保存核实入口，不连续弹通知。
- 不做未读红点、点赞、热搜、搜索分类、往期档案、逐条编辑、任务按钮或行动指南。
- 320px、390px 和桌面尺寸以及深浅主题均可读；长标题、文字放大、键盘焦点和点击区域属于正式验收。

阅读、订阅／刷新及少量设置先形成完整体验；不为凑“玩家能做什么”添加玩法。不把人工纠正作为前提：先通过创作质量让新闻值得读。施工方案第一版不设置正文编辑、单条删除和纠正工作流；模型维护时删除替换旧新闻与用户删稿是两回事。

新闻应有具体事情、世界辨识度和各自的看点；温暖、幽默、古怪、争议、生活变化与大事均可，题材服从世界。延续要有新信息，不只是换标题复读；不把每篇写成待玩家调查的任务预告。

## 9. 所有权与状态边界

世界 APP 自己拥有世界内容、连续性规则、生成与维护 Prompt、背景投影和 UI；按普通 OS 的 `domains/<domain>` 与 `apps/<app>` 边界组织，核心层只提供通用能力。本草案不冻结内部命名或目录细节。

- **长期事实**：本聊天已建立的当前世界背景、近况及维持连续性所必需的前情。需要在重开后延续，由世界 APP 的独立 sidecar 分区拥有；不回写作者世界书。
- **外部只读来源**：角色卡、世界书和剧情记录仍归原功能，不复制出第二套可编辑来源。
- **临时状态**：页面展开、请求过程、模型草稿、加载与错误状态；不作为世界事实长期保存。
- **依赖与入口**：使用现有 OS 存储、Agent、维护及主生成生命周期；通过 APP、分区和相应运行入口注册，不添加独立后台引擎。
- **删除原则**：世界 APP 的分区、注册与自身代码可以独立退场；不删除作者设定或其他 APP 数据。具体用户数据处置须在删除前确定。

不建立第二份地图、联系人或任务数据，也不为可能的联动预建共享“世界事件系统”。

## 10. 施工与明确留后的事项

本 APP 自身的更新范围、内容容量、阅读状态、错误路径与分支语义见 [施工方案](./world-app-implementation-plan.md)。历史分支保留偏好并重新建立新闻，不把父线最新近况复制成分支点事实；这是不保存历史快照的明确取舍，不承诺还原分支点新闻。

OS 内的资料共享已接通：任务、地图取既有素材包时，一并获得当前聊天已确认保存的概况和新闻；没有则省略，世界同轮维护时不重复提供。通常包含正文；安全格式化后超过初始资料预算时明确省略正文，概况、ID、标题和摘要仍完整，APP 阅读内容不受影响。任务的刷新委托与寻找应征者也使用这份资料。这里只增加参考资料，不要求自动转任务、扩画地图，不另加工具、开关、请求或持久化数据。「作为剧情背景」开关只控制主剧情 D4，取消订阅也不妨碍参考保留的新闻。世界自身不增加读取任务或整张地图的需求。

信息联动、ENA 接入、小白板能力清点和迁移／退场仍留后。小白板已存在于正式线 `upstream`，旧数据不能直接按测试线临时数据丢弃；本文不授权任何迁移、删除或兼容壳。

采用 D4 后不再保留 ↑Char 适配关卡；真实模型的新闻质量仍需单独验收。当前文档的判断标准始终是：**玩家能持续看见同一个世界的生活，即使主剧情没有用到它。**
