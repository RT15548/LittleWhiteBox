# 荒岛：工程边界与状态流

本文服务于[产品设计](island-game-target-design.md)，不包含运行时 Prompt 或工具描述文本。目标结构与已接通的实现须区分，实例验证见[自由玩法验收](island-game-scenarios.md)。

## 当前实现边界

正式代码归 [island](../apps/game/island/) 所有，已注册独立用户存档、记忆缓存、生产 Host 和游戏大厅入口；界面与场景仍在实机打磨，不作为最终视觉验收结论：

人物尚未全部按产品设计的正式阵容替换，玩家身份自选入口也未制作；角色资产与场景接入边界见下文人物实现及[人物制作说明](../apps/game/island/production/characters/README.md)。当前不是第一章完整验收交付，不能把规则测试或接口接通等同于整章玩法、美术与真实 GM 长程表现通过。

- [世界模型](../apps/game/island/model.ts)、[操作](../apps/game/island/operations.ts)与[时钟](../apps/game/island/clock.ts)：七人、实际位置与物件、共同时间、同时竞争、接触及新决策边界。地图与生理数值是制作参数，不是医学或地理标定。
- [劳动](../apps/game/island/work.ts)与[生理](../apps/game/island/physiology.ts)：实际采集、容器取水饮用、拆衣制作、适合地点建营与恢复半成品、取暖用火与煮水、脚伤、排泄、污染和清洁。基础动作已接通，全部操作入口与长程平衡尚需整体试玩。
- [场景投影](../apps/game/island/scene.ts)、[工作段](../apps/game/island/scene-work.ts)与 [GM 循环](../apps/game/island/agent/runner.ts)：玩家与 NPC 控制权分开，按实际听见范围确定受众；接到共享 Agent gateway，完整候选确认后提交。已接工具协议不等于真实模型的群像表现通过验收。
- [相遇与判断](../apps/game/island/attention.ts)：新看见对方形成个人经历，需要回应或重新选择的人由经历派生。本人发言、行动或私人打算可以回应这次相遇；不会为触发 GM 而强制取消已有劳动。私人打算只有本人知情，不广播，也不另存一份计划表。离场相遇解决后继续玩家未完成的活动；玩家首次遇见一小群人时停步，明确继续靠近后，不因同群各人依次进入视野或交谈距离而逐米叫停。这里的同群只指本次推进开始时已彼此可见且可交谈、并与玩家已感知的人相邻的现场关系，不是阵营；逐人的发现时刻、见闻和受众照常记录，独立来人及新发现遗体仍停步。
- [经历](../apps/game/island/experience.ts)与[记忆](../apps/game/island/memory.ts)：一份原始经历、逐人约定投影、原文分页、分块与先知情过滤的向量排序。[连接](../apps/game/island/agent/embedding.ts)仅取 Embedding 设置；[索引](../apps/game/island/agent/memory-store.ts)保留实际模型空间和来源摘要绑定。近期原文和主动检索已接线；真实长程召回质量及极端数据规模仍待验证。
- [死亡结算](../apps/game/island/mortality.ts)：脱水、持续缺食和疾病可终结旅程，NPC 留下原身体与物件；不是 GM 的任意杀人操作。能量收支可以为负，持续缺食影响步速和休息恢复，不在食物归零后无限存活。其他环境致死、掘墓与遗体环境影响和长程生理平衡仍需完善。
- [遗体搬移与遮盖](../apps/game/island/remains.ts)：就近抓持后沿实际路线缓慢拖移，拖移者和身体各自的路径都需可行走；同一身体不能同时被两人拖往不同处。取消、抵达或搬动者死亡时留在实际停止的位置，原随身物件随身体移动，不生成第二份尸体库存。遮盖使用真实且已脱下的衣物、布片或枝叶，耗时后整份物件改为依附该身体的 `covering` 位置，可以重新取回；遮盖不是掩埋、净化或消除遗体。记录按目击范围保存，远处人物不会自动得到死亡和搬移消息。
- 死亡与遗体发现按对应经历的实际受众唤醒仍活着的 NPC 判断，不自动取消其劳动或替他们安排清理。回应、改变行动或留下本人打算后，已回应的同一见闻不会因重载再次触发。发现遗体仍不提供未目击的死亡过程或死因。
- [存档边界](../apps/game/island/partition.ts)与[应用服务](../apps/game/island/service.ts)：当前格式校验、唯一操作指纹、玩家可知视图、完整候选提交及失败恢复。原文不复制进操作收据。重开直接开始新旅程，不保留本功能自己的旧格式分叉。

实际浏览器验收使用生产 Shell、Host、工具和文件事务，模型夹具只替代收费供应商，不冒充真实模型试演。画图已产生正式海岸入口素材；游戏内是独立 Three.js 场景。当前继续打磨完整操作入口、离场决策节奏、自由玩法、长期记忆及桌面/手机体验，不将代码检查通过称为荒岛已经完成。

人物回应失败保留已经确认的行动与说话，提示放在交谈区内，不浮层遮住移动或输入。重试只请求新的 NPC 回应；需要修改连接时，经宿主既有导航打开 Agent API，不复制一套荒岛模型配置，不自动测试连接或重新购买请求。保存结果未知仍使用单独的确认保存入口，不能混成重试模型。

界面包括玩家自己的住处/立场选择、可见人物入口、原始经历分页、实物制作与营地操作。穿着中的衣物不被自动选为拆用材料。场景的地表、落脚与选地来自同一[游戏地势](../apps/game/island/terrain.ts)，视觉移动仅回放已确认位置变化，不驱动生存时钟。树木按世界坐标稳定加载，不因镜头换区重新随机摆放。

[海岸](../apps/game/island/coastline.ts)统一生成圆化岬角与浅湾边界，可行走地面、地势及海面连接都使用这条边界。近岸距离在运行内建立空间索引，海面网格预计算岸距，避免细分岸线后每个像素遍历全岛。海面外圈要求当前岛形相对原点保持星形，实际网格测试检查海陆衔接、朝向和不跨陆地；以后调整地理内容不能另画一条纯装饰岸线。所有网格、索引与动画仅活在运行内，潮位仍由游戏时间决定，渲染浪纹不改变涉水深度或擅自推进时间。

叶芮使用[真实角色资产适配器](../apps/game/island/presentation/character-asset.ts)，其余人物沿用[程序化身体](../apps/game/island/presentation/survivor.ts)与[姿态](../apps/game/island/presentation/survivor-pose.ts)。衣物款式、穿戴层、线性色和接触高度集中在[衣物目录](../apps/game/island/clothing.ts)，是否穿着、去向及湿度只取真实物件，不由穿衣者决定款式。四件样衣分别存在，落地、递出和遮盖外观由同一网格派生；角色外观尺寸不赋予劳动或生存能力。

姿态只回放已确认的活动与位置，不推进世界时间；脚底校准只调整临时视觉组，死亡动作不再整体下沉。头部标签、手中递物和正在使用的随身饮食物品跟随骨骼；外部观察只公开可见劳动种类及正在使用物件的外形、湿度和手持份数，不暴露任务目标、物件 ID、水量或其他私人库存。取消、完成、死亡或不可见时，使用附件随投影消失；地面饮食来源保持地面物件，不重复成手持副本。遮盖物保留实物尺寸并随身体移动，不另存姿态或展示状态。

人物实例拥有骨架和衣物材质，角色几何、贴图由本次场景持有；退出顺序为人物和附件、场景资源、共享角色资产。加载可取消，失败提供保留旅程的重试，不以旧占位人静默替代。当前有必要的站走、休息、劳动、饮用、清洁、递出、拖行与死亡表现，但没有逐工序精细手势、精确握持或布料仿真；首名角色接入不代表其余五名人物或完整章节已完成。

已知地点由本人有权知道的发现经历派生，只带发现时的位置与时间，不附远处实时库存、人物或建造者。玩家可据此返程；GM 观察工具提供同一投影并分页，不要求向量检索碰巧找回常用地点。进入遮挡林带会影响视线；眼睛高度的浓密植被引用同一遮挡范围，开阔地的低矮装饰植物不另造知情边界。

采集可选择数量，按实际完成的一份份产出；画面合并连续重复劳动，原文和受众不合并。制作按同类、同持有方式汇总选择数量，再分配到真实物件；穿着中材料单列，潮湿程度影响选料和实际加工。到达水源后可以无容器原地捧饮，但不能因此获得可携带水；容器容量、未处理水和源库存仍按原规则结算。

打开带衣椰子会留下可继续加工的椰衣；用敲击工具捶取纤维搓绳，为绑扎提供不拆衣物的慢速途径。配方耗时与产量是游戏调校值，不代表真实手工生产率。地表采用四种本地生成材质，顶点权重仍从 `terrainAt` 派生；纹理只表现表面，不决定资源和遮挡。火塘显示实际燃料余量，离开后仍按共同时间燃烧。

椰树、海岸灌木、红树林、实际叶材和建筑覆盖共用一张透明叶片图集；共享材质由场景释放，换区和更新人物不能提前释放。建筑阶段由实际剩余工时派生，不另存视觉进度。如厕处为两柱一侧叶屏，[屏体尺寸](../apps/game/island/structure-shape.ts)同时供渲染和感知使用：完工后挡住穿屏视线，绕到开放侧仍可看见，不隔音，也不授予周边隐私圈；屏体本身仍可见、可被发现，但不能因此透视屏后的其他设施和人物。

潮池与渗水点的[浅凹轮廓](../apps/game/island/water-basins.ts)共用于地势、水平水面和岩边，位置从资源初始定义派生；地表网格只在这些小范围细化，角色落脚与地面点击仍取同一地势。渗水点见底时不保留水面。岩石共用已加载的礁石材质，不随每次状态更新另载贴图。

如厕叶屏只改变视线，不自动处理污物。排泄留下原位置的污物，掩埋是独立劳动；取消或未完成不算处理成功。界面和 GM 只看得到痕迹的位置、类型，掩埋后为翻动土面，不由观察获知留下者、精确时间、数量或地下内容。现场按同一投影显示简约地面痕迹，不制作排泄动画，也不另存视觉状态。

身体清洁可取用可接触的实物容器、渗水点或完工集雨处。完成时消耗该供应处的真实水量，与饮用、装水在同一库存上竞争；中止、失去水或失去接触条件不会获得清洁结果。规则只降低身体污损，不治疗感染、不清洁穿戴衣物，不视作消毒。清洁用量与效果是游戏参数；海水洗浴、衣物清洗、污物衰变及地下水污染尚未制作。已有污物与身体状态沿用旅程存档，新供应选择只存在于当前操作；无新增持久化字段或旧草案兼容分支。

[海面](../apps/game/island/presentation/ocean.ts)随共同游戏时间的潮位升降，覆盖范围直接引用渲染地表的三角面高度，不在着色器重写地势。海面覆盖潮池时不再叠放一片较低的池水；低潮时池水保留，内陆渗水处仍按自身水量显示。[脚下水深](../apps/game/island/surface-water.ts)从同一海面、实际地势和资源池水派生，影响涉水步速与接触水的真实衣物、地面物件湿度；手持物品不因站在浅水里全部浸湿。水位和湿衣只随世界步骤改变，视觉水纹使用运行内时间，减少动态效果时静止；不新增潮位、淹没图或视觉时钟存档。参数属于浅水玩法调校，尚不模拟海浪推力、游泳、漂浮、盐水倒灌和潮沟水流；不将浅水变成新的阵营或移动权限墙。

火塘施工投入的实际燃料转入该设施的燃料余量，不在施工时凭空消失，也不因取消或恢复施工再加一次。完工和点燃是不同操作；没有点燃前，不因模型调用、阅读或建造过程扣掉燃料。

资源补充由[资源规则](../apps/game/island/resources.ts)在共同游戏时间内结算，速率、容量和初始分布仍以[内容定义](../apps/game/island/survival-content.ts)为唯一依据。陆地物料和椰林缓慢补充；潮池只在高水位补入鱼、低水位可采，补充与采集共用潮位阈值。日补充量是完整潮汐周期的平均调校值，不是每次走近刷新，也不是岛上生物的实测产量。读界面、调用模型、重新加载都不补货；离场资源按同一时间推进，但远处实时存量不进入玩家观察。

初始分布提供多个可探索的椰林与沿礁岸觅食位置。供给检查只证明可持续产出的理论上限不低于七人的静息消耗；不等于已验证七人都能运回、加工、分配并吃到，也不代替营养、腐败和长程试玩。新增分布属于新旅程内容，不用运行时迁移把新资源强塞进已有旅程。

[食物保存](../apps/game/island/food.ts)以实物的 `foodSince` 保存暴露的起点，风险和异味按共同游戏时间派生；参数集中在内容定义，属于简化游戏调校，不是医学安全期限。鱼、熟鱼和打开的椰肉都继续累积；分份、转手、落地、烹调和读档不刷新起点，烹调不能清掉已经累积的变质风险。异味出现以前也不保证安全。变质不删除实物，也不禁止冒险食用；进食按实际完成时的状态增加疾病负担。

观察只给近距离感官状态，远处为尚未查看，不输出未目击的采集或开启时间；界面与 GM 共用同一投影。制作选料按可感知的食物状态分组，不混选有异味与无明显异味的材料，也不自动选入前者。食物与其中液体的感官状态分别投影，相同才合并显示；`null` 表示没有对应保存模型，不代表已确定安全。

[液体](../apps/game/island/water.ts)独立于椰肉保存：`Water.coconut` 只记录当前液体中剩余的椰水量和开启时刻，属于原容器中的长期物理事实；没有这两项，重载后无法区分添水、换容器和新开椰子。吃掉椰肉把原液体移到生成的空壳，原食物不留第二份水。倒入、饮用、清洁或倒掉都按实际比例扣除，耗尽后清空成分记录；重开随原旅程删除。保存沿用完整世界事务，失败不提交半份液体，不建额外表或缓存。

倒水需要两只实际可接触的容器，并校验目标容量和净负重变化；开始和完成分别校验，竞争或中途丢失条件不能留下半次转移。倒掉只丢弃液体，容器保留；当前不生成可回收的地面积水。`poured` 原始经历保存来源、去向和毫升数，去向为空表示丢弃，受众仍按实际目击范围。掺入未处理液体后混合物为未处理；混合不同开启时间的椰水采用最早起点，这是保守的游戏近似。饮水负担按实际摄入量结算，煮沸只改变处理状态，不重置陈椰水的变质起点。空容器内壁的残留、清洗与再污染尚未建模，不将倒空视为已经消毒。

植被按小块实例化，重用有限外形变体；镜头离开的小块可以被渲染裁剪，不每帧提交整片密丛的细叶。挡住玩家的树冠或棚顶使用局部镂空显示，让玩家能辨认自己的位置；这是镜头辅助，不把本来不在玩家观察里的 NPC、物资或设施补进场景，也不修改遮挡和历史受众。

## 1. 现有能力与不能直接照搬的部分

已核对的入口：

- [余火行动定义](../apps/game/expedition/narrative/actions.ts)与[回复提交](../apps/game/expedition/narrative/apply-reply.ts)已有模型提出合法人物操作、领域执行实际结果的机制。借鉴控制边界，不导入余火人物、好感和章节规则。
- [Agent gateway](../capabilities/agent/gateway.ts)支持工具声明、工具结果回传与会话续接。[管理员工具循环](../apps/administrator/agent/provider-loop.ts)可参考协议接合，不移植管理员权限、历史、总结和持久化流程。
- [总结配置](../../story-summary/data/config.js)提供现有 Embedding 连接设置。只引用连接配置，不使用总结数据、索引、触发器或生成模型。
- [Game module](../apps/game/module.ts)、[production module](../apps/game/production-module.ts)、[room catalog](../apps/game/ui/room-catalog.ts)是当前独立游戏接入点。游戏不加入下注 GameKind，不为荒岛增加独立应用或第二套 Agent 设置。

余火的单聊时机、剧情事实枚举、文字服饰和人物个人摘要不能直接升级为荒岛的社会、物件与群聊模型。语义不同的模块不因名称相同而复用。几何或协议层是否存在可直接共用的纯能力，在施工前按真实依赖核对，不先把余火拆成通用游戏引擎。

## 2. 所有者与终态结构

功能归 `apps/game/island/` 所有：内容、世界、时间与行动、生理、社会、知情、GM、记忆、存储和呈现都在这个边界内。核心层只使用已有的 Agent、文件事务、宿主生命周期等业务无关能力。

| 功能内职责 | 拥有的事实或操作 | 不拥有的决定 |
| --- | --- | --- |
| 内容定义 | 地形、材料、操作条件、生理规则和集中化显示文案 | 不把剧情走向或人物立场写成必经阶段。 |
| 世界与行动规则 | 实际位置、物件、设施、身体、活动过程及执行结果 | 不替人物决定愿不愿意合作。 |
| 时间调度 | 世界时间、活动进展、下一个需要决策的边界 | 不把工具调用次序或网络时间当作世界先后。 |
| 社会与知情投影 | 有来源的约定、说法、亲历和当前可知范围 | 不因同营地或同阵营自动传播过去秘密。 |
| GM 与记忆接合 | 受限场景工作段、工具循环、原文查阅与回复 | 不自己保存第二份库存、位置或阵营事实。 |
| 应用提交与存储 | 输入身份、事务、保存恢复和领域版本 | 不在视图内结算资源。 |
| 呈现 | 当前玩家可知投影、输入、镜头和素材生命周期 | 不通过全局调试数据泄露隐私，也不决定模拟时间。 |

不先创建通用 ECS、行为树、任务总线、多 Agent 平台或新的数据库依赖。实现中按这些职责划分实际文件，不为目录完整而提前造空模块。

### 单一事实来源

当前位置、物件数量、身体与活动归当前世界状态所有；呈现、操作条件和感知从中派生。过去何时发生、谁见闻及当时的说法归经历记录所有。历史事件不是另一套可写的当前库存。

明确约定与立场变化作为经历中的结构化事实记录；当前合作关系从这些记录投影，不同时持久化可各自修改的阵营表、关系快照和聊天总结。投影只描述已经确认的内容，不把人物的未表达意图变成公开承诺。

物件“实际在哪”和“谁声称拥有、允许谁使用”是不同事实；不能用所有权声明覆盖物理位置。营地不是共享背包，也不复制一套设施或人物列表作为另一份位置来源。

## 3. 控制权与工具的职责

GM 的游戏能力分为三类：读取当前可知处境与经历、为获准扮演的 NPC 提交行动、记录本段实际表达的 NPC 选择与约定。具体工具名与参数施工时再定义，不在本文提前写模型契约。

### 行为权限

- 每个工作段由应用给定可扮演的 NPC 集合；操作必须绑定其中具体的人，不能通过模型传入另一个人来扩权。
- 玩家直接操作或明确行动输入走玩家命令入口。GM 对自然语言输入的解释只能成为该次意图的执行提案，不能凭一个玩家标识取得任意操控权；含糊之处遵循产品设计第八节。
- NPC 可以提出邀请、阻拦或采取影响玩家的行动；不能把玩家的答应、同行或自愿交付当作自己可以直接写入的事实。非自愿后果仍需经过相应物理与冲突规则。
- 工具只开放实际领域行为，不提供任意改状态、增加物品、设置好感、写世界事实或执行脚本的入口。领域行为要能组合，不等于每种故事情节都新增工具。
- 物理有效性检查不承包道德判断。偷取不能只因所有权不同被拒绝；真正的封闭、距离、阻拦、物品已不在等条件照常检查。

### 读取、调查与失败

读取已知资料不花游戏时间，也不创造经历。翻找、勘查、偷听范围之外的接近等需要实际行动的行为，不能伪装成免费查询工具。未知对象不能靠枚举 ID 或读取全局列表发现。

工具参数错误与不支持的能力是调用问题，不是人物亲历。真实尝试后的可感知失败才可能成为经历；返回的原因不能顺带泄露远处藏物、未见过的人或秘密状态。

行动提案接受后通常是开始活动，而非已经完成。系统提供实际开始位置、当前进度、已发生效果与停止原因；GM 不能将“已开始取水”叙述成“带着水回来了”。

## 4. 游戏时间与 GM 调度

时间是否推进遵循产品设计第三节，不能由工具自行增加任意时长。应用只有一条权威世界时间线。

### 推进方式

1. 读取当前已确认状态及玩家此次行动，确定可推进的时间范围。
2. 找到最早的活动完成、环境影响、相遇、冲突或需要人物新决定的节点。
3. 将所有已开始且相关的活动推进到同一时刻，按真实条件结算已发生结果。
4. 对需要决定的场景组建 GM 工作段；无新决定的活动不重复调用模型。
5. 工作段确认后再继续玩家尚未完成的操作，或在需要玩家决定时交还控制。

NPC 静默安排自己的活动时，可以继续既定推进；本轮有玩家实际听到的新发言或表态时，先交还玩家回应机会，保留未完成活动，而不是自动替玩家走完后半程。这个边界不依赖发言文本的内容或语气。

角色身体信号、行动结束或条件改变可以触发决策；规则只判断“这里需要决定”，不写死角色的答案。长时间独居、两营分裂与受伤后不能仅依赖玩家主动找 NPC 聊天来唤醒世界。

新旅程需要初始人物决策，不能让六人空闲等待逐一被玩家点到。已有旅程重新打开不是新的决策事件；从已确认活动与世界节点恢复，不借重启改写计划或再购买一轮相同请求。

多个地点在同一时刻发生互不影响的事件，可以分别处理；可能竞争同一资源或相遇时，在统一的时空边界处理。工具调用得早不代表走得快。确实同时的争抢要进入冲突判定，不按数组顺序给物品，也不两边各发一份。

计划使用某件物品，不等于已经取得或预占远处的物品。若不同意图在同一边界涉及同一物件，先汇合为同一冲突处理，再确认实际效果；不能让先处理的离场工作段提前锁走资源。正在实际操作、搬运或消耗的物件则依据已有物理状态判定，不为后到者重新抽取公平结果。

继续休息或执行既有制作不需要每分钟重新问 GM。NPC 如需修改已有计划，则只由 GM 发起；不是另做一套按饥饿数值自动分配工作的人物 AI。网络等待、模型轮数和响应速度不改变到达顺序。

### 一个 GM，多段受限工作

这是同一个 GM 能力在不同场景的工作，不是每个 NPC 各有代理或独立会话史。

- 工作段固定时间、场景参与者、听众、可扮演者、输入来源与基础版本。
- 原营地与私人营地分别投影上下文。每段只得到这一方可知的状态与经历，不把全岛秘密先给模型，再指望它假装忘记。
- 群聊内部仍保留每条资料属于谁的知识，不能把当前人物知识并集当成人人共享知识。
- 有人进出或听众变化时，结束当前段再重组。分块渲染边界不是换段条件，真实感知范围才是。
- 不延续上一地点的原生供应商会话或工具消息而绕过重新投影；具体供应商续接仅在同一工作段内使用。
- 同一段不无限自主聊天。只处理当前决策及必要工具结果；回合预算耗尽需明确停在未确认处，不能偷偷跳过某一方的决策让世界继续。

失去模型连接时停在需要决定的边界并报告，不由随机脚本或统一“继续干活”静默代替人物。已确认世界保留；不因为 NPC 在离场地点就忽略错误。

## 5. 一段演出怎样与真实状态接合

建议采用工作段原子提交，避免一半人物已经执行、另一半回复失败后无法说明世界发生了什么。

### 候选执行

玩家已明确提交的话与实际操作有自己的来源身份，不在模型重试时重复追加。GM 工作段基于当时版本，在运行内候选状态上调用领域行为；工具返回候选里的真实判定结果，供后续叙述使用，不提前向玩家展示为已落盘事实。

工具连续调用看得到前一个操作的候选结果，因而不能在同段重复花掉一份材料。候选只推进本次授权的世界步骤，不能因为模型持续调用工具让岛上自行多过去一天。

一段完整输出、有效行动及其经历一起校验、原子确认，才成为世界事实。开始活动和活动完成仍是不同节点；原子确认不是把一整段远行压成瞬移。

正文与行动不能靠解析自然语言互相猜测。领域操作产生结构化结果，正文表达结果；“格式合法但正文说没加入、行动却加入”的语义冲突仍需真实模型验收，类型检查不能证明一致。

群像演出也不能靠从正文正则截取人名来判断谁说话。言语与叙述片段需有明确的语义类别和说话者身份，显示姓名从身份派生；具体输出协议施工时定义。片段随所属工作段有稳定来源，原文只保存一份，不能为屏幕气泡和长期记忆另存两套可各自修改的对白。旁白不能借这个结构成为全员听见的发言。

### 中断、保存与重试

- 模型中途失败或用户在确认前取消：不提交半段 NPC 结果；已确认的玩家输入及此前世界变化不回滚。运行内可保留已收到材料供诊断，不自动再次购买。
- 完整结果已收到，随后只是保存失败：保留同一待提交候选，按已有文件事务恢复；只重试保存，不重新发模型请求或重做随机结果。
- 保存结果未知：先确认原候选是否提交。相同输入身份与工作段身份不能重复改变资源、关系或经历。
- 一旦当前段确认，不能只重新生成一人的旧对白却保留其他人基于它产生的行动。初版建议不提供已确认世界的局部重生成；整段或整旅程回退属于单独的产品决定，不预埋分支存档。
- 候选期间如有实际游戏输入，应明确等待或中止后再提交，不让新的状态与旧基础版本混合。模型等待期间本就不推进游戏时间，不依靠持久锁实现此边界。

网络结果未知的付费调用不擅自重发。刷新后只承诺恢复已确认状态及已有文件事务能够恢复的完整候选，不承诺恢复仍在飞行中的供应商请求。

## 6. 事实、经历与说法

按时间保存一份具有稳定来源身份的经历序列，包括已确认对白和有玩法意义的世界事件。记录说话者或行为者、时间地点、内容与实际见闻者；见闻由当时空间和感知判定，不让模型自行填写“所有人都知道”。

亲历、听到某人说、自己的推测和客观发生的事不同。听说物件被偷并不证明是谁拿的；NPC 的谎言保留为带来源的说法，不覆盖世界状态。

转述产生新说法，不扩散原私聊的全部内容，也不修改原受众。同阵营、结伴迁居、共享物资或重聚均不自动合并人物记忆。

已实现的[合作记录](../apps/game/island/cooperation.ts)使用提议、个人回应、指定原话转述三种声明。提议的正文就是条款，只表示提出者本人的承诺；其他人自行同意、拒绝或退出。条款不由代码解析执行，也不成为取物、建营或搬迁的权限墙。修改条款是新提议，旧承诺及其原话仍在经历中。

[实物交接](../apps/game/island/handoff.ts)单独处理递出与接过。递出是持有者正在进行的活动，包含实物引用、接收对象和数量；东西仍留在持有者手中，接收者自行操作后才转移。部分材料分出实际份数，容器保持同一个物件及水；附近旁观者只能看到递出的数量，不能借此读取剩余库存。玩家的接收不能由 GM 代签。接收不取消接收者原有活动，但仍检查距离、可见性和携带能力；递出者必须先结束手头活动。收回、对方走远或死亡会终止递出，不留下远程预约。

递出活动属于已有旅程状态：刷新后要恢复仍在手上的物件和待接收动作，失败使用同一文件事务恢复，重开随旅程清理；不新增交易表或物权副本。借用、期限和归还条件可以用约定表达，实际交付与是否守约是不同的经历。NPC 递物会唤醒接收者作出判断；递给玩家时，客户端先暂停自动推进，留出接收或拒绝的机会。

转述只保存被引原话的引用，展示和检索时派生被引用的说话者、内容与声明类型；不附带原私聊的地点、受众或相邻内容。转述回应不会自动传授条款，需要分别转述；也不宣告该回应至今仍然有效。已听到的新回应不被后来重述的旧回应覆盖。读原始经历仍检查当时受众；后来才听说的人通过自己听到的转述查全文，不能借引用打开原私聊。保存入口按时间一次扫描校验引用与当时知情，运行内派生当前所知，不另存约定表。

社会关系须按各人可知来源形成投影，不能先算出全岛最新立场，再仅隐藏其来源。秘密答应另过的人知道自己的新选择，原营地可能仍按旧承诺等待；未告知的退出不能让别人立即停止期待或统一敌对。实际履行结果和后来获知的消息可以改变这种认识。

机密程度不是一个永久布尔值。后来在现场发现棚子是新的经历；这不表示人物突然获知当初谁怎样商量建棚。视线、声音、转述或明确展示都是获得信息的实际路径。

工具工作文本与回执不是世界经历。提交后的实际行动可以产生领域事件，其见闻者由世界判定；不能把工具返回里的完整库存、计算和私密身体数据广播给在场者。

不逐帧保存脚步或把所有生理数值变化写成聊天楼层。当前活动进展在世界状态里；有意义的发现、交付、受伤、约定等才进入经历。持续痕迹是否存在取决于具体已实现的世界对象，而非无限增长的足迹日志。

## 7. 长期记忆与上下文

### 自然语言行动入口

说话与行动分别输入。说话直接进入现场；行动意图先交给只读解释器，转换成一项具体操作或提出澄清问题。玩家在确认区看见真实对象、数量、路线、材料和可确定的耗时，确认后才经原行动入口执行。多步骤意图只提出明确的下一步，不在一次确认后自动连做。解释器没有 NPC Act 权限，提议不进入世界经历，也不推进时间。

解释器只读取玩家视野和玩家本人可查的原文，不能使用 GM 的 NPC 知识并集。当前观察与原文分页、向量工具和请求预算共用同一实现，但读者集合分别固定。候选操作先经过当前物理规则与玩家权限校验，不把合理却未实现的动作伪装成成功。

澄清问答和提议只活在荒岛服务运行内，并绑定世界 revision。澄清后可以直接回答对象或数量，前一问题和原意一起注入；世界变化后这些内容不再作为行动上下文。运行重载会丢弃未确认提议，不会丢失已经执行的世界变化。供应商失败不提交提议；解释响应丢失先重新读取，不自动重买。同一请求仍在运行内时可读回结果。

确认提议使用其原始请求身份和 revision，执行既有世界事务；保存失败保留完整候选，恢复不重跑模型、不重复操作、不自动继续时间。提议过期时不能借新的 revision 强行确认。玩家明确放弃或开始另一个意图即可替换临时提议，不新增存档表或旧格式兼容。

延续已经讨论确定的方案：原文分块向量检索，不增加独立总结生成、事件抽取或重排模型，不复用总结插件的 L0/L1/L2、数据或维护流程。

### 装配顺序

1. 将当前工作段的可扮演 NPC 作为知识范围；玩家不进入该并集，避免把玩家其他私聊带入。
2. 直接注入这一范围的当前可知处境、本人身体和当前活动、已确认合作约定及近期原文。不是直接注入全岛真实状态。
3. 原文按受众边界及长度切块，同块不混不同受众。候选先做知识过滤，再按当前处境、近期交谈与输入做向量检索。
4. 命中合并去重并保留原受众。提到了某人不等于某人知道；旧事发生在别处也可以相关，不能只按当前地图找记忆。
5. GM 按需查找经历或读取命中前后文。语义、关键词、人物和时间范围查找共用受众校验；按来源身份读取也不能绕过权限。

自动检索与主动工具使用同一入口，不各自定义一套过滤。返回精确来源、实际受众、覆盖范围和分页信息；未命中不是证明从未发生，读到部分也不等于已经看完。

Embeddings 只提供相似度表示。当前资源、位置、明确约定与关键事件状态不依赖向量碰巧命中；这类事实由世界及结构化经历投影直接提供，原始经过才按需查阅。

GM 的约定投影给出条款预览、是否截断、本人能读的来源，以及逐人最后听到的回应和出处。Observe 与初始注入使用同一分页投影，整组观察有字符预算；长期约定数量增加时通过 next 继续，不把全部条款重新注入。转述的向量片段包括实际被转述的原话，来源摘要也绑定这段原文；不能只索引一句“我来转述”，使新听者永远搜不到内容。

预算覆盖完整请求：系统资料、人物信息、状态、原文、工具定义、返回和后续轮次。不能只限制首次历史长度，就让工具读入无限原文。具体额度在模型与真实材料下验证，不在本文虚设万能上限。

### 配置与索引失败

GM 使用小白 OS Agent API。仅引用总结设置已有的 Embedding 连接配置，不读取总结生成模型或 Rerank 配置作为依赖，也不沿用总结插件启用开关。连接信息在调用边界读取，不复制到游戏存档。

荒岛拥有原文片段与派生向量索引。索引绑定来源内容及实际模型空间；原文改变只失效受影响部分，模型空间改变则相应重建，不能混排不兼容向量。

近期原文不等待向量完成。索引失败保留原文及已有有效结果，明确标注缺口，不把失败伪装成“无经历”。关键词和原文浏览是明确的独立能力，不静默宣称用它们已经完成语义召回。

仅恢复未完成且计费状态清楚的部分；成功或计费未知的请求不自动重买。旧索引在原文仍存的前提下可以清理，但重建涉及费用，应在实际操作前让用户知道。

## 8. 持久态、临时态与删除路径

以下是目标生命周期。世界与经历在 `island` 用户分区；死亡仍修改同一人物身体，不另存两套位置或物品。派生向量在 `islandMemory` 用户分区，不保存连接密钥或第二份原文。完整候选均使用已有文件事务恢复。索引只保留一个旅程与模型空间；更换后首次使用索引时替换旧缓存，读取始终校验旅程、来源及模型空间。

| 数据 | 为何要保留 | 所有者与生命周期 | 失败及删除处理 |
| --- | --- | --- | --- |
| 当前旅程世界：时间、人物身体与位置、物件、设施、正在进行的活动及必要的随机状态 | 重开页面必须接着生活，不能清空伤病、瞬移或重新抽结果。 | 荒岛旅程；重开或删除旅程结束。 | 只提交校验后的版本；失败不覆盖已确认世界，按文件事务恢复同一候选。 |
| 易腐食物的暴露起点 `foodSince` | 否则刷新、转交或烹调会把旧鱼变成新鱼；异味和风险无需另存。 | 荒岛实物；随实物留在本局，消耗后仍保留历史引用。 | 随世界候选原子保存，失败恢复同一候选；随重开或旅程清理，不加独立缓存或旧格式兜底。 |
| 原始交谈、领域经历及有来源的约定 | 长期记忆、见闻和社会关系需要依据。 | 同一旅程；当前关系由它投影，不再存可独立修改的副本。 | 与对应世界变化共同提交；随旅程清理，不碰主聊天或余火资料。 |
| 派生片段索引与向量 | 避免每次打开都重新购买同一批向量。 | 荒岛记忆；绑定原文及模型空间，原文是依据。 | 单独失败不删除原文；重建或删除旅程时清理所属索引。 |
| 完整但保存待确认的候选 | 避免已收结果因保存异常被迫重新执行或重新购买。 | 沿用现有文件事务的恢复机制，不另建永久作业表。 | 确认提交或明确放弃后清除；先确认未知结果再恢复。 |

请求上下文、工具分页游标、进行中的供应商连接、GM 候选执行、派生关系投影、寻路缓存、渲染状态、触控和镜头过程态只在运行内。持久化的是世界里已经开始的劳动，不是 JavaScript Promise 或整条自动调度队列。

NPC 行动重开后从已确认的位置和进展恢复；路径可由当前世界重算，不能把不可达时的错误吞成回营或完成。场景卸载只卸载视觉，不删人物或物资。

规则中的已知随机事件在候选内生成，随确认结果和随机状态一起提交；重试同一完整候选不重抽。随机性用于有根据的不确定结果，不用于掩盖缺少材料、路线、角色决定或社会规则。

新功能没有历史用户旅程，不添加自己旧草案的兼容层。运行时只认当前模型；未来若有真实需要保留的格式，再在升级或导入边界做一次转换，不把兼容分支塞进每日行动。

功能删除需先确定荒岛旅程导出或丢弃策略，再删功能目录、实际注册与所属数据；相关产品文档及资产一并处理。不删除共享 Agent 配置、总结配置与数据、余火旅程或钱包资料。荒岛目前没有已授权的经济功能，不预埋购入、复活和奖励流水。

## 10. 验证应证明什么

| 契约与实际故障 | 最便宜的验证层 | 现有检查不能代替的原因 |
| --- | --- | --- |
| 一件物品不能重复消耗、隔空转移；NPC 工具不能替玩家发起自愿行为 | 领域单测 | 类型正确的两个操作仍能错误使用同一份资源或控制错误的人。 |
| 多地点同时推进、相遇与打断，不受渲染和模型耗时影响 | 时间与行动单测 | 固定路线成功不证明分营后时序一致。 |
| 当前观测、旧私聊与转述不串人，直接按 ID 读取也不能越界 | 知情与检索边界测试 | 向量命中和合法 JSON 不证明人物有权知道。 |
| 同一段连续工具调用及保存恢复不重复改变世界 | 领域提交及真实文件事务集成测试 | 单个工具成功不覆盖跨调用与未知提交结果。 |
| 加入、承诺、履行、违约分开，未表态者不被代表 | 社会事实投影单测 | 几个人同处一地不能证明阵营语义正确。 |
| Embedding 失效、缺口、重建不删除原文、不静默漏记忆 | 配置/索引边界测试 | HTTP 成功、索引数量变化不证明记忆完整。 |
| 实际地图的可达、遮挡、使用范围与工具一致 | 少量真实场景集成及端到端 | mock 世界和静态截图不能证明实际地图成立。 |
| 角色选择可信、对白与行动相符、分裂不强制敌对 | 人类逐步复核与授权后的真实模型试演 | 类型、lint、单测和 HTTP 收据不能评价叙事语义。 |
| 场景可读、操作流畅、手机与宿主性能可接受 | 真实宿主实看与试玩 | 简化测试页面、截图尺寸或理论帧率不能代替体验。 |

不为每个情节重复写一套端到端；共享机制由最低层证明，代表性的自由路径再串起来。自动化脚本完成只是执行证据，质量结论必须落在实际观察到的行为上。

## 11. 尚需验证而非凭空宣布解决的风险

- 单个 GM 群聊面对带受众标识的知识并集，是否仍会让不知情者接话；机制隔离与真实模型行为都要检查。
- 主动时间与长聊结合是否让节奏自然，以及离场场景决策是否造成可接受的请求频率；不以假数字承诺成本。
- 有限物理动作是否足够表达用户的自然办法，还是频繁出现“想法合理但不支持”；通过自由玩法验收补实质能力，不靠泛用改状态工具绕开。
- 物件细度、生理反馈与自主人物是否增加有意义的选择，而不是变成琐碎劳动；需要试玩，不继续增加仪表盘解决。
- 候选执行与正文提交能否让用户始终分清提议、开始、完成和失败；工具成功数量不能代替这项体验。
