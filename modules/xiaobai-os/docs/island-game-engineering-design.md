# 荒岛：工程边界与状态流

本文服务于[产品设计](island-game-target-design.md)，不包含运行时 Prompt 或工具描述文本。目标结构与已接通的实现须区分，实例验证见[自由玩法验收](island-game-scenarios.md)。

## 当前实现边界

正式代码归 [island](../apps/game/island/) 所有，已注册独立用户存档、记忆缓存、生产 Host 和游戏大厅入口；界面与场景仍在实机打磨，不作为最终视觉验收结论：

正式六人姓名、性别、年龄和人物底稿集中在[人物目录](../apps/game/island/character-catalog.json)，运行与离线制作共用；玩家开局选择姓名、性别和成年外观年龄，确认后写入本局唯一身份，界面、GM公开观察和场景外形由它派生，外观年龄不被伪造为实际年龄，也不改变生存能力。开始、继续、重开及保存恢复沿用同一旅程事务；未确认的填写不改变旧局。不可读的测试旅程不自动迁移或删除，只有明确确认重开才替换荒岛分区。角色资产与场景接入边界见下文人物实现及[人物制作说明](../apps/game/island/production/characters/README.md)。当前不是第一章完整验收交付，不能把规则测试或接口接通等同于整章玩法、美术与真实 GM 长程表现通过。

- [世界模型](../apps/game/island/model.ts)、[操作](../apps/game/island/operations.ts)与[时钟](../apps/game/island/clock.ts)：七人、实际位置与物件、共同时间、同时竞争、接触及新决策边界。地图与生理数值是制作参数，不是医学或地理标定。
- [劳动](../apps/game/island/work.ts)与[生理](../apps/game/island/physiology.ts)：实际采集、容器取水饮用、拆衣制作、适合地点建营与恢复半成品、取暖用火与煮水、脚伤、排泄、污染和清洁。[清洗](../apps/game/island/hygiene.ts)、[照料](../apps/game/island/care.ts)与[生活条件](../apps/game/island/living-conditions.ts)接入同一实物及共同时间，包含衣物清洗、容器残留、伤口冲洗和包扎。动作与入口已接通，连续多日的供给、劳动及恢复平衡尚需整体试玩。
- [场景投影](../apps/game/island/scene.ts)、[工作段](../apps/game/island/scene-work.ts)与 [GM 循环](../apps/game/island/agent/runner.ts)：玩家与 NPC 控制权分开，按实际听见范围确定受众；接到共享 Agent gateway，快照提议与活世界的接合见第五节。已接工具协议不等于真实模型的群像表现通过验收。
- [相遇与判断](../apps/game/island/attention.ts)：新看见对方形成个人经历，需要回应或重新选择的人由经历派生。本人发言、行动或私人打算可以回应这次相遇；不会为触发 GM 而强制取消已有劳动。私人打算只有本人知情，不广播，也不另存一份计划表。离场相遇解决后继续玩家未完成的活动。时间连续流动，相遇、发现遗体等只作为事件出现并唤醒相关人物，不会让时间停下，也不会取消玩家正在进行的行走。逐人的发现时刻、见闻和受众照常记录。
- 生活提醒包括食水、疲惫、排泄、脚伤、污损与伤病恶化；按跨过的需求等级记录，不逐秒重复。提醒保留当前活动及进度，GM 得到触发原因、来源和剩余活动后再选择继续或取消。收到照料邀请、实物递交或目击取物也可触发判断。没有另设自动分配工作的 NPC 脚本，工具接通不等于真实模型已能长期妥善生活。
- [经历](../apps/game/island/experience.ts)与[记忆](../apps/game/island/memory.ts)：一份原始经历、逐人约定投影、原文分页、分块与先知情过滤的向量排序。[连接](../apps/game/island/agent/embedding.ts)仅取 Embedding 设置；[索引](../apps/game/island/agent/memory-store.ts)保留实际模型空间和来源摘要绑定。近期原文和主动检索已接线；真实长程召回质量及极端数据规模仍待验证。
- [死亡结算](../apps/game/island/mortality.ts)：脱水、持续缺食和疾病可终结旅程，NPC 留下原身体与物件；不是 GM 的任意杀人操作。能量收支可以为负，持续缺食影响步速和休息恢复，不在食物归零后无限存活。其他环境致死与长程生理平衡仍需完善。
- [遗体搬移与遮盖](../apps/game/island/remains.ts)：就近抓持后沿实际路线缓慢拖移，拖移者和身体各自的路径都需可行走；同一身体不能同时被两人拖往不同处。取消、抵达或搬动者死亡时留在实际停止的位置，原随身物件随身体移动，不生成第二份尸体库存。遮盖使用真实且已脱下的衣物、布片或枝叶，耗时后整份物件改为依附该身体的 `covering` 位置，可以重新取回；遮盖不是掩埋、净化或消除遗体。记录按目击范围保存，远处人物不会自动得到死亡和搬移消息。
- 掩埋与挖开是同一劳动入口中的耗时操作，需要真实且可取用的挖掘工具。掩埋检查高潮线以上的地面、水源间距和已有土堆；同一遗体不能同时被拖行、遮盖或挖埋。取消不提交半次埋葬，完成后原身体及依附物件保留但不可拾取，挖开重新露出。当前埋葬状态只由 `body_buried` / `body_exhumed` 原始经历派生，[索引](../apps/game/island/burial-state.ts)仅在运行内增量建立，不新增墓地表或另存尸体库存。可见土堆只公开位置和操作引用，不能直接获知地下的人与物品。操作经历仍按目击者保存，可唤醒他们自行判断。
- [环境卫生](../apps/game/island/sanitation.ts)从污物产生时间、死亡经历与当前掩埋状态派生：痕迹逐渐淡去，暴露粪便增加局部脏污，遗体异味随时间变化；异味与蝇虫削弱休息恢复，不给尸体附加自动传染光环。清理、遮盖、掩埋或换地方休息各有实际后果。玩家和 GM 得到的只有当前位置的感官反馈，不附带未看见的污染源坐标、身份或死亡时刻；地下水污染和完整微生物传播未实现。时长与强度统一来自生存内容参数，属于游戏调校值。
- 死亡与遗体发现按对应经历的实际受众唤醒仍活着的 NPC 判断，不自动取消其劳动或替他们安排清理。回应、改变行动或留下本人打算后，已回应的同一见闻不会因重载再次触发。发现遗体仍不提供未目击的死亡过程或死因。
- [存档边界](../apps/game/island/partition.ts)与[应用服务](../apps/game/island/service.ts)：当前格式校验、唯一操作指纹、玩家可知视图、活世界检查点及保存恢复；串行保存与失败边界见第五节。原文不复制进操作收据。重开直接开始新旅程，不保留本功能自己的旧格式分叉。

实际浏览器验收使用生产 Shell、Host、工具和文件事务，模型夹具只替代收费供应商，不冒充真实模型试演。画图已产生正式海岸入口素材；游戏内是独立 Three.js 场景。当前继续打磨完整操作入口、离场决策节奏、自由玩法、长期记忆及桌面/手机体验，不将代码检查通过称为荒岛已经完成。

人物回应失败保留已经确认的行动与说话。失败提示只在玩家打开的交谈区显示，带重试、模型设置和关闭入口，不在荒岛首页、地图或结局页显示，也不重复进入全局错误条。关闭仅收起当前客户端实例中的本次提示，不调用模型、不取消后台工作、不清除宿主的失败与自动重试暂停状态；同一失败的状态推送、面板切换和界面缓存重入不会重弹，新旅程或新一轮回应可重新显示失败。重试只请求新的 NPC 回应；需要修改连接时，经宿主既有导航打开 Agent API，不复制一套荒岛模型配置，不自动测试连接或重新购买请求。读取失败及保存结果未知仍使用独立恢复入口，保存异常不能通过关闭人物提示解除，也不能混成重试模型。

玩家死亡后进入[只读回顾](../apps/game/island/presentation/IslandEnding.vue)，使用原经历的玩家知情过滤与分页，不保留可操作场景或全岛结算视图。重新打开已结束旅程仍可查看；开始新旅程先回到身份选择，只有确认替换才修改存档。回顾页及未确认的身份输入只属于界面临时态，不新增结局快照或复制经历；终止条件只从玩家身体状态派生。章节与持续生活的交付边界以产品设计为准。

界面包括玩家自己的住处/立场选择、可见人物入口、原始经历分页、实物制作与营地操作。穿着中的衣物不被自动选为拆用材料。场景的地表、落脚与选地来自同一[游戏地势](../apps/game/island/terrain.ts)，视觉移动仅回放已确认位置变化，不驱动生存时钟。树木按世界坐标稳定加载，不因镜头换区重新随机摆放。

[海岸](../apps/game/island/coastline.ts)统一生成圆化岬角与浅湾边界，可行走地面、地势及海面连接都使用这条边界。近岸距离在运行内建立空间索引，海面网格预计算岸距，避免细分岸线后每个像素遍历全岛。海面外圈要求当前岛形相对原点保持星形，实际网格测试检查海陆衔接、朝向和不跨陆地；以后调整地理内容不能另画一条纯装饰岸线。所有网格、索引与动画仅活在运行内，潮位仍由游戏时间决定，渲染浪纹不改变涉水深度或擅自推进时间。

全体人物使用[骨骼角色资产适配器](../apps/game/island/presentation/character-asset.ts)，[加载器](../apps/game/island/presentation/character-loader.ts)每局只加载六名 NPC 与玩家选中的一款外观，不保留程序化占位分支。模型制作与外观范围见[人物制作说明](../apps/game/island/production/characters/README.md)。衣物款式、穿戴层、线性色和接触高度集中在[衣物目录](../apps/game/island/clothing.ts)，是否穿着、去向及湿度只取真实物件，不由穿衣者决定款式。外层、内层、救生衣与足部衣物分别存在，落地、递出和遮盖外观从统一衣样派生；角色外观尺寸不赋予劳动或生存能力。

姿态只回放已确认的活动与位置，不推进世界时间；脚底校准只调整临时视觉组，死亡动作不再整体下沉。头部标签、手中递物和正在使用的随身饮食物品跟随骨骼；外部观察只公开可见劳动种类及正在使用物件的外形、湿度和手持份数，不暴露任务目标、物件 ID、水量或其他私人库存。取消、完成、死亡或不可见时，使用附件随投影消失；地面饮食来源保持地面物件，不重复成手持副本。遮盖物保留实物尺寸并随身体移动，不另存姿态或展示状态。

[包扎显示](../apps/game/island/presentation/dressing-visual.ts)只使用观察中真实处于 `dressing` 位置的布片，按当前角色皮肤尺寸贴合骨骼，随拆布、污损和湿度更新。领域只区分足部与身体擦伤，画面分别用踝部与左前臂布带示意，不宣称精确伤口位置。衣物的脏污外观来自可见清洁度，远处未近看时不偷读原始污损值。护理双方可见时只公开正在照料的配对和大致部位，朝向与手部动作基于原骨骼临时适配；不移动角色真实坐标、不拉长肢体，也不修改已确认的模型资产。清洗与包扎使用随身材料时可见手中物件，地面材料不凭空复制为第二份附件。动作贴合与手机表现仍需实机查看。

人物实例拥有骨架和衣物材质，角色几何、贴图由本次场景持有；退出顺序为人物和附件、场景资源、共享角色资产。加载可取消，失败提供保留旅程的重试，不以旧占位人静默替代。当前有必要的站走、休息、劳动、饮用、清洁、递出、拖行与死亡表现，但没有逐工序精细手势、精确握持或布料仿真；人物资产制作与接入不等于真实宿主、手机或完整章节已通过试玩验收。

已知地点由本人有权知道的发现经历派生，只带发现时的位置与时间，不附远处实时库存、人物或建造者。玩家可据此返程；GM 观察工具提供同一投影并分页，不要求向量检索碰巧找回常用地点。进入遮挡林带会影响视线；眼睛高度的浓密植被引用同一遮挡范围，开阔地的低矮装饰植物不另造知情边界。

采集可选择数量，按实际完成的一份份产出；画面合并连续重复劳动，原文和受众不合并。制作按同类、同持有方式汇总选择数量，再分配到真实物件；穿着中材料单列，潮湿程度影响选料和实际加工。到达水源后可以无容器原地捧饮，但不能因此获得可携带水；容器容量、未处理水和源库存仍按原规则结算。

打开带衣椰子会留下可继续加工的椰衣；用敲击工具捶取纤维搓绳，为绑扎提供不拆衣物的慢速途径。配方耗时与产量是游戏调校值，不代表真实手工生产率。地表采用四种本地生成材质，顶点权重仍从 `terrainAt` 派生；纹理只表现表面，不决定资源和遮挡。火塘显示实际燃料余量，离开后仍按共同时间燃烧。

椰树、海岸灌木、红树林、实际叶材和建筑覆盖共用一张透明叶片图集；共享材质由场景释放，换区和更新人物不能提前释放。建筑阶段由实际剩余工时派生，不另存视觉进度。如厕处为两柱一侧叶屏，[屏体尺寸](../apps/game/island/structure-shape.ts)同时供渲染和感知使用：完工后挡住穿屏视线，绕到开放侧仍可看见，不隔音，也不授予周边隐私圈；屏体本身仍可见、可被发现，但不能因此透视屏后的其他设施和人物。

潮池与渗水点的[浅凹轮廓](../apps/game/island/water-basins.ts)共用于地势、水平水面和岩边，位置从资源初始定义派生；地表网格只在这些小范围细化，角色落脚与地面点击仍取同一地势。渗水点见底时不保留水面。岩石共用已加载的礁石材质，不随每次状态更新另载贴图。

如厕叶屏只改变视线，不自动处理污物。排泄留下原位置的污物，掩埋是独立劳动；取消或未完成不算处理成功。界面和 GM 只看得到痕迹的位置、类型，掩埋后为翻动土面，不由观察获知留下者、精确时间、数量或地下内容。现场按同一投影显示简约地面痕迹，不制作排泄动画，也不另存视觉状态。

身体清洁可取用可接触的实物容器、渗水点、完工集雨处或当前潮位下伸手可及的海水。完成时消耗供应处的真实水量，与饮用、装水在同一库存上竞争；海水不扣淡水，但只能粗洗。中止、失去水或失去接触条件不会获得清洁结果。身体清洁只降低身体污损，不治疗感染、不清洁衣物或伤口，不视作消毒。用量与效果是游戏参数；污物衰变及地下水污染尚未制作。

衣物和布片必须脱下、未被用作包扎才能清洗；容器须先倒空。清洗用独立水源，完成后实物变湿，水质影响剩余污损；晾干靠既有世界时间、雨水与遮蔽条件，不增加一份晾晒队列。穿着、地面放置和失禁会影响对应实物的污损，转交、分份、制作与干燥不会将其凭空清零。清洗入口放在实物旁，身体清洁留在玩家自己的身体面板。

伤口程度、伤口污损与身体污损分别记录。伤口冲洗使用可接触的已处理清水，先拆掉旧包扎；换布使用真实、干燥且较清洁的一份布片，拆下的旧布留在脚边，不删除。包扎随时间变脏，脚部包扎涉水会湿；清洁、休息及食水条件影响缓慢恢复，冲洗或换布不立即消除伤势与感染。粗糙地面继续伤脚并弄脏伤口，身体冲洗不能代替伤口处理。数值属于简化生存规则，不是医疗模拟。

照料他人走“提出具体照料—对方接受或拒绝—共同耗时—完成”的行动链。接受需先结束患者原活动；两人的对应活动就是本次同意，不持久保存通用授权。任一方取消、死亡或失去接触，另一方也解除照料；完成时重新核对物品、水量、接触与同意，失败不扣半份物资或产生治疗结果。玩家可自行处理自己的伤口，GM 只能为 NPC 接受，不能代玩家同意。

[身体接触](../apps/game/island/contact.ts)使用人物现有活动表达拥抱、牵手、亲吻和依偎的具体邀请，以及双方接受后的配对，不新增关系表、好感门槛或永久许可。双方须存活、相互可见、触手可及且之间可通行；接受时保留真实位置，靠近按共同时间限速结算，不能在 GM 连续工具调用中改变场景范围。间距与接触方式统一来自[互动参数](../apps/game/island/interaction-content.ts)。[交互入口](../apps/game/island/client.ts)不为接受接触另设推进步骤：时间本就连续流动，接受后双方按共同时间靠近。普通交谈、读取与保存确认同样不自行推进时间。接触时可继续交谈，任一方取消或死亡即解除双方活动；更换接触方式要先松开，再发出对应邀请。当前邀请、配对和经历随原旅程保存，重开一并清理。可见动作经历只给当事人及同时看见双方的人，当前接触不赋予旧私聊或此前邀请的知识。动作表现与资产来源统一见[人物制作说明](../apps/game/island/production/characters/README.md)。

[徒手冲突](../apps/game/island/conflict.ts)包含推搡、出拳与主动防护。出手先登记耗时尝试并唤醒目标和目击者，之后由共同时间推进；目标可以防护、取消劳动后离开、还击或表达自己的选择。到期在所有人移动后统一判定距离、防护和命中，同一时刻的结果先取齐再改变身体，不由人物遍历顺序决定谁能还手。命中可能打断劳动、照料和接触，推搡只在可行地面产生位移；伤势、疲劳与死亡使用原身体规则。力道、时间、距离、伤量属于游戏参数，不声称是医学或格斗模拟。徒手冲突不强制改变阵营、服从或物资归属，尚未包含武器、抓捕和多人压制。

准备状态与结果只通过个人观察及原始经历提供给 GM。玩家主动攻击须确认伤人风险；玩家观察到新的冲突或结果时，事件出现在身旁并唤醒目标；玩家可随时防护、停下或离开，时间不因此暂停，也不会替玩家等待到下一次受击。防护继续消耗体力，达到互动参数中的疲劳上限后不再挡住来袭；同一时刻对一个人的推力先合并，再检查可行地面，不按攻击者顺序逐次移动。当前攻击、防护属于原人物活动，重载保留剩余时间，取消或死亡解除；动画进度不写存档，不触发命中。

[海面](../apps/game/island/presentation/ocean.ts)随共同游戏时间的潮位升降，覆盖范围直接引用渲染地表的三角面高度，不在着色器重写地势。海面覆盖潮池时不再叠放一片较低的池水；低潮时池水保留，内陆渗水处仍按自身水量显示。[脚下水深](../apps/game/island/surface-water.ts)从同一海面、实际地势和资源池水派生，影响涉水步速与接触水的真实衣物、地面物件湿度；手持物品不因站在浅水里全部浸湿。水位和湿衣只随世界步骤改变，视觉水纹使用运行内时间，减少动态效果时静止；不新增潮位、淹没图或视觉时钟存档。参数属于浅水玩法调校，尚不模拟海浪推力、游泳、漂浮、盐水倒灌和潮沟水流；不将浅水变成新的阵营或移动权限墙。

火塘施工投入的实际燃料转入该设施的燃料余量，不在施工时凭空消失，也不因取消或恢复施工再加一次。完工和点燃是不同操作；没有点燃前，不因模型调用、阅读或建造过程扣掉燃料。

资源补充由[资源规则](../apps/game/island/resources.ts)在共同游戏时间内结算，速率、容量和初始分布仍以[内容定义](../apps/game/island/survival-content.ts)为唯一依据。陆地物料和椰林缓慢补充；潮池只在高水位补入鱼、低水位可采，补充与采集共用潮位阈值。日补充量是完整潮汐周期的平均调校值，不是每次走近刷新，也不是岛上生物的实测产量。读界面、调用模型、重新加载都不补货；离场资源按同一时间推进，但远处实时存量不进入玩家观察。

初始分布提供多个可探索的椰林与沿礁岸觅食位置。供给检查只证明可持续产出的理论上限不低于七人的静息消耗；不等于已验证七人都能运回、加工、分配并吃到，也不代替营养、腐败和长程试玩。新增分布属于新旅程内容，不用运行时迁移把新资源强塞进已有旅程。

[食物保存](../apps/game/island/food.ts)以实物的 `foodSince` 保存暴露的起点，风险和异味按共同游戏时间派生；参数集中在内容定义，属于简化游戏调校，不是医学安全期限。鱼、熟鱼和打开的椰肉都继续累积；分份、转手、落地、烹调和读档不刷新起点，烹调不能清掉已经累积的变质风险。异味出现以前也不保证安全。变质不删除实物，也不禁止冒险食用；进食按实际完成时的状态增加疾病负担。

观察只给近距离感官状态，远处为尚未查看，不输出未目击的采集或开启时间；界面与 GM 共用同一投影。制作选料按可感知的食物状态分组，不混选有异味与无明显异味的材料，也不自动选入前者。食物与其中液体的感官状态分别投影，相同才合并显示；`null` 表示没有对应保存模型，不代表已确定安全。

[液体](../apps/game/island/water.ts)独立于椰肉保存：`Water.coconut` 只记录当前液体中剩余的椰水量和开启时刻，属于原容器中的长期物理事实；没有这两项，重载后无法区分添水、换容器和新开椰子。吃掉椰肉把原液体移到生成的空壳，原食物不留第二份水。倒入、饮用、清洁或倒掉都按实际比例扣除，耗尽后清空成分记录；重开随原旅程删除。保存沿用完整世界事务，失败不提交半份液体，不建额外表或缓存。

倒水需要两只实际可接触的容器，并校验目标容量和净负重变化；开始和完成分别校验，竞争或中途丢失条件不能留下半次转移。倒掉只丢弃液体，容器保留；当前不生成可回收的地面积水。`poured` 原始经历保存来源、去向和毫升数，去向为空表示丢弃，受众仍按实际目击范围。掺入未处理液体后混合物为未处理；混合不同开启时间的椰水采用最早起点，这是保守的游戏近似。饮水负担按实际摄入量结算，煮沸改变处理状态并清除容器污损，不重置陈椰水的变质起点。未处理水与椰水留下的容器残留使用该实物的污损值；倒空、换手和干燥不清零，脏容器再装已处理水会令其重新变为未处理。空容器清洗沿用同一清洗操作，不另建容器卫生表。

植被按小块实例化，重用有限外形变体；镜头离开的小块可以被渲染裁剪，不每帧提交整片密丛的细叶。挡住玩家的树冠或棚顶使用局部镂空显示，让玩家能辨认自己的位置；这是镜头辅助，不把本来不在玩家观察里的 NPC、物资或设施补进场景，也不修改遮挡和历史受众。

- [Agent gateway](../capabilities/agent/gateway.ts)支持工具声明、工具结果回传与会话续接。[管理员工具循环](../apps/administrator/agent/provider-loop.ts)可参考协议接合，不移植管理员权限、历史、总结和持久化流程。
- [总结配置](../../story-summary/data/config.js)提供现有 Embedding 连接设置。只引用连接配置，不使用总结数据、索引、触发器或生成模型。
- [Game module](../apps/game/module.ts)、[production module](../apps/game/production-module.ts)、[room catalog](../apps/game/ui/room-catalog.ts)是当前独立游戏接入点。游戏不加入下注 GameKind，不为荒岛增加独立应用或第二套 Agent 设置。

## 2. 所有者与终态结构

功能归 `apps/game/island/` 所有：内容、世界、时间与行动、生理、社会、知情、GM、记忆、存储和呈现都在这个边界内。核心层只使用已有的 Agent、文件事务、宿主生命周期等业务无关能力。

| 功能内职责 | 拥有的事实或操作 | 不拥有的决定 |
| --- | --- | --- |
| 内容定义 | 地形、材料、操作条件、生理规则和集中化显示文案 | 不把剧情走向或人物立场写成必经阶段。 |
| 世界与行动规则 | 实际位置、物件、设施、身体、活动过程及执行结果 | 不替人物决定愿不愿意合作。 |
| 时间调度 | 世界时间、活动进展、下一个需要决策的边界 | 不把工具调用次序或网络时间当作世界先后。 |
| 社会与知情投影 | 有来源的约定、说法、亲历和当前可知范围 | 不因同营地或同阵营自动传播过去秘密。 |
| GM 与记忆接合 | 受限场景工作段、工具循环、原文查阅与回复 | 不自己保存第二份库存、位置或阵营事实。 |
| 应用提交与存储 | 输入身份、事务、保存恢复和领域版本 | 不在视图内结算资源。 |
| 呈现 | 当前玩家可知投影、输入、镜头和素材生命周期 | 不通过全局调试数据泄露隐私，也不决定模拟时间。 |

不先创建通用 ECS、行为树、任务总线、多 Agent 平台或新的数据库依赖。实现中按这些职责划分实际文件，不为目录完整而提前造空模块。

### 单一事实来源

当前位置、物件数量、身体与活动归当前世界状态所有；呈现、操作条件和感知从中派生。过去何时发生、谁见闻及当时的说法归经历记录所有。历史事件不是另一套可写的当前库存。

明确约定与立场变化作为经历中的结构化事实记录；当前合作关系从这些记录投影，不同时持久化可各自修改的阵营表、关系快照和聊天总结。投影只描述已经确认的内容，不把人物的未表达意图变成公开承诺。

物件“实际在哪”和“谁声称拥有、允许谁使用”是不同事实；不能用所有权声明覆盖物理位置。营地不是共享背包，也不复制一套设施或人物列表作为另一份位置来源。

## 3. 控制权与工具的职责

GM 的游戏能力分为三类：读取当前可知处境与经历、为获准扮演的 NPC 提交行动、记录本段实际表达的 NPC 选择与约定。具体工具名与参数施工时再定义，不在本文提前写模型契约。

### 行为权限

- 每个工作段由应用给定可扮演的 NPC 集合；操作必须绑定其中具体的人，不能通过模型传入另一个人来扩权。
- 玩家直接操作或明确行动输入走玩家命令入口。GM 对自然语言输入的解释只能成为该次意图的执行提案，不能凭一个玩家标识取得任意操控权；含糊之处遵循产品设计第八节。
- NPC 可以提出邀请、阻拦或采取影响玩家的行动；不能把玩家的答应、同行或自愿交付当作自己可以直接写入的事实。非自愿后果仍需经过相应物理与冲突规则。
- 工具只开放实际领域行为，不提供任意改状态、增加物品、设置好感、写世界事实或执行脚本的入口。领域行为要能组合，不等于每种故事情节都新增工具。
- 物理有效性检查不承包道德判断。偷取不能只因所有权不同被拒绝；真正的封闭、距离、阻拦、物品已不在等条件照常检查。

### 读取、调查与失败

读取已知资料不花游戏时间，也不创造经历。翻找、勘查、偷听范围之外的接近等需要实际行动的行为，不能伪装成免费查询工具。未知对象不能靠枚举 ID 或读取全局列表发现。

工具参数错误与不支持的能力是调用问题，不是人物亲历。真实尝试后的可感知失败才可能成为经历；返回的原因不能顺带泄露远处藏物、未见过的人或秘密状态。

行动提案接受后通常是开始活动，而非已经完成。系统提供实际开始位置、当前进度、已发生效果与停止原因；GM 不能将“已开始取水”叙述成“带着水回来了”。

## 4. 游戏时间与 GM 调度

时间规则见产品设计第三节，不能由工具自行增加任意时长。应用只有一条权威世界时间线，它活在荒岛服务的内存里。

### 活世界与时钟

- 房间打开期间，[服务](../apps/game/island/service.ts)持有一份内存中的活世界，[时钟](../apps/game/island/clock.ts)每走一个游戏秒就在原地推进：移动、活动、冲突、资源、生理与发现。时钟不等待任何决策、没有停止条件；谁也没有计划，谁就站着。
- 宿主以固定节拍把真实时间换算成游戏秒（倍率是[内容定义](../apps/game/island/content.ts)里的唯一参数），推送最新状态；客户端补间显示。前台、地图未被遮挡时前端通知宿主“时间运行”，否则暂停；存档异常未恢复或主聊天正在生成时宿主也不走时间。停滞后的补算上限一秒，不让切回标签页后瞬间过去很久。
- 玩家的移动是对活世界的即时输入：虚拟摇杆、方向键或 WASD 只上报屏幕方向，客户端按固定相机朝向换算为世界方向，由[转向](../apps/game/island/steer.ts)每个游戏秒重新瞄准同一条行走规则；松开即停。持续转向不产生经历；只有打断一项真实活动才记录一次。点地面是既有的行走操作，走动中再点只改目的地。其余玩家操作同步作用于活世界，不等待保存，也不等待模型。
- 持久化是检查点：活世界在固定间隔、离开房间、面板暂停和新旅程创建时写入分区，保存及恢复规则见第五节。进程异常最多丢失一个检查点间隔内的进展；重启必须恢复的只有已写入的检查点。聊天切换后旧活世界直接丢弃，不写入别的聊天。

### 状态所有权

[服务](../apps/game/island/service.ts)拥有活世界、当前意图及其失效代次；[宿主](../apps/game/island/host.ts)拥有当前激活身份、后台工作的控制器、规划暂停与失败状态。两层不各存一份相同的视图顺序或人物计划：

| 标识 | 所有者与用途 |
| --- | --- |
| `revision` | 分区的持久化修订号，用于文件事务和新旅程请求校验，不代表每次活世界变化。 |
| `version` / `saved` | 服务内本局变化计数与已保存检查点的对应计数，只判断是否还有进展需要保存。 |
| `generation` | 服务内解释上下文的失效代次，递增与失效条件见第七节。宿主通过只读 getter 校验解释请求，不为读取代次构造玩家视图。 |
| `stamp` | 只由宿主在每次组装完整视图时递增，覆盖世界投影及 busy、thinking、解释中、规划失败等后台状态。推送与请求回执共用顺序；服务不维护 stamp 或 touch，客户端不让较旧回执覆盖较新视图。它不写入存档。 |

### GM 调度

1. 谁需要决定由 `awaitingDecision` 从当前人物活动和原始经历派生，不另存计划表；没有活动的活人、被相遇/需求/事故等事件唤醒的人均走同一入口。
2. 宿主在后台一次只运行一个 GM 工作段。回应以玩家为锚点；普通决定从当前待决策人物中选锚点，宿主只询问是否待规划，不直接读取旅程 ID，不维护补计划表或锚点覆盖入口。运行中收到的玩家回应请求等待当前段结束；思考期间世界照常前进。
3. GM 在世界快照上调用工具，完成后按第五节接合活世界；尚待决定的人继续由普通调度发现。只要 `applied > 0`，包括保留前缀而丢弃后缀的部分成功，都清零连续无效计数；只有整段无任何操作生效才累积，连续三次后显示规划失败并停止自动请求。静默结束的 cancelled、stale、unavailable 不因先前计数而升级成失败，也不抹去已生效前缀。
4. 玩家取消只暂停自动安排，直到玩家再次说话或主动重试。错误、中断与保存的接合边界见第五节。
5. 新旅程需要初始人物决策；已有旅程重新打开不是新的决策事件，从检查点恢复，不借重启改写计划或再购买一轮相同请求。

规则只判断“这里需要决定”，不写死角色的答案。长时间独居、两营分裂与受伤后不依赖玩家主动找 NPC 聊天来唤醒世界。已回应但恶化到下一需求等级时仍会再触发判断。

### 当前现场的交谈

交谈区只展示此刻能听清交谈的人的话：服务给出玩家当前的听众集合（实际听觉范围，与视线内人物是两件事），展示层据此从玩家已知的经历里取出这些人的发言，以及玩家说过且当前听众中有人听见的话。走远的人、没人听见的自言自语不再出现在这里，仍在日志里完整保留。附近的人共用同一个交谈区，靠发言者的姓名和头像区分，不为每个人另开窗口；只有一个人听得见时就是一对一。谁来回应由 GM 依据话题与人物处境决定，不要求人人发言，一对一时不引入第三者。

### 交谈弹层、现场提示与上下文圈

交谈只含发言（speech 与 declaration）；其余经历不进交谈，由[现场提示](../apps/game/island/presentation/feedback.ts)按“与玩家有关，或在视线内发生的死亡、遗体与冲突”挑出，作为地图底部的短提示显示几秒，同一件事重复时合并成一条加次数，完整原文只在经历里。提示只播报玩家在场期间新发生的事，进入房间或重开不回放过去。交谈由玩家打开，打开期间不暂停时间；有人说话或有事等待回应时，[交谈按钮](../apps/game/island/presentation/ChatDock.vue)显示一句提示和未读数，旧话不会因为人走进听觉范围而被当作新消息。打开全屏面板会收起交谈，窄窗口下在交谈里确认的行动会收起交谈让玩家看到它发生。

上下文圈测量的是[GM 场景请求](../apps/game/island/agent/runner.ts)：与真正发给模型的是同一份组装结果，由宿主按需（打开交谈、有新发言后稍候）估算输入量，拆成人物与设定、规则与工具、现场与近期经历三部分，对照输入预算；超过留出输出余量后的线时，更早的经历会被省略。估算只读世界快照，不调用模型，也不改变世界；失败时由圈自己显示未计量，不作为房间错误。


多个地点在同一时刻发生互不影响的事件，可以分别处理；可能竞争同一资源或相遇时，在统一的时空边界处理。工具调用得早不代表走得快。确实同时的争抢要进入冲突判定，不按数组顺序给物品，也不两边各发一份。

计划使用某件物品，不等于已经取得或预占远处的物品。若不同意图在同一边界涉及同一物件，先汇合为同一冲突处理，再确认实际效果；不能让先处理的离场工作段提前锁走资源。正在实际操作、搬运或消耗的物件则依据已有物理状态判定，不为后到者重新抽取公平结果。

继续休息或执行既有制作不需要每分钟重新问 GM。NPC 如需修改已有计划，则只由 GM 发起；不是另做一套按饥饿数值自动分配工作的人物 AI。网络等待、模型轮数和响应速度不改变到达顺序。

### 一个 GM，多段受限工作

这是同一个 GM 能力在不同场景的工作，不是每个 NPC 各有代理或独立会话史。

- 工作段的快照固定当时的时间、场景参与者、听众、可扮演者与输入来源，不固定活世界。
- 原营地与私人营地分别投影上下文。每段只得到这一方可知的状态与经历，不把全岛秘密先给模型，再指望它假装忘记。
- 群聊内部仍保留每条资料属于谁的知识，不能把当前人物知识并集当成人人共享知识。
- 人物进出或听众变化后，当前段不扩充原有读取权限；重放按当前现场校验，下一段重新投影。分块渲染边界不是换段条件，真实感知范围才是。
- 不延续上一地点的原生供应商会话或工具消息而绕过重新投影；具体供应商续接仅在同一工作段内使用。
- 同一段不无限自主聊天。只处理当前决策及必要工具结果；回合预算耗尽要明确报告未完成，不能把未完成候选当作成功，亦不冻结活世界。

失去模型连接时报告并暂停自动规划，不由随机脚本或统一“继续干活”静默代替人物；共同时间和已开始的活动照常前进。已确认世界保留；不因为 NPC 在离场地点就忽略错误。

## 5. 一段演出怎样与真实状态接合

GM 工作段只提出候选操作；[重放](../apps/game/island/scene-replay.ts)把仍合法且身份对应的前缀接入活世界。整段演出不是原子世界提交，原子事务边界是保存时的完整检查点。

### 候选执行与编号翻译

玩家已明确提交的话与实际操作有自己的来源身份，不在模型重试时重复追加。[工作段](../apps/game/island/scene-work.ts)克隆当前世界，以固定场景权限执行候选操作；连续工具调用可见此前的候选结果，不能重复花掉一份材料，也不能通过调用工具推进共同时间。候选工具结果不提前展示成已发生的事实。`finish()` 仍要求至少一项成功操作；[GM 循环](../apps/game/island/agent/runner.ts)以已执行操作且本段无人待决策作为完成判断，不把空段作为正常成功。

每个成功候选步骤仅在运行内记录操作者、操作、新增经历／物件／设施的编号及所回应的具体邀请。重放从最新活世界开始，逐步翻译引用、重开当前场景权限并调用原领域操作，不把候选世界整体替换进去：

- `experiences`、`items`、`structures` 分别建立候选编号到实际编号的映射，按各自创建顺序对应；后续约定回应、转述、材料、容器、水源、设施、墓地等引用统一翻译。快照后世界自行产生的编号不被误认成候选对象，既有对象仍保留原身份。
- 实物递交、照料和身体接触的接受或拒绝绑定那一次邀请的经历 `sequence`，重放时也翻译并核对它。只匹配发起人、对象或接触方式不够；旧邀请撤销后重新提出的同样邀请，不能被迟到的旧回应接走。
- 每步先得到一个尚未接纳的领域结果，核对新增经历、物件和设施数量，并逐条核对经历 `kind`；全部对应后才记录映射并保留该步。操作不再合法、邀请已变或生成结果不能对应时，停止并丢弃该步及后缀，不让这一步的试算结果泄入世界。

已通过的前缀及对应经历保留，下一段从真实已生效状态重新观察，而非重跑旧段补齐后缀；是否再规划由第四节的普通调度决定。开始活动和活动完成仍是不同节点，候选中开始的远行不能在重放时变成瞬移。

正文与行动不能靠解析自然语言互相猜测。领域操作产生结构化结果，正文表达结果；“格式合法但正文说没加入、行动却加入”的语义冲突仍需真实模型验收，类型检查不能证明一致。

群像演出也不能靠从正文正则截取人名来判断谁说话。言语与叙述片段需有明确的语义类别和说话者身份，显示姓名从身份派生；具体输出协议施工时定义。片段随所属工作段有稳定来源，原文只保存一份，不能为屏幕气泡和长期记忆另存两套可各自修改的对白。旁白不能借这个结构成为全员听见的发言。

### 中断与串行保存

- 模型中途失败、取消或失去当前工作所有权时，不把尚未完成的候选操作提前接入世界；已确认的玩家输入、已生效的 NPC 前缀及此前世界变化不回滚。后续显示失败也不能抹掉这些事实。
- 新旅程、检查点及保存确认共用服务的 `save()` 串行入口。排队者等待前次写入结束，不继承前次异常；失败由原调用方报告。轮到自己后重新读取当前状态并检查 pending，检查点有待确认候选就不另写，新旅程也不能覆盖它；确认入口只恢复原候选。写入等待不把玩家操作或模型思考排进同一队列。
- 每次检查点克隆的是轮到该次写入时的完整活世界，事务保存世界与经历。保存期间活世界仍可前进，只把该快照对应的版本标记为已保存，后续进展留给下一次检查点。新旅程必须持久化成功后才回执。
- 保存失败、冲突或结果未知时，已有文件事务保留完整候选并暂停世界时间。恢复先确认或重试同一候选，不重新生成模型结果、不重放行动或重抽随机结果，也不拿后来的快照覆盖尚待确认的内容。
- 已生效内容不提供只改某个人旧对白的局部重生成；整段或整旅程回退属于单独的产品决定，不预埋分支存档。

### 请求回执与结果未知

[客户端](../apps/game/island/client.ts)区分世界操作传输未知与保存未知：只有 `act`、`accept-intent`、`start` 的传输异常进入世界操作结果未知锁。请求跟踪先记住带同一 `actionId` 的完成证据，再按第四节的 `stamp` 决定是否更新显示；即使完成推送先到、请求回执稍后超时，也不会把已确认操作误判为未执行，迟到旧视图也不会倒退界面。

`think`、`dismiss-intent`、`interpret` 的传输失败只报告对应请求问题，不锁住活世界，不因回执丢失自动重发付费调用；解释的后台结果与关联错误见第七节。保存未知仍由独立确认入口恢复原候选，不能靠读到一次普通视图或收到操作完成证据就假定已落盘。刷新后只承诺恢复已写检查点及文件事务能够恢复的完整候选，不承诺恢复仍在飞行中的供应商请求。

## 6. 事实、经历与说法

按时间保存一份具有稳定来源身份的经历序列，包括已确认对白和有玩法意义的世界事件。记录说话者或行为者、时间地点、内容与实际见闻者；见闻由当时空间和感知判定，不让模型自行填写“所有人都知道”。

亲历、听到某人说、自己的推测和客观发生的事不同。听说物件被偷并不证明是谁拿的；NPC 的谎言保留为带来源的说法，不覆盖世界状态。

转述产生新说法，不扩散原私聊的全部内容，也不修改原受众。同阵营、结伴迁居、共享物资或重聚均不自动合并人物记忆。

已实现的[合作记录](../apps/game/island/cooperation.ts)使用提议、个人回应、指定原话转述三种声明。提议的正文就是条款，只表示提出者本人的承诺；其他人自行同意、拒绝或退出。条款不由代码解析执行，也不成为取物、建营或搬迁的权限墙。修改条款是新提议，旧承诺及其原话仍在经历中。

[实物交接](../apps/game/island/handoff.ts)单独处理递出、接过与拒收。递出是持有者正在进行的活动，包含实物引用、接收对象和数量；东西仍留在持有者手中，接收者自行操作后才转移。部分材料分出实际份数并保留湿度、污损及保存起点，容器保持同一个物件及水；附近旁观者只能看到递出的数量，不能借此读取剩余库存。玩家的接收不能由 GM 代签。接收不取消接收者原有活动，但仍检查距离、可见性和携带能力；递出者必须先结束手头活动。明确拒收留下拒绝经历并解除递出者等待，不转移物资、不取消接收者的活动。收回、对方走远或死亡同样会终止递出，不留下远程预约。

递出活动属于已有旅程状态：刷新后要恢复仍在手上的物件和待接收动作，失败使用同一文件事务恢复，重开随旅程清理；不新增交易表或物权副本。借用、期限和归还条件可以用约定表达，实际交付与是否守约是不同的经历。NPC 递物会唤醒接收者作出判断；递给玩家时，邀请出现在身旁，等待玩家接受或拒绝；对方在此期间保持递出的姿态，玩家走开则邀请失效。

转述只保存被引原话的引用，展示和检索时派生被引用的说话者、内容与声明类型；不附带原私聊的地点、受众或相邻内容。转述回应不会自动传授条款，需要分别转述；也不宣告该回应至今仍然有效。已听到的新回应不被后来重述的旧回应覆盖。读原始经历仍检查当时受众；后来才听说的人通过自己听到的转述查全文，不能借引用打开原私聊。保存入口按时间一次扫描校验引用与当时知情，运行内派生当前所知，不另存约定表。

社会关系须按各人可知来源形成投影，不能先算出全岛最新立场，再仅隐藏其来源。秘密答应另过的人知道自己的新选择，原营地可能仍按旧承诺等待；未告知的退出不能让别人立即停止期待或统一敌对。实际履行结果和后来获知的消息可以改变这种认识。

机密程度不是一个永久布尔值。后来在现场发现棚子是新的经历；这不表示人物突然获知当初谁怎样商量建棚。视线、声音、转述或明确展示都是获得信息的实际路径。

工具工作文本与回执不是世界经历。提交后的实际行动可以产生领域事件，其见闻者由世界判定；不能把工具返回里的完整库存、计算和私密身体数据广播给在场者。

不逐帧保存脚步或把所有生理数值变化写成聊天楼层。当前活动进展在世界状态里；有意义的发现、交付、受伤、约定等才进入经历。持续痕迹是否存在取决于具体已实现的世界对象，而非无限增长的足迹日志。

## 7. 长期记忆与上下文

### 自然语言行动入口

说话与行动分别输入。说话直接进入现场；行动意图先交给只读解释器，转换成一项具体操作或提出澄清问题。玩家在确认区看见真实对象、数量、路线、材料和可确定的耗时，确认后才经原行动入口执行。多步骤意图只提出明确的下一步，不在一次确认后自动连做。解释器没有 NPC Act 权限，提议不进入世界经历，也不推进时间。

解释器只读取玩家视野和玩家本人可查的原文，不能使用 GM 的 NPC 知识并集。当前观察与原文分页、向量工具和请求预算共用同一实现，但读者集合分别固定。候选操作先经过当前物理规则与玩家权限校验，不把合理却未实现的动作伪装成成功。

解释请求由[宿主](../apps/game/island/host.ts)校验请求身份和 `generation` 后启动后台工作，立即回执含 interpreting 的当前视图，不让桥接请求等待整轮模型调用。后台的 guard 绑定当前聊天激活、该次控制器、未取消或离开及宿主可工作的状态；服务在结果返回时再核对原活世界对象与代次。任一检查失效都不写入旧提议，迟到结果不能落到新旅程或新的玩家意图上。

澄清问答和提议只活在服务运行内，绑定第四节定义的 `generation`，不绑定每秒变化的世界或存档修订号。澄清后可以直接回答对象或数量，前一问题和原意一起注入；玩家经行动入口改变世界或切换旅程后，旧上下文失效。时间流逝及 NPC 行动不单独废弃解释，确认时仍须重新核对当前物理条件。运行重载会丢弃未确认提议，不会丢失已落盘的世界变化。

后台完成后推送提议；后台错误带原请求的 `actionId`，客户端据此归到该次解释，不把随后到来的桥接超时误判成另一项未知世界操作。供应商失败不提交提议；回执丢失先读当前状态，同一请求仍在运行内时可读回结果，付费调用处理遵循第五节。后台错误可能早于桥接超时到达，客户端保留该关联证据；已取消或已不属于当前激活的结果不再发布。

确认提议使用其原始请求身份和代次，由规则按当前世界重新校验后执行；不再成立则明确失败，不重跑模型、不重复操作。玩家明确放弃或开始另一个意图即可替换临时提议，不新增存档表或旧格式兼容。

延续已经讨论确定的方案：原文分块向量检索，不增加独立总结生成、事件抽取或重排模型，不复用总结插件的 L0/L1/L2、数据或维护流程。

### 装配顺序

1. 将当前工作段的可扮演 NPC 作为知识范围；玩家不进入该并集，避免把玩家其他私聊带入。
2. 直接注入这一范围的当前可知处境、本人身体和当前活动、已确认合作约定及近期原文。不是直接注入全岛真实状态。
3. 原文按受众边界及长度切块，同块不混不同受众。主动浏览、读取和召回必须指定当前允许的一个观察者，先用此人的知情范围过滤，再做向量检索；不以同场 NPC 知识并集替代这个人的记忆。
4. 命中合并去重并保留原受众。提到了某人不等于某人知道；旧事发生在别处也可以相关，不能只按当前地图找记忆。
5. GM 按需语义召回、按时间分页浏览或按来源读取原文；引用其他人的查询结果不改变当前人物的知情范围，来源读取不能绕过权限。

初始近期资料仍按当前可扮演者汇集，每条保留原受众；查询结果则属于明确指定的人。工具返回精确来源、实际受众、覆盖范围和分页信息；未命中不是证明从未发生，读到部分也不等于已经看完。空的个人经历直接返回空结果，不读取 Embedding 配置或发起收费请求；索引仍是一份共享派生缓存，按人筛选不删除其他人已经生成的向量。

身份索引分别标明当前观察者与姓名记忆的知情者。听过的发言、本人相遇和收到的明确转述可以留下姓名对应关系，即使原文已离开近期窗口；来源引用仍指向该人物可读的经历。记得名字不提供离场者的外貌、位置、库存或当前行动，转述不授予原私聊读取权限。姓名从本局身份及人物目录派生，不另存身份副本或认识关系表。

Embeddings 只提供相似度表示。当前资源、位置、明确约定与关键事件状态不依赖向量碰巧命中；这类事实由世界及结构化经历投影直接提供，原始经过才按需查阅。

GM 的约定投影给出条款预览、是否截断、本人能读的来源，以及逐人最后听到的回应和出处。Observe 与初始注入使用同一分页投影，整组观察有字符预算；长期约定数量增加时通过 next 继续，不把全部条款重新注入。转述的向量片段包括实际被转述的原话，来源摘要也绑定这段原文；不能只索引一句“我来转述”，使新听者永远搜不到内容。

预算覆盖完整请求：系统资料、人物信息、状态、原文、工具定义、返回和后续轮次。不能只限制首次历史长度，就让工具读入无限原文。具体额度在模型与真实材料下验证，不在本文虚设万能上限。

首次装配按实际供应商消息表示估算整包输入，至少留出一份输出额度供后续工具交换；超出时只移出最旧的近期经历并标明还有更早记录，完整原文仍可查，不裁掉当前事实。观察工具以首次注入的第零页为起点，同一页再次读取只返回各观察者已变化的完整字段；空列表和空值明确替换旧内容，不省略消失的对象。首次读取其他页返回完整快照，各页分别更新。这些对照页仅在当前工作段内存在，不保存到旅程、不跨人物知识范围复用。后续轮次仍核算完整消息和工具回执，超过总预算明确中止，不能把未完成的候选提交为成功。

### 配置与索引失败

GM 使用小白 OS Agent API。仅引用总结设置已有的 Embedding 连接配置，不读取总结生成模型或 Rerank 配置作为依赖，也不沿用总结插件启用开关。连接信息在调用边界读取，不复制到游戏存档。

荒岛拥有原文片段与派生向量索引。索引绑定来源内容及实际模型空间；原文改变只失效受影响部分，模型空间改变则相应重建，不能混排不兼容向量。

近期原文不等待向量完成。索引失败保留原文及已有有效结果，明确标注缺口，不把失败伪装成“无经历”。关键词和原文浏览是明确的独立能力，不静默宣称用它们已经完成语义召回。

仅恢复未完成且计费状态清楚的部分；成功或计费未知的请求不自动重买。旧索引在原文仍存的前提下可以清理，但重建涉及费用，应在实际操作前让用户知道。

## 8. 持久态、临时态与删除路径

以下是目标生命周期。世界与经历在 `island` 用户分区；死亡仍修改同一人物身体，不另存两套位置或物品。派生向量在 `islandMemory` 用户分区，不保存连接密钥或第二份原文。检查点候选的保存与恢复见第五节，不与 GM 工作段的运行内候选混用。索引只保留一个旅程与模型空间；更换后首次使用索引时替换旧缓存，读取始终校验旅程、来源及模型空间。

| 数据 | 为何要保留 | 所有者与生命周期 | 失败及删除处理 |
| --- | --- | --- | --- |
| 当前旅程世界：时间、人物身体与位置、物件、设施、正在进行的活动及必要的随机状态 | 重开页面必须接着生活，不能清空伤病、瞬移或重新抽结果。 | 荒岛旅程；重开或删除旅程结束。 | 只提交校验后的版本；失败不覆盖已确认世界，按文件事务恢复同一候选。 |
| 易腐食物的暴露起点 `foodSince` | 否则刷新、转交或烹调会把旧鱼变成新鱼；异味和风险无需另存。 | 荒岛实物；随实物留在本局，消耗后仍保留历史引用。 | 随世界候选原子保存，失败恢复同一候选；随重开或旅程清理，不加独立缓存或旧格式兜底。 |
| 物件污损、伤口污损与实物包扎位置 | 否则重载会清空脏污，拆布或换手会凭空得到干净材料。 | 同一旅程的物件与身体；包扎只是原布片的 `dressing` 位置，拆下即回到地面。 | 与劳动结果共同保存；失败不提交半次清洗或照料，重开随旅程清理。 |
| 等待照料、实际照料与接受照料的对应活动 | 重载必须继续已同意的劳动，而非重获同意或重复扣材料。 | 原人物活动；取消、条件失效、死亡或完成即解除，不形成长期授权或第二条调度队列。 | 沿用世界候选事务；恢复同一进度，不重跑已完成动作。 |
| 原始交谈、领域经历及有来源的约定 | 长期记忆、见闻和社会关系需要依据。 | 同一旅程；当前关系由它投影，不再存可独立修改的副本。 | 与对应世界变化共同提交；随旅程清理，不碰主聊天或余火资料。 |
| 派生片段索引与向量 | 避免每次打开都重新购买同一批向量。 | 荒岛记忆；绑定原文及模型空间，原文是依据。 | 单独失败不删除原文；重建或删除旅程时清理所属索引。 |
| 完整但保存待确认的候选 | 避免已收结果因保存异常被迫重新执行或重新购买。 | 沿用现有文件事务的恢复机制，不另建永久作业表。 | 确认提交或明确放弃后清除；先确认未知结果再恢复。 |

请求上下文、工具分页游标、进行中的供应商连接、GM 候选执行、派生关系投影、寻路缓存、渲染状态、触控和镜头过程态只在运行内。持久化的是世界里已经开始的劳动，不是 JavaScript Promise 或整条自动调度队列。

埋葬只新增同一经历序列里的事实，正在挖埋仍属于原人物活动；环境变化使用已有的时间来源，因此不增加持久化环境字段、不改变当前存档格式。重载从原经历重建临时埋葬索引，重开随旅程及其引用一并清理。

NPC 行动重载后从已确认的位置和进展恢复；路径可由当前世界重算，不能把不可达时的错误吞成回营或完成。场景卸载只卸载视觉，不删人物或物资。

随机结果与世界的随机状态属于同一检查点，保存恢复遵循第五节；刷新不能重抽已经写入的结果。随机性用于有根据的不确定结果，不用于掩盖缺少材料、路线、角色决定或社会规则。

新功能没有历史用户旅程，不添加自己旧草案的兼容层。当前旅程格式为 `ISLAND_FORMAT_VERSION` 定义的版本，身体接触活动和经历显式携带具体方式，并加入徒手冲突活动；旧开发存档需要显式重开。读取不自动删档或静默填值，只有用户确认替换才写入新旅程。运行时只认当前模型；未来若有真实需要保留的格式，再在升级或导入边界做一次转换，不把兼容分支塞进每日行动。

功能删除需先确定荒岛旅程导出或丢弃策略，再删功能目录、实际注册与所属数据；相关产品文档及资产一并处理。不删除共享 Agent 配置、总结配置与数据、余火旅程或钱包资料。荒岛目前没有已授权的经济功能，不预埋购入、复活和奖励流水。

## 10. 验证应证明什么

### 持续生活与结束边界契约

以下是行为要求与故障代价，不是已经通过的结果；验证授权统一见产品设计第十二节。

| 什么情况下，用户或系统必须怎样 | 出错代价 |
| --- | --- |
| 玩家仍存活且未确认重开时，系统必须允许继续当前旅程，不因天数、设施完工或人物立场切换为结束状态。 | 意外终结用户仍在进行的游戏。 |
| 玩家死亡后，系统必须只提供已知经过回顾，不再推进该旅程。 | 已结束存档被继续修改。 |
| NPC 死亡时，系统必须保留其身体与原物件，未获知死亡的人不能自动得到消息。 | 丢失世界物件或泄露私人经历。 |
| 遗体被埋葬后，系统必须保留原身体和依附物品，挖开前不能拾取；挖开不能复制物件。 | 实物丢失或重复。 |
| 只看见土堆但未目击埋葬时，系统必须只显示土堆，不泄露地下身份、库存或原埋葬经过。 | 未知信息泄露。 |
| 挖埋被取消、操作者死亡或工具失去可用性时，系统必须不记作完成，已确认的埋葬状态保持原状。 | 遗体状态与经历不一致。 |
| 当前存档不符合现行格式时，系统必须保留原文件，只有用户确认替换才开始新旅程。 | 不可逆丢失用户存档。 |
| 清洗或照料开始后失去所需物资、接触或同意时，系统必须终止而不是扣半份资源或记作完成。 | 实物状态与经历不一致。 |
| 照料对象尚未接受时，系统必须保留邀请状态，不能替玩家接受或开始治疗。 | 玩家失去行动控制权。 |
| 同意照料后任一方取消或死亡时，系统必须解除双方对应活动，死亡后不再产生该人的操作经历。 | 人物卡在无法结束的活动，或存档不可读。 |
| 身体接触的具体邀请尚未被接受时，系统必须保留等待或拒绝，不替接收者同意，不把一种接触的回应当成另一种许可；拒绝不取消接收者原活动。 | 玩家控制权或 NPC 已有劳动丢失。 |
| 玩家的移动、转向、停下必须立即作用于活世界，不等待任何模型调用或 NPC 计划；模型思考期间时间继续，玩家操作不被锁住。 | 玩家被“等待 AI 批准”卡住，或 NPC 思考冻结世界。 |
| 同一旅程内收起交谈、查看人物或背包、返回入口再继续时，系统必须保留未发送的说话和行动草稿及阅读位置；切换旅程时清除，不写入存档。 | 未发送输入丢失，或旧旅程内容串入新旅程。 |
| 接触中任一方取消或死亡时，系统必须解除双方配对；新旁观者只能观察当前动作，不能因此获得旧私聊。 | 活动卡死、存档不可读或秘密泄露。 |
| 出手刚开始时，系统必须让目标和目击者先决定反应，不能在同一次操作中直接命中；伤势由到期的实际距离与防护结算。 | 玩家失去反应机会或伤势与经历不一致。 |
| 同时到期的攻击中，系统必须先决定本时刻的全部结果，再应用打断与位移，不由人物枚举先后吞掉另一人的尝试。 | 行动顺序偏置和已确认尝试丢失。 |
| 衣物、容器和包扎经过转手、晾干或读档时，系统必须保留已有污损，清洗才结算相应效果。 | 生活资源与伤病规则失真。 |
| NPC 工作中出现身体提醒时，系统必须保留进度供 GM 决定，持续恶化仍能再次触发判断。 | 丢失劳动进度，或人物无视危急需求。 |
| 查询某人的旧事时，系统必须先按其知情范围筛选，不能因同场、同营或重逢而读到他人的私事。 | 秘密泄露，长期人物记忆串线。 |

下表区分各类问题所需的证据，不作为编写或运行测试的任务清单。

| 契约与实际故障 | 最便宜的验证层 | 现有检查不能代替的原因 |
| --- | --- | --- |
| 一件物品不能重复消耗、隔空转移；NPC 工具不能替玩家发起自愿行为 | 领域单测 | 类型正确的两个操作仍能错误使用同一份资源或控制错误的人。 |
| 多地点同时前进、相遇与打断，不受渲染和模型耗时影响；GM 计划在世界已变时被按当前世界重新校验，不成立的部分被丢弃 | 时间与行动单测 | 固定路线成功不证明分营后时序一致。 |
| 当前观测、旧私聊与转述不串人，直接按 ID 读取也不能越界 | 知情与检索边界测试 | 向量命中和合法 JSON 不证明人物有权知道。 |
| 同一段连续工具调用及保存恢复不重复改变世界 | 领域提交及真实文件事务集成测试 | 单个工具成功不覆盖跨调用与未知提交结果。 |
| 加入、承诺、履行、违约分开，未表态者不被代表 | 社会事实投影单测 | 几个人同处一地不能证明阵营语义正确。 |
| Embedding 失效、缺口、重建不删除原文、不静默漏记忆 | 配置/索引边界测试 | HTTP 成功、索引数量变化不证明记忆完整。 |
| 实际地图的可达、遮挡、使用范围与工具一致 | 少量真实场景集成及端到端 | mock 世界和静态截图不能证明实际地图成立。 |
| 角色选择可信、对白与行动相符、分裂不强制敌对 | 人类逐步复核与授权后的真实模型试演 | 类型、lint、单测和 HTTP 收据不能评价叙事语义。 |
| 场景可读、操作流畅、手机与宿主性能可接受 | 真实宿主实看与试玩 | 简化测试页面、截图尺寸或理论帧率不能代替体验。 |

不为每个情节重复写一套端到端；共享机制由最低层证明，代表性的自由路径再串起来。自动化脚本完成只是执行证据，质量结论必须落在实际观察到的行为上。

## 11. 尚需验证而非凭空宣布解决的风险

- 单个 GM 群聊面对带受众标识的知识并集，是否仍会让不知情者接话；机制隔离与真实模型行为都要检查。
- 主动时间与长聊结合是否让节奏自然，以及离场场景决策是否造成可接受的请求频率；不以假数字承诺成本。
- 有限物理动作是否足够表达用户的自然办法，还是频繁出现“想法合理但不支持”；通过自由玩法验收补实质能力，不靠泛用改状态工具绕开。
- 物件细度、生理反馈与自主人物是否增加有意义的选择，而不是变成琐碎劳动；需要试玩，不继续增加仪表盘解决。
- 候选执行与正文提交能否让用户始终分清提议、开始、完成和失败；工具成功数量不能代替这项体验。
