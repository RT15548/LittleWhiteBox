# Dice 行动检定：完整施工验收

日期：2026-09-14。行动检定已接入小白 OS 的 Dice APP，默认关闭、按聊天启用。随机遭遇、状态栏与世界／总结增强未在本批施工。

## 交付行为

主 RP 模型输出 `<xb_action_check>` Tagged JSON；Dice 本地投 D20，将结果与清理后的正文一并保存，确认后调用宿主原生 `generate('continue')`。卡片及后文留在原 AI 楼层／候选。Dice 不注册供应商原生工具，也不使用 OS Agent API 审查每轮聊天。

完整开标签出现后才隐藏；普通 `<` 与更短的标签残片仍按普通正文显示。正常检查不保存设置，只有自有全局规则缺失／损坏才修复。不逐 token 维护规则。

失败重试沿用原骰点；刷新只恢复已落盘卡片，不扫描旧 JSON 重投，不自动续跑。连续检定上限为每候选 8 次，第八次后仍允许一次收尾续写，第九个请求不执行。

## 所有权与数据流

全部检定业务位于 `apps/dice/`：

| 边界 | 职责 |
| --- | --- |
| domain／protocol／prepare-action-check | 当前请求与记录格式、D20、锚点、模型输入输出 |
| action-check-session | 一条临时链；一次随机、保存确认、续写、取消与同骰重试 |
| generation-adapter／sillytavern-port | 本次主生成身份、宿主收尾屏障、群成员边界、原生 continue |
| message-records／message-save | 只修改 Dice 字段与所属候选；公共保存器确认、异常读回和受保护回退 |
| message-display／card-style | 从已确认记录生成安全文本卡片、精确锚点定位、恢复按钮、重绘与注销 |
| controller／DiceApp | sidecar 开关确认、文件故障恢复、最小 APP 页面 |
| production-module | 注册及生命周期组合、所选聊天清理顺序 |

持久事实只有聊天分区的启用偏好、消息／活动 swipe 中的检定记录及全局显示正则。pending、队列、取消标记、未确认候选和自动续写资格都不落盘。未确认候选只在当前运行内保留。

保存确认后不再无理由读回整聊。确认丢失时按捕获的原聊天读取；冲突不覆盖，用户明确重试也先核实。停用先取消自动资格，再等已派发写入结算，防止重新启用把暂存字段当成已确认历史。

群聊复用宿主原轮转，在下一成员 drafted／wrapper finished 边界处理前一成员。不另建群队列。恢复原角色使用宿主保存的 `original_avatar`，不靠角色显示名猜测。

跨目录修改仅为 Host／Shell 注册、生成顺序 440 与公共提示词事件适配器的 dry-run 过滤。没有修改 SillyTavern 源码、替换主 Generate、添加独立上传器、引入新依赖或引用小白酒馆运行时。

### 发现后修复的实际问题

1. 公共提示词适配器原先将 dry-run 的开始／组装结束转发给真实请求所有者，导致地图、任务、世界资料从续写中丢失。改为只转发真实生成对应的两种事件，不增加新的运行状态；商店同样遵守此边界。修复前后均检查了供应商实际请求。
2. Dice 开关页面原先直接读取 bridge 回复外层，保存成功后把状态覆盖为 `{ok,result}`，导致开关不可用。按宿主既有协议读取 `result`，且迟到回复不能覆盖更新的文件状态推送。正式页面开关往返及真实 SFC 回归测试已通过。
3. OS 重启等待尚未结算的 Dice 写入；数据清理在保存后再次核对聊天，避免延迟确认后误清另一聊天的分区。
4. 开关的显示规则预检与偏好提交共用捕获的聊天／页面校验；异步预检期间切聊不会将旧页面的开关写到新聊天，迟到的关闭确认不会取消新链。

没有为这些边界加入旧协议兼容、持久化锁或另一个自动续写协调器。

### Review 修复回归（2026-09-14）

本轮三项修复均位于 Dice 自有 `generation-adapter`，未修改酒馆本体、领域数据、Prompt 或 UI：

1. **自动续写误消费草稿／写错楼**：使用 ST 1.18 原生后续生成参数 `depth: 1`，跳过斜杠命令及输入框消费；不临时清空、缓存或恢复输入框。外层 `Generate` 不向群 wrapper 转发 depth，所以群轮转结束后的续写直接使用宿主导出的 `generateGroupWrapper`；轮转内仍调用原 `generate`。补齐独立续写的忙状态，并在提示词异步预检前后核对捕获的目标，失效时在请求前终止。
2. **重新生成漏检定**：观察区分准备／接收阶段，只放行 `regenerate` 准备期间一次宿主删除旧回复的事件；后续删除仍取消观察。
3. **关闭后新 swipe 继承记录**：新候选的 Dice 字段清理先于执行开关检查，仍忽略 dry-run；旧候选与其他功能字段不动。

Playwright 使用修复后的完整生产构建，在真实隔离 ST 1.18 上重跑原复现：普通／重新生成均为 2 请求，续写带已确认骰点；`UNSENT_DRAFT_REVIEW` 保留在输入框，不进入聊天或供应商请求；关闭后新 swipe 无记录、无卡片，旧 swipe 的记录完整保留。

新增流式普通／重新生成检查：主生成期间输入 `/echo` 草稿，续写期间继续输入并设置选区，最终草稿和选区均不变，后文仅追加原 AI 楼。续写 HTTP 503 后点击恢复，1 次请求、同一记录、草稿不变。停止输出、启用状态下新 swipe／切回旧候选、编辑锚点的既有浏览器回归也通过。

双成员群的流式／非流式完整链均复测为 5 请求、各自原楼。额外分别检查群成员间 Dice 续写、轮转结束后的 Dice 续写、群聊显式同骰恢复，Dice 发起的续写均不消费草稿。群成员间失败场景同时暴露以下宿主限制，未将其计为「群聊全程保留草稿」通过。

请求准备期间目标变化由宿主边界集成测试覆盖：保留原楼已确认骰点，0 次后续供应商请求，不写入新用户楼。该故障注入不冒充真实浏览器场景。

本轮证据脚本为 `review-boundaries.cli.js`、带断言的 `review-disabled-swipe.cli.js`、`fixed-drafts.cli.js`、`fixed-group-drafts.cli.js`，并复跑 `full-group.cli.js` 等既有场景；关闭后新 swipe 的修复截图为 `fixed-disabled-swipe.png`，保留旧 `review-disabled-swipe.png` 作为修复前证据。

### 流式异常后的原骰点恢复（2026-09-14）

追加 review 复现：Dice 续写收到损坏的 SSE JSON 帧后，ST 1.18 已停止生成，但保留 `isStopped=true` 的流处理器。原等待条件把该残留当成仍在生成，导致显式续写等待 20 秒后超时，恢复按钮也随状态变为 invalid 而消失。

修复仍位于 Dice 内：宿主屏障允许已停止的流残留，不放行仅 `isFinished=true`、仍在收尾的流；生成／保存状态及目标校验保留，不清空宿主处理器。生成适配器记录本次生成之前的处理器引用，只拒绝本次失败的流，避免污染后来的非流式回复。普通失败流的接收事件不触发投骰，Dice 失败续写也不把部分正文当成成功结果进入下一轮检定。等待失败保留原来的保存／续写恢复候选；取消或目标失效则终止。

无后文的失败可以显式沿用原骰点续写；已有部分后文的失败保留正文，提示使用酒馆普通继续，不回滚正文、不扫描失败片段重投。没有新增持久化字段、重投入口、自动重试或宿主修改。

真实隔离酒馆、更新后的生产构建回归：

- 原损坏 SSE 复现现为 3 次请求（主生成、失败续写、显式恢复），原楼补上后文，记录 ID／骰点／判定及全部字段完全不变。
- 普通主生成在完整检定块之后流式报错：1 次请求、0 次检定；随后切非流式正常生成仍完成 1 次检定和续写。
- Dice 续写先写出部分正文及完整新检定块，再报错：总计 2 次请求、仍只有原来 1 次检定，部分正文保留，没有额外自动请求或重放按钮。
- 原有普通／重新生成、输入框草稿、关闭后的新 swipe 隔离回归再次通过。
- 用户停止后无投骰，启用状态下新 swipe／切回旧候选及编辑锚点回归通过；双成员群聊的流式／非流式正常链均为 5 次请求，各自保留原楼。

群聊冒烟首次遇到宿主 `write-file-atomic` 的 Windows `EPERM rename`，服务端返回 HTTP 500。Dice 停在保存未确认状态，显式核实重试后才完成第五次模型请求；随后重跑流式／非流式完整链通过。未通过修改宿主或自动重试掩盖该写入失败。停止探针首次沿用了前一失败流的旧 `result`，过早触发停止；通过一次正常宿主生成回到探针原有前置状态后重跑通过，未改产品逻辑来迁就探针。

本轮脚本位于 `output/playwright/`：`dice-review-r2-stream-error.cli.js` 重跑原复现，`dice-fixed-stream-boundaries.cli.js` 对失败输入、后继非流式和部分正文执行断言。后者仅通过临时 token 事件延时让宿主先显示正文，再接收损坏帧；未替换原生解析、正文更新或错误处理。等待中的保存／生成屏障、超时保留恢复资格及取消／目标失效由宿主边界和 session 测试验证。

## 数据清理与卸载

模块的 `clearData` 入口只清理当前明确选中的聊天：

1. 拒绝宿主生成／保存中清理；确认关闭偏好并等待本功能在途保存结算。
2. 移除当前聊天消息及所有 swipes 的 `extra.xiaobaiOsDice` 和 Dice 正文标记，保留标记之外的正文、其他 extra 和其他 APP。
3. 使用公共聊天保存器确认；未确认或聊天改变则抛错，不继续删分区。
4. 确认仍为原聊天后调用传入的分区删除能力。该入口是模块维护接口，本批不额外加入清理按钮，也不扫描全部聊天。

清理验证层为生产模块边界集成，不声称已在用户库执行全量清理。清理结果未知时需重新加载核实；没有多端 CAS 保证。

单聊天清理不移除其他聊天仍使用的全局规则。整体卸载 Dice 时，在酒馆全局正则中删除 **小白 OS · 行动检定显示（自动管理）**，固定 ID 为 `xiaobai-os-dice-action-check-display`；停止模块、按明确范围清数据，再移除 Dice 目录与注册。仅停用会保留已保存事实；整个插件停用后不承诺继续显示自绘卡片。

构建已更新 tracked dist，并正常替换旧哈希分块；源码与旧构建可通过 Git／重新构建恢复，没有删除用户资料。未提交、未推送。

## 明确限制与未覆盖项

- 请关闭酒馆自带「自动续写」。本批没有修改这个用户设置，也不实现两套自动机制协调。
- 群聊轮转全程仍不适合提前输入下一条草稿：Dice 自己的续写不消费输入框，但 ST 1.18 下一角色的普通生成会读取它。实测前一成员 Dice 续写失败时，后续供应商请求虽被阻止，宿主下一次普通生成仍会先执行 `/echo` 草稿；事件监听器和生成拦截器无法提前阻止此宿主步骤。本批未替换群轮转或主 Generate，不承诺修复这一独立的宿主输入框行为。
- 功能开启期间不要修改或删除显示正则：宿主自身会重载聊天。误删后的下一次检查能补回规则，不能恢复被宿主打断的在途回复。
- 没有调用真实付费模型。模型能否稳定停在结果揭晓前、正确选择检定时机并遵循骰点，仍取决于实际模型／预设；模拟供应商只能证明接线和执行行为。
- 当前实机为 SillyTavern 1.18.0 和桌面浏览器的窄屏模拟；未声称覆盖所有旧宿主、移动 WebView、第三方渲染插件及多端同时编辑。
- 未实现随机遭遇、属性状态栏、D100 或世界／总结丰富随机内容；这些属于后续功能，不留空数据与兼容壳。
