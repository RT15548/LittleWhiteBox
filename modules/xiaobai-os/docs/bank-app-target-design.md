# 银行 APP 设计

Bank 提供定期存单与浮动理财，不调用模型、不注入主 RP、不解析剧情。银行属于当前 SillyTavern 用户，切聊天仍是同一份资产。

## 所有权与存储

`domains/bank/`拥有合同、事件、冻结头寸、历史校验和公开投影；`apps/bank/`拥有原子用例、计期适配、Controller 与 UI。余额和资金流水属于 Economy。

[Bank 分区](../apps/bank/partition.ts)以 `storage: user`接入用户文件；格式唯一见 [领域类型](../domains/bank/types.ts)。当前模型保存 `currentTurn`、事件和升级导入历史，开放头寸与活动由冻结事件派生。不维护第二份余额、剧情快照或聊天级银行。

## 产品合同与计期

发布合同库与当前货架分离。同一合同 ID 的期限、收益／罚金、风险与金额范围不可原地改写；新版用新 ID，下架不妨碍旧头寸验证和兑付。产品参数唯一位于 [产品目录](../domains/bank/products.ts)。

开立存单冻结本金、开始／到期回合、到期额和提前支取额；理财还冻结当次随机收益与结算额。收益只抽一次，未到期不向客户端泄漏。加载历史不按当前货架或新参数重算金额。

计期不是当前聊天 Assistant 总数，而是 Bank 的单调用户级 `currentTurn`。宿主 [回复观察器](../host/assistant-floor-observer.ts)识别页面内新完成的主剧情回复位置，已见位置的 swipe、regenerate、continue 不再推进；加载历史建立基线，不补算旧楼。换聊天重建观察基线，不倒退已确认银行计期。

只有存在开放头寸时才需要保存新增计期。未保存的计期在运行内保留并阻止新金融操作，核实或重试原提交后才能继续；不能把尚未确认回合当作到期事实。剩余期限从冻结 `maturityTurn`与已确认 `currentTurn`派生。

到期通知只依据已确认投影，首次读取不补发历史通知；窗口关闭后后台仍可观察，页面内去重状态不持久化。关闭通知界面不自动兑付。

## 资金与命令

开立：player → position escrow；结算：reserve 补足正收益、escrow 向玩家派付、亏损进入 sink，结束 escrow 为零。提前支取用冻结金额；金融操作可同时结算其他到期头寸，零金额腿不写流水。

Bank 事件与全部资金腿共用操作身份，在同一个用户文件事务提交。交叉校验只读取 Bank 与 caller-bound Economy 视图，拒绝漏款、孤儿交易和托管偏差。命令校验 actionId、revision/eventId、产品、金额和头寸状态，失败前不读取随机数；已提交动作重放不生成新 ID、不重抽。

保存明确失败不发布候选；未知结果先核实同一提交，不能重扣或重抽。恢复遵守 [Economy 文件边界](./economy-platform-target-design.md)，聊天文件不因此冻结。

## 升级与删除

已存在的故事级银行由 [升级入口](../apps/bank/application/upgrade.ts)处理：先核对旧事件与资金，再保存带来源标记的旧活动；开放旧头寸按已冻结的到期金额一次结算，清除旧故事 Bank 分区。资金、导入历史与全局 Bank 在同一用户文件提交；失败不先删除旧数据，不以新合同重判旧收益。

这是受支持现行文件的入口转换，不在日常读取保留双银行。聊天删除或分支不清空全局银行。

删除功能前确定开放 escrow、导入历史及钱包审计的策略；不能只删分区而留下无法核账的资金腿。随后清所属用户数据、目录、Host/Shell catalog 和计期／通知注册，不留旧 API 壳。

## 界面与验证

界面用清晰黑白和蓝色操作点缀，深色为中性炭黑。总览、存单、理财、持有、记录各有明确用途；产品说明整期收益（非年化）、期限、退出条件与亏损风险，不展示虚构市值。

确认框展示本笔金额及同时结算的影响；保存期间禁止重复提交、改金额和关闭。锁定理财不泄漏收益；保存失败与核实入口不能被精简掉。页面、筛选、输入与焦点仅在运行内。

最低验证：冻结合同、随机只抽一次、全局计期与历史基线、重复回复不计期、计期保存恢复、原子开立／兑付、旧头寸升级、私有收益裁剪及窄屏操作。自动检查不代替实体设备验证。
