# 荒岛：开放生存与群像设计

本文是荒岛产品范围与交付标准的唯一依据，不是运行时提示词，也不表示全部玩法已经实现。实现边界与记忆方案见[工程设计](island-game-engineering-design.md)，非固定剧情的验证方式见[自由玩法验收](island-game-scenarios.md)。

“产品边界”记录用户已明确的方向；标为“建议”的内容是此次自主推演的方案，尚未经过真实试玩，不冒充已经验证的体验。精确生态、医学、数值、镜头与画风不凭推测写成事实。

**当前首要产品目标：先达到可交给玩家测试的完整体验。** 当前版本不能作为已通过体验验收的基线。先按第九节重整呈现与操作，并完成整段玩家旅程，再请用户体验内容与玩法；不是让用户替制作方逐个找入口、排版、按钮语义和反馈上的基础问题。目标已确定不等于产品已达标。

## 1. 产品边界：一个人生活在会变化的群体里

荒岛是开放生存经营游戏。章节表示增加玩法与自由度，不表示剧情分段；第一章交付时就是一款能持续自由生活的完整游戏，不是序章、限时体验或等待后续补齐基础能力的切片。后续章节可以扩展内容，但不作为第一章生活能力、GM、长期记忆或人物美术未完成的理由。

当前以七名幸存者推演：玩家一人，六名 NPC。七人共同遇难只是开局，不是永久队伍；不要求一起行动、住在同一营地或维持同一立场。玩家可以独居、秘密建营、结伴离群，也可能重新合作。

正式人物阵容为三男三女，姓名、年龄、职业、人设与上岛前的关系统一维护在[人物目录](../apps/game/island/character-catalog.json)，GM 从这里读取，本文不另存一套人物设定。三位女性均为漂亮但轮廓与气质可辨的人物，不沿用余火现有的人体造型。玩家身份按余火的方式自行选择，不绑定某位 NPC 的性别、年龄或立场。当前人物替换与自选入口的完成情况见工程设计。

玩家只决定自己的言语与行动。一个 GM Agent 扮演六名 NPC，决定他们的对白、反应和行动，并通过游戏工具发起操作；不另做六个 Agent，也不另设替 GM 决定 NPC 人生的日程 AI。游戏规则处理物理条件、时间、资源和实际结果，不决定人物应该爱谁、站哪一边。

NPC 自主指人物有自己的意志，不是玩家的六个托管单位。玩家可以提议分工、邀请同行和请求帮助，但没有全队任务分配面板。GM 不能代替玩家答应、移动、分配个人物品或选择立场；NPC 行为与环境仍可能对玩家造成非自愿后果，不能把“玩家自主”误解为不受他人影响。

### 自由度的限制来源

| 限制 | 应如何成立 |
| --- | --- |
| 物理条件 | 距离、地形、实际物件、身体能力、时间等条件真的不满足；解释具体缺什么。 |
| 人物意愿 | 由相关人物作决定，可以拒绝、谈条件、反悔；不是全局好感门槛。 |
| 社会约定 | 行为可以违背约定，违背后有具体后果；不把“不允许”一律变成“操作不支持”。 |
| 制作范围 | 暂不支持的实质能力如实说明，不伪装成世界里永远不可能；不能由 GM 编一句成功填补系统空缺。 |

不以保持团队完整、维持某条故事线、必须先完成公共营地或必须拉够人数作为离营、探索和建造的前提。少限制不是任何话都直接变成事实。

## 2. 生存蓝图与岛屿空间

以用户提供的坠机荒岛卡为环境蓝图：热带雨季的小型珊瑚岛，幸存者由海上事故抵岛，缺少现成工具与生活物资。保留衣、食、水、住、行、卫生的相互牵制，不照搬卡中未经核实的精确数值、医学断言或性别能力概括。

人数改变后重新核算供需。不能将十五人的缺水结论直接套给七人；也不能为了制造矛盾，临时让水源枯竭或物品消失。

### 四区不是四个按钮

| 地理区 | 空间职责 | 需要设计出的内部差异 |
| --- | --- | --- |
| 西侧沙滩 | 登岸、观察海面、接触漂来物、早期停留 | 潮水可达处、较高地面、树荫、裸露地、内陆入口，不是整区都能安全露宿。 |
| 中部灌木与矮林 | 淡水线索、植物材料、隐蔽与另建住处 | 可达路径、地面割伤风险、开口与遮挡、可操作空地；能藏身的地方未必方便取水。 |
| 东侧礁岸 | 受潮汐影响的近岸觅食 | 出入路线、落脚面、潮池、浪暴露与退路；资源可见不等于能安全取回。 |
| 南端红树林 | 泥地、根系、蚊虫条件下的资源与通行 | 可站立与陷落处、绕行边缘、潮水影响；不是提高产量后换一种地面贴图。 |

具体面积、高程、潮汐和资源点待生态与关卡设计，不把“绕岛一小时”等原卡表述当已核实数据。生产地图必须呈现空间尺度与路线代价；不能视觉上走几步，规则却无提示地算几公里。

### 路线与生活空间草案

建议把区域落实成相互连通的地形，而不是四张相邻房间。以下是制作空间时要检验的布局草案，不是唯一道路清单或预先开放给玩家的地图标记：

| 连接与空间 | 可产生的实际选择 |
| --- | --- |
| 登岸带—西岸较高地面—植被边缘 | 容易接触海面与漂来物，能转入遮蔽；从潮水影响处搬离物资应有真实距离和劳动。 |
| 植被边缘—中部取水一带 | 较直接的取水通路；穿行条件影响伤脚、负重和可见性，不要求先接受取水任务才可进入。 |
| 西岸—北侧绕行带—中部或东岸 | 提供不必总经过原营地的另一种路线；距离、暴露与地面条件应有不同，不能只是视觉分叉后立刻合并。 |
| 中部—东侧礁岸，与沿岸进出路线形成回路 | 允许从内陆接近觅食区，也能根据环境选择沿岸返回；具体潮间带通路取决于真实地形与潮位。 |
| 西岸或中部—南端红树林边缘 | 允许从边缘观察、绕行和接近资源；不把整片区域做成只能点“进入沼泽”的危险按钮。 |
| 中部路径旁与较偏离通路的可操作地面 | 提供接近取水、较隐蔽、较方便运输等不同组合，由玩家选择和改造；不能只有一个无代价最优的“私人营地槽”。 |

植被密度、可站立地面和低矮地形共同形成大大小小的生活空间。表中路径不把道路之外统一设成不可走；能否穿过由实际地形与人物条件决定。独立通路也不能保证绝对隐蔽，别人可以通过同样的世界探索。

### 空间必须同时支持生活和秘密

可行走地形、物件占地、视线与交谈范围来自同一世界，不维护一张只给 GM 编故事的地图。视觉遮挡与声音传播分开：看不见不等于听不见，站在同一区域也不等于参加同一场对话。

营地、藏物点和生活设施按位置成立，不按阵营占有整张区域。可建位置由地面、空间和施工条件判定，不只开放几个固定建营插槽。渲染可以分块加载，但加载边界不能成为世界边界或知情边界。

探索只显露实际观察或获知的内容。玩家与 NPC 都没有全岛实时定位；玩家地图不展示未发现的秘密营地、别人正在做的私事或准确库存。知道某处存在，不等于知道那里此刻发生什么。

## 3. 生活活动，而不是固定主线

玩法由处境推动：察觉需求或机会、采取行动或与人协商、承担时间和物资代价、得到结果，再据新处境作决定。这是解释行为之间的关系，不是强制执行的任务顺序。

饮水、食物、身体、遮蔽、工具、探索和共同生活可以交错。玩家可以先独处、先照顾伤者、先寻找海岸线，也可以改变主意。没有“第一天必须搭棚，第二天必须团结，第三天必定内讧”的脚本。

### 时间推进

荒岛是自由探索的地图游戏，不是等模型批准才能前进的回合游戏。游戏时间随现实时间连续流动，按固定倍率换算（初版为现实 1 秒对应游戏 6 秒，是试玩校准的参数，不是承诺）：

- 岛在玩家面前、地图未被遮挡时，世界时间持续前进：玩家、NPC 的移动与劳动、潮汐、生理与资源都在同一条时间线上同步发生。
- 离开房间、切到后台、打开背包/制作/建造/身体/日志等全屏面板、重开确认、存档异常未恢复、主聊天正在生成时，时间暂停。打开交谈区不暂停：现场交流与生活同时进行。渲染动画不决定生理结算。
- 玩家的移动、转向、停下立即生效，不调用模型，不等待任何 NPC。手机在左下角用虚拟摇杆自由行走，桌面可用方向键或 WASD；点地面则走向该点，走动中再点会改道。
- NPC 有自己的生活：没有打算的人先停在原地，由 GM 在后台为他们决定，决定到达后由游戏规则执行行走与劳动。模型思考不暂停世界，也不阻挡玩家；所以 NPC 的计划会晚于“想到”的时刻生效，世界已变导致不能成立的部分被丢弃，相关人物之后重新被询问。
- 交谈不按 token 或楼数扣时间；说话本身是即时事件，对方的回应在后台生成，到达时才进入现场。
- 时间快，人不快：时间倍率只作用于世界时钟（生理、潮汐、资源、劳动耗时），人物在屏幕上的走路速度按正常步速设定，二者是两个独立参数，游戏秒内的步幅由它们换算。因此走同样的路耗掉的游戏时间更多，体力与饮水的消耗随之上升，需要在试玩中一并校准。
- 游戏时间与现实时间的比例通过真实地图试玩校准，而非此处凭空定数值。

时间不替玩家做决定：危险、相遇与冲突以事件出现在身旁，玩家可随时停下、防护或离开。GM 的决策调度见工程设计，只在有人需要新决定或玩家说话时调用模型，不做常驻轮询。

### 行动有过程

区分提出打算、开始行动、进行中、完成、主动中止和被打断。到达与产出不能在意图提交时直接发生。

取水要有水源和承载方式；制作要有材料和加工条件；途中返回只得到已经完成的部分。长时操作可以取消或改主意，已经消耗的时间、材料和身体代价不自动退还。中间产物是否可保留由该加工过程定义，不统一判作全部成功或全部报废。

## 4. 人的身体与日常需求

身体是活动条件，不是一组无关进度条。玩家与 NPC 受同一套生存规则约束；自身需求由本人决定怎样应对，遵循第一节控制边界。

| 方面 | 必须连通的后果 | 不采用的简化 |
| --- | --- | --- |
| 饮水、进食 | 获取、携带、食用方式、身体需要与后续劳动能力 | 有食材就等于吃到，有容器就等于水安全。 |
| 睡眠与暴露 | 休息条件、遮蔽、潮湿、风雨与恢复 | 点休息就无条件满状态。 |
| 足部与其他伤病 | 行走、负重、加工、伤口照料、是否需要帮助 | 所有伤害只扣同一条生命，不改变行动。 |
| 排尿、排便 | 身体需要、地点、姿势和可达性、事后清洁、环境处理 | 合并为卫生扣分，或给所有人相同定时便意。 |
| 清洁与衣物 | 可用水、材料、穿着、晾干条件及工具材料用途 | 一句“洗好了”生成干净衣物，或湿衣立即必然致命。 |

具体疾病发生率、尿量、食水需求、热暴露与感染进程必须核实后校准。数值表达游戏尺度时注明是游戏参数，不伪装成医学结论。伤病可恶化乃至死亡，但不预定谁必须死来推动戏剧。

### 排泄必须可以实际解决

如厕是与饮水、进食并列的个人行动。地点距离、地面、遮挡、潮汐，是否能走到、能蹲起、是否需要他人帮助，都会影响选择。没有如厕设施不代表不能排泄，设施改善条件而非解锁人体功能。

身体与手部清洁、弄脏的衣物、可用材料和用水来自真实物资。排泄地点、废物处理与取水、备餐、睡觉位置构成环境后果；潮水和掩埋不能默认消除风险，也不规定几个人必然在几天内污染整岛。

需求不等于公开信息。如厕、经期或其他身体不适不自动进入全员知识，也不默认必然带来羞辱。画面不需要排泄动画，文字无需露骨；行动条件与后果不能因此被省略。

身体界面先告诉玩家自己能感到的症状和行动影响。其他人的隐私状况由观察或告知获知，不给玩家七人的实时身体管理表。自身普通生理操作的快捷方式可以优化，但不得替玩家默许移动到某处或接受他人照料。

## 5. 物件、获取与制作

### 同一件东西从头到尾是同一件

物件有实际所在处、持有或穿戴关系、数量与必要的功能条件。共同物资是放在某处且有使用约定的物品，不是所有队员随时能调用的云背包。

衣物、救生装备和回收物首先有原用途；拆改会失去哪些功能，需要按物件定义。衣着、材料与场景显示引用同一物件事实，不能衣服已经剪成绳子却还穿在身上。

物理接触条件与权利主张分开。可接触他人物品不等于被允许使用；阵营关系也不能自动授予隔空取物能力。具体偷取行为与信息后果见第六节。

### 制作围绕能力，不围绕固定科技树

| 能力方向 | 解决的限制 | 不自动获得的能力 |
| --- | --- | --- |
| 切割、刮削、敲击 | 加工原本难以处理的材料 | 有尖边不等于耐用、安全或适合所有材料。 |
| 绑扎、连接 | 组合、固定、搬运 | 任意植物条或布条不等于相同强度的绳。 |
| 收集、盛放、运输 | 留住水、携带东西 | 储水、净水、耐火是不同条件。 |
| 防护 | 降低特定地面或操作风险 | 临时包裹不等于鞋，不消除全部伤害。 |
| 捕捞与收集 | 改变食物取得方式 | 有工具不保证有收获，还受地点、时机和维护影响。 |
| 遮蔽、存放与生活设施 | 改善休息、保存、隐私和卫生 | 一个设施不统一提升全岛所有人的状态。 |

具体成品由加工方式、材料功能和用途组成；同功能材料可替代，但重量、耐久、持水或耐热等差异应保留。初版只表达会改变实际玩法的属性，不模拟无意义的材料学细节。

不是每个想法都要一个专用配方或菜单项。能由已有动作与材料能力组成的办法应能执行；产生新的物理功能则需要真实规则支持。GM 可以解释与提出办法，不能临时发明产量、成功率或无限工具。

### 第一件工具不能依赖自己

开局内容需要做材料可达性审核：

1. 先列徒手能搬、拆、撕、折或利用的真实物品。
2. 再列哪些加工能由这些条件完成，以及付出的原用途损失。
3. 由此展开切割、绑扎、承载等后续能力，而不是默认石斧开局。

可推演的起点包括利用衣物已有结构、拆取确实可拆的部件、利用实际找到的容器或边片；这些只是候选，不是承诺开局一定有理想残骸。珊瑚岛不默认有制刃石材、矿石、藤条和任意食用植物。

开局物件与当前配方集中在功能的内容定义中，耗时与产量是待长程试玩校准的游戏参数。不能一边坚持极少物资，一边靠 GM 随时捡到恰好所需的东西补洞。

## 6. 私人营地、共同生活与立场变化

### 三条关系不能合并

位置与同行是当前行动；住处与合作是生活安排；结盟与立场是社会关系。同行不自动入伙，同住不自动同意共用全部物资，改变阵营不自动搬家。

营地是实际地点及其生活设施，不是把整片区域划成独占领土的旗帜。玩家独自搭建也成立，不必凑人数或先退出某个正式组织。秘密住处是否被发现取决于实际信息途径，不靠“私有”标签获得隐身。

阵营是已形成的合作与支持关系，不是必须先创建的组织菜单。建议初版用有参与者与来源的明确约定表达加入、退出、共享、互助和反对等立场；没有约定时允许保持独立与不确定，不强行给每个人填唯一阵营。

### 立场变化要改变生活

承诺在这里共同生活、愿意参与什么劳动、是否共享某批物资、是否在争端中支持某人，都应成为后续决策能直接读到的事实，而不是只靠向量检索翻旧话。

约定成立与约定履行分开。邀请被接受可以先于搬家；说好带水不等于水已交付；承诺后来可以被违背。违约留下已经发生的经过，不倒改成从未答应。

GM 只能代表当前扮演的 NPC 表达选择，不能替玩家同意，也不能由一个 NPC 的话替未表态者签约。含糊的话保留为说法，不自动升级为全员契约。无需每次交谈填表或反复弹窗；只有实际影响物资、时间或参与者权益的歧义需要澄清。

分裂可以引发分工缺口、分配争执、互助停止或新的协作，也可以和平发生。旧营地的人各自反应，不统一敌对；不同阵营的人仍可保持私人友谊、交换物品或共同照料伤者。NPC 也能主动离群、另结关系，不是只有玩家能发起变化。

### 隐瞒、偷取与发现

对放在可接触处的物件，是否能取走由物理条件决定；是否算偷取由已知的所有与使用约定判断。门、容器封闭状态、看守或当事人的实际阻拦可以构成阻力，不能用阵营权限凭空造墙。

别人看到离开，只知道离开；发现少了容器，只知道物件不在原处。目击、转述、怀疑、指认与真实行为分开记录，不能直接把怀疑判成事实。被怀疑的人可以解释、隐瞒或撒谎；说谎不修改世界事实。

明确暴露的痕迹按世界对象与条件存在。暂未制作的痕迹种类不能由 GM 随意拿来保证发现或保证隐瞒成功；不先为每次移动存一套永久足迹系统。

## 7. 分开后仍是一座岛

各地人物的活动共享第三节的时间规则。离场不等于冻结：已开始的取水、休息或制作继续推进；需要改变打算时交给 GM 决策。不会因为玩家没看见，就补造某人瞬间做完一整天劳动的结果。

各地对同一水源、路径、容器和其他稀缺对象的竞争按实际时空处理。两处同时发起行动不能各自得到一份同样的物品，也不能由模型工具调用顺序任意决定谁早到。

人物重逢时，表现其真正经历过的变化。玩家可以先看到棚子修好了、某人不在或库存变少，再从交谈获知原因；不能自动播放自己不在场的全知回放。

临时合作不要求共同居住。营地靠近水源不等于拥有全部淡水；实际控制、接触、协商和冲突才决定别人怎样取用。

## 8. 交谈、表达与玩家行动

近处可交谈者由实际位置与感知范围派生。玩家与一个 NPC 独处时可私聊；其他人在交谈范围内时使用群聊，初版不增加同场耳语频道。“独处”不是整张地图只剩两人。

每段回复固定当段参与者与听众。有人走近、离开或打断时，先结束这一段，再建立新范围；不能用最后的名单追溯修改前面谁听到了什么。非参与者即使听到，也不被迫逐人发言。

GM 可以在一次场景回复里安排多个人说话、沉默或行动，不要求六人轮流报到。表达与工具执行的接合、跨场景调度和失败处理见工程设计。

不把每次点头、停顿和表情都做成需要领域工具批准的动作。没有改变实际处境的表达可以自由演出；一旦涉及位置、物件、身体、活动或已确认约定的变化，就需要对应的真实结果，不能只靠正文宣布发生。

玩家既可以直接操作场景，也可以明确表达自己的行动意图。聊天陈述、愿望、假设与明确的行动指令不同；“我有一把刀”不生成刀，“如果我拿走水”不立即执行拿水。

建议自然语言行动先形成对本次玩家意图的解释，再复用实际操作规则。对象、数量或重大后果含糊时请玩家确认，明确的普通动作不反复审批。GM 不能借解释意图补上玩家未决定的后续选择。

## 9. 主画面与美术要求

以超过《余火》的可行走生活场景质量为交付目标，不以四个资源节点、表单或静态背景图替代游戏。主人已授权正式制作及必要绘图；素材生成完成不等于画面通过验收。核心操作遵循第三节的自由移动规则，交谈遵循第八节的实际现场与人物控制边界。

### 现版不是默认合格的设计底稿

保留已确认的玩法、世界事实和正确的数据逻辑；现有布局、文案、控件、信息密度、交互反馈与视觉表现全部重新审视。已有代码、已经接线、测试通过或暂时没人指出问题，都不是保留某项设计的理由。现版只用于盘点功能，不作为审美基准；整改范围不止用户已经举出的例子。

每项呈现都应回答：玩家现在要做什么，这项信息或操作为什么此刻出现，完成后看到什么，失败时怎样继续。只改颜色、边框和按钮名称，不算完成重整；移除重复信息也不能顺便丢掉有用功能或真实的知情差异。

### 气质与构图

制作方向采用斜俯视、清透的半写实 3D：白沙与浅海保留明亮的热带光线，树冠、地表与物件分层，人物和设施尺度可信；营地逐渐留下湿木、晾晒、损耗和劳动痕迹。生存的艰难来自实际生活，不靠全图灰褐滤镜。镜头近处看人和物，拉远辨地形，但不因此获得远处人物与秘密营地的实时信息。现有场景与最终目标的差距仍需实景审视，不以这个方向说明代替验收。

整体气质是明亮、有生存紧张感的海岛群像冒险。地图、人物、交谈和工具使用一致的尺度、排版与视觉语言，不把通用网页聊天框贴在场景上。画面主角是玩家所处的真实空间；玩家、附近人物、可接近物件与探索方向有清楚的视线落点，辅助资料按需展开，不用七人管理表覆盖场景。

岛屿轮廓、地标、岸线、水陆交界、地面与植被层次需要整体构图。营地建设、物品放置、潮水可达处和局部遮挡应在画面上可读，不只是背后数值变化。

美术重点是生活逐渐留下的可见差异，不是特效数量。基础几何可用于内部验证，不能当最终交付；漂亮插画也不能掩盖无法行动的地图。排泄等需求不要求露骨动画。

### 交谈是与现场的人交流

- 交谈按需打开，默认收起，不因模型回应或失败自动展开。有人说话或有事待回应时提供轻提示，由玩家决定何时进入；不是要求玩家盯着聊天才能知道发生了什么。
- 正文和交谈人物是重点。手机竖屏与横屏打开交谈后占满游戏可用区域，不保留半截地图抢占阅读空间；收起交谈才回到地图。宽敞桌面可在交谈旁保留场景。隐藏的地图不继续绘制或接收输入，世界时间仍按第三节的交谈规则推进。现有弹层方向、尺寸、比例与头像栏不视为必须保留的设计。
- 在场信息有一个明确的展示位置，不在标题下列一遍全员姓名，再在下一排头像下重复列名。当前发言者仍须在自己的发言处清楚可辨；可见者与实际听众的区别按需要表达，不用重复名单掩盖语义。
- 附近的人共用同一个交谈区，不为每个人另开窗口；人多不等于必须依次发言。范围由第八节的感知事实决定，不显示未获知的关系、身体或阵营状态。
- 人物呈现、姓名、动作与对白形成阅读层次；不能只把人物图缩成一排小头像、把正文挤到剩余空间，就视为完成群像设计。正文中说话与动作的轻量视觉区分不改写内容，不增加一套强制输出格式。
- 输入区紧凑、尺度协调、发送控件对齐。按钮按玩家能理解的实际用途命名，不用“听他们说”“看看怎么做”等措辞包装一次模型调用；是否需要续轮、模式切换和确认，先审操作必要性，再决定位置，不默认保留现有控件组合。
- 上下文圈在交谈界面明确可见，反映下一次请求的输入用量，点开能看到当前用量、输入上限与构成。无法计量时如实显示，不伪造进度；接近上限的处理须与实际请求策略一致，不以隐藏调大限制代替完整体验。
- 打开交谈不改变第三节的时间规则，也不清空草稿或阅读位置。新消息不强拉正在回看的内容；玩家发送成功后能立即确认自己的内容已进入交谈。早期原文从经历入口读取。

### 工具、状态与反馈各归其位

行囊回答“我带了什么、能怎样用”；查看某处物资先满足接触或观察条件。地图回答“我知道哪些地方”，而非展示世界调试数据。工具按活动组织，低频操作按需出现，不把全部能力平铺成按钮或表单。

交谈只呈现对应现场的交流。采集、拾取、发现、身体信号、相遇、危险等反馈与对白分开；普通完成反馈轻量出现后退场，完整记录在经历里。危险、需要决定的事和错误有相应的辨识度及处理入口，不一律堆成聊天楼层或常驻提示墙。

长时操作表达正在做什么、已经发生什么、何时会停以及怎样中止；模型等待与游戏内劳动不是同一进度条。预计耗时同时写岛上时间和现实时间，玩家看得出要等多久。只在做决定时给出必要的耗时、资源损失和明确风险，不为每个界面堆说明文字。

### 交给用户之前的体验验收

验收由制作方先按第十二节的授权边界完成，用户反馈用于检验内容、玩法和真实偏好，不用于代做基础产品检查。下列要求用真实组件与实际画面验收，不以源码文字断言、构建成功、没有溢出或精修静态样稿替代；未验证项明确列出，不宣称可交付。

| 玩家旅程 | 必须达到的体验 | 未达标的代价 |
| --- | --- | --- |
| 进入与继续旅程 | 能理解身份选择与继续入口，进场先认出自己、环境和可操作方向，无需制作方口头解释。 | 无法开始或误操作存档。 |
| 探索与观察 | 移动、转向、停下的反馈直接，人物、物件与路径可辨，信息不遮住操作目标。 | 无法探索或误触。 |
| 打开并持续交谈 | 知道和谁交流、谁在说话，正文有足够空间，输入、发送、等待、上下文与收起自然连贯；覆盖空态、多人、长内容及更新中状态。 | 阅读或交流无法正常进行。 |
| 执行行动与返回 | 能理解动作对象、必要代价、实际进展和结果；取消、返回、重新打开不会丢失应保留的状态。 | 错误消耗物资、丢草稿或迷失流程。 |
| 错误与恢复 | 模型、场景或保存失败能区分，提供正确恢复入口，保留已确认进展，不用错误面板抢占整个游戏。 | 丢数据、重复付费或无法继续。 |
| 整体视觉与设备适配 | 桌面、手机竖屏与横屏都逐段走完；看人物、读正文、触控、键盘弹出收起及返回都协调，场景与界面有统一的审美和主次。 | 虽能运行但不可用、无沉浸感。 |

只加载必要的视觉区域；离场人物有领域活动，不等于全岛常驻渲染。性能边界与《余火》相同，要在仍运行酒馆的桌面和手机上检查，不以持续后台 WebGL 或模型调用制造“活着”的假象。

## 10. 持续生活、死亡与重开

玩家自行决定当下目标：满足生活需要、改善住处、探索材料、与人合作或离群生活。目标可以改变、搁置或失败，系统反馈实际结果，不通过固定天数、必做任务、阵营归属或剧情节点宣布通关。

当前交付范围不包含救援艇、登艇离岛或获救结算。人物可以希望获救、讨论求救；已有求救标记只是可建造、可观察的实物，不保证产生外部响应，也不解锁结局。人物愿望不是全局任务，GM 的描写不能替代尚不存在的外部行动规则。

玩家死亡即结束本次旅程；不能复活、战斗重试或读回本局较早节点继续，必须重开。结束后可以查看已知经过，不能继续推进世界或操纵其他幸存者。重开创建新的旅程，不继承旧局物资、秘密、约定或人物经历。

NPC 死亡不删除人物：身体在死亡位置保留，随身物件仍依附该身体，活动立即中断。尸体不是自动散落的一包战利品；搬运、搜取、安置及环境影响需要各自的实际行动规则。发现尸体不等于目击死亡，也不自动获知死因。没有目击或消息来源的人不会因全局人数变化自动知道谁死了。

## 11. 制作次序：按能否自由成立，而非按固定剧情

内部制作可以分批，交付按完整游戏判断。制作顺序不是玩家任务顺序，也不代表某个阶段完成就可以发布第一章。

| 制作顺序 | 交付内容与完成门槛 |
| --- | --- |
| 正式人物阵容 | 按[人物目录](../apps/game/island/character-catalog.json)中的 ID，保留 `ye` 已认可造型，接着完成 `lin`，再制作其余四名 NPC 与玩家外观。逐人完成独立人体与脸型、自然姿态、关节变形、衣发与穿脱、游戏内动作；参数表、灰模或换色占位不算正式人物完成。具体工序以[人物制作说明](../apps/game/island/production/characters/README.md)为准。 |
| 自由生活与 GM 行为 | 食水取得、运输、加工、存放、使用，以及衣物、排泄、清洁、休息、伤口照料都能实际执行；NPC 使用同一能力但自行决定。独居与分营不是一次演示，必须能持续生活；拒绝、竞争、私聊、离场、重逢及旧事记忆能影响后续选择。 |
| 整体场景与操作 | 四区具备实际空间差异，正式人物、物件、设施和劳动表现统一；玩家能理解如何行动、取消、转向和处理失败，不靠工程说明或七人管理表。 |
| 实际交付 | 开局自选、持续生活与分营、长期交谈、保存重进、死亡与重开在真实酒馆中成立；真实 GM、长期记忆、桌面与手机体验按授权完成确认。构建成功或模型接口接通不等于通过。 |

当前完成程度由工程设计与人物制作说明记录，不在此另建一份进度事实。当前优先完成第九节的完整体验重整与验收，再推进上表中尚缺的内容；不以增加无关系统替代尚未完成的基本体验。

玩家旅程从选择自己的身份开始，进入可观察和操作的生活空间，自行决定去哪里、做什么、与谁交谈。实际行动给出消耗、进展、结果或具体阻力；未执行成功就不宣布完成，保存或模型失败保留已确认的进展并提供对应恢复入口。退出后可以接着本局生活；死亡后的处理见第十节。

入口使用统一海岸插画，横竖屏采用各自构图。创建身份在同一页完成姓名、性别、成年外观和可选的阅历、特长简介；仅替换已有旅程时确认不可逆后果。简介属于本局玩家身份，随存档创建和删除，由 GM 与行动意图解释器读取；不新增独立档案或缓存。NPC 的公开观察不包含这段简介，仍需通过交流和观察了解玩家。简介不直接授予物资或绕过行动条件。

场景、交谈、工具与状态反馈的呈现标准统一见第九节；此处不另固定某一版面板布局或复制一套交互要求。

[自由玩法验收](island-game-scenarios.md)是能力检查集，不是新手任务、主线或 NPC 计划，也不是执行测试的授权；具体授权边界见下一节。

## 12. 自主推进与授权边界

主人已要求按完整可交付目标持续制作，不在每个切片结束后停工。当前边界如下：

| 决定 | 何时必须确认 | 当前处理 |
| --- | --- | --- |
| 场景、镜头与临时人物呈现 | 随正式制作与实景验收推进 | 按第九节方向制作，人物底稿可替换。不能把几何占位或精修封面作为游戏画面交付。 |
| 当前项目所需绘图 | 主人已明确授权 | 沿指定第三方服务生成必要素材，保留收据；失败不自动重买，已成功素材不重复购买。 |
| 本地浏览器体验验收 | 主人已明确授权 | 使用真实组件和本地内存数据检查桌面、手机竖屏与横屏的完整操作；可以补足本地验收夹具，不调用付费模型、不读写真实存档。类型检查、lint 与生产构建继续执行；其他测试操作仍需对应授权。 |
| 付费 GM / Embedding 质量测评、外部发布 | 对应操作前另取授权 | 美术授权不扩展为收费测评或推送发布；离线模型夹具不能证明真实群像与召回质量。 |

时间随现实时间连续流动，规则见第三节；游戏与现实的时间比例真实试玩后可以据体验调整，不靠新增开关同时维护两套时间规则。精确资源、材料与医学参数属于需要查证和测试的制作工作，不把它们当作用户必须凭空回答的问题。

临时人物可直接制作，之后集中替换内容定义，不把性格、姓名或职业写进控制权、死亡与行动判定。死亡政策已经确定，见第十节。
