## 初审（2026-09-27）

- 旧三关开场即可凑齐三组，后两关主要加数量；旧测试只证明可解，没有验证暂存决策。替换关卡，不用文案补救。
- OS 已有 additionalPartitions/storeFor/filesFor；Moving 自有分区可与钱包同文档事务提交，不需改三款赌局事件。
- 收费局不能继续只存在 Vue 内：Host 执行保存、UI 呈现确认结果；不用 localStorage 保钱包。
- 先测完整解空间最低暂存压力，再选第一章及高难阈值；艺术场景必须表现真实依赖，不能隐藏限制。
- 生成合格后收费；保存不明复核同一个提交。意外退出与主动放弃分开。
- 工作区另有绘图、地图、管理员、摘要等改动，避开；最终构建自然包含现有源代码，不回滚他人产物。
- 初审允许施工；生成性能、经济恢复和视觉必须实测后给结论。

## 批次

1. 新依赖模型、求解器、五关、随机高难筛选；实验可解性/下界/随机分布，排除轻松绕法。
2. 独立分区、校验、命令、原子结算；真实协调器测重复、失败、未知提交、恢复、首通、报名、胜败、放弃。
3. Host/bridge 身份与版本控制、保存确认、跨关闭恢复；不使用模拟本地钱包代替实际服务。
4. 两套奶色房间、空间依赖和待打包架；移除旧第三房和局部临时会话。
5. 浏览器实际五关/付费局、核对净收益与恢复；窄屏/横屏/字体放大/输入/WebGL/旧游戏；全量检查和构建。
6. 终审目标逐项证据，替换旧验收报告，不提前宣称完成。

## 第二章三档递进施工

已确认方向：累计通关升档、失败不降档、最高档无限随机；不加收益限制。所有者仍是 Moving；参数在 policy，通关事实只认既有财务收据，展示和出题派生。没有新增持久化实体、依赖、注册入口或历史兼容分支，删除边界不变。

实施顺序：三档互斥分类与生成效率实验 → 收据派生档位/存档校验/Host 生成 → 简明档位与进度 UI → 升档、败退不降档、重载及未确认终局测试 → 实际浏览器跨两次升档和最高档再开局 → 构建/lint/全量检查与终审。现已完成；当前检查数量、性能样本、浏览器账本与已知无关失败统一维护于[验收报告](./moving-game-verification.md)，不在此重复抄录。

终审：第一章关卡与奖励不变，第二章难度参数集中定义；旧单档 API 已替换，不留兼容默认档。Host 根据确认收据决定目标档，分区解析按本局入场成绩复验；本局档位与下局档位明确分开。所有失败/恢复路径不增加胜场或重复发奖；最高档不承诺无限变难或杜绝高手获利。界面只增加档位、升档进度和付费结果下一档提示，短窗口的新增结果样式限于第二章。没有提交、推送或用户钱包操作。
