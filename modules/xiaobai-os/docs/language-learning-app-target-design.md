# 普通小白 OS「语伴」APP：产品设计

## 1. 文档性质

本文是「学习工作台 + 学习搭子」的产品事实来源，定义训练、布局、性能、提示词归属与体验要求。[实现架构](./language-learning-app-architecture.md)记录现行职责、接缝和验证边界，不另写一套产品流程；共享资金归属、升级与结算规则引用 [Economy 平台设计](./economy-platform-target-design.md)。

实现围绕直接学习的工作台与独立交流的语伴组织，数据安全、发布确认、故事隔离及奖励边界继续保留。产品要求、代码实现、浏览器交互与真实模型质量是不同层面的证据；完成前必须按 §12 分别验证，不能仅凭文档或测试数量宣称体验达标。

名称为「语伴」，完整名称「小白语伴」，桌面名称「语伴」，内部 APP / 领域 ID 为 `learning`。本文不保存模型 Prompt 正文，也不把产品说明变成界面上的常驻介绍。

训练主线为基于文章的阅读与写作。听说设计见 §11，录音、转写、音频评估尚未接入；不把未接入能力摆成假按钮，不以设计要求宣称已有对应能力。

## 2. 产品定位

**一处可直接操作的学习工作台，加上一位以角色身份陪在身边的学习搭子。**

工作台是小白X学习助手的人格与教学空间，承载材料、教学讨论、写作、批改、修改和复习；搭子是用户选择的角色，承载陪读、答疑和自由聊天。用户掌握学习节奏，不必通过聊天指挥 AI 逐个拿出功能。两者共享当前学习事实，不共享整段对话、摘要或人格记忆；不增加第三个代理，也不让两个 AI 互相聊天。聊天本身不自动变成作答、目标变更或结课。有材料时一起学，没有材料时也能聊。

用户应感受到的三件事，是取舍时的最终标准：

1. **简约、美观、有科技感，让人想上手摸一摸。** 双主视觉（左工作台、右语伴）和它们之间的切换本身就是体验；少说明、少设置，动作就在内容旁边。
2. **科学、有内涵，让人相信在这里能学好。** 批改有依据，复习按 SM-2 排程且看得见，进步来自真实作答而不是装饰数字。
3. **有持续的动力。** 该给的奖励就给，不扣、不责备、不制造欠账；语伴以角色身份带来陪伴和趣味，而不只是一台批改机器。

- 教的是现实用户，不是玩家 persona。角色设定中的语言能力、年龄、学历不作为用户学习水平。
- 角色性格、共同经历和当前故事总结只影响搭子的表达与互动亲近感；不是课程主轴，更不是语言知识的权威依据。
- 学习目标先决定训练什么，再选择材料。BBC 等真实内容、考试相关资料、生活主题均可；直接在工作台备课不因选了搭子就成为角色私有材料。使用搭子故事背景的委托及其他剧情限定教材保留来源范围。
- 教室独立于主剧情：不写私人信息楼层，不注入 D1/D4，不改变关系、时间、任务或地图，不把上课当作剧情接受轮。
- 人设影响表达而不牺牲教学正确性。古代角色也可担任现代语言老师，不必编造故事内留学经历；不以羞辱、情感施压或故意教错维持人设。
- 不承诺保过、官方评级或仅靠文字训练就能掌握听说。教学有效性需要真实学习反馈验证。

## 3. 终态所有权与依赖

```text
modules/xiaobai-os/
├─ domains/learning/       学习档案、学习项、作答证据与完成规则
└─ apps/learning/          课程组织、资料获取、工具、专属存储适配及 UI
```

这是职责边界，具体接缝见实现架构。学习业务不进入 Messages、Fourth Wall 或 OS Kernel，也不复用语义不同的通讯记录。

- **学习 APP**拥有学习数据、教学交互、内容来源标注、评估与学习奖励资格。
- **agent-core / Agent Capability**继续拥有共享配置和 Provider。联网渠道及 Key 沿用共享配置，不在学习档案里复制；用户级学习数据也不塞进 API 设置仓库。
- **TTS 模块**继续拥有合成、音色解析、供应商设置及可丢弃的合成缓存。学习 APP 拥有本课的播放控制、录音交互和教学用途，不复制 TTS API 或占用主聊天的播放队列。
- **宿主上下文能力**提供当前角色、世界书与总结的只读资料。选择老师可参考信息 APP 的已知人物入口，但不创建通讯联系人或号码。
- **Economy**拥有小白币与流水，账户及存储范围见 Economy 平台设计；学习 APP 只通过窄能力申请自己的奖励，不直接改余额。
- 通过现有 Host/Shell APP catalog 注册；这是用户主动上课的 APP，不加入剧情自动维护队列。未交付前不注册占位图标。

学习 APP 持有自有用户文件的读写适配，存储与恢复入口见实现架构 §3，不由聊天 sidecar 保存学习档案。“用户级”不等同于跨设备同步，具体能力需实测。

当前实现采用 Host 会话内已确认版本：首次加载、明确重新加载和未知保存恢复才读取用户文件；正常保存以服务端成功响应确认，重开课堂不对账。保留本页串行、过期动作检查及奖励幂等，不额外维护多设备/标签页同时编辑。

### 3.1 业务概念

| 概念 | 持有的事实 | 不能混成什么 |
| --- | --- | --- |
| 学习档案 | 各语言目标、用户偏好与有依据的分项能力 | 单一聊天摘要或一条总等级 |
| 教材 | 已取得的文本/音频内容、出处、节选关系；有则保留对应文稿 | 一张卡片上的渲染字符串，或把音频 URL 当完整教材 |
| 课程与练习 | 本次目标、引用哪份材料、呈现方式、要求怎样作答、考察什么 | 每个题型一套 App，或把“听力”直接等同于“录音回答” |
| 作答尝试 | 真实选择、排序、文字或录音，以及当时看过/听过的帮助 | 被识别文字覆盖的录音，或 AI 猜测的用户表现 |
| 评估 | 对哪次尝试、哪个能力作出什么判断，依据与可改进之处 | 用户原答，或没有音频依据的发音分数 |
| 学习项 | 具体表达、用法或知识点及相关证据，供后续复习 | 独立复制的错题库、掌握库与单词库 |

**训练目标、材料形态、回答方式、评估依据分别表达。** 例如听一段话后点选答案仍是听力训练；对照文章朗读不是独立口语表达；听写的键盘输入也不是一堂阅读课。加入录音只增加一种真实作答载体，不需要另建“语音学习进度”。

这张表固定语义边界，不要求每行各建一张表或服务。实现只为实际启用的形态建立明确类型，不预埋视频、直播、任意组件协议或无用途空字段。

### 3.2 AI、程序与外部能力的分工

AI 负责选材、整理、出题、解释、语义评估、复核和自然陪伴，自行组织一次完整请求中的工具使用；程序拥有真实提交、引用校验、保存、SM-2 排程、视图生命周期及既定奖励结算。可见阶段描述已发生的学习事实，不是工具通行条件。外部服务负责检索、合成，以及接入后确实支持的识别能力。AI 产出内容不等于流程已经完成，切换界面也不等于重新开课。

训练操作从工作台直接进入应用服务；工作台教学对话和搭子聊天是两个独立会话。两边引用同一份课程、原答和反馈，不各存一份进度。学习搭子能帮助理解，但不持续主持课堂、催促或擅自推进训练；正式训练的阶段与完成条件见 §6，陪读权限见 §8.3。已有原生题型和媒体仍归学习功能，不借 Messages 或 Fourth Wall 实现一套聊天资产。

课件允许渐进完善：未使用内容可修改或删除，已有作答、听取或笔记证据的题和材料保留原貌，另加更正或铺垫。同一读写课可补选定段落讲解、加题和增加写作练习，不把一次加题当换课。替换未完成课件时，在工具内等待用户确认；接受或拒绝都回到原任务继续，不要求用户再发一条请求。已确认奖励不随调整改价，也不凭对话制造学习成绩。帮助条件见 §6.2。

两个主体复用同一调用底座与模型配置，不增加第三层代理、额外评分模型或不同供应商要求。工作台各类请求拥有同一套学习工具，入口用途只定位资料与意图；工具成功或连续读取不强制结束任务。搭子通过 LearningRequest 自己写自然语言任务、必要背景和预期结果，发出即返回，不被工作台绑住；LearningTaskGet 可查任务。工作台结束后自动激活搭子回复，即使用户正在看工作台、没有开启陪读；搭子正忙则等当前回复结束后送达，不要求用户再说一句。结果进入正常聊天历史，通知失败可单独重试，不重跑教学工作。主动陪读保持只读。工具只开放学习自有能力，不获得改钱、改主剧情、写作者世界书或执行页面代码的权限。Prompt、工具与资料的唯一归属见 §14。

请求中的课程资料与用户原答取自已确认学习事实，概览由它们派生，不另存“掌握结论”。当前材料完整性、不同用途的资料范围和上下文预算统一见 §14.2；翻页、视图卸载与模型历史整理不能悄悄改变这些边界。

人物身份与学习事实分开，稳定前缀与动态资料的装配规则见 §14.2。角色设定影响表达与关系，不决定用户能力、评分标准或允许写入的范围。

每个主体保存自己的已完成交流和摘要，重开后接续。较早交流可整理为摘要，只有完整、确实缩短且仍对应原前缀的摘要才能替换原记录；失败保留原对话。当前工具链只在运行内保留协议数据，当前教材与真实原答每次从唯一学习事实来源提供，不复制进长期记忆。存储归属及删除见 §4.2。

### 3.3 统一终态：生成、发布、确认是三个不同事实

| 边界 | 唯一所有者与规则 |
| --- | --- |
| 接口生成了什么、是否正常结束 | Agent Core 依据真实供应商协议判定；收到文字、SDK 返回快照或连接结束都不能单独证明成功。Learning 不另写供应商兼容判断 |
| 哪些内容已向学生发布 | Learning 应用流程统一决定交流与学习内容的发布；工作台、语伴/头像预览、历史、摘要、笔记及朗读消费同一含义的已发布内容，不各自补判 |
| 哪些学习事实已确认 | Learning 仓库确认课程、作答、帮助、评估与完成；修改工具返回对应保存回执，只有确认结果才成立，资金事实仍只认 Economy |

这不是三份需要同步的日志：原始消息可保留一份并派生各用途投影，发布资格和保存关联只在运行内；学习事实和两边的会话记录各有自己的所有者，见 §4.2。Host 管停止、课堂身份和恢复入口，UI 只呈现确认结果与安全进度，不负责猜测答案是否泄露。

普通交流不要求模型先调用工具或申报帮助范围。完整交流在本轮结束后保存到所属会话；会话保存失败保留已显示回复并提示核实，不重新调用模型。各修改工具独立保存，已确认学习内容立即可用，后续模型失败不撤销此前结果；依赖这些变更的工作台正文仍需正常结束并确认保存后发布。工具名、阶段、数量等安全进度可以实时显示；原始参数、结果、推理及未发布正文不是学生可展开查看的调试内容。

停止阻止之后的执行和新发布，已发布交流、已确认学习事实不回滚；已经发出的写入只能核实，不能靠取消假装撤销。仅因保存未确认而等待的内容，须在同一课堂仍保留原关联、核实到精确原提交后，按明确恢复操作接回；停止作废、课件替换失效或切换课堂的文字不能复活。不重新生成或重执行工具来“恢复”一次保存。

## 4. 长期资产、临时状态与删除

### 4.1 学习跟人走，故事不串卡

同一用户按目标语言分别积累学习资产，换语言是切换档案而不是覆盖。切卡、换老师、创建故事分支或删除聊天，不清空已学语言；分支也不复制出另一套学习进度。

学习记录引用的语言知识可以共用，但角色资料、共同记忆和师生闲聊不跨卡提供给新老师。由剧情生成的练习保留来源边界：新卡只沿用不含故事细节的学习结论，必要时换题，不把旧故事原文带入新请求。用户自己查看旧学习记录不等于授权把旧故事交给另一个角色。

复习题组继承所用学习项及可读证据的访问范围；只要使用了故事限定内容，生成的题目也留在该故事。更换文章不清空两边的聊天或摘要，原文章退场后，相关交流仍保留原来的访问限制。

使用私有背景修改已有公开课件，不拒绝这次修改，而是把课件留在当前故事。用户可在课件旁选择“跨故事使用”，确认将当前课件、参考答案、讲解和笔记用于自己的其他故事；原有作答、评估和两边聊天不因此公开。确认期间课件版本改变，需要重新确认；之后再次加入私有资料，课件重新限定到对应故事。已有学习进度与奖励归属不随课件范围变化而改写。

共享课件上的作答和反馈仍各自保留范围。当前故事只以可用的作答、反馈及修订链继续训练；重交只替换自己可用的未批改草稿，不清理另一故事的原答。阶段、统一批改与结课使用同一范围，不拼接不同故事的私有答案。跳过修订针对选中的那份作答，新原答或后续修订仍按自己的反馈判断；结课奖励仍按课程只发一次。

“用户级”指当前宿主用户的持久空间，不是所有宿主账号共享，也不代表向其他用户公开。

### 4.2 最少必要持久事实

| 内容与所有者 | 为什么需要保存 | 生命周期与删除 |
| --- | --- | --- |
| Learning：工作台按语言的教学对话；搭子按稳定会话 ID 的私聊及各自摘要 | 重开后延续各自的交流，不用课程成绩冒充人格记忆 | 工作台使用 Learning 用户分区，搭子使用现有聊天分区；姓名用于展示和查找，不作为持久身份。清空某边对话同步清理其摘要，不删作文；删除学习资料清理相关引用。过程轨迹与在途状态不保存 |
| Learning：各语言目标、自评、有依据的能力判断与教学/媒体偏好 | 重开后继续按用户目标教学；不能每次重新认识学生或重新选讲解语言、练习音色 | 用户可修改目标与偏好、删除某语言档案或清空学习数据；切卡不删除 |
| Learning：学习项及必要的题目、作答、帮助使用情况、反馈与来源 | 支持针对性复习、解释判断依据，避免把看过当作学会；语法本、生词本是其中语法与词汇知识点的视图 | 保存有复习价值的证据，不无限归档每条闲聊；用户可移除学习项及其自有记录 |
| Learning：语法与生词项的 SM-2 必要排程状态、最近有效复习依据，以及进行中的复习题组 | 重启后必须继续同一复习安排，有限代表证据不能伪装成完整排程历史 | 随知识点保存；题组独立于当前课程，中断后继续同组。删知识点/语言/全部学习数据一并删除。评改未确认不更新排程；重试同次作答不重复推进 |
| Learning：当前课程、实际使用的教材及逐段讲解、题目、初稿/修订（可跳过）/评估/范文及其对应关系、开课确定的奖励 | 重新打开后继续同一训练，原答和修订不可重建；不能因网页变化或重开而换题、重新批改 | 结课后保留当前训练供追问；换课前可导出，之后保留必要学习证据与完成凭据，释放其余课件；放弃课程不清空既有水平 |
| Learning：已提交的录音、必要原始音频及其资源引用（相应能力上线时） | 原始作答不可重建；回听、复核及恢复同一道音频练习需要实际声音 | 与课程/尝试绑定，删除时清理自有附件；不复制到主聊天媒体库，生命周期见 §11.5 |
| Learning：完成事实、结课小结与本次奖励依据、归属、额度 | 重开后可看收获、确认是否完成、恢复同一次领奖，不重复发币 | 随相应学习记录保留；删除不撤销既有收入，也不据缺失记录重新补发历史奖励 |
| Economy：已到账奖励流水 | 幂等结算的唯一资金事实 | 归属、分支与删除规则见 Economy 平台设计；删除学习数据不删账本 |

不保存角色卡和世界书全文副本、网页搜索结果全集、API Key 副本、模型思考、完整请求日志或每个教学判断的历史版本。材料只保留实际使用且允许保存的必要内容与出处，不建设网页镜像库。

请求、候选评估、流式文本、选区、布局焦点、展开/滚动和未提交输入属于当前学习会话的运行内状态，不由可卸载的重视图独占。左右切换保留现场；整页关闭/刷新前提示未提交内容可能丢失，不承诺草稿已进入档案。主动陪读计时、动画进度和待切换目标不持久化；已保存的课程与原答不是后台任务快照。视图与会话的区别见 §8.6。

切换语言前，若有未提交输入，先让用户选择继续编辑或放弃并切换；取消不能改变当前语言或输入。只更换语伴时保留同一语言的练习与作答草稿，仅对将清空的未发送聊天确认。

录音中的音频块、麦克风句柄、对象 URL、播放器位置、波形、合成在途请求同样是临时态。用户确认提交后，录音才作为作答资产保存；合成缓存仍归 TTS，缓存丢失不等于学习记录丢失。

保存失败不发布新水平；结果未确认时核实同一次保存，不让模型重新评估覆盖。用户移除学习项后，不在隐藏摘要里继续保留该项错题与熟练度判断。清空学习数据须确认范围；功能退场时清理学习自有用户数据并删除注册和目录，保留共享 API 配置及已确认的 Economy 流水。

明确清空对话后，本地不再用旧交流继续生成或保存；保存回执未知时提示核实，不能把未确认当作已保存。核实成功同时完成该会话的界面恢复，之后的新交流不得把已清空内容写回；采用服务器版则恢复实际保存的记录。

## 5. 开始训练前的设置

第一次进入选择学习语言；搭子可选，可以先自己学：

1. **语言**：本次目标语言；切语言切换档案，不覆盖另一语言的资产。
2. **语伴（可跳过）**：从当前故事的已知人物名单里点一位，或先直接进入学习设置。

语伴名单与信息 APP 联系人同一来源：只取故事记忆整理出的已知人物，按姓名与别名排除玩家本人；角色卡标题、群聊成员卡名不当作人物姓名，所以不能默认“当前角色”。名单里没有想要的人，可填姓名和一句身份说明。名单为空（常见于故事记忆尚未整理出人物的新聊天）时说明原因并直接给出填写入口，不让用户卡在这一步。语伴按聊天记住，同一聊天不再询问；换卡需重新选择。关系与共同记忆只取当前故事的真实资料，不虚构亲密关系。语伴身份与 TTS 音色分开，换语伴不清空学习资产。

选择语言后，用一页轻量目标确认展示考试、当前水平和目标水平，再开始训练；允许保留“不备考／不确定”等默认值，不要求先做分级测试。讲解语言和兴趣收在可展开的次级设置中。确认须等到实际保存成功才离开，保存失败保留输入并可原处恢复；已有语言档案不因开始下一篇反复建档。首页明确标出学习设置入口，不能只用语言名称暗示其中还藏着考试和水平。

各项设置的默认值如下，之后随时可改：

| 设置 | 默认 |
| --- | --- |
| 考试 | 不备考；可选雅思、托福、DSH 等，考试体系不混成一个通用等级 |
| 当前水平 | “不确定”，由第一篇短材料的真实作答判断；AI 的能力判断与用户自评分开保存 |
| 目标水平 | 比当前高一级；备考时按相应体系表达 |
| 讲解语言 | 中文；与目标语言分开 |
| 题材兴趣 | 不限，边用边调；用户在对话中明确说“想看体育新闻”也可更新 |

不因一道错题擅自降低用户目标，也不强制先做完整分级测试。语言按实际能力呈现，不凭一个下拉框承诺所有考试、发音或语言教学均已验证。没有阅读材料时可直接和语伴聊天。设置由用户在界面明确保存，不以模型是否回复作为保存成功依据。

“更换语言和语伴”从语言选择开始，不落在上次残留的目标设置步骤。保存语伴的结果不明时，就地提供核实与采用已保存设置的入口；核实不重新写入，也不调用模型。核实前不接受新的聊天输入，避免恢复后清空用户刚写的话。

## 6. 读写训练与学习判断

### 6.1 围绕一篇文章完成输入与输出

主流程：

**训练设置 → 网络取材与适配 → 逐段阅读、讲解与总结 → 全文作文 → 评分与纠错 → 用户修订（可跳过） → AI 复核与范文 → 语法本/生词本复习。**

这是推荐路径，不是强制状态机，也不依赖语伴聊天主持。用户可以提前批改、只改几句、继续修订、索取范例、加题或调整训练范围；系统不要求用户猜下一步要发哪条指令。未写内容仍显示未写，缩小目标后的结课须引用真实练习及有效反馈，不能把缺口伪装成已完成。

**取材与适配**

AI 从网络选取一篇真实新闻或文章，BBC 是来源示例；根据当前水平、考试和目标整理成稍高于当前水平的训练材料。适配的是内容难度与教学支架，不是一律把词换难；较低水平可使用明确标注的改写或节选，保留原文出处。难度不等于篇幅，题材与目标的关系要说得清楚。获取和来源边界见 §7。

**先能学，再补齐**

- 点“开始读写”先检查取材配置，再启动一次完整任务。模型自行组织正文、讲解和作文题，优先让用户拿到可读内容；正文应有主旨、细节与连贯段落，足够支撑本次总结和讨论。篇幅由教学目标和用户水平决定，不设机械最低词数。
- 正文确认保存就进入阅读。段末总结框由程序随段落建立，不等模型逐题生成；用户可立即读、写、提交总结和聊天。
- 模型可按需要补任意段落的讲解、增加作文题或专项练习，不按固定批次或阅读顺序解锁。展开已有内容不发模型请求。
- 每个有效修改独立保存，不等最后一句“准备好了”才发布，也不因为某个工具成功就结束整项任务。过程卡展示真实工具动态，可暂停。
- 追加内容不锁住文章和输入，已有学习证据不被覆盖。缺失内容在对应位置显示；讲解失败不阻断模型尝试其他工作，保存状态不确定时则先核实原提交。
- 暂停、失败或重开后，已保存内容仍可使用。用户选择继续准备时只补缺失部分，不重新选文章、不重做成功阶段；返回课程本身不自动调用模型。
- 已提交部分随时可批改，不以讲解、作文题和全部原答齐全作为门槛；未写、待评和已评分别呈现。

**每段的组成**

1. 阅读正文，保留连续文章的结构。
2. 默认折叠的本段知识：需要认识的生词、短语和适合写作迁移的句式、语法规则、句间衔接与连贯性。展开仅查看已生成内容，不每点一次调用模型。
3. 段末绿色写作区域：用户用自己的语言总结本段大意，提交后由 AI 审阅。总结考察理解与表达，不要求逐句翻译或复刻参考句。

段落审阅与全文批改是不同侧重：前者通常回应本段主旨，后者集中评价已提交内容并给出语言纠错。用户可以要求提前深入批改或看范例；提供的帮助照实记录，不把看过反馈或范文后的表现算作首次独立水平，也不把老师示范保存为用户原答。

当前会话中，段落审阅留在对应已提交总结下，不被聊天、下一段提交或重挂载顶掉。重写后只显示新原答对应的审阅，不把旧点评套在新稿上。正式批改和修订反馈来自已保存记录；已完成段落审阅随工作台对话保存，并保持对应原答的关联；保存失败明确提示，不能把点评移到另一份答案。

**文末作文**

基于全文生成一道作文题，可是读后感、对某观点的看法、是否赞同及理由，或处于某情境会如何行动。题目与材料有实际关联，并允许用户表达不同立场。

用户最初提出的篇幅为约 **300 字**；界面必须按目标语言明确显示计量单位。中文按字，英语等相应写作按词；备考题若使用考试自身篇幅要求，在开始前明示，不默默把“字”和“词”互换。篇幅是训练要求，不是评分算法。

用户可统一提交整份训练批改，也可先批改已经写好的部分。缺项保持真实状态，不用空答案补齐，更不能把未审填成普通成绩。已评初稿与修订保留对应关系；继续编辑的是新稿，不让在途评估错配到被改写的文本。

### 6.2 错题库与掌握库是学习记录的不同视图

使用同一份学习项与证据，不在两套库之间复制、搬运事实。界面暂称「学习记录」，提供待加强、待复习、已能独立使用等阅读视角，不做永久“毕业”承诺。

作答原文、提交和是否使用帮助由 APP 根据实际操作记录；AI 通过工具给出有对应证据的教学判断，不能自行补写用户答案、练习次数或“已独立完成”的事实。

自由答疑不需要模型为每句话申报。程序记录用户实际打开的提示、答案、文稿、已公开同题反馈等帮助；引用文章问意思不创建作答、成绩或学习项。程序不能证明任意自由讲解绝无暗示，“已能独立使用”仍是基于真实尝试与可观察条件的教学判断，不是无帮助考试认证。真实模型的自然度、准确度与提前泄题另行评审，不以结构校验代替。

显式文稿、参考答案和正式提示先保存对应条件，再允许展示；保存失败不揭示。保存与人的实际阅读无法原子发生：若保存后、展示前停止，已确认帮助仍保留，不能承诺等于用户确实看完。相同保留内容的已确认曝光不因一轮里临时改成别篇再改回而消失；只随对应课程/保留证据存续，不建立全网阅读档案。

- 标记“不懂”表达学习需求，不等于答错；看了解释也不直接计为掌握。
- 选择题答对只能说明本次识别正确，不自动证明写得出或说得出。
- 不同日、不同情境的独立理解题可支持阅读/听力理解，不要求为了证明理解额外写作。词汇/语法的独立运用仍需产出证据；听力有慢放、重听、文稿帮助时记录为辅助练习，不算独立听力成功。
- 得到提示、看过答案或同题反馈后再答对，与首次独立完成区分记录；不反过来改变第一次作答时的条件。
- 在隔开的练习中换情境独立用对，是更强的掌握证据。复习安排依据真实作答和间隔，不按离开天数机械降级。
- 同一表达的识别和主动使用可以表现不同；不把一个等级或单一进度条当全部能力。
- 只沉淀有教学价值的学习项，不把每个词、每次点击全部自动收藏。用户主动收藏的内容也可独立移除。

自由表达的反馈区分语义错误、语法错误、正确但不够自然、同样正确的其他表达。参考答案只是示例；不能把措辞不同全部打成错题。对有争议的判断，用户可点「有疑问」请老师复核；未确定的问题不继续作为确定错题传播，也不因此扣分或扣币。

语法本与生词本复习从工作台或各自本子直接进入，安排见 §6.6；语伴也可自然提醒值得练的知识点，不把到期项呈现为欠账。停学后用轻量尝试接上，不断签、不责备、不制造情感债务。

模型按用途获得当前时间、到期数量及可分页的学习项。复习排程由程序确定，AI 负责围绕选中的知识点出题和评改，不任意重写到期日期。新增学习项不会让早先到期项静默消失。

### 6.3 有学习方向，不是每天随机搜文章

老师围绕用户目标形成当前阶段的少量重点，例如听懂日常叙述、找出文章论据、写清事件先后。用户能看懂“为什么今天练这个”，也能选择专项或换题材；不预先生成几十节不可调整的长期课表。

每次安排兼顾值得回顾的旧内容和一个适合推进的新目标，比例随表现与可用时间调整，不固定每日单词数或强求每课都有新知识。短时间重复同一道题是练习，不包装成新的独立掌握证据。对已能独立完成的内容自然提高难度或换情境，避免永远做简单题赚币。

阅读理解、听觉理解、书面表达、口头表达分别积累证据；词汇、语法等知识点可跨这些能力复用。没有测到的能力保持未知，不由阅读等级推算听说等级。报考目标对应的能力要求与题型应有来源，正式测评与日常辅导分开，AI 不凭几次练习承诺考试分数。

### 6.4 反馈可复核，不用单一分数糊住差异

客观题可按已确认的答案规则本地核对，开放答案由模型解释判断；模棱两可的选项、缺信息的题目是教材问题，不计成用户错误。评估应与发布的题目、材料及本次作答一致，不能为迁就结果事后悄悄换题或改答案。

内容理解与表达形式分别反馈：意思对但语法有问题，不全盘否定；听写中的拼写与没有听懂区别说明；语音识别不确定时不能直接建立发音错题。复核有误就修正相应评估与学习判断，不保留互相矛盾的两套结论；保留原始作答，不建设无限版本档案。

### 6.5 按已提交内容批改，就地修订可分批、可跳过

统一评价覆盖逐段总结和文末作文，各自关联实际提交版本；全文作文按用户自己的段落定位问题，不混淆文章段落、总结段落与作文段落。显示每项待评/已评，缺失反馈不能由总分掩盖。

第一轮完整反馈包含：

| 类别 | 用户看到的内容 |
| --- | --- |
| 内容与任务完成 | 总结是否准确、观点是否回应题目、理由与组织是否清楚 |
| 语法错误 | 原句位置、具体错误、为什么错、涉及的语法规则与修正建议 |
| 词汇错误 | 不合适的词义、搭配或语域，以及合适的替代和原因 |
| 衔接与连贯性 | 指代、逻辑连接、句间/段间推进的问题及更顺畅的写法 |

按段点列反馈，真正错误、正确但可优化、同样正确的其他写法分别标识。不能用高级词数量或篇幅直接打分，也不因为用户观点不同就判错。备考评分参照对应考试维度并标明是练习估评；无考试目标时按已展示的训练维度给评价，不伪造官方等级或把不同量尺合成不明总分。

修订不要求重写全文：每条反馈旁边就地改对应的句子，改几句算几句，可分批提交，也可在复核后继续改。AI 说明改对了什么、还剩什么，不强迫反复修改。用户也可以选“不改了，直接看范文”，跳过不扣奖励。原始作答和各份有效修订保留关联，不覆盖其反馈依据；看过反馈后的改善与独立表现分开。

通常在复核后提供优秀示范作文，目标是比用户目标等级高一级，同时保持可学习性、回应同一道题。不同等级体系不能机械加一；已到体系最高级时提供该级高质量范文，不虚构等级。用户明确想先看范例时也可以提供，之后的作文照实记录范文帮助；范文不是用户掌握证据。

默认完整路径由已评初稿、已复核或跳过的修订及已保存范文派生完成；用户缩小学习目标时，老师也可通过 LearningComplete 引用真实作答和有效反馈结束本课。两者共用一次完成事实与奖励，不以 HTTP 成功、一段鼓励或模型口头“结课”代替。未做内容仍保留真实状态。保存/模型失败只恢复相应操作，原答、已确认反馈和有效修订不重买、不重做。

### 6.6 语法本、生词本与 SM-2 复习

间隔复习是用户相信“在这里真能学会”的基础，它必须让用户看得见、跟得上，而不只是后台一个日期。

**入本**

- 批改中的语法错误通过绿色关联标记进入语法本：能从原句看到相关规则，也能从规则回看例证。标记是关联入口，不是在文章旁再建一套独立错题库。
- 批改中的词汇错误（词义、搭配、语域）进入生词本；逐段知识里的生词和短语由用户点“收藏”加入，不自动收录每个词。
- 同一语言中语义相同的知识点只有一条学习项，多次错误或成功作为它的证据；不能仅凭标签文字相同就合并不同规则，也不把纯风格建议当作错误自动入本。有争议的判断先复核，修正误判后同步修正该项。

**用户看到的**

- 打开工作台即提示“今天有 N 个语法点 / 生词该复习”，可一键开始；没有到期项时如实显示，不制造欠账感。
- 每组复习完成后，每个知识点显示下次见面时间，如“3 天后再见”“下周再练”。
- 完成后仍能逐题查看题目、自己的答案和批改解释；点击卡片或结果行回看，也可直接问语伴，不只留下对错统计。
- 语法本与生词本里能看出哪些已经稳定、哪些反复出错，以及每条的原句例证。
- 点“3 天后再见”可看到一句依据，如“这次独立答对，间隔拉长”“看了提示才对，过几天再练”，不做常驻说明。
- **成长视图**：从真实作答派生，例如“冠词：上月错 7 次，最近三篇全对”、从反复出错变为稳定的条目数、作文各维度的近期反馈对比。只展示有证据的变化；证据不足时如实说“还需要几次练习才看得出”，不画空洞曲线。

**一组复习**

复习什么、复习多少由 SM-2 决定：今天到期的知识点就是今天的复习内容，**每个到期项一题**，完成后交 AI 评改。到期三项就是三题，不用未到期的项凑数——提前复习会打乱间隔，只多费时间。题目情境和顺序随机化，每题能追溯到知识点，开放表达接受合理变体。没有到期项时显示“今天没有要复习的，下一批在 X 天后”，不伪造题目，也不补入未同意的新知识。题组一经开始便固定，返回页面或重试评改不重新抽题；它独立于当前读写课，做复习不会挤掉进行中的文章。

**离开一段时间后**

到期项很多时（例如一周没来），一次最多出 20 题，逾期最久的优先；做完可以接着开下一组，也可以停下，剩下的顺延，不因离开天数机械降级，也不责备。20 是为一次坐得住而设的体验上限，不改变任何一项的排程。

**质量分与排程**

SM-2 原版由用户自评 0–5 分，但自评普遍偏高；这里由 AI 依据本次真实作答给出质量判断，程序按固定、可解释的映射更新排程：

| 本次作答 | 质量 | 效果 |
| --- | --- | --- |
| 独立答对、表达自然 | 5 | 间隔拉长 |
| 答对但有犹豫或小瑕疵 | 4 | 正常拉长 |
| 看了提示才答对 | 3 | 间隔少量拉长 |
| 答错或答不出 | 0–2 | 该项从头再来，近期再练 |

每个到期项一题、一个质量分、推进一次排程。排程与“是否已能独立使用”是不同事实：提示后改对、重复原题和机械复述不能自动变成独立掌握。算法常量、聚合、争议/删除/复核的处理在实施阶段集中定义并用行为测试验证；不能把当前启发式间隔换个名字称作 SM-2。

只保存维持重启后排程所必需的状态和复习依据，所有者及失败/删除路径见 §4.2，不积累永久事件日志。确认作答和评改后才推进一次排程；模型错误、保存未确认、重复提交与反复查看反馈不推进。长期证据被修正或删除时，依赖它的排程一并校正，不凭截短历史重建虚假熟练度。

## 7. 教材来源与联网边界

联网复用既有工具调用底座，训练请求按目标搜索、读取文章并组织材料，不为选材增设一个 Agent 或审批流水线。关键词由模型提供，程序保存实际节选和来源，区分原文、教学改写与自编材料；训练与陪伴的资料范围见 §14.2。

共享联网检索是找真实材料的重要入口，不是围绕剧情补资料的附属工具。选材同时考虑学习目标、语言难度和兴趣；BBC 等是来源示例，不是必须绑定的唯一媒体。考试要求优先核对考试组织等可靠来源，生成题不能标成真题。

搜索摘要不等于精读正文；必须经过正文获取、可用性确认和必要适配再成为教材。共享 Key 和正文提取的接缝见实现架构 §7；不在产品文档复制源码状态，也不另存 Key。

优先选择目标语言的原始发布者、可靠媒体或教育机构的文章页。候选网页不可读、内容残缺或不合适时，可换候选或调整关键词再搜索，不限制成“只搜一次”；拿到合适正文后即组织教材，不为了挑选而继续空转。服务鉴权或权限失败则明确说明，不靠反复搜索解决。

动态卡区分找到候选网页、取回网页文字与整理教材；取回文字不表示已经认定为合格文章。正文是否足够、主题是否适合以及如何适配，由模型结合目标和用户要求判断；程序不以最低字词数代替教学判断。

教材明确区分原文节选、教学改写、AI 自编练习。真实材料显示来源与链接；改写标注改写，不把媒体名称挂到模型补写的段落上。只基于已实际拿到的内容出题；材料不足则换可访问来源，不绕付费墙、不编造缺失正文，不默认转载全文。

搜索只携带选材所需的主题、语言、难度等信息，不把角色卡、私人剧情、人物记忆或用户作答原文自动发给搜索服务。网页正文视为资料，不作为控制工具和改档案的指令；链接和引用按不可信外部内容处理。

没配置 Key 时，在首次模型调用之前提供“设置联网取材”“读语伴原创”和暂不开始；确有当前教材时可继续已有课文。设置直达共享 API 设置，不重复做密钥表单。已配置但未能取得文章时，在当前任务附近提供“重新找一篇”“读语伴原创”和暂不开始；已有教材与已提交作答保留，若保存状态未确认则先核实保存。原创必须由用户明确选择，不静默改成伪称联网的新教材，也不把 API 错误记成用户答错。进入页面、翻阅已保存材料不重新搜索。

音频材料区分真实录音与 TTS 合成。取到 BBC 文章后用 TTS 朗读，应标为“原文节选 · 合成朗读”，不是“BBC 原声”；合成材料可以训练听力，不冒充真实播音、多人自然对话或正式考试录音。真实录音的文稿、说话人和时间对应关系只在来源可支持时提供，不让模型编造精确时间轴。

用户也可明确提供一段文本或来源链接作为本课素材，仍经过同一教材与练习流程；链接无法读取时如实说明。文件上传、音频格式及大小上限由实际接入能力确定，不顺手扩成全格式资料管理器。

## 8. 互动设计：工作台与学习搭子的可变布局

### 8.1 产品感与信息层级

主角是用户正在读、写、修改的内容；搭子是与之相邻的交流空间。学习助手按需在工作台内展开：点击入口或批改旁的追问即可进入教学对话，关闭恢复阅读位置。不增加第三栏，也不常驻第二个输入框。学习工作台、语伴聊天、语法本和辅助管理各有位置，不把全部内容铺成设置长页或通用卡片墙。

- 阅读区以文章标题、来源和正文为中心，训练标题与目标收进次级展开项；段落知识折叠、写作区就地出现。全篇流程进度与提交操作相邻，不占阅读首屏，不以悬浮欠交数量遮挡正文或输入。批改定位原句和用户段落，反馈与修改动作相邻。
- 阅读与批改随时可切换，已保存范文另有入口，而不是将结果继续堆在文章尾部。用户直接提交时进入对应结果区域；未产生批注的总结可收起，有待改内容直接展开。后台搭话或模型更新不能强制切走用户正在看的空间。
- 复核后直接展示真实修改稿，并清楚标识原稿与批注。原稿里的错误不因“已经修改”变为绿色正确表达；未复核的编辑也不冒充已改对。完成页同时能看见学习完成状态与范文入口，奖励状态就地展示，不用全局警告条播报成功。
- 从学习本开始或继续复习，直接进入当前题组，不能只提示“先完成复习”却不提供题目入口；选项变动立即影响可提交状态，不要求切页刷新。
- 无材料的学习页突出读写主入口，专项练习为次级入口；当前语言、考试与水平显示为可调整的摘要，完整设置留在设置页。聊天空态可直接打招呼，不先解释模型如何运行。
- 文案面向在酒馆里学语言的人：陪读说明表达有人陪着学，等待说明正在做的学习活动，失败说明影响和可用的下一步。不展示原始工具名、参数或协议数据，也不把费用提示写成产品介绍。工作台自动发起的任务指令不伪装成用户聊天气泡。
- 工作台与聊天共用真实请求过程的“学习动态”：运行时展开，显示当前轮次、实际动作、已完成步骤与失败反馈；结束后可折叠回看，失败过程默认保留展开，并可就地停止。成功步骤不因进入下一轮而消失，重复尝试也不合并成一句“正在回复”；用户手动展开/收起和查看旧步骤时不被更新打断。过程里的公开说明与最终回复区分呈现，技术诊断仍留在诊断层。只显示安全的动作名称、数量、失败字段类别与已发布说明，不公开尚未展示的答案、原始网页内容、模型推理或密钥；不额外调用模型来生成进度说明。
- 确认操作使用具体动作名称（例如删除记录、放下练习），并说明会失去什么、保留什么；不能用简短文案隐藏数据损失。奖励只有实际到账才显示入账加号，未领取、失效与已到账清楚区分。
- 绿色用于写作训练与语法关联等学习标记，错误/建议仍用图标和文字区分，不依赖红绿颜色表达全部语义。
- 画面清透、正文对比清楚，延续宿主字体和正常阅读尺度；深色主题不做灰雾，留白不补口号、副标题、英文眉题或重复说明。
- 来源、题目、教学解释和反馈是必要内容；设置、记录、导出、声音与奖励收获放在低频入口，不占据文章主空间。
- 训练进度由真实提交与反馈派生；不以装饰性的假统计、无依据的熟练度环或连签数字营造“产品感”。来自真实作答的数据（例如某条语法从反复出错到稳定）应当好好展示，见 §6.6。
- 关键时刻要有触感，动效短、可被“减少动态效果”关闭，且不阻断操作：
  - 修订时改对的句子就地变绿并收起，一句一句“消掉”；
  - 复习一题一张卡，答完翻面看点评；整组评完后每个知识点落下“3 天后再见”这类小标签；
  - 完成时“本篇完成”与奖励在原工作台出现短动效，不跳页、不弹窗。
- 单段、长文、长答案、批改中、保存失败和空态都必须设计；正常、等待、停止与恢复的动作位置一致，不靠全屏旋转圈掩盖阶段。
- 模型提供内容和学习判断，应用以自己的原生组件排版；不让模型生成任意 HTML/CSS 或新的页面结构。

### 8.2 同一空间，按可用宽度改变布局

固定空间关系：**工作台在左，语伴在右。** 按 APP 实际容器宽度而非设备名称选择布局；桌面中的窄 OS 窗口也使用窄屏方案。

| 宽度/焦点 | 主画面 | 另一侧 |
| --- | --- | --- |
| 宽屏并排 | 左工作台、右语伴 | 可调整两者主次，不能挤到不可读 |
| 窄屏学习 | 工作台占满可用内容区 | 右侧保留语伴头像入口 |
| 窄屏交流 | 语伴聊天占满可用内容区 | 左侧保留工作台图形入口 |

窄屏切换：

1. 点右侧语伴头像：语伴从屏外右侧向左进入，工作台同步向左退场，左侧出现工作台入口。
2. 点左侧工作台图标：工作台从左侧回来，语伴向右退场，恢复右侧头像。
3. 两边是同一学习现场中的两个独立交流空间，不是覆盖式弹窗或重新打开页面。页面横移，按钮接替出现；无需把整页缩成圆球。
4. 不采用上下分屏、底部半屏聊天或硬塞一条窄右栏。可用宽度不足时只展示一个完整活动空间。
5. 横竖屏、窗口宽度变化保留当前焦点与现场；键盘弹起按剩余可视高度安排聊天或写作，不触发反复布局切换。
6. 点击是完整可用的切换方式，不依赖滑动手势；按钮有键盘焦点和无障碍名称，非活动侧退出焦点与读屏顺序。减少动态效果时直接或短过渡切换，语义不变。

工作台入口是一枚专门设计的书页/练习册意象矢量按钮，与语伴头像的尺度、边缘和触感协调；不用可见的“工作台”中文字样或 emoji 代替设计。最终轮廓在真实画面中打磨，不在本文凭空冻结图稿。左右位置有导航意义，入口不得随意交换侧边；避开正文操作、输入、提交和系统安全区。

窄屏入口固定在内容区右中／左中，平时大半收在屏幕外，露出 18px 可点击窄边；采用深浅主题均清晰可辨的克制实色，不使用半透明底色。阅读和聊天保留正常、对称的边距，不为入口整列让位。手机点击露出部分直接切换，不能先展开再要求点第二次；鼠标悬停或键盘聚焦时可完整露出，焦点与未读标记必须可见。退回常态不改正文宽度，也不依靠额外后台计时器。

题目／材料课件只覆盖工作台，不遮挡侧边入口或宽屏语伴区。侧边切换保留课件、未提交答案和阅读位置；离场课件退出焦点与返回操作，回到工作台恢复。只有确认、授权等真正需要用户决策的弹窗阻断两边操作。

无材料时语伴可直接占据主画面；工作台仍可从图形入口进入设置、开始训练或查看学习资产，不用伪造空课文维持双栏。

### 8.3 学习搭子：自然陪读，不替用户主持流程

语伴保持角色卡的身份、性格和恰当的共同记忆。它能教用户，也能感叹、联想和讨论，不始终以考官口吻说话；不靠故意教错、羞辱、催促或情感压力维持人设。

**有能力，但不接管。** 工作台直接操作与聊天委托是同一套应用能力的两个入口。用户明确要求取材、开始复习或执行某项训练操作时，语伴可以代办；普通问答、表达困难或讨论方向不自动变成改目标、换课、提交或结课。会丢失当前成果的替换或删除先确认。备课、批改期间仍可交流，交流不能覆盖正在处理的原答或取消工作台任务；冲突操作明确等待或由用户取消原任务后再发起，不暗中排队。

主动陪读规则：

- 用户开启主动陪读并处于前台安静阅读训练材料时，在 **3–12 分钟**之间随机安排下一次搭话机会，不是到点必须发言；入口轻量，展开后说明陪伴体验，并在同处提供可展开的费用说明。费用按用户所用 AI 服务计费，不在正文首屏常驻技术说明。正常滚动与翻阅不反复重置计时；主动发言或转入正常交谈后重新安排。
- 发言围绕当前段落并结合全文、表达方式或语伴自己的发现，一两句即可；没有值得说的内容可以保持安静，不重复寒暄、不要求每条都以提问结束。参考意图是“原来这个表达还能这样用”，不是固定循环播放的台词。用户没回复也不催促，不在每次展开知识、提交段落或修改句子时播报。
- 未提问也能感到有人在陪读；用户主动发言则正常回应。搭子每次知道完整材料，资料边界见 §14.2。
- 不在用户正在输入、提交、评估、保存待核实或已有模型请求时插入新的主动请求；不抢焦点，不抢占或取消用户请求。受阻的计时不积成队列，恢复可陪读时重新安排。
- 主动消息归搭子自己的聊天记录。工作台可见时只在头像旁短暂展示简短气泡，收起后可从未读入口打开完整对话；不会自动横移进聊天，也不朗读尚未授权的声音。
- 消息不能代写段落总结、提前泄露作文范文或自动提交学习结果。相关帮助依 §6.2 记录；仅在 Prompt 中写“别泄题”不能替代输入与工具权限边界。
- 用户可随时暂停主动陪读。离开 APP、页面后台、无阅读材料或切到其他非阅读活动时不启动新陪读调用；回到前台不补发“错过的消息”，重新计时。
- 计时器、待发意图、气泡展示时长是会话临时态，不持久化、不做系统通知或后台推送。主动请求失败如实留状态，不伪造发言、不立即自动重买请求；错误恢复仍按 §10。

学习中的关键时刻，语伴以角色身份在场：

- **完成时**：结果留在工作台，不强制额外生成庆祝消息。搭子在下一次交流中读到已公开结果后，可以自然回应观点或进步，不把工作台批改冒充自己的发言。
- **记得进步**：可引用语法本/生词本的真实证据，如“上次还把 however 用错，这次挺顺”；不编造没有记录的进步。
- **等待时**：备课、批改需要时间时，用户可以先和语伴聊聊；用户主动发起的聊天不受“忙碌时不插话”限制，只是不影响正在进行的备课或批改。

上述随机机制只针对陪读。没有材料时仍可自由聊天，但不据此默认增加后台闲聊或自动催学。进入、重开和左右切换本身不触发模型。

### 8.4 阅读、写作与反馈的直接操作

选中原句可提问、标记不懂或听示范；手机长按之外提供可发现的选句提问入口，不依赖语言是否以空格分词。选区引用实际保存的段落，提问切到同一语伴并带上引用，不另开一套临时聊天。选择、标记和查看已生成讲解是本地操作；用户确认发送才请求回答。

段落总结在原段末输入，文末作文有足够编辑空间和清楚的字/词数。用户能直接到达待写、待修改的位置，不被迫在每一段后打开教学弹窗。移动端批改与修改按同一原答锚点切换或就地展开，不强做两个狭窄文本栏；分清真正错误、可选优化和范文。

原生选择、匹配、排序、原文依据、填空、自由文字组件仍可用于专项/语法练习。选择可改、确认才提交；排序有点选移动替代拖拽，合理表达变体由语义评价处理。提示和参考答案是明确的帮助入口；用户可以暂离或放弃，不设置“答对才可退出”。

准备训练、查看批改、提交修订、进入复习和换材料都有直接入口；不必先让语伴发工具卡片。替换未完成课程须说明将释放的课件、作答和笔记并确认；新课确认成功后才替换，失败保留旧课，旧入口不能误覆盖后来的课件。修改目标只影响之后的安排，不暗改正在评分的题目要求。

语伴聊天输入可自然增高，引用独立呈现；回复期间可编辑下一条草稿，旧回包不清空它。看旧消息时，新消息不强拉到底部。学习进度显示在工作台当前动作附近，聊天进度留在对话内；仅有实际阻断时显示必要通知。所有正文、气泡、预览、笔记、朗读及读屏内容共同遵守 §3.3，不能用小气泡旁路展示私有候选。

### 8.5 完成、收获与下次继续

完整读写训练的完成条件见 §6.5，语法本/生词本复习见 §6.6。用户无需在已完成这些步骤后再点一个空的“完成”按钮；应用确认学习成果后衔接 §9 的既有奖励。专项小单元按自身事先约定完成，不能把它的较短条件套给读写训练。

成果就在原工作台可见：初稿、纠错、修订、复核和范文能按对应关系阅读，语法与词汇问题分别进入语法本和生词本。结课不强制跳页，继续聊天、查看反馈、复核争议不再次结算。

同一运行内返回恢复草稿和位置；重载恢复已保存的训练事实和各自会话。已结课的当前课件仍可追问，开始下一课前可导出需要保留的作文和笔记；保留与清理范围见 §4。没有训练材料时，语伴仍是完整聊天体验。

### 8.6 性能：轻会话常驻，重视图按需挂载

“两个相邻空间”是交互关系，不要求两套完整 UI 永久运行。学习会话持有必要状态；可卸载的文章、编辑器、长消息列表和媒体视图只负责呈现。

| 生命周期 | 保留 | 释放或暂停 |
| --- | --- | --- |
| 学习侧可见 | 会话数据、工作台视图、轻量头像/消息提示、必要陪读调度 | 隐藏聊天的长列表渲染、尺寸监听、滚动跟随和装饰动画 |
| 聊天侧可见 | 同一会话数据、聊天视图、左侧入口 | 隐藏阅读/写作重组件与其观察器；陪读调度按 §8.3 停止 |
| 横移过渡 | 准备好的目标视图与正在退场的视图短暂共存 | 过渡结束立即卸载非活动重视图，不将短暂共存变成永久缓存 |
| 离开 APP / 页面后台 | 已确认资产及仍有效的运行内恢复资料 | 无可见消费者的渲染、动画和陪读计时；调用与媒体按 §10、§11 处理 |
| 宽屏两侧均可见 | 两侧必要视图 | 仍释放关闭的低频管理页、未用播放器和无消费者监听 |

草稿、选区锚点、展开、阅读/聊天位置由会话持有，不放在待卸载组件的唯一局部副本里；它们仍是临时态，不为切页新增数据库、快照、锁或磁盘缓存。

目标视图先准备、恢复现场，再开始横移；不能先露出空白再补排版。切换不重新搜索、生成、批改或复制整份课件。首次加载确实需要等待时保留原视图并反馈准备状态；不能以常驻两套重 UI 或显示过期页面截图冒充流畅。

快速反向切换、重复点击、宽度变化和过渡中断只认最后有效目标，清理失效视图；过渡不另建持久队列。卸载视图不等于取消已提交的评估或删除会话，流式接收与保存由应用/Host 持有，隐藏侧只更新必要数据，不持续全量 Markdown 渲染。

性能按代表性长文章、完整批改、长聊天、输入法/软键盘和反复切换实测：检查首切/回切可交互延迟、长任务、布局跳动、内存与监听数量是否稳定，隐藏侧是否停止无用工作。验收需同时满足状态正确与实际流畅；不能用单张截图、空态或“用了 transform”证明达标。

### 8.7 参考的边界

ebook 的可变主次与窄屏横移是空间参考，老四次元壁的头像是陪伴入口参考；语伴不复用其业务数据或聊天所有权。实际渲染生命周期见实现架构 §6；参考产品不能作为本产品性能达标的证据。

## 9. 学习奖励与跨存储边界

只奖励，不惩罚：完成有意义的学习单元、认真修正、完成复习均可成为奖励依据；错误、看提示、跳过或缺席不扣币。不按字数、耗时、对话轮数、点击次数或正确率发币，不通过模型输出的金额直接入账。

奖励分短练、常规、深练，金额以 [学习奖励规则](../domains/learning/reward.ts)为准。档位看学习量及相对本人水平的挑战，不把高语言等级天然算成高奖励，复习也不天然低一档。读写训练由老师备课时选档；复习题组在开组时由程序按题量定档。程序映射金额并在开始时展示、保存，结束时不能随口加减。做完一组复习即发奖，跳过修订不影响读写训练的奖励。

奖励不与拥有麦克风、付费音色或特定模型绑定；不同可用方式都应有合理的完成路径。重复播放、反复重录和单纯耗时不单独刷奖励；“完成练习”和“证明掌握”仍是不同事实。

完成条件见 §6.5、§6.6，确认保存后通过 Economy 自动结算，没有额外的完成/领奖按钮门槛。缩小目标后的结课仍需真实练习和有效反馈；不要求全答对。无作答、仅聊天或播放不能凭一句话获得奖励，主动陪读也没有结课权。

钱包归属、跨卡领取及升级前课程奖励的处理统一见 Economy 平台设计。学习完成、账本入账、学习回执是三次独立保存确认，实现接缝见实现架构 §7，不能宣称学习进度与发币天然原子。产品要求如下：

- 正常结课且钱包已开、经济存储可写时自动结算；钱包未开则保留成果，提供「开通钱包并领取」，不擅自开户。结课后继续追问不延迟或重复结算。
- 保存学习失败，不发奖；学习保存成功、发奖失败，学习仍然完成，就地提供领取/核实入口，不要求重学或重新评估。
- 完成事实保存开课确定的奖励意图，不因重试、重新进入、反复看结果或复制故事分支产生第二份学习完成资格。
- 切聊天、关 OS 后未提交的调用停止；已发出的保存或记账按实际结果核实，不假装已经撤销，不把旧页面的迟到结果交给另一课堂。

不新建通用跨库事务框架、持久任务队列或第二本钱包；恢复只核实原完成资格及其保存结果，不重新上课或重复生成。

## 10. 调用、失败与无障碍体验

- 显式交流、取材、提交后对应阶段的审阅/批改/复核、复习出题会调用模型；主动陪读只按 §8.3 调度。打开、阅读、选中、导航、左右切换、已有讲解/反馈不因操作本身发请求。客观题可先本地核对并保存；不把每次原生操作都无条件接到一次自由教学请求。评估失败不丢已保存原答，恢复不要求重新作答。
- API/联网出错就在当前动作附近解释，保留材料和作答；重试同一意图，不重复收答案或再次计奖。重新进入不自动重复失败请求或弹同一通知。
- 搭子和学习助手的聊天失败或停止后，在原消息旁提供“重试回复”，保留原引用，不需要重新输入；重试不追加第二条用户消息。只重试当前会话尚未回答的请求，已有回复的保存问题单独核对。备课失败/停止后的原因与恢复操作在同一张动态卡，重试保持原联网或原创选择；读不到网页正文、联网连接失败和 AI 回复失败分别说明，不能只写“未完成”。
- 保存未确认时可阅读已确认记录，但不继续发布依赖该结果的新水平或奖励；核实优先于重新生成。技术失败不进入错题库，不降低水平。
- 模型/工具的安全进度实时呈现，老师正文按 §3.3 发布；失败、停止和保存未确认保留此前已发布交流，并清楚显示中断或待核实状态，不展示私有草稿充当回复。同一会话只对符合恢复条件的原提交接回内容，不重复追加、不再请求模型，也不清空新输入。整页刷新或明确放弃该会话后不承诺恢复临时回复，已保存资产仍完整保留。
- 切卡、换语言、换老师时，取消尚未提交的所属运行并隔离迟到回复；已确认学习事实保留。新老师不接收旧老师私聊全文。
- 320px、390px、桌面及深浅主题都可阅读；支持文字放大、键盘选择和提交。选区动作之外有可发现的替代提问入口，不能只靠悬停、手势、红绿颜色或拖拽。

声音相关调用另作区分：用户点击朗读可能发起 TTS 请求，但不应再调用教学 LLM 重写原句；已有音频的暂停、倍速、重听是本地播放；开始录音只请求设备权限，确认提交后才可上传给明确支持的服务。看文稿/字幕按 §6.2 先保存再揭示，重听和慢放等使用条件随作答提交，不每次操作都保存一条事件。

同一题的练习内容、已提交尝试和待评估结果分开：评估失败可用同一尝试重试，材料不重搜、录音不重录、奖励不重领。媒体失败只阻断依赖该媒体的动作；后台晚到的合成、识别结果不能跳回旧题、播放出声或改写当前语言的学习记录。

## 11. 声音与多语言：完整设计、按能力交付

### 11.1 声音依赖与接入边界

下面定义声音能力的复用位置与限制，不代表真实供应商、实体设备或教学质量已经验收。当前接入范围见实现架构 §7。

| 能力 | 当前事实与证据 | 学习 APP 的决定 |
| --- | --- | --- |
| 文本合成 | [TTS 外部接口](../../tts/tts.js)的 `xiaobaixTts.synthesize` 返回 Blob，接收音色、情绪、取消信号和本次语言/合成语速，复用已有缓存 | 直接消费合成能力，不另写供应商请求，不用教学模型生成假的语音结果 |
| 目标语言音色 | [现有音色列表](../../tts/tts-api.js)含英式、美式英语与日语选项；TTS 还支持配置的鉴权音色 | 英日示范有现成基础；其他语言按实际音色与试听验证，不仅凭音色名宣称质量 |
| 教学播放控制 | [TtsPlayer](../../tts/tts-player.js)提供暂停/继续、倍速、跳转、进度和释放；facade 的 `createPlayer()` 与主队列、即时语音共享同一 TTS 播放所有者 | 复用播放器实现，以课程自身的实例/句柄管理播放；不改主聊天实例的回调或队列 |
| 消息式即时播放 | [playTransientVoice](../../tts/tts-playback-runtime.js)是单条即时播放，当前调用只传文本/情绪并返回停止句柄 | 适合参考生命周期，不足以直接承担逐句重听、选音色、暂停与倍速；不把信息/四次元壁的语音气泡照搬为课堂播放器 |
| 合成参数与设置 | facade 的 `getVoices()` 只读投影音色和可用性，不含密钥；外部合成的 `language` / `speed` 只覆盖本次请求，省略沿用全局设置，结果参数参与缓存键 | 不为上一次课改掉全局语言/语速，不让 iframe 或模型读取密钥；音色可选不等于实际语言质量已验收 |
| 合成取消 | 免费请求及[鉴权完整下载](../../tts/tts-api.js)均传递 AbortSignal；TTS 清理会取消外部合成、释放所有播放客户端；缓存迟到也检查失效 | 分别验证取消、迟到结果与资源释放；固定传输检查不能替代真实供应商及设备验证 |
| 录音与识别 | 学习 APP 尚未接入录音或转写 | 录音是浏览器采集，转写是独立服务能力，分别验证与接入；不是 TTS 的隐藏功能 |
| Agent 音频输入 | 现有部分宿主适配出现音频映射，但 [Google 直接适配](../../agent-core/adapters/google.js)、[Anthropic 直接适配](../../agent-core/adapters/anthropic.js)的普通输入转换目前只处理文字与图片 | 不宣称共享 Agent 已统一支持录音；未知/不支持时不把音频硬塞入每轮教学历史 |

实现优先复用合成与播放器已有代码。学习 APP 的音频资源、课程操作和录音保存在自己的边界；若需要播放器的暂停句柄、可用音色或最小播放互斥入口，扩展 TTS 的通用媒体接口，不把听写、评分、老师身份塞进 TTS，也不扩建全 OS 多媒体框架。

### 11.2 声音互动设计

| 用途 | 用户怎样用 | 教学与记录边界 |
| --- | --- | --- |
| 老师讲解朗读 | 点某段说明旁的播放，文字仍可见；连续语音辅导须主动开启 | 声音服务陪伴与理解，不因播放结束就增加掌握度；听力题不能自动朗读尚未揭示的文稿 |
| 单词/短句示范 | 选中片段后点「听示范」，可以重听或慢放 | 朗读本课实际文字，不另调 LLM 改句；中文解释与外语示范分段选合适音色 |
| 听后理解 | 先听片段，再选择或回答；主动请求文稿时切入辅助理解 | 可以使用合成材料，须说明来源；看过文稿的尝试不能当作纯听成功 |
| 听写 | 听短片段后输入，提交后对照与解释 | 记录本次是否慢放、重听、看文稿等必要条件，不把一次拼写错直接推成听力差 |
| 跟读练习 | 听一句，暂停后自己跟读，再听示范；录音可用时比较自己的声音 | 无录音/音频评估时仍能练，但只表示做过自练，不给虚构发音分数 |

播放条提供播放/暂停、进度、重听和本地倍速，时长来自真实媒体元数据，不按文字长度假算精确秒数。完整段落播放与短句示范分清；TTS 可按确定的句段分别合成以支持逐句重听，真实音频只有可靠分段/时间标记时才显示逐句跳转。没有时间对齐就用普通进度条，不生成假的逐词高亮。

同一道听力练习使用确定的文本和播放版本；用户改音色或重新合成时不能悄悄替换已经提交的尝试依据。普通复习允许重新合成，但不宣称与之前的原始波形完全相同。合成原文、音色及实际来源作为材料信息，临时对象 URL 不进入存档。

语音默认由用户点击启动，不打开 APP 就出声。用户选择连续语音辅导后，只顺序播放本课已确认且当前允许展示的内容；打断、切题、进入录音或关闭 APP 时停止所属播放。浏览器阻止自动播放时显示可点击的播放入口，不自动循环重试。

### 11.3 录音、口头表达与转写的完整路径

录音可用时使用短轮次、轮流说话的辅导，不以实时通话、持续监听、打断检测或自动端点识别作为首个实现前提。

1. 用户点击录音才申请麦克风权限；提示当前正在录音，并提供明确停止与取消。
2. 停止后可本地预听、删除重录或提交；预听不上传，关闭前对未提交录音说明会丢失。
3. 确认提交后才将本次需要的录音交给已配置且支持的识别/音频服务，不默认发送全课音频。
4. 转写可用时显示识别文字，允许用户指出“识别错了”；机器转写与用户修正有来源区别，不覆盖原录音或冒充原声。
5. 老师针对本次真实可用证据反馈，再让用户尝试改进。识别失败只重试识别，不要求重录；录音清晰度不足时才解释原因并建议重录。

录音、转写、语言评价、发音评价不是同一个开关：

- **只有录音与播放**：支持跟读自查/回听，不能假装老师已经听懂。
- **有可靠转写**：可以讨论表达内容、用词和句法；用户修正过的文字只能支持相应文本判断，不能反推原始口语的流利度或发音。
- **有实际音频评估**：才可基于声音讨论相应的可懂度、停顿、发音等；需要真实支持与校准，不因模型接受文件就提供“口语 87 分”。

需要音频反馈的题，在开始前说明能力是否可用。未配置转写时可以明确选择本地跟读自练或文字表达练习，不让用户录完才发现整段无处提交。用户不方便开口时可换可完成的任务，仍有正常奖励；不把打字替代偷偷记作口语成功。

识别或音频服务结果只按需供本次评估使用；后续普通教学以已确认的学习事实和必要文本继续，不反复携带原音频造成不支持的模型连续报错。发生不支持/格式问题时可移除该待提交录音、改用文字或切换支持的服务；一份坏附件不能锁死全部学习历史。

### 11.4 设备、权限与声音互斥

录音入口可用性由安全上下文、浏览器权限、实际编码格式和服务支持共同决定；手机通过 HTTP 访问宿主、WebView 拒权、没有麦克风等都是需要实测的外部边界，不按浏览器名字猜支持。

采集归学习 Host 管理，UI 只发送明确操作和显示状态，不在域模型保存设备对象。现有 [OS iframe](../host/lifecycle.ts)只显式声明剪贴板能力，不能假定录音权限已接好；实施时验证宿主采集或明确的 iframe 授权路径，不用大范围放开权限解决单项能力。

开始录音先停下本课播放，避免把老师声音录成用户作答；停止录音立即释放麦克风轨道，保留预听所需的临时音频。取消、切聊天、切语言、离开 APP 或采集异常时释放所属轨道、临时音频和对象 URL；上传/识别失败则保留可重试的已录内容。录音中不偷偷预取并播放下一句。真实上传前让用户知道接收的服务及用途，不增加每句话都要确认一次的重复弹窗。

主聊天队列、即时语音与学习播放器通过 TTS 的共享播放所有者协调：新的明确播放请求打断或暂停旧的语音，旧页面的迟到回调不能把新的播放状态清掉；不通过清空主聊天队列、覆盖全局回调或关闭整个 TTS 开关实现。若全局主聊天朗读已暂停，学习结束不擅自恢复出声。背景音乐不属于本课播放器，不接管音频控制模块。

### 11.5 音频资产与删除恢复

分清三类资源，不能统一往学习 JSON 塞 Base64，也不能全部当作随时可丢的缓存：

- **可重建的合成声音**：复用 TTS 缓存；学习记录保存必要文字和声音来源。缓存不可用时明确需要重新合成，不能悄悄切到另一音色还声称是当时录音。
- **本次题目实际使用、需要保真的源音频**：若要支持中断恢复或逐段复核，在授权允许的范围内保留必要片段与引用；无法合法保留的材料不承诺永久离线回听，不能仅凭随时可能失效的远程链接设计恢复。
- **用户确认提交的录音**：不可重建的作答，由学习 APP 在当前宿主用户空间持有独立资源，尝试只保存引用、真实元信息及必要转写。未提交的预听录音仅在内存，不持久上传。

音频上传与学习记录也不是天然原子：资源保存并确认后才能发布指向它的作答，评估失败不重传已确认录音；资源状态不明先核实，不先显示已保存。由学习 APP 清理已上传但未被记录引用的自有资源，不擅自删除共享媒体或 TTS 缓存；接入前须验证具体文件接口和清理路径。

用户可删除某次录音而保留题目及文字作答；依赖声音的反馈须显示原音已删除，后续不能再声称据该音频重新验证。删整次尝试/课程/语言档案或清空学习数据，一并处理其独占附件与引用。完成事实与既有奖励仍遵守 §4、§9，不因为删除音频扣币。共享合成缓存由 TTS 自己过期/清理，学习数据清空不伪称已经删除共享缓存中的所有副本。

### 11.6 多语言与能力缺失时的体验

共用的是目标、材料、练习、反馈与复习循环，不是假定所有语言同一种教法。英语拼写与时态、日语假名/汉字读音与敬语等需要对应的题材与反馈；等级体系也不能随意互换。发音示范优先选择适合目标语言的音色，实际试听失败或质量不适用就说明并换音色，不以角色气质优先牺牲示范清晰度。

能力信息细分为“可朗读、可播放材料、可录音、可转写、可做哪些音频反馈”，而不是一个笼统的 `voice=true`。它由已知接入与本次设备条件得出，不在每次打开时调用供应商自动探测，不把这些临时能力写入用户的长期水平。

TTS 未启用时，阅读与文字练习仍然完整可用。朗读和听力入口明确提醒「使用语音前，请先开启 TTS 模块」，操作时就地引导，不自动启用或在重进页面时反复弹通知。模块关闭与暂时合成失败分别说明；后者保留同一道题，可重试或明确转为另一训练。没有文稿的真实音频不能伪造文字替代；读过替代文本后也不能再把该次表现归为纯听力。尚未实现的录音/评估能力不显示假按钮，但课程、作答和证据模型从第一版就遵守上述独立边界。

声音设置与播放失败处均提供启用引导；模块关闭时说明宿主开关位置，启用后再提供音色设置入口。不会显示一个名称承诺打开设置、实际只能重复“未启用”的按钮。

## 12. 验证要求与能力边界

先验证一份完整读写训练及相邻的陪伴/复习，再验证保留能力；不先铺全技能大厅。以下是持续有效的验收要求，不是通过记录：

- **教学与真实模型**：初学与较熟练用户、英语与日语样本；未知水平、理解正确但表达弱、合理答案变体、提示后答对、短期复习和隔时迁移。真实输出不能手改后冒充效果；练习完成率不能冒充提分证据。
- **资料与外部协议**：联网渠道从检索到足够正文的实际可用性、来源/改写标注、不可访问网页、缺 Key 与服务故障；私人故事不作为搜索词外发。
- **资产与奖励**：切语言、换语伴、分支、删除聊天后的进度隔离；完整路径自动完成与缩小目标后的有据结课均不伪造未做内容，无作答不能结课、对错/提示不减奖、开课金额固定；结课保存失败不发币、正常自动结算、发奖失败只补领、未确认核实与同一奖励去重。
- **读写闭环**：首次语言／语伴选择、目标确认与语伴名单空态、难度适配与来源、逐段折叠讲解、逐段总结审阅、文末作文、全部作答统一批改、就地修订与跳过修订、复核与范文逐项走通。段落锚点、评价版本、待评缺口、合理答案、范文揭示时点与字/词单位都需证据。
- **连续任务与自主安排**：复合指令完整转交、确认接受/拒绝后继续、取消待确认工具、同课加题、早批改、分批及再次修订、按需提前范文、同轮跨主课/复习读取、成功保存后模型失败、先改设置再提交原答；这些操作不被入口名或整体阶段阻断。
- **语法本、生词本与 SM-2**：原句关联、生词收藏、质量映射、逾期优先与单组上限、同知识点多证据、争议撤销、按到期项出题（不凑数）与随机变题、无到期空态、确认前不推进、重复提交不推进、重启/删除/复核后的排程；用固定时间和随机源验证数据，不断言反馈文案。
- **成长与触感**：成长视图每条变化都能追到真实作答，证据不足时显示如实空态；修订消句、复习翻卡、下次见面标签与完成动效在减少动态效果时降级且不阻断操作。
- **语伴在场**：完成时回应作文内容而非套话；引用的进步都有语法本/生词本证据；备课/批改等待中用户可自由聊天且不影响进行中的请求。
- **可变布局与性能**：宽容器并排、窄容器双向横移、两侧图形入口、软键盘和横竖屏、草稿/选区/位置恢复、快速反切、减少动态效果、非活动侧焦点隔离。长内容下验证隐藏重视图卸载、监听与内存稳定及首切/回切流畅，不只看截图。
- **主动陪读**：固定时钟验证随机范围、前台/后台、输入/请求忙碌、暂停/恢复、失败与离开；不积压、不抢焦点、不强制切屏、不自动写学习事实。真实模型另验角色自然、内容相关、不重复或泄题。
- **提示词与上下文**：§14 每个用途的输入/能力对应，完整材料不随翻页丢失，全部原答对应评分版本，隐藏答案/范文与跨卡资料不外露；提示词不对用户开放编辑。检验实际请求与结果，不写提示词字符串快照。
- **TTS 真实接入**：英日示范、音色选择、合成缓存命中/失效、暂停/慢放/重听、播放互斥、自动播放被拒、合成取消与切卡后晚到结果；确认不改全局设置、不污染主聊天队列。
- **教学证据**：先读后听、先看文稿再作答、重听慢放、转写经人工修正、录音删除等条件不会变成虚假的独立听说掌握；声音服务失败不记为学习错误。
- **端到端发布契约**：所有现有 Provider 路径的正常/非正常结束；工具参数、结果、历史、摘要、笔记、朗读等出口都不能绕过正文发布；相同内容经中间编辑仍保留已确认帮助；停止、失败、保存未确认及精确恢复分别验收。最低有效验证层见实现架构 §8，不按测试数量宣布闭环。
- **录音能力上线前**：桌面/手机/WebView 的权限与编码、预听不上传、重录删除、轨道释放、上传未确认、识别失败后重试、附件清理及不支持音频的 Provider 恢复。

当前不建设：学校/班级系统、排行榜、打卡惩罚、订阅推送、完整考试题库平台、云端网页收藏库、无限师生聊天档案、实时语音通话、未经验证的发音打分或主剧情联动。这些边界不排除已有 TTS 支持的正式听力与朗读功能，也不删掉录音作答的终态设计。

外部能力的接法和验证边界见实现架构 §7、§8。源码与协议可用不等于真实服务验收；录音、识别及音频评价分别列证据，不用一种能力的成功替另一种背书。

## 13. 实现约束

以下不是预埋功能清单，而是第一版就必须遵守的边界：

1. 用户级学习事实与聊天级剧情/资金分开；课程进度不落进卡内聊天记录。
2. 材料、题目、尝试、反馈与学习项有清晰引用；题型和媒体形态不决定资产归属，不复制多套进度。
3. 原始作答和模型评估分开；媒体来源、输入方式、帮助条件和可评价的能力保持一致。
4. TTS 合成复用现有模块，课程播放有自己的所有权；录音、识别、发音评估不是 TTS 的同义词。
5. 教材声音、可丢合成缓存和不可重建的用户录音有不同生命周期；先确定可恢复/可删除方式再实现上传。
6. 本地交互、媒体调用、教学模型请求和持久保存分开；失败重试相应步骤，不重跑整堂课。
7. 同一次学习完成及奖励有稳定身份，学习文件、Economy 和学习回执的未确认结果可分别核实；不引入第二钱包或分布式事务框架。

控件与服务接入遵守工作台/会话/语伴的边界，不以聊天消息加熟练度数字代替训练流程。已发布文件格式的升级策略见实现架构 §3；格式变更先核对真实样本，在升级入口一次转换，不能虚构旧记录的修订阶段或 SM-2 历史。自己的旧 UI/API/协议分叉不构成兼容义务，整理界面不需要双轨永久保留。

开工前还须明确：未显示视图的卸载不带走草稿、评估与保存所有权；布局状态不进入长期档案；任务提示词不塞进课件；复习日期不同时由模型与程序维护。实际新增持久字段逐项回答原因、所有者、生命周期、失败与删除路径，不能以“文档写了”跳过数据设计。

## 14. 提示词归属与上下文装配

本节规定设计职责，不是可直接注入的模型提示词，也不是在旧 Prompt 尾部追加的新禁令清单。实现时同步清理与新模式冲突的“老师必须主持所有流程”引导，保留真实发布、证据和工具权限契约。正式提示词需按实际 schema、注入与能力查证后编写、评审，再落地。

### 14.1 每类规则只有一个归属

| 层 | 唯一职责 |
| --- | --- |
| 主体身份与相处规则 | workbench 为小白X应用人格；companion 为所选角色及关系、人物表达；同一次请求只有一份身份定义，不与任务块争夺角色 |
| 学习领域规则 | 目标、自评、真实表现、材料、原答、帮助、评估的含义，以及什么证据支持什么判断 |
| 本次任务块 | 取材整理、段落审阅、统一批改、修订复核/范文、语法出题/评改、陪读或答疑；按真实用途选取，不把每项任务写成第二份全能 system prompt |
| 工具描述与 schema | 工具何时使用、输入/返回形状、字段语义和引用范围；数值约束引用领域常量，不在上层重复手写 |
| 动态数据投影 | 当前设置、实际材料、已提交答案、反馈与必要进度；与读取工具共用事实和形状，数据不伪装成系统指令 |

学习相关 Prompt 和工具归 Learning，跨功能确实共用的人物表达规则保持原所有者。身份、收尾和每项教学判断各定义一次；入口按钮表达用户意图，不内嵌另一份批改标准。共享 Agent Core 继续只提供业务无关能力，不把“段落总结/语法本”塞入核心。

### 14.2 完整材料与按用途提供的证据

请求显式指定 workbench 或 companion，引用和练习定位只是附带资料，不切换主体或任务。工作台装配应用人格、本轮教学任务、学习档案、相关作品和自己的教学历史，不读取角色卡或主剧情。搭子装配角色身份、相关酒馆背景、自己的聊天记忆和本次学习现场，不读取工作台工具日志或未公开答案。

语伴每次陪读或答疑固定拥有**本次完整训练材料**：实际供阅读的全文、各段公开讲解与公开题目。当前阅读段落/引用只是额外定位，不以当前屏幕或材料索引替代全文。未公开参考答案、范文、评估草稿和其他卡的私密内容不属于这份材料。

“本次”跟随用户正在学习的单元：看复习卡时问答取得该组复习、当前题目及已公开的真实作答和反馈，不默认套用旁边的课文。手机切到语伴、桌面直接聊天和接续追问遵守同一规则；明确引用优先于默认学习位置。

逐段审阅获得本段原文、题目和对应真实总结；统一批改获得所有已提交总结、全文作文、任务要求与帮助条件；修订复核获得初稿、已确认首轮反馈和修正版；语法练习获得选定知识点及可传递证据。正式批改可读取评估所需答案，但公开时机仍由应用流程控制。无材料聊天仍带当前语伴身份与必要交流，不编造一份课程上下文。

稳定身份/领域规则与当前任务分层；核心人物资料保持稳定，时间、阅读位置、近期交流和学习变化放动态区。同一工具循环冻结输入，只追加协议所需结果；不承诺所有供应商均有前缀缓存。

完整材料每次请求只注入一份，不复制进每条历史消息；较早闲聊可以整理，但当前材料与本次必需原答不能静默截断成摘要。超出实际上下文能力时明确说明并让用户选择合适材料/模型，或在取材阶段明确缩短训练范围；不能一边宣称语伴读了全文，一边只传当前段。历史压缩失败保留原文并报告，不能为省 token 编造掌握结论。

页面、角色卡和网页内容分别作为资料处理，均不能修改工具权限。工作台的学习工具常驻，任务块只给教学指导，不把入口名或阶段变成限制；主动陪读的只读边界由调用层落实。写入统一经过结构、真实证据、访问范围及保存校验。

### 14.3 管理与变更范围

内置提示词按上述用途集中维护，使用稳定键而非人类可读标签作为契约；页面文案、日志、帮助说明与模型规则分开定义。改一条教学规则应只改它的归属，不需要同步改按钮、UI、工具和数份默认模板。

提示词不开放用户编辑：我们自己的教学规则尚未定型，无法判断哪些可以交给用户改而不破坏批改、排程与奖励。不提供覆盖配置、导入或管理页，也不新增长期自定义存储。

实现验收检查实际装配输入、字段语义、工具权限和用户可观察输出，不断言 Prompt 的字面句子或文件位置。真实模型另验难度适配、批改准确、角色自然与泄题风险；结构/单测全绿不代替这些质量结论。
