# 普通小白 OS「语伴」APP：产品设计

## 1. 文档性质

本文记录已确认的定位、资产边界和教学方向，2026-09-07 更新为老师主导的对话课堂。它是产品设计，不是施工方案；使用既有 Provider/Tavily/TTS 接缝，实际落地范围和验证限制见施工方案 §13。程序链路验证不代表真实教学模型、在线素材和声音质量已经验收。

用户已确认：学习是独立于剧情的正向教育；老师是认识用户、保有当前故事记忆的 NPC；学习资产属于用户而不是角色卡；真实外部材料是重要教学来源；AI 通过工具维护学习档案；有学习奖励、无惩罚，小白币仍属于对应聊天；老师依据实际学习通过工具结课，成果确认保存后由程序按开课约定结算，不要求用户再点完成。

主人已确定名称为「语伴」，完整名称「小白语伴」，桌面名称「语伴」，内部 APP / 领域 ID 为 `learning`。介绍语为「熟悉的人，陪你学会新的语言」。具体页面、练习组织和恢复行为采用下文方案；数据契约、工具职责、运行默认值与实施顺序见 [语伴施工方案](./language-learning-app-implementation-plan.md)。本文仍是产品设计，不冒充实现或教学验收，也不保存模型 Prompt 正文。

本设计按听、说、读、写的完整终态确定领域边界，再按真实可用能力交付；不能先做成纯文本聊天，日后再为语音推翻课程、作答和学习记录。已有 TTS 是正式复用能力，朗读、示范与合成听力纳入产品主线；录音、转写、音频评估分别查证和接入，不用“语音以后做”掩盖设计空缺。

## 2. 产品定位

**由喜欢且认识自己的角色担任私人老师，使用真实材料和有依据的练习，帮助现实中的用户学会语言。**

角色让用户愿意来，教学设计让用户来了以后真的有所收获。它不是给聊天窗口加外语模式，也不是用角色头像装饰传统刷题表单。

- 教的是现实用户，不是玩家 persona。角色设定中的语言能力、年龄、学历不作为用户学习水平。
- 角色性格、共同经历和当前故事总结影响辅导口吻与互动亲近感；不是课程主轴，更不是语言知识的权威依据。
- 学习目标先决定训练什么，再选择材料。BBC 等真实内容、考试相关资料、生活主题均可；剧情只是可选素材之一。
- 教室独立于主剧情：不写私人信息楼层，不注入 D1/D4，不改变关系、时间、任务或地图，不把上课当作剧情接受轮。
- 人设影响表达而不牺牲教学正确性。古代角色也可担任现代语言老师，不必编造故事内留学经历；不以羞辱、情感施压或故意教错维持人设。
- 不承诺保过、官方评级或仅靠文字训练就能掌握听说。教学有效性需要真实学习反馈验证。

## 3. 终态所有权与依赖

```text
modules/xiaobai-os/
├─ domains/learning/       学习档案、学习项、作答证据与完成规则
└─ apps/learning/          课程组织、资料获取、工具、专属存储适配及 UI
```

这是终态职责边界；第一批目录已按此落地，具体已实现部分见施工方案。学习业务不进入 Messages、Fourth Wall 或 OS Kernel，也不复用语义不同的通讯记录。

- **学习 APP**拥有学习数据、教学交互、内容来源标注、评估与学习奖励资格。
- **agent-core / Agent Capability**继续拥有共享配置和 Provider。Tavily Key 沿用共享配置，不在学习档案里复制；用户级学习数据也不塞进 API 设置仓库。
- **TTS 模块**继续拥有合成、音色解析、供应商设置及可丢弃的合成缓存。学习 APP 拥有本课的播放控制、录音交互和教学用途，不复制 TTS API 或占用主聊天的播放队列。
- **宿主上下文能力**提供当前角色、世界书与总结的只读资料。选择老师可参考信息 APP 的已知人物入口，但不创建通讯联系人或号码。
- **Economy**拥有对应聊天的小白币与流水；学习 APP 只通过窄能力申请自己的奖励，不直接改余额。
- 通过现有 Host/Shell APP catalog 注册；这是用户主动上课的 APP，不加入剧情自动维护队列。未交付前不注册占位图标。

用户级学习业务是相对现有聊天 sidecar 的新存储需求。实现前须验证宿主提供的用户级持久化边界，由学习 APP 持有读写适配；不为单个消费者预建全 OS 用户资产平台。本文不把跨设备同步等同于“用户级”，具体能力需实测。

当前实现采用 Host 会话内已确认版本：首次加载、明确重新加载和未知保存恢复才读取用户文件；正常保存以服务端成功响应确认，重开课堂不对账。保留本页串行、过期动作检查及奖励幂等，不额外维护多设备/标签页同时编辑。

### 3.1 从第一版就分开的业务概念

| 概念 | 持有的事实 | 不能混成什么 |
| --- | --- | --- |
| 学习档案 | 各语言目标、用户偏好与有依据的分项能力 | 单一聊天摘要或一条总等级 |
| 教材 | 已取得的文本/音频内容、出处、节选关系；有则保留对应文稿 | 一张卡片上的渲染字符串，或把音频 URL 当完整教材 |
| 课程与练习 | 本次目标、引用哪份材料、呈现方式、要求怎样作答、考察什么 | 每个题型一套 App，或把“听力”直接等同于“录音回答” |
| 作答尝试 | 真实选择、排序、文字或录音，以及当时看过/听过的帮助 | 被识别文字覆盖的录音，或 AI 猜测的用户表现 |
| 评估 | 对哪次尝试、哪个能力作出什么判断，依据与可改进之处 | 用户原答，或没有音频依据的发音分数 |
| 学习项 | 具体表达、用法或知识点及相关证据，供后续复习 | 独立复制的错题库、掌握库与单词库 |

**训练目标、材料形态、回答方式、评估依据分别表达。** 例如听一段话后点选答案仍是听力训练；对照文章朗读不是独立口语表达；听写的键盘输入也不是一堂阅读课。加入录音只增加一种真实作答载体，不需要另建“语音学习进度”。

这张表固定语义边界，不要求每行各建一张表或服务。实现只为实际启用的形态建立明确类型，不预埋视频、直播、任意组件协议或无用途空字段。

### 3.2 AI、程序与外部能力的分工

AI 决定选材、练习内容、教学解释、语义评估、何时收课和下一步建议；程序记录真实操作，校验教材/题目/作答的引用，控制保存、录音播放及既定奖励结算；外部服务负责检索、合成，以及接入后确实支持的识别能力。

语伴的内核是一位持续工作的工具型老师。老师对话就是主页：了解目标、选材、解释、调整难度、安排练习和结课均由老师衔接。老师能读档案/课程/真实原答/历史学习项，查背景、联网取材、增补课件、复核及结课。工具按需展开材料、练习和听力窗口，操作结果回到同一对话；资产是辅助资料，学生不必翻档案向老师汇报。课文和六类答题控件仍有专用阅读/操作空间。

课件允许渐进完善：未作答内容可修改或删除，已有作答、听取或笔记证据的题和材料保留原貌，另加更正或铺垫。已确认奖励不随调整改价，也不凭对话制造学习成绩。自由交流给出的题目帮助与听力原文揭示同样计入后续作答条件。

同一个辅导 Agent 即可完成这些教学判断，不预设出题、批改、督学多 Agent。工具只开放学习自有的窄读写：档案、教材/练习、基于实际作答的评估与学习项、有依据的结课；老师不能随意改金额或凭对白发币，学习工具不获得改钱、改主剧情、写作者世界书或任意执行页面代码的权限。工具 schema 与 Prompt 在施工时按各自职责编写，不把教学策略塞进持久数据。

每次请求直接给老师当前语言目标、全部学习项的技能／状态概览、最近可读的结课摘要、学习项与到期复习分页、本课索引及聚焦题目的完整材料和原答。旧课详情按需读取，其他语言切换后读取；不靠无限聊天历史维持学习水平，不把整份课件重复放进每条历史消息。概览由当前学习资产计算，不另存一份“掌握结论”。

上下文按稳定程度排列：身份与教学职责 → 核心人物设定 → 课堂历史摘要 → 最近完整对话 → 学生本轮原话与动态学习／剧情资料。身份直接是老师本人；核心设定正文前置，人物近况、共同记忆、近期剧情与世界书阅读页放在动态区。时间、进度和临时状态不改动稳定前缀，同一工具循环只追加结果。布局为供应商前缀缓存创造条件，不保证所有接口都会命中缓存，也不新增持久化缓存。

当前课堂保留完整工具轮次和已提取来源，停止或重进 APP 不等于清空对话。沿用 ebook 的主动计量思路及小白助手的历史摘要：提前整理较早交流，保留具体困难、讲解、约定和下一步，而不是等报错后直接丢弃。摘要确认完整且确实缩短后才替换旧轮次；失败保留尚未替换的原对话，当前工具链和真实原答不被截断或重执行。用户可明确清空临时交流而保留学习资产；切聊天/语言/老师及成功的数据清理会释放对应临时资料，整页刷新后靠已保存课程和进度接续。

## 4. 长期资产、临时状态与删除

### 4.1 学习跟人走，故事不串卡

同一用户按目标语言分别积累学习资产，换语言是切换档案而不是覆盖。切卡、换老师、创建故事分支或删除聊天，不清空已学语言；分支也不复制出另一套学习进度。

学习记录引用的语言知识可以共用，但角色资料、共同记忆和师生闲聊不跨卡提供给新老师。由剧情生成的练习保留来源边界：新卡只沿用不含故事细节的学习结论，必要时换题，不把旧故事原文带入新请求。用户自己查看旧学习记录不等于授权把旧故事交给另一个角色。

“用户级”指当前宿主用户的持久空间，不是所有宿主账号共享，也不代表向其他用户公开。

### 4.2 最少必要持久事实

| 内容与所有者 | 为什么需要保存 | 生命周期与删除 |
| --- | --- | --- |
| Learning：各语言目标、自评、有依据的能力判断与教学/媒体偏好 | 重开后继续按用户目标教学；不能每次重新认识学生或重新选讲解语言、练习音色 | 用户可修改目标与偏好、删除某语言档案或清空学习数据；切卡不删除 |
| Learning：学习项及必要的题目、作答、帮助使用情况、反馈与来源 | 支持针对性复习、解释判断依据，避免把看过当作学会 | 保存有复习价值的证据，不无限归档每条闲聊；用户可移除学习项及其自有记录 |
| Learning：当前已保存课程、实际使用的材料节选、已提交作答与当前练习进度、开课确定的奖励档位/金额 | 重新打开后仍能读同一段、接着做，不因网页变化换题或因配置变化改奖励 | 结课后保留当前课件供追问；开始下一课时保留必要学习证据与完成凭据，释放其余课件；放弃课程不清空既有水平 |
| Learning：已提交的录音、必要原始音频及其资源引用（相应能力上线时） | 原始作答不可重建；回听、复核及恢复同一道音频练习需要实际声音 | 与课程/尝试绑定，删除时清理自有附件；不复制到主聊天媒体库，生命周期见 §11.5 |
| Learning：完成事实、结课小结与本次奖励依据、归属、额度 | 重开后可看收获、确认是否完成、恢复同一次领奖，不重复发币 | 随相应学习记录保留；删除不撤销既有收入，也不据缺失记录重新补发历史奖励 |
| Economy：已到账奖励流水 | 对应聊天余额和幂等结算的唯一资金事实 | 沿用账本生命周期；删除学习数据不删账本，删除聊天不删学习资产 |

不保存角色卡和世界书全文副本、网页搜索结果全集、API Key 副本、模型思考、完整请求日志或每个教学判断的历史版本。材料只保留实际使用且允许保存的必要内容与出处，不建设网页镜像库。

请求、候选评估、流式文本、选区、弹层、滚动和未提交输入属于运行内状态。返回页面保留输入；关闭/刷新前对未提交内容明确提示，不承诺未保存内容已进入档案。已保存的课程与作答不是后台任务快照，而是用户再次进入时需要继续的学习事实。

录音中的音频块、麦克风句柄、对象 URL、播放器位置、波形、合成在途请求同样是临时态。用户确认提交后，录音才作为作答资产保存；合成缓存仍归 TTS，缓存丢失不等于学习记录丢失。

保存失败不发布新水平；结果未确认时核实同一次保存，不让模型重新评估覆盖。用户移除学习项后，不在隐藏摘要里继续保留该项错题与熟练度判断。清空学习数据须确认范围；功能退场时清理学习自有用户数据并删除注册和目录，保留共享 API 配置及已确认的 Economy 流水。

## 5. 初次认识用户与老师选择

首次进入由老师引导简短了解，不要求先填完一张长表：

1. 想学哪种语言；已有档案则直接切换，不重新初始化。
2. 目前大概什么水平；允许回答“不知道”，不要求认识等级标签。
3. 想达到什么目标，例如日常交流、阅读原文、某项考试及目标水平；有考试日期可补充，不强制设置期限。
4. 通过一小段材料或短练习开始了解实际表现；结果只是初步判断，不冒充完整分级测试。

讲解语言默认沿用用户能理解的语言，允许修改；目标语言与讲解语言分开。是否能开声音、是否方便说话是当前使用条件，不是永久能力标签，不需要用户解释残障或个人原因。初始只问完成第一课所必需的内容，其余偏好在使用时逐步确定。

目标由用户决定，AI 可通过工具整理保存用户表达的意愿；能力判断依据作答逐步更新，二者不能混写。不能因一道错题擅自降低用户目标。用户能查看和修正自己的目标及自述，不需要阅读内部 JSON。

语言选择提供常用语言便捷入口，不因英语、日语是主要例子而冻结为仅两种语言。支持的训练能力应如实展示，不用一个语言下拉框宣称所有语言的发音和考试体系都已覆盖。

老师从当前已知人物中选择，也允许按姓名与必要身份补充。候选排除用户自己；卡名不等于人物姓名，不能直接把 `name2` 当老师。换老师不重测、不清空学习资产，也不必虚构与陌生角色已有亲密关系。

老师身份与朗读音色分开：用户可以选择适合目标语言的现有音色，不表示角色换人，也不承诺复刻 NPC 声音。老师引用只在所属聊天语境恢复；通用教学偏好按用户/语言保存，不建立跨卡可编辑人物档案。

## 6. 教学方法与学习判断

### 6.1 一次课有一个可解释的小目标

主循环是：接触材料 → 尝试理解或使用 → 针对卡点得到帮助 → 再独立尝试 → 之后换情境复习。

它不是每堂必须走完的固定流水线。老师依据目标和表现选必要环节；用户可要求解释、换例子、换题材、降低难度或今天少练一点。课程可以短，但不以发送消息数量替代完成学习。

- 理解检查可先允许中文回答，分清“没读懂”和“读懂但不会用外语说”。
- 单词、词组、句式和语法在材料中结合教学；出现明确薄弱项时做专项练习，不强求每课覆盖所有技能。
- 复述和总结有价值，但不是万能题型：它同时考理解和表达，需要分别反馈。
- 备考围绕目标考试的能力与可靠资料组织；日常学习围绕真实理解和表达。共用教学循环，不做两套割裂系统。
- 原文难度不合适时换材料或明确提供改写版；不把一整篇高难报道加中文翻译就称为适合初学者。

### 6.2 错题库与掌握库是学习记录的不同视图

使用同一份学习项与证据，不在两套库之间复制、搬运事实。界面暂称「学习记录」，提供待加强、待复习、已能独立使用等阅读视角，不做永久“毕业”承诺。

作答原文、提交和是否使用帮助由 APP 根据实际操作记录；AI 通过工具给出有对应证据的教学判断，不能自行补写用户答案、练习次数或“已独立完成”的事实。

- 标记“不懂”表达学习需求，不等于答错；看了解释也不直接计为掌握。
- 选择题答对只能说明本次识别正确，不自动证明写得出或说得出。
- 不同日、不同情境的独立理解题可支持阅读/听力理解，不要求为了证明理解额外写作。词汇/语法的独立运用仍需产出证据；听力有慢放、重听、文稿帮助时记录为辅助练习，不算独立听力成功。
- 得到提示、看过答案或同题反馈后再答对，与首次独立完成区分记录；不反过来改变第一次作答时的条件。
- 在隔开的练习中换情境独立用对，是更强的掌握证据。复习安排依据真实作答和间隔，不按离开天数机械降级。
- 同一表达的识别和主动使用可以表现不同；不把一个等级或单一进度条当全部能力。
- 只沉淀有教学价值的学习项，不把每个词、每次点击全部自动收藏。用户主动收藏的内容也可独立移除。

自由表达的反馈区分语义错误、语法错误、正确但不够自然、同样正确的其他表达。参考答案只是示例；不能把措辞不同全部打成错题。对有争议的判断，用户可点「有疑问」请老师复核；未确定的问题不继续作为确定错题传播，也不因此扣分或扣币。

复习是老师下次自然带回一个值得练的点，不是打开就看到几百条欠账。停学后用轻量尝试接上，不断签、不责备、不制造情感债务。

老师每次交流直接看到当前时间、到期数量及按到期时间排序的一页学习项，后续可分页读全。程序的复习日期只供选择教学重点，不替老师制定强制课表；更多学习项不会让最早到期的内容静默消失。

### 6.3 有学习方向，不是每天随机搜文章

老师围绕用户目标形成当前阶段的少量重点，例如听懂日常叙述、找出文章论据、写清事件先后。用户能看懂“为什么今天练这个”，也能选择专项或换题材；不预先生成几十节不可调整的长期课表。

每次安排兼顾值得回顾的旧内容和一个适合推进的新目标，比例随表现与可用时间调整，不固定每日单词数或强求每课都有新知识。短时间重复同一道题是练习，不包装成新的独立掌握证据。对已能独立完成的内容自然提高难度或换情境，避免永远做简单题赚币。

阅读理解、听觉理解、书面表达、口头表达分别积累证据；词汇、语法等知识点可跨这些能力复用。没有测到的能力保持未知，不由阅读等级推算听说等级。报考目标对应的能力要求与题型应有来源，正式测评与日常辅导分开，AI 不凭几次练习承诺考试分数。

### 6.4 反馈可复核，不用单一分数糊住差异

客观题可按已确认的答案规则本地核对，开放答案由模型解释判断；模棱两可的选项、缺信息的题目是教材问题，不计成用户错误。评估应与发布的题目、材料及本次作答一致，不能为迁就结果事后悄悄换题或改答案。

内容理解与表达形式分别反馈：意思对但语法有问题，不全盘否定；听写中的拼写与没有听懂区别说明；语音识别不确定时不能直接建立发音错题。复核有误就修正相应评估与学习判断，不保留互相矛盾的两套结论；保留原始作答，不建设无限版本档案。

## 7. 教材来源与联网边界

联网沿用 ebook 的工具调用方式：同一个角色老师保留教学与共同记忆上下文，自主搜索、读取文章并组织教学。关键词由老师提供，程序不为联网另拆上下文、增加检索审批或搭选材 Agent。程序保存实际节选和来源，区分原文、教学改写与自编材料。

Tavily 是找真实材料的重要入口，不是围绕剧情补资料的附属工具。选材同时考虑学习目标、语言难度和兴趣；BBC 等是来源示例，不是必须绑定的唯一媒体。考试要求优先核对考试组织等可靠来源，生成题不能标成真题。

**已查证的当前能力：** [Tavily 搜索实现](../../agent-core/tavily-search.js)请求 `/search`，使用 `include_raw_content: false`，向消费者提供标题、URL 与摘要；这不保证取得可用于精读的文章正文。[OS API 设置页](../apps/agent-api/ui/AgentApiApp.vue)当前隐藏 Tavily 设置区。后续实现必须验证正文获取及可达的共享 Key 配置入口，不能直接把摘要冒充全文，也不能据此复制另一份 Key。

教材明确区分原文节选、教学改写、AI 自编练习。真实材料显示来源与链接；改写标注改写，不把媒体名称挂到模型补写的段落上。只基于已实际拿到的内容出题；材料不足则换可访问来源，不绕付费墙、不编造缺失正文，不默认转载全文。

搜索只携带选材所需的主题、语言、难度等信息，不把角色卡、私人剧情、人物记忆或用户作答原文自动发给搜索服务。网页正文视为资料，不作为控制工具和改档案的指令；链接和引用按不可信外部内容处理。

没配置 Key 或获取失败时，保留已有教材与已提交作答，并提供配置、重试或明确选择既有材料/自编练习的入口。不静默改成伪称联网的新教材，也不把 API 错误记成用户答错。进入页面、翻阅已保存材料不重新搜索。

音频材料区分真实录音与 TTS 合成。取到 BBC 文章后用 TTS 朗读，应标为“原文节选 · 合成朗读”，不是“BBC 原声”；合成材料可以训练听力，不冒充真实播音、多人自然对话或正式考试录音。真实录音的文稿、说话人和时间对应关系只在来源可支持时提供，不让模型编造精确时间轴。

用户也可明确提供一段文本或来源链接作为本课素材，仍经过同一教材与练习流程；链接无法读取时如实说明。文件上传、音频格式及大小上限由实际接入能力确定，不顺手扩成全格式资料管理器。

## 8. 互动设计：老师对话与教学窗口

### 8.1 产品气质与页面关系

界面是清亮、有老师陪伴的现代语言 APP。用户主要面对老师这个交流者；需要看文章、听音频或操作练习时才展开对应窗口，不让学生在几套管理页面之间组织课堂。

- 延续 OS 字体；白色阅读面、墨色正文、清晰蓝色操作，深色采用中性炭黑与亮字，不铺蓝雾或灰绿蒙层。常规主标题约 20–22px，正文 15–16px；触控热区保留，视觉元素不随之膨胀。
- 主画面留给师生对话与常驻输入；材料、作答有专用窗口，不给每段文字套卡片。留白不补口号、英文眉题、常识说明或统计占位；不编造熟练度、打卡或学习时长。
- 本地图标采用语言对话意象，桌面图标与页面蓝色一致；不增加字体、图片服务或运行依赖。
- 主路径是「与老师交流 ↔ 教学窗口」。初次只选择语言、老师，目标和水平由对话收集；课件、笔记、目标、记录、收获与设置收进辅助菜单。没有五栏导航或独立备课仪表盘。

### 8.2 老师：不用自己组织课堂

进入后面对当前老师的连续对话。没有历史时可直接发言或点「开始交流／继续学习」；老师按已有目标和实际证据安排内容，缺什么就自然追问。学习目标的修改、想换题材或降低难度都可以直接说。

打开、返回、重看资料不调用模型；明确发言、开始交流或交答案才请求老师。不在每次打开时重新寒暄、搜索和测级；API 故障不影响已确认资产阅读，发送失败保留输入。

模型调用提示放在首次交流处；TTS 未开启在实际播放处提醒，保存/冲突/奖励问题就地提供恢复入口。既有笔记与老师讲解朗读仍可访问，不把管理入口铺满主画面。

老师回复的进度跟在最新对话下方，不占用顶部通知栏。输入区为同一表面内的文字框与发送键：单行垂直居中，多行自然增高，引用单独放在输入行上方；回复时原发送位置切换为停止。阅读较早对话时，新进度与回复不强行拉回底部。

### 8.3 教学窗口：内容按需展开

老师通过工具选择当前材料或练习，确认保存后展开一个窗口，并在对应回复下留下重开入口。窄屏为底部面板，宽屏为居中阅读/练习窗口；清晰显示来源和固定奖励。练习关联材料可展开，听力保留播放控制和显式文稿入口。

关闭窗口回到同一老师对话，不删除课件或未提交草稿。选段提问把原文带回主输入框，不另开一套辅导聊天；重开恢复阅读位置。工具读取与资产维护不会一律弹窗，只展开老师明确选出的教学内容。

想放下未完成的课时，直接告诉老师，由老师弹出「换一课」确认。确认后才准备新课，新课保存成功再替换；取消、请求失败或保存失败均保留原课。确认只对应当时那一课，旧对话中的入口不能覆盖后来的课件。

阅读交互：

- 桌面用文本选择、移动端用长按选择，出现「问老师」「标记不懂」；也可复制原句到提问框。日语等语言不依赖空格切词。
- 选中、划线、取消标记是本地操作，不自动请求模型。确认「问老师」才提交所选原文及必要上下句。
- 标记不懂后，用户可继续读，再集中提问或请老师据此安排练习；不每划一个词就弹一张词卡。
- 提问引用固定到本课实际保存的材料，不因网页刷新或模型改写而指错句子。重新选材不能悄悄替换正在作答的文章。
- 全文翻译不默认展开；需要时可主动请求。是否借助帮助是学习依据，不是羞耻标签或扣奖依据。

声音交互在同一课堂内，详见 §11：材料有可收起的播放条；选中短句可直接「听示范」；老师的说明可按需朗读。听力题先呈现声音和题目，文稿是明确的帮助入口，不在另一处卡片、老师气泡或无障碍替代文字中默认泄露答案。

### 8.4 作答：点击与打字各司其职

| 交互 | 教学目的 | 操作约定 |
| --- | --- | --- |
| 选择、匹配 | 区分含义、检查理解，降低表达门槛 | 选中后可修改，点提交才算作答；不选一次立即判错 |
| 选出原文依据 | 检查答案是否建立在阅读理解上 | 选句或段落并确认，不要求在手机上精确拖到某个字符 |
| 排序、填空 | 定向练习容易绕开的结构与表达 | 排序提供点选/移动按钮，不仅支持拖拽；填空允许合理变体 |
| 改写、补一句 | 在有支架的情境中主动使用 | 有明确目的，不只要求猜出唯一参考句 |
| 简短回答、复述、观点表达 | 检查理解与独立组织语言 | 按练习目的打字或录音提交，分别反馈内容与语言；不凭篇幅或高级词数量打高分 |
| 听后选择、听写 | 检查听觉理解与声音到文字的转换 | 支持重听、慢放和请求文稿，实际使用的帮助进入评估条件 |
| 跟读、口头回答 | 练习声音模仿或独立口头组织 | 示范、录音预听、提交分开；有何种音频依据才给何种反馈，不靠点击完成假定发音正确 |

这些是同一课堂里的少量原生练习组件，不是各自独立的模式或题库。AI 组织教学内容，APP 负责确定的选择、输入、提交和反馈；模型不生成任意 HTML、CSS 或可执行界面。

有提示内容的题目提供「给点提示」，每题可看解释或先跳过。提示逐步帮助，不一开始给完答案；看过答案后可以换一个例子再试。用户随时能暂离或放弃，不被“必须答对才能退出”卡住；中途退出保留进度，不等于自动结课领奖。

作答区根据当前练习呈现实际需要的输入，不用“文字/图片/语音”三态菜单代替学习方式。录音是明确的开始、停止、预听、重录和提交；停止录音不等于发送。允许打字替代的题要说明替代后实际练到的能力，不能把打字答案标成口语评估。

### 8.5 反馈、收束与下次继续

提交后保留用户原答，再给出本次最值得改进的少量内容：哪里理解正确、哪里有问题、为什么、可以怎样再试。先保证回应具体有用，不逐字挑刺，也不无条件夸奖。

老师依据真实作答和反馈判断小目标是否完成，通过工具收课；不要求固定两题或用户另点结束。成果保存成功后自动按既定金额结算，实际到账才显示到账提示。本次收获简短展示“练了什么”“哪些已经能独立做”“下次值得再练什么”，可主动展开，不是领奖必经页。完成学习不等于已经独立掌握，不强迫每次做完长课才算认真学习。

结课后仍可留在课堂追问，不强制跳页，也不因继续提问拖延结算或再次奖励。老师的收课口吻可以亲切、有角色感，但不能把尚未确认的保存或记账说成已到账。

学习记录中可打开相关题目、自己的回答、解释和来源，并主动再练；再次尝试保留必要的变化依据，不覆盖成仿佛从未出错。记录按用户需要服务复习，不做无限对话档案。

返回恢复当前运行内的阅读位置与输入。重新打开恢复已确认课程，已结课的当前课件仍可查看和追问；后续交流中老师可以开始下一课，保留旧课必要学习证据与奖励凭据。尚未完成的课只能增量调整，放下整课仍需用户明确操作；同一轮不能结课又替换刚完成的证据。

### 8.6 一次完整体验示例

以下是产品流程示意，不是真实模型效果或 BBC 原文：

1. 用户已有英语档案，想提高阅读与简短表达；选择当前故事中的熟悉角色做老师。
2. 点击开始，老师依据目标取一段可核实来源的短文，说明本次只练“找主要信息并简要转述”。
3. 用户标出两处不懂，先做一个理解判断，再在原文中选出依据；没有被迫先用英语写长文。
4. 用户写两三句概括。老师发现理解正确，但一个表达需要修正，给出解释和新的短练习。
5. 老师依据实际作答和反馈通过工具收课，留下有价值的学习项；保存成功后给所属聊天结算开课时展示的奖励，用户仍可追问。下次用不同内容检查能否独立使用。

老师可以有熟悉的口吻和恰当的共同记忆，但不把报道硬改成故事续写，也不每堂课都要求总结剧情。

同一材料还可以用于另一种课：先听合成节选并回答，再对照文稿解释卡住的地方，最后听写一句或尝试口头复述。它仍使用同一份教材、练习和学习项，不复制成“语音版课程库”；如果用户已经读过文稿，本次不能记成首次盲听成功。

## 9. 学习奖励与跨存储边界

只奖励，不惩罚：完成有意义的学习单元、认真修正、完成复习均可成为奖励依据；错误、看提示、跳过或缺席不扣币。不按字数、耗时、对话轮数、点击次数或正确率发币，不通过模型输出的金额直接入账。

奖励确定为短练 20、常规 40、深练 60 小白币，看学习量及相对本人水平的挑战，不把高语言等级天然算成高奖励，复习也不天然低一档。老师备课时选档，程序映射金额并在开课时展示、保存，结课不能随口加减。

奖励不与拥有麦克风、付费音色或特定模型绑定；不同可用方式都应有合理的完成路径。重复播放、反复重录和单纯耗时不单独刷奖励；“完成练习”和“证明掌握”仍是不同事实。

老师有教学结课权：依据本课真实尝试和反馈提交结课小结，程序校验实际依据、确认保存，再通过 Economy 自动结算；没有额外的完成/领奖按钮门槛。小目标已得到充分练习即可，不要求全答对或固定题数；无作答、仅聊天或播放不能凭一句结课话术获得奖励。**用户级学习存储与聊天 sidecar 不在同一个文件事务里，不能宣称学习进度与发币天然原子。** 产品要求如下：

- 奖励绑定学习单元开始时的稳定聊天身份，界面说明归属；改名不改变归属，切卡不能把同一奖励转到另一张卡。
- 正常结课且钱包已开、归属聊天可写时自动结算；钱包未开则保留成果，提供「开通钱包并领取」，不擅自开户。结课后继续追问不延迟或重复结算。
- 保存学习失败，不发奖；学习保存成功、发奖失败，学习仍然完成，就地提供领取/核实入口，不要求重学或重新评估。
- 完成事实保存本次确定的奖励意图，账本按同一完成标识幂等记账；重试、重新进入、反复看结果或复制故事分支，不产生第二份学习完成资格。
- 切聊天、关 OS 后未提交的调用停止；已发出的保存或记账按实际结果核实，不假装已经撤销。回到归属聊天才能继续领取，不偷偷写另一个当前聊天。
- 归属聊天被删除时，学习成果仍保留，不能自动把未领奖励转到别处；已有奖励遵守 Economy 的分支与删除语义。

不新建通用跨库事务框架、持久任务队列或第二本钱包。施工时须证明“完成事实 + 现有账本幂等”足以处理重开与未确认状态，再冻结接口；这是必要的数据安全检查，不是扩建学习系统的理由。

## 10. 调用、失败与无障碍体验

- 显式交流、开始/继续教学和作答后老师续教调用模型；打开、阅读、选中、导航、已有提示/反馈不调用。客观题先按答案键核对并保存，再把真实原答与核对结果交给同一老师；老师可解释、拿出下一题或结课，不重复生成已有判断。续教失败不丢已保存原答，恢复不要求重新作答。
- API/联网出错就在当前动作附近解释，保留材料和作答；重试同一意图，不重复收答案或再次计奖。重新进入不自动重复失败请求或弹同一通知。
- 保存未确认时可阅读已确认记录，但不继续发布依赖该结果的新水平或奖励；核实优先于重新生成。技术失败不进入错题库，不降低水平。
- 同一会话核实成功后接回原来的老师回复和教学窗口，不清空已有对话、不再请求模型；未提交的新输入保留。整页刷新或明确放弃该会话后不承诺恢复临时回复，已保存资产仍完整保留。
- 切卡、换语言、换老师时，取消尚未提交的所属运行并隔离迟到回复；已确认学习事实保留。新老师不接收旧老师私聊全文。
- 320px、390px、桌面及深浅主题都可阅读；支持文字放大、键盘选择和提交。选区动作之外有可发现的替代提问入口，不能只靠悬停、手势、红绿颜色或拖拽。

声音相关调用另作区分：用户点击朗读可能发起 TTS 请求，但不应再调用教学 LLM 重写原句；已有音频的暂停、倍速、重听是本地播放；开始录音只请求设备权限，确认提交后才可上传给明确支持的服务。看字幕、放慢速度等帮助可在提交时一并记入必要事实，不每次操作都保存一条事件。

同一题的练习内容、已提交尝试和待评估结果分开：评估失败可用同一尝试重试，材料不重搜、录音不重录、奖励不重领。媒体失败只阻断依赖该媒体的动作；后台晚到的合成、识别结果不能跳回旧题、播放出声或改写当前语言的学习记录。

## 11. 声音与多语言：完整设计、按能力交付

### 11.1 已有底座、缺口与复用位置

以下结论来自 2026-09-06 的代码核实，不代表已经通过真实供应商、浏览器或教学质量验收。

| 能力 | 当前事实与证据 | 学习 APP 的决定 |
| --- | --- | --- |
| 文本合成 | [TTS 外部接口](../../tts/tts.js)的 `xiaobaixTts.synthesize` 返回 Blob，接收音色、情绪、取消信号和本次语言/合成语速，复用已有缓存 | 直接消费合成能力，不另写供应商请求，不用教学模型生成假的语音结果 |
| 目标语言音色 | [现有音色列表](../../tts/tts-api.js)含英式、美式英语与日语选项；TTS 还支持配置的鉴权音色 | 英日示范有现成基础；其他语言按实际音色与试听验证，不仅凭音色名宣称质量 |
| 教学播放控制 | [TtsPlayer](../../tts/tts-player.js)提供暂停/继续、倍速、跳转、进度和释放；facade 的 `createPlayer()` 与主队列、即时语音共享同一 TTS 播放所有者 | 复用播放器实现，以课程自身的实例/句柄管理播放；不改主聊天实例的回调或队列 |
| 消息式即时播放 | [playTransientVoice](../../tts/tts-playback-runtime.js)是单条即时播放，当前调用只传文本/情绪并返回停止句柄 | 适合参考生命周期，不足以直接承担逐句重听、选音色、暂停与倍速；不把信息/四次元壁的语音气泡照搬为课堂播放器 |
| 合成参数与设置 | facade 的 `getVoices()` 只读投影音色和可用性，不含密钥；外部合成的 `language` / `speed` 只覆盖本次请求，省略沿用全局设置，结果参数参与缓存键 | 不为上一次课改掉全局语言/语速，不让 iframe 或模型读取密钥；音色可选不等于实际语言质量已验收 |
| 合成取消 | 免费请求及[鉴权完整下载](../../tts/tts-api.js)均传递 AbortSignal；TTS 清理会取消外部合成、释放所有播放客户端；缓存迟到也检查失效 | 固定网络/媒体边界测试已过，真实宿主切换、供应商取消和浏览器音频仍待验收 |
| 录音与识别 | 本扩展业务代码未查到完整 `getUserMedia` / `MediaRecorder` / 转写流程 | 录音是浏览器采集，转写是独立服务能力，分别验证与接入；不是 TTS 的隐藏功能 |
| Agent 音频输入 | 现有部分宿主适配出现音频映射，但 [Google 直接适配](../../agent-core/adapters/google.js)、[Anthropic 直接适配](../../agent-core/adapters/anthropic.js)的普通输入转换目前只处理文字与图片 | 不宣称共享 Agent 已统一支持录音；未知/不支持时不把音频硬塞入每轮教学历史 |

实现优先复用合成与播放器已有代码。学习 APP 的音频资源、课程操作和录音保存在自己的边界；若需要播放器的暂停句柄、可用音色或最小播放互斥入口，扩展 TTS 的通用媒体接口，不把听写、评分、老师身份塞进 TTS，也不扩建全 OS 多媒体框架。

### 11.2 第一批就按正式功能设计的声音互动

| 用途 | 用户怎样用 | 教学与记录边界 |
| --- | --- | --- |
| 老师讲解朗读 | 点某段说明旁的播放，文字仍可见；连续语音辅导须主动开启 | 声音服务陪伴与理解，不因播放结束就增加掌握度；听力题不能自动朗读尚未揭示的文稿 |
| 单词/短句示范 | 选中片段后点「听示范」，可以重听或慢放 | 朗读本课实际文字，不另调 LLM 改句；中文解释与外语示范分段选合适音色 |
| 听后理解 | 先听片段，再选择或回答；主动请求文稿时切入辅助理解 | 可以使用合成材料，须说明来源；看过文稿的尝试不能当作纯听成功 |
| 听写 | 听短片段后输入，提交后对照与解释 | 记录本次是否慢放、重听、看文稿等必要条件，不把一次拼写错直接推成听力差 |
| 跟读练习 | 听一句，暂停后自己跟读，再听示范；录音可用时比较自己的声音 | 无录音/音频评估时仍能练，但只表示做过自练，不给虚构发音分数 |

播放条提供播放/暂停、进度、重听和本地倍速，时长来自真实媒体元数据，不按文字长度假算精确秒数。完整段落播放与短句示范分清；TTS 可按确定的句段分别合成以支持逐句重听，真实音频只有可靠分段/时间标记时才显示逐句跳转。没有时间对齐就用普通进度条，不生成假的逐词高亮。

同一道听力练习使用确定的文本和播放版本；用户改音色或重新合成时不能悄悄替换已经提交的尝试依据。普通复习允许重新合成，但不宣称与之前的原始波形完全相同。合成原文、音色及实际来源作为材料信息，临时对象 URL 不进入存档。

语音默认由用户点击启动，不打开 APP 就出声。用户选择连续语音辅导后，只顺序播放本课已确认且当前允许展示的内容；打断、切题、进入录音或关闭 APP 时停止所属播放。浏览器阻止自动播放时显示可点击的播放入口，不自动循环重试。

### 11.3 录音、口头表达与转写的完整路径

录音可用时使用短轮次、轮流说话的辅导，不以实时通话、持续监听、打断检测或自动端点识别作为首个实现前提。

1. 用户点击录音才申请麦克风权限；提示当前正在录音，并提供明确停止与取消。
2. 停止后可本地预听、删除重录或提交；预听不上传，关闭前对未提交录音说明会丢失。
3. 确认提交后才将本次需要的录音交给已配置且支持的识别/音频服务，不默认发送全课音频。
4. 转写可用时显示识别文字，允许用户指出“识别错了”；机器转写与用户修正有来源区别，不覆盖原录音或冒充原声。
5. 老师针对本次真实可用证据反馈，再让用户尝试改进。识别失败只重试识别，不要求重录；录音清晰度不足时才解释原因并建议重录。

录音、转写、语言评价、发音评价不是同一个开关：

- **只有录音与播放**：支持跟读自查/回听，不能假装老师已经听懂。
- **有可靠转写**：可以讨论表达内容、用词和句法；用户修正过的文字只能支持相应文本判断，不能反推原始口语的流利度或发音。
- **有实际音频评估**：才可基于声音讨论相应的可懂度、停顿、发音等；需要真实支持与校准，不因模型接受文件就提供“口语 87 分”。

需要音频反馈的题，在开始前说明能力是否可用。未配置转写时可以明确选择本地跟读自练或文字表达练习，不让用户录完才发现整段无处提交。用户不方便开口时可换可完成的任务，仍有正常奖励；不把打字替代偷偷记作口语成功。

识别或音频服务结果只按需供本次评估使用；后续普通教学以已确认的学习事实和必要文本继续，不反复携带原音频造成不支持的模型连续报错。发生不支持/格式问题时可移除该待提交录音、改用文字或切换支持的服务；一份坏附件不能锁死全部学习历史。

### 11.4 设备、权限与声音互斥

录音入口可用性由安全上下文、浏览器权限、实际编码格式和服务支持共同决定；手机通过 HTTP 访问宿主、WebView 拒权、没有麦克风等都是需要实测的外部边界，不按浏览器名字猜支持。

采集归学习 Host 管理，UI 只发送明确操作和显示状态，不在域模型保存设备对象。现有 [OS iframe](../host/lifecycle.ts)只显式声明剪贴板能力，不能假定录音权限已接好；实施时验证宿主采集或明确的 iframe 授权路径，不用大范围放开权限解决单项能力。

开始录音先停下本课播放，避免把老师声音录成用户作答；停止录音立即释放麦克风轨道，保留预听所需的临时音频。取消、切聊天、切语言、离开 APP 或采集异常时释放所属轨道、临时音频和对象 URL；上传/识别失败则保留可重试的已录内容。录音中不偷偷预取并播放下一句。真实上传前让用户知道接收的服务及用途，不增加每句话都要确认一次的重复弹窗。

现有主聊天队列与即时语音是不同运行，不应假定已全局互斥。接入时在 TTS 边界补最小的所属播放协调：新的明确播放请求打断或暂停旧的语音，旧页面的迟到回调不能把新的播放状态清掉；不通过清空主聊天队列、覆盖全局回调或关闭整个 TTS 开关实现。若全局主聊天朗读已暂停，学习结束不擅自恢复出声。背景音乐不属于本课播放器，不顺手接管音频控制模块。

### 11.5 音频资产与删除恢复

分清三类资源，不能统一往学习 JSON 塞 Base64，也不能全部当作随时可丢的缓存：

- **可重建的合成声音**：复用 TTS 缓存；学习记录保存必要文字和声音来源。缓存不可用时明确需要重新合成，不能悄悄切到另一音色还声称是当时录音。
- **本次题目实际使用、需要保真的源音频**：若要支持中断恢复或逐段复核，在授权允许的范围内保留必要片段与引用；无法合法保留的材料不承诺永久离线回听，不能仅凭随时可能失效的远程链接设计恢复。
- **用户确认提交的录音**：不可重建的作答，由学习 APP 在当前宿主用户空间持有独立资源，尝试只保存引用、真实元信息及必要转写。未提交的预听录音仅在内存，不持久上传。

音频上传与学习记录也不是天然原子：资源保存并确认后才能发布指向它的作答，评估失败不重传已确认录音；资源状态不明先核实，不先显示已保存。由学习 APP 清理已上传但未被记录引用的自有资源，不擅自删除共享媒体或 TTS 缓存；具体文件接口和清理证据在施工时验证。

用户可删除某次录音而保留题目及文字作答；依赖声音的反馈须显示原音已删除，后续不能再声称据该音频重新验证。删整次尝试/课程/语言档案或清空学习数据，一并处理其独占附件与引用。完成事实与既有奖励仍遵守 §4、§9，不因为删除音频扣币。共享合成缓存由 TTS 自己过期/清理，学习数据清空不伪称已经删除共享缓存中的所有副本。

### 11.6 多语言与能力缺失时的体验

共用的是目标、材料、练习、反馈与复习循环，不是假定所有语言同一种教法。英语拼写与时态、日语假名/汉字读音与敬语等需要对应的题材与反馈；等级体系也不能随意互换。发音示范优先选择适合目标语言的音色，实际试听失败或质量不适用就说明并换音色，不以角色气质优先牺牲示范清晰度。

能力信息细分为“可朗读、可播放材料、可录音、可转写、可做哪些音频反馈”，而不是一个笼统的 `voice=true`。它由已知接入与本次设备条件得出，不在每次打开时调用供应商自动探测，不把这些临时能力写入用户的长期水平。

TTS 未启用时，阅读与文字练习仍然完整可用。朗读和听力入口明确提醒「使用语音前，请先开启 TTS 模块」，操作时就地引导，不自动启用或在重进页面时反复弹通知。模块关闭与暂时合成失败分别说明；后者保留同一道题，可重试或明确转为另一训练。没有文稿的真实音频不能伪造文字替代；读过替代文本后也不能再把该次表现归为纯听力。尚未实现的录音/评估能力不显示假按钮，但课程、作答和证据模型从第一版就遵守上述独立边界。

声音设置与播放失败处均提供启用引导；模块关闭时说明宿主开关位置，启用后再提供音色设置入口。不会显示一个名称承诺打开设置、实际只能重复“未启用”的按钮。

## 12. 后续验证与留后事项

先验证一堂真实可用的课，而不是先铺全技能大厅。最少需要覆盖的稳定契约：

- **教学与真实模型**：初学与较熟练用户、英语与日语样本；未知水平、理解正确但表达弱、合理答案变体、提示后答对、短期复习和隔时迁移。真实输出不能手改后冒充效果；练习完成率不能冒充提分证据。
- **资料与外部协议**：Tavily 从检索到足够正文的实际可用性、来源/改写标注、不可访问网页、缺 Key 与服务故障；私人故事不作为搜索词外发。
- **资产与奖励**：切语言、换老师、分支、删除聊天后的进度隔离；真实单题可结课、无作答不能结课、对错/提示不减奖、开课金额固定；结课保存失败不发币、正常自动结算、发奖失败只补领、未确认核实与同一奖励去重。
- **交互**：完整走一遍标记、提问、作答、反馈、复习；验证本地题后的老师收课、无手动完成门槛、结课后继续追问、中途退出恢复、移动端文本选择、键盘替代、返回位置与已有内容阅读不产生模型请求。
- **TTS 真实接入**：英日示范、音色选择、合成缓存命中/失效、暂停/慢放/重听、播放互斥、自动播放被拒、合成取消与切卡后晚到结果；确认不改全局设置、不污染主聊天队列。
- **教学证据**：先读后听、先看文稿再作答、重听慢放、转写经人工修正、录音删除等条件不会变成虚假的独立听说掌握；声音服务失败不记为学习错误。
- **录音能力上线前**：桌面/手机/WebView 的权限与编码、预听不上传、重录删除、轨道释放、上传未确认、识别失败后重试、附件清理及不支持音频的 Provider 恢复。

当前不建设：学校/班级系统、排行榜、打卡惩罚、订阅推送、完整考试题库平台、云端网页收藏库、无限师生聊天档案、实时语音通话、未经验证的发音打分或主剧情联动。这些边界不排除已有 TTS 支持的正式听力与朗读功能，也不删掉录音作答的终态设计。

上述底座的源码核实、Tavily Extract 官方协议核实、确定的接法和实施前验证门槛已记录在 [语伴施工方案](./language-learning-app-implementation-plan.md)。源码与协议可用不等于真实服务验收；录音、识别及音频评价分别列证据，不用一种能力的成功替另一种背书。

## 13. 防止返工的开工约束

以下不是预埋功能清单，而是第一版就必须遵守的边界：

1. 用户级学习事实与聊天级剧情/资金分开；课程进度不落进卡内聊天记录。
2. 材料、题目、尝试、反馈与学习项有清晰引用；题型和媒体形态不决定资产归属，不复制多套进度。
3. 原始作答和模型评估分开；媒体来源、输入方式、帮助条件和可评价的能力保持一致。
4. TTS 合成复用现有模块，课程播放有自己的所有权；录音、识别、发音评估不是 TTS 的同义词。
5. 教材声音、可丢合成缓存和不可重建的用户录音有不同生命周期；先确定可恢复/可删除方式再实现上传。
6. 本地交互、媒体调用、教学模型请求和持久保存分开；失败重试相应步骤，不重跑整堂课。
7. 同一次学习完成及奖励有稳定身份，跨用户数据与聊天账本的未确认结果可核实；不引入第二钱包或分布式事务框架。

可分批交付控件与服务接入，但任何一批都不能以“现在只有文字”为由把终态压缩成聊天消息加一个熟练度数字。新增录音时应扩充作答载体和媒体适配，而不是推倒档案、课程、复习与奖励。尚未启用的具体格式不预建兼容壳；本功能仍是测试线新设计，无自己的旧实现需要兼容。

产品主线是：**真实材料与可操作练习是主体，角色用文字和声音辅导；学习资产随用户积累，小白币在所属聊天奖励。**
