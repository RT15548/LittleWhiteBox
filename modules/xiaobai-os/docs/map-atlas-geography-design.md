# Atlas 通用空间地图：最终设计

状态：按 2026-09-27 已批准的 Atlas 重整方案更新。GPU 候选实现与验收缺口见 [重整验收记录](map-atlas-gpu-verification.md)；未完成必要验收前不替换发布构建，不宣称整体完成。

本文是世界／地区地图的空间模型、题材覆盖、投影、绘制和关联编辑的唯一规格来源。[施工文档](map-atlas-implementation-plan.md)只记录实施位置、顺序、检查与证据；[Map APP 总体设计](map-app-target-design.md)继续拥有产品入口、维护触发、主 RP 摘要和存储安全规则。

## 1. 终态结构与所有权

Map 领域拥有地点、路线、空间要素和坐标关系；Atlas 界面消费统一只读投影；Scene 独立负责具体地点内部。全部长期事实进入原 `map` 分区，不建立第二套地图状态、题材存档或渲染存档。

### 1.1 题材无关，不是地球地貌专用地图

“世界”指故事最外层的探索空间，不等于大陆；“地区”指其中的探索分区，不只指行政区。海域、星区、巨型建筑分区、飞船甲板都能承担地区角色，不靠它们的名称猜层级。

第一版的通用空间表达能力不低于现有 Scene：自然、城市、水上／水下、室内巨构、飞船／空间站、太空和幻想空间都属于交付范围。题材通过空间语义、几何和材质组合表达，不为每种题材建立独立模型、工具、渲染器或“地图模式”持久字段。

第一版 Atlas 使用固定朝向的二维俯视／平面投影，通过材质、明暗和有界符号表达空间；不增加可旋转三维世界沙盘、球面地理、天体运动或物理仿真。Scene 已有二维／三维出口保持独立。题材覆盖不等于为所有事物提供专属三维资产。

### 1.2 AI 与插件的分工

| 责任 | 所有者 |
| --- | --- |
| 有什么、范围／走向／位置、空间类别、材质、所属地图、已知连接和承载关系 | AI 根据设定和已知事实提交；新增合理空间仍受总体设计的证据边界约束 |
| 坐标正逆转换、组合投影、几何校验、裁剪、遮罩、稳定细节、标签与全图范围 | 插件根据同一份空间事实计算 |
| 树冠、屋顶群、山纹、金属分缝、水面纹理等表现细节 | 插件生成，不产生可探索实体或长期事实 |
| 原子编辑、删除引用清理、版本转换、保存确认 | Map 领域与既有存储流程保证，不靠 AI 自行遵守事务步骤 |

AI 不负责逐棵植树、逐栋填满城市、计算多边形布尔运算、维护各地区的河流副本或手算所有关联坐标。程序也不替 AI 猜失落的空间映射、真实入口、桥梁或已发生的到访。

### 1.3 开工边界

- `domains/map`：当前格式、空间语义、不变量、坐标运算、浏览成员及可绘制内容的纯投影。
- `apps/map`：维护与管理员接入、工具编译、UI、材质与装饰生成；不另存空间事实。
- 几何／材质仅在语义相同且有真实消费者时共享。不能把 Scene 的家具、人物或生命周期实体直接搬成 Atlas 的空间要素。
- 沿用 Map 分区、Host／Shell、维护与管理注册入口；不增加核心层地图业务。
- 利用现有 Three.js 建立 Atlas 专用正交俯视出口，SVG 保留地点交互；不套用 Scene 内部模型，不新增地图服务、远程素材或运行依赖。像素倍率、按需帧调度和资源所有权在两个真实渲染消费者间共享，不改变 Scene 外观。
- 删除功能仍是移除 Map 目录和注册，再一次清理 `map` 分区；共享通用资产按现有所有权保留。
- 真正需要兼容的对象是宿主／WebView、供应商工具协议和用户明确保留的现有地图；不为自己的旧实现保留永久运行分支。
- 最少必要验证由第 10 节定义，不以测试数量或代码接通代替验收。

| 长期事实或临时数据 | 所有者与生命周期 | 失败与删除 |
| --- | --- | --- |
| 地点、路线、人物位置、Scene | Map 领域；跨重启保留故事与探索事实 | 沿用既有身份、保存安全和第 6 节依赖处理 |
| 坐标框架、映射、地图空间边界 | Map 领域；框架明确归属 Atlas 或某个地点，空间不随页面销毁 | 非法编辑拒绝；删除处理所有存活引用 |
| 空间要素及明确的承载／跨越关系 | Map 领域；稳定 ID、所有者、坐标框架和几何，不能从显示范围恢复这些事实 | 不随关联入口或页面销毁；按第 6 节处理 |
| 投影、掩码、细节、标签布局、视口、空间索引 | 当前运行内派生；资源随视图生命周期释放 | 不持久化，不新增缓存实体、恢复日志或地图截图 |

## 2. 包含关系与坐标关系

### 2.1 两种关系分别记录

- 地点 `parent` 只表达包含关系，决定地区归属和浏览成员，不隐式指定坐标框架。
- Atlas 的每个坐标与几何明确引用所属框架；框架 ID、地点 key 与视图 ID 分开。Scene 仍使用自己的内部几何，不因本次升级合并坐标。
- 坐标映射独立于地点包含树；改变包含关系本身不重解释坐标，也不自动建立映射。
- 第一版只支持固定朝向、平移和正的等比缩放。地表图北向上；其他题材沿用明确的二维参考方向，不强行赋予地理北方。不支持跨框架旋转、镜像、非等比缩放或透视。
- 子框架点到父框架为 `p_parent = s * p + t`，逆向为 `(p_parent - t) / s`；只存一份参数，多级正逆变换由它派生。
- 框架与映射引用必须存在、无环，比例有限且大于零，平移和源／投影几何满足统一数值约束。缺少映射是资料未确定，不默认单位变换。
- 楼层、甲板、星区之间的可达关系不等于共面映射。没有明确转换路径时，只保留关联和各自本地空间，不能因数值相近把内容叠到一起。

### 2.2 地图空间边界不是视口

地区空间边界是明确几何，用于裁剪跨区投影；它也不等于城市建成区、海岸线或房间墙体。相同边界确实服务多个用途时引用同一几何，而非复制数值。

`viewBox`、全图包围盒、缩放倍率、屏幕尺寸及可见地点集合均不参与解释映射。增加远山、空间站或其他远处要素可扩大“全图”，但不移动已有空间点；普通更新保持用户视口。

只有完整转换路径和明确地区裁剪范围都存在，才能显示外部空间的局部投影。缺少其中之一时保留已知本地内容，不复制、拉伸世界图到任意矩形中冒充当地空间。

## 3. 通用空间要素

### 3.1 基础表达与语义

面积、边界、线／带和点是基础几何；环境介质、地表覆盖、地势、人工结构、通道、地标和特殊区域是空间语义。矩形、圆形、开放／闭合轮廓及经过给定节点的曲线均有正式表达；开放线不能被擅自闭合，轮廓不能被包围盒替代。

材质描述表面，类别描述空间用途，几何描述形状，三者独立组合。首版覆盖现有 Scene 已有的通用材质语义，并提供 Atlas 所需的地势、聚落和环境表达；不能只给海洋、太空换一张背景就算支持。材质与绘制规则是集中定义的闭合词表，不接收任意 CSS、SVG、URL 或着色器。

| 内容 | AI 提交的空间信息 | 插件的表现职责 |
| --- | --- | --- |
| 陆地、沙地、冰雪等覆盖 | 范围与表面语义 | 表面纹理和轮廓 |
| 山地、峡谷、山脊 | 范围及主要走势 | 有方向的地势明暗、山纹；不伪造测量高度 |
| 森林、植被 | 覆盖范围及已知类型 | 有界树冠与植被纹理，不逐棵建地点 |
| 水体、河道 | 面积或中心走向与空间宽度 | 水面、河道成形与岸边表达 |
| 城市、村镇、设施群 | 建成区范围、已知密度与建筑形态 | 屋顶／结构块面，不凭空创建街道或目的地 |
| 人工基底、甲板、墙界、桥面 | 面或边界，以及必要的承载／跨越关系 | 木石／金属结构、边界与接缝 |
| 道路、走廊、航道 | 真实走向；有实际宽度时提供宽度 | 通道外形、交汇与轮廓，不自动推断可达性 |
| 星域、天体、小行星带、星云 | 有界范围、位置或分布走向与语义 | 空间背景、轮廓、稳定群集符号 |
| 浮岛、裂隙、传送区域等 | 明确范围、语义、已知连接 | 通用几何与材质表达，特殊外观不自动生成连接事实 |

没有专属图形配方的对象，按明确的通用类别、合法材质、原轮廓和名称绘制。这是正式基础能力，不丢弃对象，不猜成森林、城市或家具。

### 3.2 城市与真实地点

地区范围、建成区范围和可探索地点分别表达。一个地区可同时包含城市、港口、森林、河流；城市也不必固定成为新的浏览层级。不增加第四颗“城市地图”按钮。

- 城市的名称、包含关系和到访状态继续由地点拥有；建成区只记录范围与概貌。表示同一对象的名称引用地点，不能维护两份。
- 有依据时提供低矮密集、规则街区、高层集群或分散村落等形态；程序不从名字猜时代或建筑风格。
- 背景屋顶和结构块面是材质细节，不创建独立地点 key、名称、点击入口、搜索条目或到访状态；不能与真实地标使用同一套交互外观。渲染所需的细节标识只是源要素派生的临时数据。
- 真实酒馆、车站、医院等复用已有地点身份。只有位置就画位置标记；有明确占地才画真实占地。占地只保存一份，绘制和细节避让引用它。
- 背景建筑避开已知水域、道路、公园及真实建筑占地；街区缝隙不能冒充真实可通行巷道。
- 城市总体组织属于 Atlas，具体地点内部继续由 Scene 表达，不在地区图生成桌椅、房间或 NPC 副本。

### 3.3 连接事实与线路几何

路线的端点、方向性和可达关系仍由 Map 路线记录拥有。其真实道路／航道走向若有记录，则引用唯一的线路几何，不在路线和空间要素中重复保存点列。

只有连接、没有走向时仍可在详情读取关系，但不自动在地理底图补成实体道路。缺少可定位端点的地点路线不画假端点；独立记录的河流或不绑定地点的线路仍可按自身几何绘制。交叉的两条线不自动连通，跨水的连接也不自动变成桥。

### 3.4 所有权、坐标、承载与显示分别处理

- 每项空间要素有稳定 ID、明确所有者、源框架和几何；改名、关联目的地、当前视图或显示比例不改变身份。
- 所有者控制生命周期；源框架解释坐标；明确的承载／跨越关系解释局部组合；浏览范围决定显示哪些投影。它们都不能由地点 `parent` 或可见性互相猜测。
- 跨区河流、航道等由共同上层地图拥有，只保存一份源几何。地区显示转换并裁剪后的结果。
- 森林入口可以关联森林，但不拥有整片森林；删除入口只清关联。
- 海岸轮廓由已记录的陆地／水体边界组合派生，不维护独立海岸线。未知边界不能从视口矩形补出。
- 承载／跨越关系只在确有多层空间含义时记录，例如桥面跨河、人工甲板位于水面上；不暴露任意绘制层号来让 AI 排画面。关系必须有依据、无环且引用完整。

## 4. 统一投影与浏览行为

统一投影分别给出本层全部地点、可定位标记、可绘制线路、空间要素、结构化未定位原因及完整可绘制范围。它们来自同一份事实，但不是同一个集合。

- 顶部沿用世界／当前地区／当前场景。世界的地点成员只有地区，地区的地点成员只有归属该地区的具体地点；具体归属和到访推导遵循总体设计。
- 空间要素的浏览归属由语义所有者的最近地区决定，与表达坐标的框架独立；具体地点的建筑占地归该地点所在地区，尚无地区的具体地点占地不能成为世界地貌。
- 世界只绘制世界级地貌、可换算的地区边界概貌和地区入口。地区内建筑、道路、装饰不进入世界绘制、标签或全图范围，放大也不展开。
- 地区绘制本区要素；映射与边界均已知时，裁剪显示世界级地貌。其他地区的细节不进入；明确承载／跨越依赖的外部几何仅参与遮挡，不因可换算而获得绘制资格。
- 横幅、列表、筛选和搜索使用本层全部地点，不因无坐标或无 Scene 而排除。界面位置标记只使用可定位子集。
- 无坐标或转换路径未知的地点仍可打开详情、已有 Scene 和包含关系，不安排示意坐标、不假居中。未定位原因使用语义标识，文案只在表达层集中定义。
- 回到玩家位置按实际 actor 的层级选择视图：仅知地区时选中该地区；具体地点无法定位时打开其详情并保留未定位状态，不把地区中心当作精确位置。
- 只有空间要素、没有地点时仍显示地图、缩放和全图；零地点列表空态不遮盖图面。地区的“零地点”指本层没有子地点，不是删除地区身份。
- 全图考虑目标空间全部可绘制范围和必要视觉边距；地区只计本区裁剪部分，不能被整条世界河流撑大，也不能只计算当前视口已经生成的细节。
- 没有可绘制内容时才显示绘图空态，有地点仍保留列表和详情入口。未知资料和普通未定位不是阻断弹窗；读档／保存故障仍走既有错误路径。
- 打开、切换、定位、缩放和材质生成只读本地数据，不调用模型。普通更新保留有效浏览目标和视口；切聊清理临时浏览状态。
- 没有数字坐标支持的垂直、星际或传送连接可以存在；三层入口不强迫所有地图共享一个平面。

## 5. 绘制组合与稳定细节

### 5.1 介质与结构，不以陆地为全局底板

图层顺序负责可读性，空间组合负责含义；两者不能互相替代。未记录范围使用主题图纸底色，不补地形或星点。已知环境只有一种介质时，图纸可沿用它的底色以保持连续构图；底色不是范围外存在该介质的事实，覆盖情况由第 8 节的派生诊断表达。

| 组合 | 第一版规则 |
| --- | --- |
| 海域／真空等环境与其中对象 | 环境不要求存在陆地；人工结构、岛体或天体按自己的明确几何显示，不被环境全部擦除 |
| 同一地表上的水域、森林、山纹、城区细节 | 水域／河道从该地表的地面细节中排除交集，包含完整树冠、屋顶和阴影，不能只检查采样中心 |
| 明确的桥面、甲板、浮岛等独立承载表面 | 先依已记录关系组合承载面，再在该表面内绘制内容；下方水体或空域不能误裁上方内容，不自动推断通行连接 |
| 森林与山地 | 覆盖与起伏可以组合，不互相整片抹掉 |
| 同类覆盖交叠 | 主体与装饰作为完整图层按语义依赖和稳定 ID 绘制，不透明后层覆盖前层而不重复加深。不单独裁去后层装饰，也不引用隐藏同材质承载体来制造空洞 |
| 同层无法由语义确定的矛盾表面 | 返回结构化冲突，拒绝关联修改组；不按数组次序覆盖。AI 修正空间含义或关系，程序负责重算遮罩，不要求 AI 手工剪多边形 |

组合由集中定义的空间语义和明确关系决定，不以“水域永远最高”或题材专用分支处理。不同框架只有完成有效投影后才参与同一空间的组合。普通地图不需要额外声明承载关系来排序每一项。

### 5.2 同源细节，先生成再投影裁剪

树冠、屋顶、小行星装饰和山纹由稳定要素 ID 与源框架原始坐标确定。先定义源空间中的确定性分布，再投影和裁剪；不能按地区 key、视口、数组下标或每幅图独立随机播种。

- 相邻地区的同源内容能拼回同一份几何和细节分布。
- 缩放、拖拽、切图、改变输入次序或增加无关要素不重撒已有装饰。
- 按尺度显示同一确定性集合的稳定子集，不重新随机生成；可按源空间格子按需枚举，避免先遍历巨大地图。
- 地表与道路使用网格，山脉与沙丘使用源坐标上的有界起伏网格，树冠、屋顶与小行星使用实例化形体。山脉保留棱线，沙丘使用平滑明暗；细节只表达材质，不提供测量高程或新增通行路线。
- 区域轮廓、承载链交集、水陆排除项使用当前视口 GPU stencil。固定数量的 stencil 位可复用计算多级交集，不为每个要素分配整图位图蒙版。明确跨越关系不被承载体继承的下层排除项抵消；山地明暗与下方植被相乘，不整片覆盖树冠。
- 材质只用 renderer 内共享的小纹理，不逐地形生成 PNG、瓦片或图集。主体地形保留完整轮廓；只为当前层和当前视野生成细节，预算不足降低装饰密度和网格细分，不隐藏主体。
- 地貌缓存只在当前挂载内存活；结构键不包含名称、人物位置或到访状态。离开视野淘汰对应缓冲，关闭地图、切入 Scene、切聊释放 GPU 资源，不建立跨挂载的大型地貌缓存。
- GPU 模块加载前显示廉价纯色底图；图形失败明确报告，保留 SVG 地点导航，不启动旧重纹理链路。
- 装饰不产生地理事实。背景星点不变成天体地点，屋顶不变成建筑列表，纹理间隙不变成可达路线。
- 元素数、点数、细节数、采样和裁剪成本有界；上限集中定义，序列化体积继续受 Map 分区约束。不能静默截断真实几何来满足绘制预算。
- 仅复用 Scene 已证明适合的基础能力；Scene 当前林地配额依赖元素集合，不能直接声称已经满足 Atlas 跨图稳定性。

### 5.3 图面与交互

第一版用有材质、有轮廓层次的地图表达，不统一套绿灰地表。海水、金属基底、城市、雪地与太空应凭图面可区分，而不是靠长说明或只有主题背景变化。

世界／地区是连续地图，屏幕是观察窗口；Scene 是具体地点内部的布局。借鉴 Scene 的 AI／程序分工，不借用“把一个完整场景模型摆在中间”的构图。

- Atlas 画布铺到 APP 边缘，搜索、三层切换、定位和本层横幅浮在地图上；打开地点详情不缩小或重新解释地图。
- 有地形时初始视野展示可探索的局部空间，不自动缩成完整可见的小方块；纯地点图保持成员总览。当前点提供初始锚点，地理范围约束不必要的空白。
- “全图”是明确的总览操作，纳入全部地形并避开实际控件范围；定位同样避开当前顶部和详情遮挡。视口尺寸、控件遮挡和坐标映射各自独立。
- Atlas 的缩放、全图、定位和图例由同一个悬浮操作栏布局，不各自绝对定位。窄屏位于详情下方；宽而矮的 APP 窗口把详情侧置，按实际面板边界避让。响应条件取 APP 容器尺寸，不借用浏览器窗口高度。
- 图层几何可以有矩形边界，但包围盒不生成地理轮廓；海域、太空等环境的已知范围不能看起来像贴在 APP 背景上的另一张卡片。

固定排列环境／承载表面、覆盖与地势、结构及通道、地点标记与标签；组合关系可以形成局部子层，不能反过来修改源几何。真实地点和当前位置优先可读；程序细节不能挡住入口或伪装交互对象。

沿用 OS 字体、局部主题、拖拽／缩放／全图。窄屏不把地图挤成表单，不增加题材设置面板、第四层导航或解释墙。检查触控、键盘焦点、可访问名称、文字放大、返回与深浅主题；视觉通过必须检查真实生产组件。

## 6. 空间编辑、提交与删除

原子边界由空间依赖决定，不等于单个数组项，也不只等于地点父子链。

- 同次涉及映射、归属、源框架、承载／跨越关系、依赖几何或被引用对象的修改，按真实依赖闭包形成候选组，验证最终结构及存活引用。
- 同组一起接受或一起拒绝；非法比例、循环、悬空引用、越界几何或未完成的改框架不能留下半套修改。合法结果不依赖输入次序。
- 独立组可部分成功；共享一个不变框架不自动让所有无关对象成为一组。若框架本身被修改，则必须检查受影响对象。
- 改变框架摆放意味着整体移动其中内容；仅更换几何的表达框架则由已知映射转换坐标以保留位置。两种意图明确区分，正逆换算由程序完成，不让 AI 逐点重算。
- 返回的 applied／skipped 与实际接受的组一致。重建仍要求整轮候选成功，不能以部分组替换旧地图。
- 删除地区清理其及被删除后代拥有的空间要素和框架，沿用既有地点／路线／人物／Scene 级联；不删除仅投影流经此地的世界级河流等对象。
- 删除关联目的地只清理关联，不删除独立空间要素。所有权移交和依赖修正属于同组。
- 删除框架／承载表面前处理存活引用：坐标有明确转换路径才可转换，承载含义不能仅凭换坐标修复；不能解决则拒绝该组。不得猜坐标、悬空引用或连带删除无关世界对象。
- 通过领域校验的组进入 Session staging，最终沿用 Map revision 与 Kernel sidecar 原子保存。保存失败、结果未确认或迟到结果走既有安全栅栏，不新增日志或恢复状态。

## 7. 既有地图的格式转换

明确保留用户现有地图的地点身份与包含关系、路线、Scene、人物位置、到访事实及已记录坐标的原始含义，不为所有测试线旧实现建立永久兼容。

- 改格式前按现行类型、校验与已发布的字段契约冻结受支持输入格式，使用独立历史格式转换器；不能用新类型冒充旧版本。该格式的所有合法输入均属于支持范围，不由收集到的样本决定。
- 旧地图缺少新增地貌字段是正常输入：在读取入口转换为空空间要素集合，不凭空生成地貌。新增框架及引用不得损失旧事实，新增校验和序列化容量必须容纳合法旧输入的转换结果，不能让原本合法的地图因扩充而无法读取或保存。
- 实现方先完成格式覆盖、数据保留、边界与失败路径测试；用户后续提供的真实存档只做补充确认，记录来源且不修改样本来迁就转换器，不作为开工或声明该格式受支持的前提。若补测暴露缺陷，修复通用规则并补回归，不按样本身份添加特例，不把基本正确性的责任转给用户。
- 旧 position 按当时直接父级坐标契约解释。父地点的位置不是自动已知的局部原点，地点包围盒不是比例依据；不能把楼层／房间坐标直接铺到地区图。
- 缺少映射时，在当前模型中无损表示原局部框架和坐标，保持关系未确定。它是正常不完整资料，不是旧字段袋、迁移待办状态或渲染双读分支。
- 旧地点 terrain 的景观标签作为当前模型的合法地点属性保留，与独立空间几何分工明确；不能凭一个标签生成森林边界、城区面积或永久所有权，也不把其可区分值改写成模糊文本或另存旧格式副本。
- 无法投影的地点按第 4 节保留在正确列表，等待依据资料补全；不能删坐标、清 Scene、重置到访或静默重新绘图。
- 转换仅在读取／导入／升级入口执行，业务层只接收通过校验的当前模型，写入只输出当前格式。转换结果通过既有保存入口确认后替代旧格式，普通绘制不执行迁移。
- 转换不调用模型。解析或保存失败保留原存档并走现有错误路径，不发布半份结果。停止接收受支持旧输入格式须以明确完成的数据升级为依据，不保留旧 UI 或旧写入协议。
- 新版本号只是格式实现细节，不作为推断真实用户历史的依据。

## 8. 工具的两个真实消费者

沿用 MapAtlasRead／MapAtlasEdit 扩展空间事实，不另设“生成城市”“绘制地形”任务。Scene 工具仍负责内部布局。

- 普通维护与管理员共享模型、内容投影、编译校验和业务契约；各自只适配真实分页、草稿与保存包装，不覆盖整段共享描述。
- AI 日常操作面围绕“选择已有地图、提交空间要素、更新或删除指定 ID”组织。必要框架及引用随资料提供；创建地图所需内部标识由程序管理，不要求模型自行搭建实现级对象图。
- AI 给出少量轮廓／走向点和必要空间尺寸；插件完成曲线、带状面、裁剪和细节。新建合理空间与修复旧坐标是不同任务，未知旧映射不能随意补齐。
- 只有确需修正空间关系时才提供高层映射／换框架意图；依据明确锚点与比例计算。不能把投影矩阵、反向参数、裁剪片段、视觉层号或纹理控制暴露为日常维护任务。
- 初始资料和按需读取使用同一内容投影；按集合有界分页，清楚表示缺失、未定位和未内联，不把未列出当作不存在。
- 世界／地区记录附带派生底图诊断：是否有地表或环境、哪些已定位入口没有覆盖；摘要给出缺口地图数量，编辑回执给出相同计算的缺口。河流本身不替代主体底图，港口入口可以由水域覆盖。诊断只读，不保存完成标记，也不是画面质量分数。
- 维护与管理员先建立环境／主体地表，再建立主要地形、地区与入口，最后补当地细节。地点数量足够不代表地图完整；允许依现有设定补合理普通地理，事件、隐藏地点与未知坐标关系仍受证据边界约束。
- 工具读回的是源框架中的可编辑事实，UI 读的是投影及裁剪结果；不能把地区内的河流片段误写回整条世界河流。
- Schema、字段说明、维护指导、管理员入口和可执行示例一起更新。本文不复制实际模型提示词；实现阶段按真实字段写入唯一契约来源。
- 内部修参反馈给同一工具循环；用户只看到必要运行／失败／保存状态，不增加整理地图弹窗。查看或材质绘制不调用 API。

## 9. 在现基础上的实施边界

具体落点、顺序和交付关卡只在 [施工文档](map-atlas-implementation-plan.md)维护。第一步在正确领域边界内建立当前模型与升级入口，不能先在 renderer 塞地形 JSON、再计划拆回领域。

本轮实现范围包括完整通用空间表达、现有地图保留、世界／地区投影、两个工具消费者及第 10 节验收，不把水上、人工结构、太空或城市留作后续题材包。

不改自动维护触发时机、主 RP 摘要内容边界、Kernel 提交协议、Scene 内部模型和三维资产系统；不引入 GIS／导航服务、任意素材下载、可旋转世界沙盘、物理模拟或新持久化分区。不自动提交、推送或清档。真实模型调用按本轮用户授权的正常维护／管理员三类内容验收执行，不擅自换账号或扩大调用范围。

### 10.2 题材覆盖

同一套生产工具与渲染器完成下列全部输入，不写样例专用分支；每类都有世界／地区对应关系、可进入的地点和至少一次增量修改。

| 编号 | 代表内容 | 关键图面与行为 |
| --- | --- | --- |
| T01 | 山地、森林、跨区河流 | 自然地貌可辨，水陆关系与跨图连续性正确 |
| T02 | 河港城市、郊外、真实地标 | 城市不止图钉，街道与背景纹理不混淆，不全区铺屋顶 |
| T03 | 海洋／水下、岛屿、平台、航道 | 无陆地仍有有效地图；平台可见，海面纹理不生成航路 |
| T04 | 巨型建筑／地下城、楼层或甲板、通道 | 人工基底与边界可辨；上下层不混铺，明确入口不被填死 |
| T05 | 太空、天体、空间站、小行星带、航线 | 不是换背景的地表图；背景星点不变成可访问天体 |
| T06 | 浮岛、特殊介质、裂隙、传送连接 | 通用几何可以表达无专属资产的内容，不凭外观推断可达性 |

浏览器覆盖桌面、390px、320px与深浅主题；核对真实图面、触控、键盘、文字放大、返回和空态。真实模型另在授权范围内完成上述题材的首建与连续修改，不手调输出坐标，不用手写 fixture 或 HTTP 成功替代模型使用质量。

### 10.3 重整性能与发布关卡

固定使用现有酒馆、山谷、舱室三个 Scene，不加重基线；同一浏览器、窗口与操作序列各重复五次。Atlas 加载峰值、稳定增量内存、交互耗时 P95 不超过三个场景对应最大基线的 1.25 倍。浏览器进程占用、JS 堆、GPU 资源估算分别报告，不能用缓存字节替代总内存。

验收首次加载、30 次开关、100 次缩放／地区切换、地形编辑与至少 20 分钟连续使用；无崩溃、无持续资源增长，释放后回到预热基线附近。未取得的手机或显存总量实测明确列为未验证。

自然、城市、太空分别通过正常维护生成及管理员补图流程，保留原始模型调用和结果；这项与生产组件视觉、性能验收共同通过后，才替换发布构建并删除旧 Worker／瓦片／PNG／纹理缓存及专属测试。关卡前旧文件只能断开入口留作待清理项，不得作为运行时回退。
