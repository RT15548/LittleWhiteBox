# Map APP 三维视图升级设计

本文记录九类程序造型与三维场景的首轮基线。已完成的后续扩充见 [37 类物件与三维素材扩充计划](./map-3d-assets-expansion-plan.md)：当前为 22 类本地模型＋14 类程序造型＋1 类出入口标记，完整 icon 词表为 55。后续扩展了 `icon` 可选值及说明，不属于本文“tool 不变”的首轮范围；存档字段、二维空间表达与地图业务未改变。

## 1. 目标与结论

在不修改 Map Agent 的 tool、Prompt、`MapDomainV1` 和现有存档格式的前提下，为 Map APP 增加三维场景视图。打开 APP 时优先显示当前角色所在的 active 场景，默认三维；没有可用当前场景时显示世界地图。二维场景保留为可切换视图和 WebGL2 不可用时的回退。世界地图始终使用现有二维实现。

终态结构只有一份地图事实、两个渲染出口：

```text
Map Agent tool
    ↓
当前 MapDomainV1（唯一事实来源）
    ├── MapScene.vue       现有二维 SVG
    └── MapScene3D.vue     新增 three.js 视图
```

三维视图改变的是素材和绘制方式，不改变 AI 对空间的描述方式。AI 仍然负责场景中的几何轮廓、位置、朝向、物体语义、材质和确定性；渲染器负责把这些字段表现成平面或立体。

## 3. 数据和责任边界

三维渲染只读当前 `MapScene`。它不得读取 label 猜物体，不得把材质或模板选择写回存档，也不得为缺失字段生成新的地图事实。

AI 当前可以提供：

- `shape` 和 `geo`：矩形、圆形、开放路径、闭合路径、曲线或点位置；
- `category / kind / icon`：墙、家具、道路、入口、人物等语义；
- `material`：木、石、布、玻璃、金属等材质 token；
- `rotation / closed / certainty`：朝向、路径闭合和确定性。

渲染器可以约定显示高度、墙厚、倒角、灯光、阴影和细节密度，但这些约定不属于地图事实。当前 schema 没有真实高度、墙厚、门宽、楼层高度和堆叠关系，因此三维结果是有空间感的表现层，不是精确建筑模型。

## 4. 渲染规则

### 4.1 墙体与建筑边界

- `category: wall` 的 path/curve 沿原始点列生成墙段；不填充墙内部。
- 墙厚和高度使用渲染器常量；不同材质只改变表面材质。
- `closed: false` 保持开放；AI 在入口处留下的断点就是门口，不由图标自动挖洞。
- 默认保留墙体完整显示高度，“低墙”默认关闭，按需手动开启。开启时统一降低所有墙段，关闭时恢复完整显示高度。只缩放竖直方向，不依赖世界原点、视角、路径顺序或推断的房间中心；旋转和平移不会让墙体忽高忽低。该开关不改变地图数据。
- 矩形 terrain 作为地面；没有 terrain 时不擅自补房间边界。

### 4.2 区域、道路和水域

- 闭合 rect/circle/path/curve 按原轮廓生成薄面或低矮区域。
- 开放 path/curve 生成带宽度的道路或线；宽度是类别的显示常量。
- 不规则轮廓使用原始路径挤出，不能退化为包围盒。
- 森林等区域可使用稳定种子的有限装饰；装饰是显示细节，不逐项进入存档。

### 4.3 物体模板

当前二维组件 `SceneObject.vue` 中的 9 类自有物体造型，建立对应的三维模板注册表：

`table`、`counter`、`chair`、`bed`、`shelf`、`sofa`、`bridge`、`tree`、`rock`。

九类均支持矩形占地；桌、树、岩石还支持圆形。其他圆形及不规则形状使用原轮廓示意，不将圆椅等硬套成矩形模板。家具部件和连续墙段采用实例绘制，重复材质/几何由当前场景共享。

模板只读取物体的占地、朝向和材质。桌腿、椅背、床垫、书格等是模板细节；不向 AI 反向要求三维坐标，也不把这些细节写回场景。酒馆模板使用桌面收边、渐细桌腿、框架椅背、吧台凹面板和圆润软垫；书架只表现格架，不补入地图没有提供的书本或摆件。模板内所有部件仍位于原始占地内；程序造型或本地模型未覆盖原占地范围时，由场景组装层统一补原始地面轮廓，并保留朝向和 certainty 线型。已贴合占地的造型不加框，不提供物件选中线框。

模板不存在时按形状降级：

- rect → 矮矩形体；
- circle → 矮圆柱；
- 闭合 path/curve → 原轮廓薄挤出；
- 开放 path/curve → 线段；
- icon/label → 位置标记或标签。

不提供物件分类列表或点选检查面板；模板与占地示意仅是绘制规则。`certainty: unknown` 表示空间事实不确定，不得拿它代替“没有三维模板”。

### 4.4 图标、材质和文字

- 人物、门、楼梯、方向和其他点状语义继续使用本地 Material Symbols 位置标记。人物圆形、门和楼梯矩形等带尺寸输入保留薄占地轮廓及中心标记，不生成实体人物、门扇或台阶。
- 当前 22 个材质 token 映射到 three.js 的颜色、粗糙度、透明度和有限纹理；不新增材质字段。木地板拼缝与家具木纹分别处理，布料、石材等使用有限程序纹理及轻微凹凸；深色主题不再统一染暗实体材质。
- 标签来自 `element.label`，不因三维模板增加新名称。人物和入口分为原坐标位置点、图标、文字三个部分；位置点固定，图标与文字在屏幕空间独立避让，并用短线连接偏移图标与位置点。先排玩家、入口及其他标记，再排文字，避开缩放控件；文字放不下时可以隐藏，不能连带隐藏位置标记。关闭名称只隐藏文字。
- 极端密集、多个标记同点时不承诺全部图标互不重叠，但不删除标记或移动地图事实，玩家优先。上述布局只存在于当前视图，不新增持久状态。
- 旧 Game Icons 资源不自动恢复到 OS Map；当前 OS 使用的本地图标字体保持不变。

## 5. 模块设计

`MapApp` 拥有当前场景/世界入口、二维/三维模式和本次 APP 的三维故障状态。`MapSceneView` 只拥有低墙、名称开关和两种视图，不维护场景物件选择；这些状态均不进入存档。

模板覆盖归入 `three/scene3d-presentation.ts`；身份标记分类由二维、三维共同使用，位于无 GPU 依赖的 `scene-geometry.ts`。二维组件不依赖 three 目录。

`apps/map/ui/three/` 的边界如下：

- `MapScene3D.vue`：接收 `MapScene`，管理 canvas、加载/卸载和 WebGL 状态；不拥有地图业务状态。
- `scene3d-geometry.ts`：将现有场景几何转换为 three.js 几何，复用 `scene-geometry.ts` 的路径语义。
- `scene3d-templates.ts`：9 类物体模板的程序几何；模板覆盖判断位于 `scene3d-presentation.ts`。
- `scene3d-materials.ts`：MapMaterial 到 three.js 材质的映射；`scene3d-textures.ts` 只负责有限程序纹理。
- `scene3d-labels.ts`：投影原始锚点并更新静态 DOM；`scene3d-label-layout.ts` 只计算屏幕空间图标和文字布局，不修改锚点。不拦截拖动，不注册点击操作。
- `scene3d-model.ts`：组装场景物件、表面、森林装饰和统一低墙显示；不维护可拾取对象或选中轮廓。
- `scene3d-resources.ts`：管理当前场景资源，确保共享资源只释放一次。
- `three-runtime.ts`：three.js、OrbitControls、renderer 创建和释放；按需加载，不在二维启动路径初始化。

生产 `MapScene.vue`、`MapViewport.vue`、`SceneObject.vue` 和 `scene.css` 不改业务语义。Map APP 只增加模式状态和渲染出口；三维组件不能复制一份 tool、存储或场景编译逻辑。

## 6. 交互与失败处理

- 默认当前 active 场景 + 三维；没有当前场景显示世界图。首次异步读到地图或空地图首次绘制成功后也应用此规则。用户主动选过视图后，状态推送不抢走其浏览位置；切换聊天由现有 Shell 重新挂载 APP。
- 当前 APP 内二维/三维模式随用户选择，重新打开回到默认；不新增模式或相机偏好持久化。明确选择一个没有布局的地点时保留现有空态与更新入口。
- 场景仅用于浏览：PC 左键拖动旋转、滚轮缩放、`Shift + 左键`拖动平移。平移使用控制器原生的组合键操作；取消三维右键绑定，右键（含组合键）不移动地图，避免给出可拖动的反馈，但不保证阻止浏览器自身的后退手势。画布提供悬停提示。触屏单指拖动平移，双指拖动旋转、捏合缩放。保留全图、低墙和名称；键盘提供方向键、`+/-` 和 `Home`。二维/三维均无物件列表、物体点选、高亮或底部选中信息。世界地图保留地点点选、详情及场景导航。
- 场景的图例和“回到当前场景”与视图切换正常排布，不绝对定位覆盖场景工具栏；窄屏多条状态提示出现时，顶部可滚动并保留地图操作空间。
- 二维继续使用现有 `MapViewport` 的平移和缩放实现，不复制手势代码。
- three.js 仅在进入三维时加载；初始化失败、WebGL2 不可用、上下文丢失或 renderer 出错时立即切换二维并显示可关闭的一次性提示。本次 APP 内禁用三维重试，重新打开可重试；此提示不覆盖保存/冲突状态。
- 场景数据更新只重建所属场景资源并保持相机。同一场景在本次打开期间沿用首次建立的坐标原点与比例，扩大或平移 viewBox 不重新缩放、移动既有几何；手动“全图”按最新范围取景。此坐标换算随场景切换/卸载释放，不写存档。退出三维/卸载时释放 renderer、controls、观察器和监听器；加载尚未完成时退出，不再初始化运行时。
- 三维不能阻塞地图读取、保存、Agent maintenance 或主 RP Prompt；地图失败状态仍由现有 Map 服务处理。

## 7. 性能与资源

- three.js 与 OrbitControls 使用固定版本并随插件本地打包，不产生 CDN 请求。
- 默认不加载 glTF/OBJ 等任意模型；9 类模板使用程序几何，避免用户准备大量文件。
- 限制单 Scene 的元素和点数沿用领域上限；装饰采用稳定种子和预算，禁止按面积无限生成。
- 使用正交相机、按需渲染、最高 1.8 像素比和 1024 阴影贴图；隐藏时停止帧请求。画布尺寸调整与绘制在同一帧完成，避免清空缓冲区造成闪白。
- 使用中性色调映射、主光和补光；阴影范围随场景几何更新而重新收紧。完整高度包围盒只属于本次场景资源，供取景和灯光使用，不受低墙开关影响。表面按稳定绘制顺序做微小竖直分层，避免地板与地毯的深度冲突，不改变平面位置。
- 世界图和纯二维路径不请求三维动态分包；字体继续来自插件本地 Material Symbols 文件。程序材质纹理为当前场景临时资源。
- 程序纹理固定为 128×128，按材质/用途共享，切换场景和卸载时由同一资源所有者释放；无新素材下载、后处理链或依赖。
- 资源释放必须覆盖 geometry、material、texture、renderer、controls、ResizeObserver 和 pointer listeners。

## 8. 实施顺序

1. 固定三维渲染模块边界和资源版本，先不接 UI。
2. 接入墙、地面、路径、圆形和不规则闭合轮廓，验证同一坐标与二维一致。
3. 建立 9 类物体模板，并为每类保留明确的无模板降级路径。
4. 接入材质、图标、标签、朝向、确定性和统一低墙开关。
5. 在 MapScene 入口增加二维/三维切换、加载状态、错误回退和资源清理。
6. 先用酒馆、溪谷、观测舱三组现有工具 fixture 做渲染回归，再做真实浏览器手工验收。
7. 完成构建、类型、lint、imports、bundle 大小和无外部请求检查，并按已确认决策默认开放三维场景。

## 9. 测试和验收

逻辑和集成测试保护这些稳定契约：

- 相同 `MapScene` 在二维、三维中的元素数量、坐标、半径、路径点、旋转和入口缺口一致；
- 9 类模板分类正确，缺少模板的 rect/circle/path/curve 不丢轮廓；
- 墙不被当作面积填充，开放线不被错误闭合；
- 低墙只改变高度；偏心、多房间、独立墙段、反向点列和旋转轮廓的占地与缺口不变，关闭时恢复原高度；
- 材质、certainty、标签和人物身份只影响表现，不修改领域数据；
- 标签拥挤、NPC 先于玩家输入、窄屏控件占位和名称开关不隐藏玩家/入口或移动位置锚点；
- 场景切换和组件卸载后无旧 renderer、监听器或纹理残留；
- three.js 不可用或上下文丢失时，二维地图仍可平移、缩放和切换场景，世界地图仍可点选地点。

真实浏览器验收覆盖桌面、390px、320px、深浅主题、旋转、缩放、双指手势、名称上拖动、世界地点导航、当前/已记录场景切换、低墙、二维回退和 WebGL 初始化失败。需要查看实际截图；测试通过不能替代视觉检查。

真实模型验收仍需使用独立测试聊天，记录原始 tool 输出、二维/三维截图和增量差异；手写 fixture 只能证明渲染契约，不证明 Map Agent 的自然语言构图质量。

## 10. 风险与明确限制

- 没有高度和墙厚字段时，三维高度是风格化约定；不能用于精确测量或物理模拟。
- AI 给错墙点、门口或物体占地时，三维会忠实呈现错误，不承担自动建筑纠错。
- Material Symbols 提供的是点状图标，不会自动生成对应实体模型。
- 三维模板越多，维护成本越高；新增模板必须有稳定的 icon/shape 语义和删除路径，不能按单个剧情对象写专属模型。
- WebView/GPU 能力不一致，因此二维回退属于正式能力，不是临时调试分支。

这份方案的发布判断标准是：三维作为可选表现层已经覆盖常见场景，并且缺少模板时仍能诚实、稳定地显示原始空间信息；它不要求 AI 学会 3D 建模，也不要求改变现有地图协议。
