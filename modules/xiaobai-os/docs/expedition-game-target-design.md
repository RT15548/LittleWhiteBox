# 余火：第一章实现边界

产品与世界设定见[世界与战役设计](./expedition-campaign-design.md)。当前版本只制作第一章“哨站救援”，第二章待续；没有旧随机房间入口、独立交付测试页或后续空章节。

战斗规则以[战斗与成长设计](expedition-combat-design.md)和[第一章战斗编排](expedition-chapter1-combat.md)为准。独立战斗段、推进节点奖励、健康重试与场地分区已接入；本文说明它们的实际边界，不将自动验证视为真人体验或真实手机验收。

## 所有权与唯一事实来源

功能全部归属 `apps/game/expedition/`，经 Game module、production runtime 与 room catalog 注册。内容、模型、存储、AI、交互和画面均在该目录内；共享层只提供 Agent、文件事务、钱包和宿主生命周期。不增加依赖或宿主聊天 participant。

- `content/courtyard-*` 定义场景、门、交互、遭遇与连接。建筑 footprint 同时产生可视建筑和碰撞，地图视图从同一内容派生。
- `content/campaign-actions.ts` 定义剧情行动的参与者、前提、结果和含义，AI 行动提案与领域规则共同引用，不各自判断剧情是否可推进。
- `content/supplies.ts` 定义物资接收交互、开放条件和当前处境；地图、领域规则和对话共用。`campaign/progress.ts` 从已发生事实投影当前行程，`campaign/awards.ts` 定义事实对应的奖励身份与金额；不增加进度或提示快照。
- `campaign/` 拥有旅人资料、所选章节、已确认的章节事实、所在场景、收藏和装配、战斗起点、进度、已确认交谈。`campaign/traveler.ts` 定义姓名与性别，`content/chapters.ts` 定义可玩章节；界面与对话都从当前战役派生。剧情记录按发生顺序保存，接应和回营状态从规则判定。
- `world/` 处理实际位置、扫掠碰撞、视线、路径与交互距离。
- `combat/` 处理固定步长战斗，不读 DOM、时间、网络或模型。世界中的战斗使用相同碰撞、弹体遮挡和寻路。
- `content/courtyard-encounters.ts` 定义各段触发、战区、波次与成长节点；`combat/chapter-encounter.ts` 管理一次性点火与增援，`combat/world-bosses.ts` 拥有章节首领招式，`content/combat-policy.ts` 集中调校数值。UI 从相同战斗状态显示预警，不自算第二个计时器。
- `docs/expedition-cards/` 是共用提示词、世界与人物卡的唯一设定源；`narrative/` 负责读取、个人知情投影、上下文整理与回复校验。
- `service.ts` 拥有游戏与钱包原子提交、个人摘要提交和正在进行的对话；`host.ts` 区分视图连接与请求身份，切走视图不取消请求。
- `presentation/` 和房间组件只负责本地预测、输入、UI 与 Three.js 生命周期。人类可读内容集中在内容文案和 `copy.ts` 中。

## 第一章循环

檐下接下救援 → 岔口 → 正门、烽火台或旧水道 → 牢房开门 → 受困者实际返营 → 解除门厅封锁 → 核对物资 → 与三娘收尾。

正门先熄火可截断内堡增援；水道先救人会留下警报后果，仍可回头截断。正门没有隐藏警报倒计时；烽火点火只在该战斗段推进，交谈、暂停、离线和等待 AI 不推进。门厅开战时固定是否有有限增援。撤离与接应规则见[第一章规划第五节](expedition-cards/chapter1-plan.md#五地图与移动)；小门开启后是可重复使用的真实捷径，不是菜单传送。章末保留营地与可选根庭的回访。

六职业是不同作战方式，入场即可选择。移动时自动攻击，玩家控制走位、闪避与技能。职业、数值、遗物触发和外观分别归 `ids.ts`、`content.ts`、`relics.ts`、`outfits.ts`，显示层不另定数值。

收藏保存遗物的唯一等级，有限装备槽只保存引用。获得遗物或升级不删除卸下的收藏。营地与休整点可重新装配，装配本身不治疗、不重抽；允许保留或装配尚无触发来源的遗物，界面提示其联动缺失。

遗物按推进节点发放，不按击杀发放。路线替代来源共用节点，战斗与放行都能完成节点。首次完成时确定候选和领取地点，现场领取；暂不领取、重开和保存确认不重抽。满槽可以当场替换或只收藏。节点候选、当前打开节点及必要的内部完成段归战役所有，随新旅程清理；不复制剧情事实。

战败可在同一段起点、同一随机种子和装配下满生命重试，职业资源恢复该段标准开局；或回营整备。水道前段与闸口看守是独立战斗，已经确认的前段、救援、收藏和奖励不倒退。没有付费复活、下注或出售永久战力。

入口顺序为标题、创建旅人、篇章、职业、入场。已有旅程可直接继续，也可从标题查看篇章。第二章只显示待续，不可进入。创建过程不落盘，最终启程才保存；标题不加载战斗场景。地图展示地域与道路，行囊管理遗物与衣装，手记记录亲历与当前行程，菜单只放继续、音效、操作和返回标题。

菜单可以返回标题，不重置进度。标题中的新旅程需填写旅人资料、选择职业并明确确认。重开替换当前故事、构筑与交谈；衣装和资金收据保留，不能反复领取首胜奖励。不增加多槽存档或跨战役人物记忆。

## 保存与资金

用户级 `expedition` 分区保存当前战役、已确认的交谈、首次奖励收据、购买收据与所选外观。它们需要在关闭浏览器后恢复，因此持久化；按键、摇杆、镜头、面板、路径缓存、正在调用的控制器、未确认回复和本地预测不持久化。

各受困者的返营事实归战役既有 `facts` 记录所有，人物与事件的对应定义在 `content/people-places.ts`。它记录已经发生的救援，不等于当前坐标，因此在离营和重启后保留；随本次旅程重开或删除一并清除，保存失败沿用分区事务的候选恢复。整体救援完成事实蕴含两人均已返营，已完成的现行存档无需补写事件。当前脱困阶段、行动能力和模型现场资料从事件与位置派生，不另存快照。

客户端提交有界的压缩方向／闪避／技能输入，Host 从已确认检查点重放，不接受客户端生命、坐标、胜负或掉落。正常暂停先提交剩余输入，意外关闭只承诺最近已确认进度。本地自动化和手工编辑本人存档不是此协议声称防范的作弊。

余额只来自 Economy，奖励和购买凭据是权益唯一来源。所有 `expedition:` 钱款流水与领域收据双向校验；奖励、所有权和钱款在同一事务提交。同一个 actionId 不重复付款或奖励。保存失败或结果未知时保留原候选，通过文件确认恢复，不生成新身份买一次随机结果。

阶段奖励沿用既有资金收据及其账户生命周期，不增加表、字段或迁移格式；发放规则见[收尾与阶段奖励](expedition-cards/chapter1-plan.md#收尾与阶段奖励)。已有旅程的完成事实在下一次有效游戏操作时可补领尚无收据的阶段奖励，不改写原有收据。已到账提示只存在于当前视图，关闭即可清除；重新进入从手记查询本次旅程的收据。

余火以当前第一章模型作为首个正式发布基线；早期测试旅程不属于受支持的历史格式。不保留测试线 V1/V2/V3 转换器、旧阵容映射、旧随机房间或旧协议分支。无效分区报余火自己的错误，不关闭整个 Game App；不会静默覆盖原文件。玩家可明确选择丢弃无法读取的测试旅程，重建当前分区；这会清除旧剧情与人物记录，权益只从现行共享账本重建，不解析旧游戏格式、不改钱包流水。重建写入失败仍保留同一候选，通过确认保存恢复；有效旅程不能走这个破坏性入口。

此次战斗升级保留紧邻的有效 V6 旅程；仅在分区解析入口转换成当前格式，规则与退出条件见 `migration-v6.ts`。人物记录与权益不清空，旧战斗不混入新编排，已清地点不重新布兵。

删除功能需先决定战役及权益的导出／清理策略，然后删除功能目录、三处注册和所属分区；共享钱包的既有流水、其他应用与共享 AI 设置不删除。聊天清理不清用户级游戏数据。

## 人物交谈

使用小白 OS 共享 Agent Capability，但不导入聊天正文、角色卡、世界书或酒馆记忆，也不向它们写战报。人物回复只由玩家明确发送交谈触发；行走、战斗和场景机关不调用模型，不产生自主 NPC 对话。

人物知道自己的身份、可知的已确认事件和自己与玩家的交谈。玩家资料来自当前旅程，欲望和关系意图不预定；好感与阶段资料遵循 [第一章规划第四节](expedition-cards/chapter1-plan.md#四好感)。人物自由回复、好感方向与合法行动提案同次返回，通过游戏规则校验后原子提交；数值不替代共同经历，也不代表玩家同意亲密。

日常互动属于 AI 正文，不另建固定菜单或追加脚本。对白中的剧情行动由 `service.ts` 提交领域规则，实际行动、好感变化与可选表演随这一条对白原子保存，不制造第二条人物回复。

个人摘要的触发、等待、重试和生命周期遵循[人物与互动](expedition-campaign-design.md#人物与互动)，阈值只定义在 `narrative/memory.ts` 的 `MEMORY_POLICY`。`narrative/memory-jobs.ts` 拥有运行内任务，`service.ts` 负责将完整且缩短的摘要文本与 throughId 原子合并进当前存档；失败不改原记忆。摘要整理会产生模型调用，不是自主 NPC 对话。

预算不是对供应商窗口的假设。供应商明确以结构化 `context_length_exceeded` 拒绝时，摘要缩小批次，交谈可强制整理旧前缀后重试一次；最小批次仍放不下则明确报错。网络错误、超时、鉴权失败和不完整回复不触发自动重发。

`narrative/response.ts` 是回复分段格式的唯一定义，提示词、解析与模型历史回放共用；存档保存正文与结果，不保存传输标签。对白、附带行动、异常原文与保存恢复遵循[人物与互动](expedition-campaign-design.md#人物与互动)的统一规则。请求过程态不落盘，页面退出后不保证恢复未确认回复。

切换 App、收起窗口只断开视图；页面存活时回复仍可保存。明确停止、聊天身份变化和运行时销毁才取消。主聊天生成可以阻止新请求，但不让已经收到的回复因为它开始而作废。网络结果未知时不自动重发。

## 画面、操作与性能

主画面是可行走的场景，不是缩在面板中的示意图。营地、城门、烽火台、水道、牢房、门厅和根庭有各自建筑轮廓。画面显示真实出口、机关、可见人物和警戒者，状态改变对应门、火、接应位置与居民变化。地图使用同一地形和交互数据，不维护第二套连通图。

`scene.ts` 拥有镜头与渲染器，scene kit 复用几何和材质；静态地景按空间与材质合批。事实不变不重建人物／机关层，门状态相同不重建碰撞空间。只加载当前场景，离开时释放所属资源；暂停和静止场景跳过无效绘制。DPR 与阴影分辨率有上限，不为增加细节另开后台 WebGL 画面。衣橱的预览只在面板打开时存在。

输入朝向来自同一相机方位，键盘与触摸共用固定输入。第一触点独占摇杆，技能指不干扰移动；松手、取消、失焦、切场和卸载释放输入。预警使用实际长度、宽度、半径和安全内圈，减少动态效果不隐藏危险。

护盾余量是脚下细能量条，空盾隐藏，头顶仅保留短时格挡、吸收和破盾反馈。烽火状态只在主 HUD 表达，不在烽火模型上重复挂牌。音效为本地 Web Audio，默认关闭；画面与声音失败明确提示。

## 验证

规则层检查两条完整路线、救援因果、门与碰撞、遗物装配、警报、战败、输入重放和人物知情范围。真实文件事务检查重复、未知、取消、恢复、钱款与交谈原子性。浏览器从正式 Game 房间入口检查桌面、手机竖屏、短横屏、键盘、触控、长交谈、错误、关闭重开与资源释放。

策略模拟只证明可达与协议行为，不等于真人乐趣、模型人格质量或真实手机帧率。过程日志和测试数量不属于产品文档。
