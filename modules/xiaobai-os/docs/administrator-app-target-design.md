# 管理员 APP 终态设计

## 0. 状态与范围

状态：Host/Shell 入口、领域管理工具、独立会话及图片、流式 UI、全局 APP 认识和只读诊断已接通；提示词与工具说明已按小白助手的写法分层归位，完整工具定义按 APP 整包提供。各轮验证记录见第 11–14 节；不能以隔离模拟测试代替真实模型质量验收。

管理员是 OS 本身应有的常驻 APP，帮助用户理解和使用整个 OS、查证运行问题、协调已有管理操作，而不是接管所有 APP。它可以解释 APP 用途；业务数据查阅和修改限于现有管理入口。

全局认识与诊断仅增加 APP 自有说明、环境快照和一个只读工具；提示词规范化只整理表达与所有权，不改变工具协议或业务行为。两者均不扩大业务权限、后台维护输入范围或自动调度。综合检查、解释、规划和整理依靠模型及现有工具，不拆成细碎工具。

## 1. 产品行为与权限

用户打开管理员即可聊天，无需先选问题类型或找到某个 APP 的纠错按钮。

| 用户意图 | 管理员行为 |
| --- | --- |
| 询问用途或操作范围 | 根据实际 APP 目录回答；存在于目录不等于能读其私人内容或替用户修改 |
| 排查运行问题 | 检查现有运行状态，区分观察事实与可能原因，不自动恢复或修复 |
| 询问记录原因 | 读取有关记录和必要原文，解释核实到的情况；询问本身不等于允许改数据 |
| 指出记录有误、要求核查修正 | 查原目标、原记录与剧情事实，有依据后修正；不要求用户先自行整理全部证据 |
| 明确指定修改结果 | 按用户的管理指令处理，不再以剧情是否已经发生作为授权门槛 |
| 对象或修改含义不清 | 先读当前数据缩小范围，仍无法确定时再问一个必要问题 |

管理员的直接对话属于用户管理指令；它读到的任务、地图、世界资料和 RP 文本是资料，不会因为其中写了命令就获得管理权限。历史管理员回复和旧工具结果也不等于当前数据。

权限大于小白酒馆当前助手聊天的含义是：能实际修改已接入 APP 的业务数据，而非只能解释、建议用户手改。它不因“剧情应该怎样发展”拒绝用户明确的修改意图。

技术边界仍是普通 OS：通过 APP 提供的操作管理 OS 数据，不提供任意 JavaScript、文件系统或跨 APP JSON patch。小白酒馆的聊天产品可作行为参考，不能导入 Tavern DB、manager 或会话语义；第四面墙的皮下聊天也不是管理员。

## 2. 现有业务管理范围

| 所有者 | 已接入管理能力 | 必须保持的领域边界 |
| --- | --- | --- |
| Tasks | 查任务与累计事实，核查原文，纠正进展，完成或判定失败当前 active 任务 | 判据引用[任务设计 §4.3](./tasks-app-target-design.md#43-活动任务)；状态与既有奖励结算一起提交 |
| Map | 查图册与场景，按用户要求纠正地点、连接、人物位置和场景布局 | 由 Map 编译空间操作并校验引用，管理员不直接改渲染器 |
| World | 查并修改世界概况、新闻与已有记录 | 当前 World 数据不等于 SillyTavern 世界书；不得声称已经修改角色卡或世界书 |

业务管理有意保持上述范围，不以管理员名义继续接管其他 APP。实际能力由本轮成功打开的管理入口与工具定义决定，不另建权限白名单。未注册管理入口、管理资料打开失败和 APP 加载故障分别表达，不给假成功。

任务终态重开、合同目标或报酬修改、配置修改、自动修复和通用 JavaScript 均不在本轮范围。工具按 APP 整包提供的规则见第 4.2 节；不做逐工具发现、依赖解析或全局加载框架。不冒充具备暂缺的业务操作，也不把缺少入口说成用户没有权限。

## 3. 历史原文查阅

管理员需要程序提供的聊天搜索和分页读取，不让模型执行终端命令，不把整个长聊天一次性灌入上下文。

- 来源与读取范围：[聊天读取工具契约](../apps/administrator/agent/chat-tools.ts)。
- 存储：直接读取宿主已有消息；不向聊天 JSONL 添加原文副本、搜索索引、向量或每楼标记。实际返回给模型的搜索／读取页进入管理员会话历史，原文快照与续读缓存仅活在本轮运行内，保存位置见第 6 节。
- 搜索：按关键词或短语定位消息，返回命中片段、消息位置、说话人及继续查找位置。未命中只表示这次查询未命中，不等于事件没发生。
- 读取：按消息范围取原文；长消息支持继续读取，返回实际覆盖范围与截断信息。模型可以围绕搜索结果读取前后文，也能按范围顺读，不把关键词当唯一证据。
- 搜索按一个名字或短语做普通文字匹配，空格和标点按字面处理；多个线索分别搜索，未命中时缩短或换词。工具参数说明提供这条选词指导，不新增正则或中文分词能力。
- 初始上下文：当前聊天身份、已接入 APP 的能力目录、必要对象摘要和最近管理员对话；对象详情和旧原文按需读取。注入与读取使用同一投影，不保留两份不同形状的事实。
- 运行期间绑定聊天与消息快照；切聊停止旧工作，消息编辑或换 swipe 后重新核实已引用内容，避免按过期原文写入。长楼层续读沿用先前版本，不刷新旧依据；版本变化须从头重读。
- 引用原文时给用户可识别的消息位置和短摘录；后续原文已变更时，旧摘录只能作为当时查阅记录，不能冒充当前证据。

它只能依据实际读到的材料说明结论，不能把局部查阅包装成“查过全部历史”。现有维护只捕获接受轮，不因新增管理员自动获得历史搜索能力。

### 楼层编号契约

楼层号唯一依据是 SillyTavern 当前聊天 UI 的编号，从 `0` 开始；对应 `getContext().chat` 的原始数组下标。宿主 `public/script.js` 的消息渲染以 `messageId` 同时设置 `mesid` 和 `#${messageId}`，重排时也同步更新两者。

- 用户说“第 55 楼”或“#55”，读取的就是 `chat[55]`；工具参数、搜索结果、原文引用和界面展示沿用同一编号，不加减一。
- 分页及只显示部分历史，都不能重新编号。不存在的指定楼层应明确返回该状态，不能换成相邻楼层。
- 楼层号不是 JSONL 的物理行号，不计文件头或 metadata，也不是 Assistant 回复数、完整来回数或筛选后列表的序号。
- 读取范围两端均包含：55–57 楼就是 55、56、57。长消息的内部读取位置与楼层号分开，不能用一个含义不明的 offset 同时表示二者。
- 删除、插入或重排消息后，后续查询按当前宿主编号；已引用材料按本节的运行快照规则重新核实，不能把旧 #55 当成永久消息身份。

## 4. 终态结构与唯一事实来源

```text
apps/administrator
  对话、工具循环、运行状态、历史、UI
       │
       ├─ Agent capability：供应商会话
       ├─ 聊天原文读取适配：当前宿主聊天
       ├─ 环境读取适配：APP 注册表、维护状态、生成状态、两套存储控制器
       └─ 管理能力注册：路由到所属 APP
             ├─ apps/tasks：任务操作 → Tasks + Economy
             ├─ apps/map：地图操作 → Map
             └─ apps/world：世界操作 → World
```

- 管理员拥有自己的会话与交互，不拥有第二份任务、地图或世界数据。
- APP 用途由各自 `descriptor.ts` 的必填 `description` 所有，名称与说明从实际模块注册表派生；管理员不维护另一份用途目录。
- 各 APP 自带管理投影、领域说明、工具声明与执行入口；操作仍调用本 APP 的 application/domain 层。存在多个真实接入方后，共享注册层只做发现、路由与注销，不认识任务状态、地图字段或世界新闻。
- 聊天查阅最初服务管理员，先置于管理员的宿主适配内；出现第二个真实消费者后才提取通用能力，不预建虚拟文件系统、向量库或长期索引。
- 复用现有 Agent gateway、agent-core 协议适配、Kernel 事务和保存恢复，不新增供应商 SDK 或另一份 API 设置。
- 后台维护与管理员分别拥有提示词和调用流程。前者基于接受轮维护，后者回答用户并执行管理指令；只共享确实相同的领域操作，不能把 maintenance 的 manual 模式改名当管理员。

### 4.1 环境快照与只读诊断

- `domain/environment.ts` 定义管理员的环境类型和读取接口；`host/environment.ts` 显式投影安全字段。Host 装配只注入窄读取接口，不传整个运行时，不新建全局能力、监控服务或轮询。
- `agent/os-tools.ts` 所有单个无参数 `OSInspect` 工具及返回契约；查询目录、维护、主聊天生成及两套存档状态，不读取其他 APP 私人对话、账户明细、密钥、完整配置或文件定位信息。
- `agent/tool-executor.ts` 的共同资料入口为每轮生成一份环境观察，正式请求与上下文计量均从该入口取得；`OSInspect` 用同一读取投影实时刷新。初始观察不持久化，已经返回的工具结果按第 6 节进入既有会话历史。
- APP 状态的观察范围及字段含义以 [OSInspect 工具契约](../apps/administrator/agent/os-tools.ts) 为准；不透传原始错误正文、错误代码和堆栈。管理入口打开失败另报结构化不可用状态，不透传其原始错误。
- 维护启用状态来自实际参与者的 `isEnabled('automatic')`；现有状态、结果和原因类别来自 runner，不解析 UI 文案。缺少参与者不是自动维护关闭；维护记录是内存状态，重启后无记录不能推断从未运行。`lastProcessedAt` 投影现有 `lastRunAt`，只表示最近 updated／unchanged／partial 完成时间，不能冒充最近尝试时间。
- 聊天存档与用户存档独立报告保存状态和待处理候选；其中一套 ready 不证明另一套正常。任一读取异常明确返回诊断失败，不用正常默认值掩盖。
- 读取前后核对发起时聊天身份，取消和切聊终止旧查询；旧剧情证据失效不妨碍查看同一聊天的新运行状态。查询不恢复、不重试、不触发后台生成、不改配置，也不测试连接。查询结果的管理员会话保存不等于业务写入。
- 工具沿用既有轻量活动回执，文案集中于 `ui/copy.ts`；环境和完整结果不进入常规 frame 推送。管理员或共用模型本身不可用时仍依靠现有界面，不承诺通过聊天自救。

### 4.2 按 APP 整包提供工具

- 首轮工具仅有 `ToolsLoad`；其可选 `apps` 数组使用实际管理注册 ID，一次可选多个 APP。省略或传空数组只提供公共工具；选择 APP 时，一次提供其完整读写工具，并同时提供 ChatSearch、ChatRead、OSInspect、ToolResultRead。全量加载后为 15 个工具。
- `agent/tool-loader.ts` 所有入口契约和本轮加载状态。短目录来自成功打开的管理会话，复用 participant 的 ID、名称及工具的名称、用途标签和 effect；APP 失败仍由初始资料报告，不列成可加载包。加载返回当前 APP ID 和工具名，不复制完整 schema 到结果中。
- 重复加载不重复添加或重排；参数错误或任一 APP 不可用时整批拒绝。加载不读取业务资料、不执行管理操作、不调用恢复或模型，也不代表用户授权修改；仅其实际调用结果和回执进入既有管理员历史。
- 只延后完整工具定义的发送，不延后 APP 安装或管理会话准备。现有领域说明和初始资料保持不变；共享提示词仅增加入口说明，目录和完整加载契约放在工具定义。APP 自有领域规则与业务参数仍按第 8 节分层。
- 模型循环每次请求获取当前工具列表，请求与计量使用同一快照。只执行该请求实际提供的工具；同批回复先加载、再调用新工具时，后者返回未加载，不执行。新工具从下一次请求可用，原有执行和保存守卫不变。
- JSON 模式复用 agent-core 现有工具文本协议；有状态原生会话在工具集合实际变化时重建并回放保留历史，不重复执行业务工具。重复加载不重建会话。固定说明保持稳定，但工具列表变化仍可能影响供应商缓存。
- 加载选择只属于本轮运行，新用户请求、重新生成或切聊不继承，也不从历史加载结果恢复。新 APP 沿用第 8.1 节注册即可加入目录；注销后新运行不再提供该包。无新增配置、持久化字段、依赖或通用加载服务，删除管理员时随目录退场。

## 5. 执行、并发与失败反馈

一轮管理对话：理解意图 → 按需取得完整 APP 工具包 → 读取必要资料 → 调用对应操作 → 确认保存结果 → 回复用户。现有资料足够时可直接回答，无需加载工具；无需修改的询问不为了展示工作而调用写工具。

工具结果区分读取成功、改动待保存、保存确认、失败和结果未确认。界面与模型使用同一个执行结果；文字说“已改好”不能替代写入回执。

每项写入使用所属 APP 的最新状态校验和既有事务能力。任务结算必须保持任务与资金原子；修改任务、地图、世界等多个独立对象不默认承诺全局一键回滚，部分成功需逐项说清。

世界按概况、新闻 ID 保留读取基线；地图按已读地点、连接、人物与场景保留基线，提交时检查目标及父级、端点、场景所有者等关联对象。读取另一对象不会刷新旧对象的依据；无关对象的新改动保留，不要求整个领域都回到同一旧版本。长资料续读也检查对应对象，不能拼接不同版本。

管理员修改会使同一对象上尚未提交的旧维护结果失效，提交前仍以 revision/预期内容校验拒绝覆盖。后续维护从已修正的当前记录出发；避免旧请求覆盖与模型今后仍可能误判是两件事，不能宣称 CAS 能永远阻止误判。需要长期保留的用户设定写入对应 APP 的事实，不靠管理员聊天充当隐形规则库，不新增永久全局锁。

取消阻止后续模型调用与未提交操作，不撤销已保存结果。提交已经发出时先确认其结果；保存恢复只确认或重提同一候选，不重新执行业务工具。

失败就在原对话保留原因和恢复操作。保存恢复分为「检查保存结果」「重新提交」「放弃未保存内容」：检查仅读回，重新提交执行随候选保留的原守卫（包括尚未进入 Kernel 提交阶段的管理员会话候选），放弃保留服务器记录。首次创建且服务器确认文件从未存在时，放弃恢复未初始化状态；已有文件丢失仍视为冲突。停止或证据失效不妨碍确认已落盘结果，但所有 APP 的重新提交入口都不能绕过原守卫。维护的提交守卫只包含可重复检查的聊天、原文、启用和取消约束，一次性 session 状态及写入门控不混入恢复校验；保存未确认只停止后续维护，不等同主动取消。重载后读取真实 APP 状态，不把中断的请求自动重跑，也不从聊天中的成功文字推定写入成功。

同一工具调用身份只对应一条执行记录，准备回执失败与已派发业务结果未知分开处理。同一现场确认业务成功后直接补写对应回执，不调用模型；回执保存失败只恢复回执，不能重做业务。历史记录缺少可核验的运行凭据时保留当时的未确认状态；后续修改覆盖或核验失败返回明确核验结果，不阻断管理员打开、不重放旧写入。首次初始化前即建立临时发送生命周期，覆盖初始化、上传、用户消息保存和生成；同一现场确认后接续原发送一次，停止或停用使整个生命周期失效，重载不恢复。

失败后的模型请求统一使用第 7.5 节的「重新生成」，不保留恢复旧工具循环的重试入口。保存确认仍沿用本节的三项恢复操作，与发起新的模型生成分开。

## 6. 状态与生命周期

| 数据 | 所有者 / 范围 | 为什么保存或不保存 | 失败与删除 |
| --- | --- | --- | --- |
| 管理员对话、工具调用及实际返回结果、操作回执 | administrator / 当前聊天 sidecar 分区 | 下一轮及重开后需要沿用已查证的历史；保留工具参数、返回页、中间正文及协议回放所需 Provider payload，不保存整份请求、动态系统提示词或未返回的原文缓存 | 每组调用保持结果配对，执行结果与回执一起保存；失败暂停后续调用，确认只补存，不重做业务；删除回复同时删该轮工具历史，清空不撤销 APP 修改 |
| 管理员历史摘要及覆盖边界 | administrator / 同一分区 | 重开后复用摘要；边界覆盖完整旧轮次或当前轮已闭合工具组，唯一摘要与边界共同决定有效上下文 | 摘要与边界一起保存，失败保留旧版本；原始对话和工具消息不因总结删除；删除／重新生成涉及摘要覆盖内容时使其失效 |
| 当前输入草稿、流式片段、工具循环、取消信号、原文快照和续读缓存及待提交修改 | 当前运行内 | 属于过程状态，不需要重启恢复；与已经返回模型的工具消息分开 | 结束或切聊释放；未完成状态不伪装成成功记录，不恢复旧执行队列 |
| 保存失败后的经过展示 | administrator / 当前失败运行 | 从仍在内存的运行记录派生完整播报与简短工具状态，不新增持久化字段或第二份工具结果 | 结束后仍可折叠、展开，明确标记保存未确认；确认保存后读取已保存历史，放弃或切聊移除；不恢复旧工具循环 |
| 初始环境快照 | administrator / 当前运行内 | 按第 4.1 节随当前资料读取，不建持久快照、缓存或新字段 | 下一轮重新观察；已返回工具结果仍按会话历史处理 |
| 任务、地图、世界事实和资金 | 对应 APP / 原有作用域 | 沿用各 APP 唯一存储与不变量 | 由所属 APP 的恢复和删除路径处理，管理员不复制 |
| Provider 配置和已有全局设置 | 原有设置所有者 / 全局 | 不因管理员对话属于某个聊天而改变作用域 | 沿用现有设置入口与生命周期 |

对话记录只用于沟通连续性，重试依据真实业务状态与既有提交确认；不得为管理员另建永久执行队列或第二份业务账本。管理员记录保存与业务修改不是同一个成功概念：业务已保存而聊天记录保存失败时，明确区分，不能重做业务来补聊天。

读取现有 v1 管理员文件时在解析入口一次性转换为当前格式，保留已有文字、回执、图片引用及摘要；旧实现未保存的工具内容无法补回，不伪造。日常运行只使用当前模型，下一次保存写入当前格式。

会话、待保存候选、控制器操作和异步结果绑定发起时的聊天生命周期。切聊立即隔离旧状态；迟到的成功、失败或未确认不能回写新会话，已确认删除仍只清理原聊天附件。

聊天分支、重命名、删除沿用 OS sidecar 生命周期。清空对话与删除分区都需要用户明确操作；记录损坏只隔离管理员 APP，不静默清空、不阻断整个 OS。

管理员分区键为 `administrator`。图片使用宿主图片接口，存放在 `/user/images/xb-os-admin-${osId}/`，记录只保存路径与文件名。分支先复制到新聊天独占目录，再保存 sidecar；删除消息、清空、分区删除均先确认记录保存，再回收对应附件。未确认保存不提前删图，清理失败保留明确恢复入口。整个过程不向酒馆 JSONL 写入管理员正文或图片。

## 7. 界面

沿用信息 APP、第四面墙的聊天布局。按 frontend-design 的活动优先原则，主角是对话，不做管理表单墙。

- 桌面固定「管理员」入口；顶部为标题、上下文用量和清空聊天入口，中间为聊天记录，底部为输入栏。
- 上下文入口与计量展示按第 7.3 节；清空入口放顶部，点击后确认，删除范围按第 6 节，不混入业务数据清理。
- 点击消息显示就地操作：删除、重新生成；原用户消息已删除的回复不提供重新生成。不在每条消息下常驻操作栏，键盘与触屏都能打开；语义按第 7.5 节。
- 底部左侧直接选图，中间输入文字，右侧发送；可只发图片，也可附文字。发送前有缩略图和移除按钮，草稿清理时机按第 7.5 节。当前模型不支持看图时明确说明，不静默丢图只发文字。
- 工具活动按第 7.1 节显示操作摘要，不在聊天中提供工具原始全文展开器。
- 成功结果保留简短回执；失败保留本条对话的重新生成或保存确认入口，输入不丢失。
- 其他低频操作放菜单；不常驻功能介绍、权限解释或每个 APP 的设置表单。
- 返回桌面或关闭面板不把已发出的写入说成取消；再次打开恢复当前进度。切换酒馆聊天遵循第 5、6 节边界。
- 窄屏、深浅主题、长消息、键盘焦点与触控操作须用真实组件验证；设计稿不算浏览器验收。

### 7.1 流式工具展示

用户需要看懂“正在查哪儿、准备改什么、结果如何”，不需要围观模型的工具协议。每次工具调用只展示：操作名称、有限的目标信息、执行状态，以及返回后的短结果或错误。展示数据从真实调用和执行结果派生，不解析模型说了什么来判断是否成功。

例如，查信件时先显示“搜索原文 · 伊莱、信件”，返回后显示命中数量；随后显示“读取 #55–#57”；修改时显示任务名称与保存状态。这些是界面交互示意，不是已存在的工具名或模型调用样例。

- 流式生成工具参数、工具实际执行、等待保存与保存确认分别展示，不能参数还没生成完就标成执行中。只消费已经可识别的目标信息，不逐 token 格式化整份参数 JSON。
- 进行中的操作就地更新，AI 播报与简短工具活动按实际轮次连续保留；下一次输出或工具调用不得自动折叠已经展开的工作经过。整个 turn 结束（含失败、停止）时才把全部经过收成一条，置于最终回答之前；用户手动展开后，普通状态刷新不得再次收起。工具参数和返回全文从不进入经过列表。
- 面板只接收轻量展示投影，不通过 frame 消息把完整 Read 结果、全量地图、工具参数或 Provider payload 传给前端后再用 CSS 隐藏。折叠不等于懒加载，也不等于释放内存。
- 必须查看证据时，跳到对应酒馆楼层，或按需打开有分页上限的原文片段；关闭后卸载并释放。它是独立的证据查看，不是把全部工具返回铺在聊天里。
- 状态文案由集中定义的状态标识映射；不把错误原始 JSON 或堆栈当普通聊天内容。可见错误仍需说明具体操作和恢复方式。

### 7.2 渲染与内存预算

界面显示量、模型上下文量和持久历史量是三个不同边界，分别受控，不靠一个“最多显示多少条”掩盖其他两处的无限增长。

- 聊天分页、活动窗口与消息正文块上限统一由 [administrator policy](../apps/administrator/domain/policy.ts) 定义。消息正文按需展开后续块，拼回同一正文再解析 Markdown，保留跨块语法上下文。工作经过不按轮数或播报长度分页：运行中传输本 turn 的完整播报与简短工具状态，中途重开也完整恢复；历史行只携带经过轮数，展开后一次读取该 turn 的完整轻量经过。读取结果按聊天、消息、历史版本及展开生命周期校验，不拼接新旧版本。折叠时卸载经过正文，移出活动窗口释放组件。向上翻页保持阅读锚点，不无限累积历史行。
- 流式文本合并更新、节流渲染，只更新当前变化的消息或工具行；最终完成和失败状态及时刷新。不在每次流式回调中重做整段历史的 Markdown、语法高亮、工具结果 JSON 序列化或全量历史快照传输。
- 消息正文及流式回复复用 OS 共享安全 Markdown 组件：支持段落、列表、表格、链接和代码复制；代码中的 HTML 不作为页面执行，不加载模型正文中的远程图片。
- 用户向上阅读时不强制拉回底部；新内容用“回到最新”入口表达。面板隐藏后停止视图刷新；是否取消后台操作仍遵循第 5 节，不由渲染生命周期决定。
- 搜索按批处理并让出主线程，支持取消；结果有输出预算和继续位置。处理当前消息时不反复复制整个聊天，也不在每次重绘时重新搜索。
- 模型已经收到的工具结果按第 6 节保留；不会仅因本轮结束就清空。临时原文缓存仍由 `agent/tool-results.ts` 限量，超限淘汰旧结果，续读引用失效时明确提示重新查阅；下一次运行或切聊释放缓存，不额外建长期原文缓存。会话记录和 UI 展示分离，大结果不进入 frame 推送。
- 上述限制保证的是新增传输、渲染和临时工作集可控，不声称宿主原有聊天数组或整个 sidecar 的加载成本已经消失。

### 7.3 模型上下文管理

按完整交互而不是任意条数维护上下文。管理员持久会话及摘要覆盖边界投影出同一份有效历史，供请求、计量和总结读取；UI 不展示完整工具结果，不影响模型下一轮使用这些历史证据。

- 每次模型请求前计入静态规则、工具定义、APP 投影、管理员历史、已有摘要及本轮工具结果；预算还需给回复与后续工具结果留余量。总量按完整请求的消息顺序、工具配置和供应商推理回放策略估算，分项保持相同的 USER 边界。供应商原生 session 续接也必须管理已累积上下文，不能只算本次新发的消息。
- 搜索结果与 Read 从入口分页限量，不等溢出才把已经送进模型的全文隐藏。模型需要更多证据时继续读取，返回值明确实际范围，不能把截断片段当全文。
- 较大的工具结果由 `ToolResultRead` 按同一 reference 和连续 offset 续读，nextOffset 为 null 表示该结果已读完；原文自身的下一段仍由原工具读取。结果页不再次分页或复制入资料缓存；已经返回的页作为历史工具消息保留，但 reference 只在原运行缓存有效期间可用于续读，重开后要查更多资料须重读来源。
- 达到总结阈值时，将已有摘要和之后全部有效会话历史一次总结，包含当前轮已完成的工具调用与结果，不按楼层筛选或固定保留最近几轮。当前用户请求仍以原始请求继续提供。工具 call/result 配对不拆散，摘要记录覆盖位置但不删除原始工具消息；替换上下文时按供应商协议重建会话。
- 摘要保留用户明确要求、已确认的修改、未解决问题、必要对象与原文定位，不塞入旧 Read 全文。它不扩展任务目标，也不能把一次操作扩大成永久授权；涉及当前业务事实仍重新读取所属 APP。
- 压缩成功且重新计量确实减少上下文后才替换摘要和边界；失败保留旧历史并明确反馈，不静默删聊天、不发送已知超出预算的请求。单轮本身过大时先减少读入范围或结束当前处理并说明，不能无限重试总结。
- 顶部上下文入口只显示用量圆环，不在圈内放数字，也不常驻用量文字；保留「上下文用量」可访问名称。圆环进度表示估算输入用量占管理员可用输入预算的比例；预算未知时显示未计量状态，不伪造进度。点开查看约用 token、预算及组成，整理历史时显示对应状态。只打开页面或翻阅历史不触发模型总结。
- 工作输入预算与总结阈值统一读取 `apps/administrator/domain/policy.ts`，界面和请求前检查使用同一策略。该处同时定义摘要输出预算与图片预留；这是应用预算，不是模型真实窗口。摘要请求也受预算限制，异常超大输入明确报错；供应商明确报告上下文超限时，收缩后最多自动重试一次模型请求，不重跑业务工具。
- 「本轮工具结果」计入最后一轮尚未被摘要覆盖的工具消息，结束和重开后仍计量；进入下一轮后，之前的工具消息归「聊天与摘要」。这里是有效输入的本地估算，不是供应商计费 token 或磁盘总量。

### 7.5 消息操作与图片边界

- 删除针对选中的管理员聊天消息，不顺带删除后续聊天，不撤销该轮已保存的 APP 修改。删除或重新生成涉及已摘要内容时，使受影响摘要失效并从保留记录重建，不能让已删内容继续由摘要带入模型。
- 「重新生成」先将会话截断到选中消息对应的 USER，删除该轮旧回复、工具消息与 Provider payload、操作回执、错误、后续对话及受影响摘要，确认保存后进入与发送相同的正常生成链路。末尾已是 USER 时直接生成，不再追加 USER。每次读取当前 API 配置，新建模型会话，保留正常读写工具；不恢复旧工具循环。保存截断失败时不调用模型；同一现场确认保存后只接续一次，停止、放弃或重载不自动生成。已经保存到各 APP 的业务事实不随聊天截断回滚，新生成按当前事实处理请求。原用户请求已删除时无法重新生成。
- 429 等传输错误只用于界面反馈，不进入后续模型历史或摘要输入；保留下来的历史回复仍携带完成／中断状态，业务操作回执仍作为参考资料。
- 历史窗口以会话 revision 为缓存边界，更新时刷新当前窗口并保留阅读锚点，不混合不同版本的行。正文续读以聊天、消息身份和 revision 定位；同一消息独立保留展开范围，刷新完整范围后一次替换正文，旧请求迟到后不再回写。切换消息或聊天时重置展开范围；刷新失败显示已知的当前首段和错误，并允许重新展开。
- 对话删除、清空、重新生成不能与本会话进行中的操作并发；用户可先停止，已发出写入的结果确认仍按第 5 节处理。清空确认处简短说明不会撤销已完成的管理修改，不把这段说明常驻聊天页。
- 发送与重新生成从准备阶段就显示进行中状态和停止入口，覆盖初始化、图片上传及 USER 保存；关闭再打开仍可停止。停止阻止后续模型调用，已发出的存储操作按原确认流程收尾，不伪装成已经撤销。
- 业务写入经读回确认后，将同一次确认的操作回执和对应工具结果一起保存；保留当前聊天正文，不覆盖其他窗口的新回复。若确认改变了已摘要的记录，则使受影响摘要失效。
- 图片属于用户发送的管理员消息，不是生图功能。活动窗口内图片使用惰性加载和有界预览；图片输入计入第 7.3 节的模型预算，历史请求不反复附带 base64。支持 PNG/JPEG/WEBP/GIF，单张最多 4MB。
- 附件由管理员消息拥有，已发送图片随历史恢复，未发送图片只属于草稿。上传或 USER 保存失败保留草稿；每次发送用临时提交标识绑定草稿版本，接收确认从已保存的 USER 派生，与可见分页和 AI 是否结束无关。确认后立即清理该版本，不清除后来编辑的文字或附件；重新生成不接收草稿。后续看图／模型失败保留已发送消息和附件，不静默转成纯文字请求。发送始终发送新草稿，不根据可见历史切换操作；重新生成通过消息菜单发起。截断回收被删除消息的附件、保留目标 USER 的附件，回收规则见第 6 节。

## 8. 提示词分层

实现按以下结构组织；主对话与历史摘要由[管理员提示词](../apps/administrator/agent/prompt.ts)定义，领域块与工具由各 APP 提供。以小白助手的协作语气为参照，先帮助模型理解环境与用户，再说明查证和操作方法。

1. 共享层：身份与协作职责 → OS 环境与已有资料 → 查证路线 → 结果含义 → 唯一的交流与收尾规则。身份、协作和交流段用中文，与面向用户的语气同源；技术事实用英文说明。不点名业务领域，不把连续对话写成反复判断授权的流程。摘要保留当前目标、已商定的细节、具体进展与未完成事项。
2. APP 领域层：各自 `management/prompt.ts` 以 `# <领域> domain` 开头，交代领域概念、`What you have` 和确有必要的领域判断。资料说明与实际 `initial` 投影一致；不重复身份、协作要求、结果通则或收尾规则。任务判据引用任务自身定义，不另维护管理员版本。
3. 工具层：各自 `management/tool-contract.ts` 集中管理模型契约和轻量活动标签。description 按操作 → 返回 → 适用场景 → 范围及真实注意事项组织；默认值、上限、过滤、遗漏与 null 的含义归 schema 字段。分页和长度数值引用实际执行常量，不手写第二份数字。
4. 资料层：第 4.1 节的环境观察、当前 APP 业务投影、原文和工具结果；APP 用途只从目录取得，不重复工具参数、领域判据或动态设置。[资料说明](../apps/administrator/agent/reference-data.ts)集中定义当前资料、对话摘要、历史操作、图片与初始分页的引导文字；正式请求和上下文计量仍使用同一投影。资料与管理对话的区别由共享层解释一次，范围与截断随资料表达，不将动态文本拼入可信规则。

实现时逐条对应实际能力；一个事实只写一处，其余引用或派生。共享层说明如何理解讨论、查证与修改需求，工具说明专注用途、返回和实际限制，不重复协作要求。

查证路线按用户提供的线索选择：指定楼层直接读取，事件或词句先搜索再读上下文；任务异议按原目标对照原文，明确管理修改按指令执行。回复以答案和实际结果为先，所有请求涉及的领域处理完再收尾；普通讨论不强制套操作汇报。

### 8.1 新 APP 的接入约定

沿用现有 `ManagementParticipant` 注册，管理员按第 4.2 节直接派生可加载包，不另维护目录、权限白名单或全局加载框架。已接入的任务、地图、世界提供以下实际参考结构：

```text
apps/<app>/
  descriptor.ts                 APP 名称、用途与必要边界
  management/
    prompt.ts                   管理领域资料与判断
    tool-contract.ts            管理工具定义、参数说明、返回契约及活动标签
    participant.ts              初始投影、调用本 APP 服务、保存与恢复衔接
  tools/                        管理与后台维护确实共用的操作契约、编译与判据
```

- 仅供认识的 APP：随正常 APP 模块注册提供 descriptor 即可，不为进入目录虚构管理能力。私有内容不会随用途说明自动开放。
- 有意开放管理的 APP：在自身模块声明现有 `MANAGEMENT_CAPABILITY` 依赖，安装时注册 participant，并把注销函数交给 `execution.addCleanup`；现有生产装配示例见任务、地图、世界的 `production-module.ts`。管理员从成功打开的 session 获取 prompt、initial 和 tools，无需修改共享提示词或新增领域路由分支。
- `participant.ts` 保留业务所有权：initial 与 Read 共用投影；执行仍经过本 APP 的服务、领域校验和保存守卫。工具的 effect、目标摘要和保存结果必须符合真实行为，不因接入管理员绕过原校验。
- 多种调用流程共享操作时，参数和共同说明只在 APP 的 `tools/tool-contract.ts` 定义。管理契约按实际分页形式提供 Read，给共享写工具注入当次保存与返回说明；后台维护注入草稿及运行结束后的保存说明。两者不是同一种保存语义，不能把一份说明原样用于两边。没有真实第二个消费者时无需预建共享层。
- prompt 和工具定义随 APP 代码加载，初始投影属于运行态；不新增持久化提示词、配置或缓存。APP 注销即移除其管理入口，删除数据仍遵循所属 APP 的策略。
- 接入检查保护真实契约：投影与分页、敏感数据边界、工具路由与 effect、保存/恢复以及切聊隔离。参数形状交给类型检查；不靠断言提示词、标签字面量或文件布局维持这份约定。
