# Dice：行动检定与随机遭遇

Dice 是普通小白 OS 的剧情检定 APP，不是游戏大厅的大话骰。主 RP 模型提出行动检定，本地程序裁定，再由原主 API 续写；随机遭遇只作本地判断，不另开剧情 Agent。

## 设置与范围

玩法偏好由 [DiceSettings](../apps/dice/types.ts)定义，统一经 OS 设置仓库保存到 `xiaobaiOs.apps.dice`：

- 行动检定与随机遭遇是两个独立全局开关，默认关闭；换卡、换聊天和刷新保留。
- 行动检定可选 D20 或 [D100 属性鉴定](./dice-coc7-design.md)。D100 面板、能力目录及算法只在该文档定义。
- D20 频率为标准／积极，默认标准；是模型判断倾向，不是固定概率或次数配额。切档只影响后续请求，不重算结果。
- 旧正式线的轻量频率仅在 [设置加载](../apps/dice/settings.ts)转换为标准，运行时不保留第三档。
- 设置确认后生效，失败恢复已确认值。不从某个聊天的旧开关推断全局意愿。

行动检定需要关闭酒馆原生“自动续写”；只提示限制，不改用户设置或增加协调器。开启检定会增加主 API 续写请求，费用取决于上下文与供应商计价。

## D20 规则与请求

[行动检定规则](../apps/dice/domain/action-check.ts)唯一拥有难度区间、随机采样与临界判定。模型按已确立能力、行动方式和环境选难度；程序独立抽取该档 DC 与 1–20 骰点，1 大失败、20 大成功，其余按 `roll >= DC`。实际 DC 与结果一起保存，后续规则变化不重判历史。

`stat`是检定项目名称，不表示读取了角色属性。一次返回只能执行一个请求；同一 AI 候选的总次数由 `MAX_ACTION_CHECKS`定义，按全部执行历史计数，删标记、重试或刷新不重置。最后一次允许收尾续写，超过上限不继续自动请求。

正式 [请求契约](../apps/dice/protocol/request.ts)使用 AI 新增正文末尾的 `<xb_action_check>` JSON 块。字段、长度、允许值、解析与模型示例归同一契约，不在文档复制另一份 schema：

- 可见行动先发生，停在结果之前；闭标签后只允许空白。
- 围栏、行内代码、引用、历史正文与推理区不是执行请求。
- 截断、多请求或非法必需字段不执行，不自动请求模型修复。
- Tagged JSON 不是供应商原生工具，不强制整个回复为 JSON。

## 同楼执行与保存

运行捕获聊天、消息对象、活动候选、正文和原始记录。宿主接收事件只捕获目标并返回；不能在被宿主等待的回调中再等待宿主收尾或下一次 Generate。

执行顺序：等待当前原生调用释放 → 重新核验目标 → 本地裁定 → 同步更新消息与活动 swipe → 揭晓 → 原生 continue。群聊必须保留原成员、原楼及 wrapper 归属，不能把全局空闲等同于同楼续写资格。

结果记录在 AI 候选的 `extra.xiaobaiOsDice`，已执行请求原位变为 `[dice:记录ID]`。当前消息与活动 swipe 是宿主要求的同一候选工作副本及存档，不是两套独立历史。正文、其他字段及非活动候选不能被顺手改写。

普通新检定不专门上传或读回整聊天；结果先成为当前页事实，随宿主正常保存持久化。保存前关页可能丢失未保存结果，不建补掷队列。显式恢复的原生保存与付费重掷各有自身边界，不把普通新检定的零专用保存约束套到它们。

### 标记与恢复

- 卡片、结果回注和恢复资格由正文中有效标记派生，顺序取首次出现顺序；未知或重复 ID 不创造新结果。
- 移动标记移动显示位置；删除标记移除显示及回注，不删除执行历史或返还次数。
- 末尾仍是有效标记时，可显式沿用骰点续写；已有后文则用酒馆继续。编辑、重载和渲染本身不发请求。
- 新 swipe 清除可能继承的 Dice 工作字段，旧候选不动。切候选只读取，不重掷。
- 停止后保留已应用结果，不自动恢复；旧调用迟到不能结束新恢复调用或清掉其注入。
- 显式恢复可经原生保存写入已采用结果，只保存原聊天；不等待后再选择另一个聊天。
- 正式线 V1 记录由 [冻结读取器](../apps/dice/storage/records-v1.ts)直接转为当前记录；只读不回写，旧 offset/digest 不进入当前引用语义。受支持格式见 D100 文档。

### 付费重掷

末尾有效检定可在续写前重掷。价格与规则唯一位于 [reroll.ts](../apps/dice/domain/reroll.ts)：只改变骰面和裁定结果，保留原请求、DC 或属性阈值，不新增一次检定。

[重掷服务](../apps/dice/application/reroll-service.ts)先交付新结果，再有界保存；已知余额不足时拒绝，交付后被其他消费用完余额时不撤销骰点，按现行服务规则处理费用。覆盖结果和扣款在同一用户文件事务，稳定操作身份防止重复扣费。保存失败明确报告，不重抽或替另一聊天重试。

`resultOverrides`由 Dice 用户分区拥有，以原检定 ID、固定裁定依据与操作版本关联；读取时仅应用匹配依据的覆盖。它不复制完整消息或面板，随显式结果清理删除。运行内重试、队列及结果投影不另建持久任务。

## 随机遭遇

[遭遇规则](../apps/dice/domain/encounter.ts)对每个合格的新用户回合取一次随机数：高影响 1%、中影响 3%、低影响 5%、不触发 91%，三档互斥。任意等级触发后冷却两个真实用户回合；第三个新回合恢复抽取。关闭期间实际出现的用户回合也占位置。

判断归用户消息的 `extra.xiaobaiOsDice.encounter`，记录触发等级、未命中或冷却跳过；负结果也是已作出的事实。冷却从当前保留消息派生，不存第二个计数器或随机原值。

- normal 新用户回合才能首次决策；regenerate、swipe、continue 只读已有结果。
- 历史没有记录不补抽；打开 APP、重载、无新用户输入、quiet、impersonate、dry-run 和私人信息投影不创建回合。
- 群聊只影响本轮第一个真实主 RP AI 回复及其续写，不给每个成员再次触发。
- 低影响融入当前互动、可忽略；中影响提供可回应变化；高影响可明显改变局面但不替玩家决定或结算重大后果。不固定事件种类或吉凶。
- 世界背景／总结只按各自开关提供可选参考方向。Dice 不读其内容、不检查向量、不复制新闻或记忆、不新增模型调用。

基础提示与参考拼接由 [遭遇 Prompt](../apps/dice/protocol/encounter-prompt.ts)拥有。判断仅进入当前用户消息内存，随宿主正常保存，不独立保存整聊天或追踪模型是否落实了事件。

## 注入、显示与生命周期

检定与遭遇分别注册自有 Prompt；实际深度与排序以 [注册定义](../apps/dice/prompt-registration.ts)为准。请求组装后、取消、切聊或停用时清理归属本请求的注入，交错的 dry-run 不能拿走真实请求的结果。正文标记在 [发送边界](../apps/dice/host/request-filter.ts)过滤，不改保存正文。

显示正则是 Dice 自有的宿主持久配置，固定 ID 为 `xiaobai-os-dice-action-check-display`。启用及真实生成前检查，缺失／禁用／损坏才修复，正常检查不保存设置；关闭功能不自动补回。完整开标签出现后隐藏协议，半截前缀仍按普通文本显示。仅 AI、仅显示，不改原始解析文本、不启用用户禁用的整个正则扩展。生成期间修改或删除规则可能触发宿主重载并打断回复。

卡片用安全文本显示当次请求及裁定；新结果揭晓、历史静态显示，减少动态效果不阻断操作。遭遇提示挂在所属用户楼内部，文案由 [遭遇标签](../apps/dice/ui/encounter-label.ts)定义；不占新楼、不写正文、不从 AI 内容猜插入位置。

关闭 OS 窗口或切 APP 不停后台玩法。关闭对应开关、停用 OS、切聊天使旧处理失效，不中止无关请求。整个 OS 停用后不保证自绘卡片继续显示，重新启用按记录恢复。

## 所有权、清理与限制

`apps/dice/`拥有领域、协议、Host、设置、用户分区和 UI；不导入 Tavern 运行时。人物面板及覆盖结果归用户文件，玩法开关归设置，原骰点及遭遇归消息；不再使用聊天级 Dice 开关分区。

显式清理指定聊天：先关闭玩法并确认，等待已有重掷保存 → 清除该聊天检定 ID 对应的用户覆盖结果 → 清除消息及全部候选中的 Dice 数据与标记 → 确认聊天保存。失败如实停止，可重新执行；不扫描未选择的聊天，不清空全局人物面板或其他 APP 字段。旧聊天经济分区的升级清理由存储入口拥有。

整功能退场还须处理面板／设置／覆盖结果及自管正则，移除目录、catalog、事件与 Prompt 注册；已有钱包审计不倒扣，先确定数据策略。直接删插件后需在酒馆全局正则中手动删除自管规则。

不提供事件池、概率编辑器、NPC 属性管理或后台语义评分。模拟供应商能证明协议与请求顺序，不能证明检定时机、遭遇尺度或叙事质量；这些真实模型项目尚需单独验收，实体 WebView 也不由桌面模拟保证。

## 检查

规则用确定随机源单测；消息／候选、停止、群聊、设置及资金用边界集成；原生生成和显示用真实宿主检查。运行 OS 的测试、lint、类型与构建，重点回归同楼续写、重掷单次收费、标记编辑、全局偏好和跨聊天隔离，不断言 Prompt 或 UI 文案字面量。
