# 语伴：实现架构与验证边界

## 1. 文档分工与功能边界

[产品设计](./language-learning-app-target-design.md)是用户体验与业务要求的唯一来源。本文只记录当前实现的职责、接缝和验证方式，不保留分批施工日志、旧版界面基线或阶段测试数量；历史决策从 Git 历史查找。

语伴由 Learning 自有领域、应用、存储、Prompt、工具和 UI 组成。它复用宿主上下文、Agent Capability、共享联网、TTS 和 Economy，不拥有主剧情、私信或四次元壁的会话。没有新增依赖、通用教育框架或跨应用任务平台。

聊天的 learning 分区保存稳定 ID 的搭子会话与当前选择；learning-workbench 用户分区按语言保存教学对话。两边仅保存交流正文、各自摘要、访问范围与学习引用，工具轨迹及在途状态只在运行内。奖励政策由 learning-rewards 分区管理，已到账资金只认 Economy；学习完成凭据不是第二本钱包。

工作台同一语言的存储按资料访问范围保留记忆片段；读取时只合成当前故事可访问的交流与摘要，写入不覆盖其他故事的私有片段。片段不是另一套人格或课件副本，只用于保持已有资料的访问边界。当前段落审阅在历史压缩后仍保留一份关联原答的正文，供阅读页重开恢复，不再重复回放进模型历史。

账号身份、运行时 chatIdentity 和持久故事 osId 各司其职。显示名不是任何一种持久身份；换卡不会复制语言档案，旧卡私密材料不能成为新卡模型输入。

## 3. 持久状态、保存与删除

长期事实及其产品理由见产品设计 §4。当前文件外壳和写入容量由 [storage/document.ts](../apps/learning/storage/document.ts)维护，结构由领域解析器校验，不在文档再复制字段清单和容量数值。

语言档案拥有当前课程 unit、独立复习题组 review、学习项与完成凭据。修订作为关联原答的另一份尝试保存；批注引用对应原答段落和精确词句，知识项通过 itemId 关联；范文不是用户尝试。学习阶段只有一个派生入口 [stage.ts](../domains/learning/stage.ts)，不另存步骤号或进度百分比。

[work.ts](../domains/learning/work.ts)拥有当前故事的作答访问规则。当前课件投影要求题目、原答、已有反馈及修订来源均可读取，供界面、LearningRead、阶段与结课使用；按答案 ID 复核或删除时，当前作答不可读仍可使用自身范围可读的保留证据，不以来源课件是否退场区分。复核 focus 和输入范围均来自实际选中的作答来源，不能带入隐藏课件；按钮与命令共用操作判定，修订依赖同时检查当前作答与保留证据。写入始终按 ID 修改完整文档及对应证据副本，不能把过滤后的视图保存回去。结课记录阶段实际采用的原答与末次修订，不引用被替代的旧草稿。课件范围变化不重写原答范围，字段含义见产品设计 §4.1。

跳过修订以原答 ID 列表保存在所属读写课程中，是用户重开后仍有效的选择，不是运行锁；新增原答/修订不继承旧选择，删除原答及其修订链时同步移除，删课时一并退场。它与原答使用同一仓库确认机制，没有独立缓存或保存路径。单独删除原答不能连带删除当前故事不可读的修订；明确删除整课、知识项或语言仍按其完整所有权清理。

### 保存边界

- 首次读取与明确刷新访问宿主文件，正常读和重开课堂复用已确认版本。缺文件与坏文件分开处理，错误不能初始化覆盖。
- 仓库串行处理写入。明确上传成功确认候选；响应丢失才核实原候选，不把网络异常当作未落盘。原操作的确认通知随候选只保留在运行内；立即成功、核实成功、重传原候选成功或采用同一候选均由仓库通知一次，用于登记提交回执和本请求保存的课件身份。拒绝、未确认及采用其他服务器内容不通知成功，候选确认或放弃时释放通知。
- 未确认保存保留原确认视图和精确 commitId；核实、重试原候选、采用服务器版是不同动作。只有原依赖仍有效的等待保存正文可以接回。
- 语伴选择及私聊属于聊天 sidecar，工作台对话属于用户分区，各自的保存状态和恢复入口独立于 Learning 用户文件。核实使用文件协调器的只读恢复，采用服务器设置是明确动作；确认语伴改变后才清理对应交流，同一语言的工作草稿保留。
- 清空回执未知时，runner 先退休本地旧历史，runtime 仅在运行内保留原会话标识以完成确认恢复。核实或采用服务器版后重新接续实际保存状态，不重发模型请求，也不将恢复应用于已切换的另一会话。
- 用户实际揭示的帮助允许与工作任务保存合并，但只合并相同单元、相同题目及其实际材料的追加曝光事实。[merge-exposure.ts](../domains/learning/merge-exposure.ts)还保留等待原答落盘期间新增的读写讲解及作文题，不合并目标、原答或任意课程修改。
- 每个修改工具在返回前保存，下一工具从最新确认事实继续；后续模型失败不撤销此前成功工具。仓库队列和引用校验保留并行原答、帮助及笔记。并发变化使候选在发送前取消时，session 撤掉候选及其临时焦点、展示和工具登记，模型可读取最新记录后重新修改；这不是需要核实的未知写入。默认编辑目标若被外部替换，须重新读取或明确指定 unitId；任务自己的换课会更新焦点，不取消自己。
- 学习项证据由 assessment 统一投影，按题目实际引用保留材料；读写课的段落总结只留对应段落，作文不重复保存文章，其他附加题不沿用作文的裁剪规则。
- 宿主上传没有服务端 CAS。本实现不承诺多设备或多标签同时编辑；不增加锁文件、心跳或自动对账。
- 整页重载只恢复服务器上的长期事实。未提交草稿和未保存模型候选不承诺恢复；页面关闭前对真实未提交编辑提示风险。

### 当前格式与旧格式入口

已发布的语伴选择格式由 [companion-v1.ts](../apps/learning/upgrade/companion-v1.ts)冻结，在选择服务的读取入口一次转换为稳定会话；旧运行内混合历史不伪造成两份持久记忆。

独立会话最初的引用式格式由 [memory-v1.ts](../apps/learning/upgrade/memory-v1.ts)冻结，真实样本为 learning-memory-v1.json。会话存储边界从仍存在的来源一次派生权限，交给 runner 的始终是当前格式；新保存直接携带交流与摘要的访问范围。旧格式已因来源丢失而失效的交流不能推测所属故事或公开恢复。

运行时只认当前格式。已发布 v1 学习文件在 parseLearningDocument 入口一次升级：

- 保留语言设置、语法/词汇学习项及其证据；缺失的排程历史不推算，按升级规则重新开始。
- 不保留旧课程、其他技能学习项和旧完成凭据，包括其未领奖励。
- 日常业务不携带 v1 分支；兼容对象仅为这份已发布文件格式。规则与样本在 document 及 [learning-storage.test.js](../tests/learning-storage.test.js)，不为旧 UI 或工具留兼容壳。

删知识项、原答、课程、语言和全部数据分别走应用服务，处理依赖反馈、排程及仍有其他引用的证据。conversation-references 从本轮实际资料派生访问范围，交流还继承其所用历史与摘要的范围；该权限随记忆保存，不再用来源是否仍存在来决定记忆是否有效。显式删除仍按引用清理相关交流与摘要；替换文章不走对话删除。清空 Learning 不撤销 Economy 已到账流水。

故障页的“重置学习数据”与正常删除分开：经确认只覆盖损坏的 Learning 用户文件，保留各故事的搭子对话、用户级教学对话及已到账流水，不联动删除其他分区。JSON 语法错误与领域校验失败都提供重置，网络读取失败不当作文件损坏。重置回执未知时保留同一候选核实；坏文件发生变化后重新征求重置确认，仍复用原空候选。写入前发现文件已经修好则采用可用记录，不再覆盖。上述恢复状态只在当前运行内保留。

普通保存回执未知时，若核实读到损坏文件，同样开放重置；用户确认后丢弃旧编辑候选及其确认回调，创建独立的空候选。重置前若读到原编辑已成功，则正常确认该编辑；读到其他可用文件则采用它，不执行重置。对话重建只读取状态已确认的存储，未确认时不把旧缓存标记为恢复完成；核实成功后再恢复实际已存对话，继续保存不能覆盖掉漏载的消息。

故障重置不以共享用户文件（钱包、教学对话）的待确认写入为前置条件，也不重试或放弃其他存储的候选。原生课程操作只要求学习文件可用：历史尚未确认时，教学回复暂留当前运行并标记对话未保存，课程与答案照常写入 Learning 文件。历史确认后先接回已存前缀，再保留本次新回复及其操作状态；未接回完整历史前不提交覆盖式对话保存。钱包及搭子对话按各自回执恢复，不因学习重置被清空。

测试线与正式线共用“报错 → 确认重置 → 重新开课”，v1 无法升级读取时也不要求用户手工修文件。重置的确认回执统一退休旧备课、来源选择、委托及课程操作状态，再从原存储接续保留的对话；直接成功与稍后核实成功不分叉。界面在恢复完成后进入开课设置，不停留在旧失败流程；可正常读取的历史文件不因版本旧而被重置。

功能退场的数据策略是删除 Learning 自有数据，不迁入四次元壁。移除步骤：取消所属运行；一次清理 Learning 用户文件、用户分区 learning-workbench / learning-rewards 及各聊天的 learning 分区；删除 Learning 注册与目录。共享配置、TTS 公共能力、Economy 已到账流水和其他领域数据保留。现有 module.clearData 仅定义聊天分区清理边界，内核没有应用卸载命令，不能把删除聊天当作全用户学习数据卸载。

## 4. 工作台任务、交流与能力

workbench 与 companion 显式分派到两个 teaching 实例，分别拥有消息、错误、摘要和取消。工作台不调用角色上下文适配器；搭子可读公开学习资料、指向活动，或调用 LearningRequest。自然语言委托与学生原话分字段传递，原始引用、定位、帮助条件和提交回执仍由应用提供；LearningSubmit 只从学生原话提取答案。普通问答不自动成为作答或设置变更。

委托由 delegated-work 持有任务记录，接受时同步占用工作台运行通道，立即返回 taskId；执行不绑定语伴回复的取消信号。同一原消息重试时，相同委托复用已接受回执，新的用户消息可以发起新任务。LearningTaskGet 和上下文共用任务概要，按 taskId 查询完整结果。工作台状态在每次语伴模型请求前刷新，忙碌提醒只在实际忙碌时进入本轮学习资料，排在用户发言前；不进入固定人设或聊天历史。原生续聊渠道在资料变化时重建本轮请求，替换旧状态而非叠加提醒；状态不变时继续原会话。打开课件与提交新委托还在执行入口检查当时状态。

任务记录保留完整委托、原答依据、提交回执、资料范围与引用，以及单元／题目／选区目标；模型转述不改变来源权限。目标仅跟随本任务已经确认的替换，外部替换不使后续委托默认落到主课。工作失败或取消后的重试恢复同一任务和完整请求，更新原任务结果并再次通知；每次运行的身份隔离迟到回调。以上均为当前课堂临时态，没有新增持久任务队列。

结果以独立 task-result 用途串行送入语伴通道，重新读取最新交流与学习事实。只有回复生成并确认保存，通知才标记送达；失败保留任务结果，重试仅重做通知，已生成而未确认的回复只核实或补存原候选。通知作为无用户发言的回复沿用既有历史格式，原始结果、待通知状态和任务回执不持久化。切换两侧视图不参与调度；换学习身份、关闭 App 或清理会话时退休对应临时记录，不承诺跨刷新续跑。

通知轮自己的后续委托回执随该轮保留，失败重试复用已接受任务；成功即释放请求快照。普通失败对话在新的用户对话开始后不再提供原轮重试，后台通知不使它失效。朗读与笔记从已发布 turn ID 取得正文和原学习目标，不缓存第二份“最新回复”，也不以文字相等判定回复身份。

[work-target.ts](../apps/learning/application/work-target.ts)统一建立本轮目标：作答反馈与段落审阅从保存的原答派生单元和题目，聊天沿用引用位置，通知及重试保留原目标。归档原答不借用后来打开的课程，批量任务不猜测单道题。目标只活在该 turn 的运行内；[reply-note.ts](../apps/learning/application/reply-note.ts)供按钮和保存命令共用定位与重复笔记判定，正文相同但题目或选区不同仍是不同笔记。

[agent/access.ts](../apps/learning/agent/access.ts)选择初始资料和目标单元，不决定工作台能做什么；[tool-contract.ts](../apps/learning/agent/tool-contract.ts)给所有工作台请求同一套学习工具。角色分工与主动陪读的只读边界由同一集合落实到请求和执行。

- 备课/批改可以与交流并存。停止聊天不停止工作任务，停止工作任务不清掉聊天。
- 冲突的原生操作和委托明确拒绝，不隐藏排队。主动机会遇到忙碌直接让位。
- 交流提交的原话与帮助条件取消息到达时的依据，不使用模型改写后的答案；随后回复里的提示不能倒改这次原答的条件。
- 复习提交后的阶段推进归 runtime，而非可能已卸载的复习组件。
- 阶段请求只取得当前待评原答或修订，包括争议后重新待评的答案；已解决反馈不因恢复操作重复评估。
- 原答先确认，再调用相应教学任务。未确认的用户输入不能成为已提交成绩。
- 读写入口在模型会话之前检查所选共享联网渠道配置；缺配置时暂存本次选择意图，等用户明确选原创或进入设置，不写入学习档案。继续已有文章不做联网检查或重新选材。
- 一次读写准备是一条完整模型工具循环；模型自行选择取材、发布正文、补讲解和出题的次序。正文由 lesson 编译器建立总结题。工具成功、重复读取、添加练习都不会触发人为收尾；provider-loop 只遵守协议终态、取消、真实失败和总轮数预算。
- 换课先由 session 校验完整候选，有效且确实需要授权时才交给工具执行器等待确认。接受后按最新记录重新校验并执行，拒绝或参数错误交还模型继续其他工作。不结束任务、不排队重建请求；确认不保存为持久实体。原生换课意图只对应当时确认的课件，发布新文章后继续编辑不再继承换课意图；显式 newLesson:false 始终编辑选中课件。材料/题目展示链接在内容退场时清理，不阻拦换课或编辑。
- 准备任务不占用用户提交和交流的运行通道；暂停准备不取消并行聊天或总结审阅。运行标记和取材选择只在当前会话存在，恢复依据仅是保存内容中的缺口。

## 5. Prompt、资料与发布

产品职责见产品设计 §14。代码归属如下：

- [prompt.ts](../apps/learning/agent/prompt.ts)：两个独立主体的身份、学习事实、教学判断、本次意图及唯一收尾规则。工作台常驻必要教学指引；任务块定位本次请求，不裁剪能力。
- [tool-contract.ts](../apps/learning/agent/tool-contract.ts)注册学习工具；独立读写准备工具位于 [preparation-tools.ts](../apps/learning/agent/preparation-tools.ts)。用途、返回值、字段及限制归对应工具所有，数值引用领域常量。
- [context.ts](../apps/learning/agent/context.ts)：当前请求实际资料；[data-projection.ts](../apps/learning/agent/data-projection.ts)与 LearningRead 共享读取投影。
- 人物表达复用 character-dialogue 的真实共享规则；提示词不进学习文件，不提供用户覆盖配置。
- 历史整理仅消费已发布交流；当前工具续跑按 Agent Core 协议保留必要载荷，不将其当成已对用户说过的话。

每次陪聊、答疑或主动陪读都带完整公开材料和实际设置；锚点只定位，不替代全文。复习准备/批改及其原答复核读取 review，不能误用相邻文章。段落审阅只取得公开题目，正式评估另有对应答案规则；已归档或尚未公开的评估必需材料只补在该次评估 focus，不重复注入当前全文。

review-prepare 的初始范围由 access 中的学习项／证据投影决定。公开任务不自动注入私有资料；LearningRead 可按需读取当前故事可见的资料。reading 在运行内记录实际返回对象的来源，初始上下文与工具读取使用同一机制；原答、批改、结课摘要分别继承自己的范围，不用原答或课件 ID 代替嵌套内容的范围。分页只累计实际送入上下文的那一页，引用供删除清理使用，来源元数据不进入模型消息或持久化。session 累计读取范围，后续课件和对话共同继承，不因替换来源或重试丢失。

课件新增或改写内容使用故事资料时，课件整体收窄到该故事；旧答案、评估、归档证据和已获奖励不随之改写来源。课件访问范围不等于不可变的奖励 originOsId。用户可通过工作台“跨故事使用”明确发布当前版本，course-sharing 以原文档 commitId 验证确认未过期，沿用仓库的保存／核实机制；只发布课件，不发布聊天、旧答案、评估或学习项。后续再次使用私有资料修改时重新收窄。

Core 负责真实协议终止；Learning 负责发布和保存依赖。修改工具返回实际保存状态，confirmed / unchanged 才是确定结果。未确认写入暂停后续变更，只核实原提交；恢复回执不声称未执行的剩余工具已完成。停止/失败后已经确认的事实不倒退，未发布候选不复活。

普通交流不要求工具声明。同一个工作台响应中的正文要等本批工具全部成功、写入全部确认后才能发布，单个工具的回执不能放出整批正文。工具校验失败或用户拒绝操作时只撤下该批正文，工具循环继续接收结果、纠正和执行；后续保存不复活失败批次的正文。已发布的普通交流不因会话记忆保存失败消失。正式提示、答案和文稿由原生 reveal / LearningReveal 记录曝光；原答与修订共用 attempt 中的帮助条件计算，提前保存的范文也计入后续修订，引用文章问意思不触发曝光。质量边界见产品设计 §6.2。

历史压缩必须完整、有缩短收益且未过期。并行任务只在原历史前缀和摘要仍相符时替换所属主体的历史；不能删除另一条正在运行的交流。当前材料和本轮必需原答不被压缩为摘要。

## 6. 阅读、复习与双空间生命周期

具体体验见产品设计 §6、§8；这里固定实现边界：

- 学习助手在工作台内按需展开，复用带 target 的 LearningConversation；关闭恢复文章位置。聊天与工作台分别持有轻量草稿，界面卸载不取消任务。
- 读写在 LearningReading / LearningGrading 直接完成。专项题保留原生控件；LearningActivity 只在打开时挂载，不承担主读写流程。
- 原文引用由 reading-selection 校验 UTF-16 偏移与精确原句，兼容无空格语言和跨码元字符；打开引用不发送模型请求，不覆盖已有聊天草稿。
- 写作、修订、设置、聊天与专项草稿由轻会话保存；保存回执只退休匹配的提交，不清空等待期间的新输入。
- 修订界面和离开提醒共用 revision-work 的当前原答／批注投影，按单题是否正在修订判断，不借用整课阶段。读写附加题使用与专项题相同的提交标记；只有新作答已保存时才退休输入，失败保留。
- 复习卡片允许再次作答；重答仍使用原生题型控件，新尝试保留旧作答。重答草稿在轻会话中保留，保存失败不退出编辑，收到新尝试的确认后才收起。
- 当前学习单元及复习题定位同属轻会话。LearningApp 从工作区的滚动、交互及切换取得定位；显式引用覆盖默认定位，重视图卸载不丢失追问目标。Host 校验目标仍是本故事可读的当前课或复习组，再由 access/context 选择同一公开投影。
- 段落审阅由 teaching 按原答 ID 保留已发布对话对象的引用，工作台投影与聊天使用同一份内容；历史压缩不清掉当前作答的审阅。原答删除／重写时清理对应引用；已完成审阅通过会话记录的原答关联恢复，不复制正式评分。
- Reading 的当前查看页属于轻会话；主动工作台动作由 LearningApp 导向对应结果或复习题组，不把模型状态更新当作强制导航命令。复核显示实际 revision，原稿标记始终只代表原稿。
- learning-editor 在重挂载时恢复光标和编辑器滚动，不自动聚焦软键盘。页面与消息滚动在返回时恢复；看旧消息不会被新回包拉到底部。
- 窄屏转场期间两侧短暂共存，结束后卸载非活动重视图；快速反向只认最后目标。宽屏比例调整保留两侧可阅读宽度，减少动态效果时即时切换。
- 陪读调度由轻外壳持有。[companion.ts](../apps/learning/application/companion.ts)拥有随机机会范围，[use-learning-companion.ts](../apps/learning/ui/use-learning-companion.ts)接入可见性、输入、菜单和任务状态；无后台补发。
- 一次安静结果不写空消息、不追加请求。工作台完成结果不写成搭子发言，也不为庆祝另发模型调用；搭子下一次请求读取公开结果。
- 学习动态从当前请求的进度与已脱敏消息派生，工作台和会话使用同一组件；运行时展开、结束后收起可回看，成功/失败步骤都保留。进度只属运行内，不新增长期记录或模型请求。同步命令完成时发布最终状态，避免中间推送令界面丢弃语言选择等操作的回执。
- Learning 的 UI 请求统一在 use-learning-state 形成 JSON 数据快照，再交给 FrameBridge；引用选区、答案和修订中的嵌套响应式对象不跨 iframe。FrameBridge 区分发送失败和回执超时，并释放失败请求的计时器。发送失败保留输入，不要求重载；回执未知只提供状态核对，不自动重发。其他后台任务的推送不能抹掉本次失败提示。
- 聊天重试由各自 teaching 实例保留本轮原请求、消息到达时的作答条件、已确认提交回执和工具轨迹，只存在于当前会话；失败或停止且没有待核实保存时，Host 投影该条消息的重试权限。重试继续同一轮回复，模型收到此前工具执行证据，不重复用户气泡。原答及修订回执随搭子委托和重试共用，同一消息重发同一提交只返回已有回执；新消息仍可再次作答。本请求自己保存的换课（含搭子委托）更新可恢复材料身份。初次运行、委托和重试都用消息到达时的记录核对原始选择，用当前记录投影可操作课件；旧选文和原请求保留，已退休题目的 focus 为空，不伪装成新课题目，复习组不会因旧 ID 退休而转向普通课。外部换课、新聊天、换语言/角色、清空或结束实例后旧重试失效；保存未确认仍走原候选核对，不重新生成。
- 备课的失败原因与恢复按钮归同一动态卡；停止首次备课也保留入口，重试沿用原来的联网/原创选择并读取已保存内容，不重做成功工具。联网过程只投影允许的错误分类及 HTTP 状态，原始响应、地址、凭据和正文不进入过程元数据。
- 模型与协议异常保留实际错误消息、错误码、HTTP 状态和响应结束原因，在失败位置直接展示；工具校验展示具体字段与规则，不用通用连接提示或失败数量替代原因。错误展示与日志不序列化请求配置、请求头或完整响应对象。
- 工具调用尚未开始执行而模型请求已结束时显示“未执行”，不冒充联网拒绝；已开始但中断的工具显示停止。搜索与网页提取分别显示候选数和取回文字的网页数，不把传输成功等同于文章质量通过。
- 语法批注直接打开同一知识项及证据；生词收藏、学习本和 SM-2 都消费既有学习项。排程不由模型设置，到期选择与单组上限以 schedule/领域常量为准。

SM-2 排程和各自完成交流需要跨重启保存；计时、动效、布局、滚动和模型在途进度均为临时态。是否首次批改以已保存评价为准，重放已有评价或只补学习项引用不推进排程。当前与归档答案共用重评规则：只校正仍由该答案决定的排程，不覆盖较新作答的结果。删除或复核最后推进排程的证据时，按领域规则重建入口状态，不伪造不存在的完整复习历史。

## 7. 外部依赖与能力限制

### 教材

联网沿用 Agent API 所选 Tavily/Exa 的配置与传输实现；Learning 的 [materials](../apps/learning/materials)拥有选材流程、来源索引和节选校验。原文由实际提取段落产生，教学改写另标来源；搜索摘要不能冒充原文。仅读取返回的安全公开网址；不提供任意文件或内网 fetch 能力。

课堂来源缓存只在运行内；已保存教材查看不重搜。缺配置、网页不可访问、限流或正文不足都明确报告，替换来源/自编需要符合产品约定。工具详情不显示搜索参数或原始正文，不因此声称实际外发内容的语义安全已经得到证明。

取回的实际可读文字交给模型判断是否适合本次教学，不用机械最低词数筛掉短文。来源索引和原文节选仍按真实提取结果校验；正文质量、页面导航、访问提示及相关性由本轮模型判断，不添加关键词黑名单或额外评审模型。搜索失败保留结构化 HTTP 状态供安全反馈，不从人类错误文案解析原因，不自动重发未知请求。

### 声音

TTS 拥有合成、音色配置和缓存，Learning 拥有自己的播放控制及听取条件。隐藏/卸载视图不持有音频资源唯一副本；停止、换课堂和迟到返回受所属运行保护。显式播放、慢放和重听不变成额外教学模型请求，也不改主聊天设置或清空其队列。

录音、转写和发音评估尚未接入。不能从 TTS 或文字批改成功推断四项语言能力均已验证。

### 奖励

[rewards.ts](../apps/learning/application/rewards.ts)协调已确认完成、Economy 幂等入账、Learning 回执三步。发币失败不撤销学习完成，恢复只处理原资格；不把页面切换、回复到达或动效结束当作到账依据。

payPending 统一消费当前语言全部已确认、未领取的完成记录，不以当前课槽位或入口前后的 ID 差集判断资格。工作台各类运行（原生教学、对话、委托、后台备课）统一在 teaching 收尾，后续模型失败或停止不撤销已经确认的结课；纯原生作答／删除学习项产生的结课及保存恢复也交给同一结算入口。结算请求在运行内串行，遇到存储异常结束本次扫描并报告，核实或下次进入再恢复；切换课堂后的迟到任务不在新课堂结算。

### 宿主

注册沿用 Learning module/descriptor/production module、Host/Shell catalog 和懒加载入口，不加入剧情维护 participant。兼容目标是 SillyTavern 1.14/1.18、现行浏览器/WebView 和实际供应商协议；推送正式线前必须启动 1.14 检查扩展加载，不用类型检查代替宿主运行证据。

## 8. 验证方式与交付边界

| 要证明的契约 | 最低有效层 |
| --- | --- |
| 阶段、批注、真实原答、SM-2 和证据删除 | 领域/应用语义测试 |
| 任务资料、工具许可、公开与隐藏内容 | 实际请求/工具执行边界测试 |
| 并发帮助、保存失败、未知写入与精确恢复 | 仓库和真实应用集成，保留失败收据 |
| 协议真实结束和停止后不发布 | 实际适配器/SDK 的固定传输测试 |
| 引用提问、逐句修订/跳过、入本、宽窄切换及焦点 | 正式组件浏览器操作；引用提问须经过真实 iframe/FrameBridge，不能用直接方法调用代替传输边界 |
| 非活动重视图释放、长内容切换和监听趋势 | 浏览器测量，区分桌面模拟与真实移动设备 |
| 教材适配、批改准确、范文等级、角色自然和泄题 | 授权真实模型样本及独立语义评审 |
| 联网服务实际可达、TTS 音质与设备播放 | 对应真实服务/设备验证，不能由本地模拟背书 |

常规检查：npm run test:xiaobai-os、npm run lint:xiaobai-os、变更 JS 的 ESLint、npm run lint:imports、npm run build:xiaobai-os、git diff --check。仅改变 TTS/Core 时补其对应检查，不越界重构。

隔离预览使用实际 Learning 组件、runtime 和内存仓库，Provider 仅给固定响应。它证明交互、状态和失败处理，不证明模型教学质量或真实新闻可获取。浏览器截图及临时探针放 output/playwright，不作为长期设计或验收日志提交。

真实付费模型/联网/TTS 调用需要明确的服务授权。未取得实际输出时，交付必须写“未验证”，不能用结构测试、HTTP 成功或固定脚本代替质量结论；同样不得把桌面 Chromium 检查冒充实体手机/WebView 验收。
