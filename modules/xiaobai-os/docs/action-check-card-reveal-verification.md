# D20 卡片与揭晓流程

## 边界与体验

本轮只升级行动检定的聊天卡片和揭晓流程，功能所有者仍为 `apps/dice/`。规则、JSON 协议、Prompt、消息记录格式、开关存储均不变；不修改 SillyTavern 本体、不新增依赖。

- 唯一事实来源：已确认保存的行动检定记录。动画不能调用随机源、保存聊天或自行请求模型。
- session 顺序：保存确认 → 揭晓 → 原生继续。揭晓约 2 秒，末尾留约 300ms 展开判定。
- `revealing`、取消信号、动画帧和 DOM 缓存都是当前运行的临时态，不写入文件或消息 extra。
- 角色与检定项合并在卡片顶部，自然换行；新骰点滚动时不显示最终判定文字／结果色。骰面停稳后，大字成败下方并列展示「掷骰」与「难度」，不要求用户从骰面辨认并跨卡片比较数字。
- 骰子采用枪灰金属面、方向性银色倒角和浅金刻字。反光随旋转变化，成败颜色只用于判定文字；不改变卡片尺寸。材质用 SVG 渐变／刻槽光影近似，不新增贴图、WebGL 或外部资源。
- 行动与风险居次，长风险可展开。续写错误在卡片下方单独显示，不混同于剧情中的失败。
- 历史、重载、切回旧 swipe、保存／续写重试不重播。不添加重投按钮。
- 停止、切聊、编辑、停用会取消续写资格，已确认骰点保留。减少动态效果、隐藏页面或卡片卸载会结束展示等待，不悬挂生成链。

## 结构

| 位置 | 职责 |
| --- | --- |
| `application/action-check-session.ts` | 保存后揭晓屏障、取消检查、恢复跳过揭晓 |
| `host/generation-adapter.ts` | 揭晓期间使用宿主忙态／停止控件，尊重群聊包装器的控件所有权 |
| `host/message-display.ts` | 确认记录、安全正文锚点、按消息／swipe／记录身份复用卡片、错误恢复入口 |
| `ui/check-card.ts` / `host/card-style.ts` | 结果布局、语义、主题与窄屏样式 |
| `ui/d20.ts` | Three.js 二十面体几何／旋转，投影与光照到 SVG；每个结果面朝向读者 |
| `ui/reveal.ts` | 有限时长、可取消的展示；清理帧、计时器与事件监听 |

历史卡片没有 WebGL 上下文、纹理缓存或持续渲染循环。动画每帧只更新 SVG 属性，不触发聊天的子节点观察重绘。普通刷新与追加正文尽量复用同一 DOM，保留展开状态与焦点。删除路径仍是停止模块、按已约定范围清理 Dice 消息事实／分区，再删除目录与注册；没有额外动画数据需清理。

每颗骰子自有 SVG paint 定义，临时递增 ID 只用于避免同页渐变／滤镜引用冲突，不调用随机源、不持久化。定义随 SVG 一起卸载，移除历史卡片不影响其余骰子。刻槽滤镜作用在投影后的字形上，避免对亚像素字号直接滤镜造成数字发糊。

SillyTavern 的流式文字渐入使用 morphdom，可能把没有 ID 的普通 span 改造成正文片段。卡片使用独立 ID 接入宿主的 keyed-node 规则：宿主可以移除节点，但不能把缓存组件改写成另一种节点。不是在每次重绘时检查并修复已损坏的组件。实际流式单次／连续检定已验证卡片数量与事实数量一致。

## 验证

使用隔离的 SillyTavern 1.18.0、完整 OS 生产构建和本地模拟供应商；不调用付费模型，不操作用户真实聊天。四种结果的视觉案例在测试页面临时固定随机输入，出现已确认记录后立即恢复随机函数；产品没有固定骰点开关。

行为回归覆盖：

- session 确认保存之后才揭晓，揭晓结束前不续写；停止／目标编辑取消，恢复沿用原骰点且不重播。
- 宿主忙态和停止入口；迟到的旧揭晓不能解除后来生成的忙态。
- 实际卡片隐藏判定、最终显示原骰点；全部 20 个最终点数朝向读者。
- 取消、减少动态效果、后台页面、DOM 卸载均能结束等待并清理动画帧。

## Dice 启动生命周期补查（2026-09-14）

此前依赖验证先选聊天再初始化 OS，漏掉了实际插件启动时尚未打开聊天的路径。使用同一隔离酒馆，在欢迎页启动生产宿主，复现「Dice暂时无法打开 / APP background start failed」；控制台 AggregateError 内层为 `chat_unavailable: No chat is currently open`。Dice 后台启动调用 `store.read()` 被拒绝，注册表随即释放失败 runtime，之后打开聊天不会自行恢复。退出已有聊天时的后台切聊读取也会触发同类失败。

聊天文件解析与分区发布已经由 OS 的 chat binding lifecycle 负责。Dice 删除后台启动、切聊中的两次重复读取，让监听器可以在无聊天时正常注册；实际打开设置页与修改开关仍保留原有读取、校验和事务。显示层订阅分区变化，确保慢加载完成后「沿用骰点续写」等入口及时刷新；订阅随模块 execution scope 清理，不新增持久态、重试或缓存，不改协议、Prompt、骰点、消息记录与开关格式。

`tests/dice-lifecycle.test.js` 复用真实生产模块、注册表和事务协调器，仅替换外部 I/O 与显示／生成工作器。两条回归覆盖无聊天启动、已有聊天启动后退出、进入下一聊天、原开关值及零额外写入；并检查晚到的偏好直接到达显示消费者。保留原数据清理契约测试。

浏览器探针在 `output/playwright/os-host-timeout/`：`dice-startup.cli.js` 复现并核对无聊天启动；`dice-full-entry.cli.js` 恢复真实 manifest/index.js 自动入口，不手动初始化 OS，确认欢迎页已注册 Dice 监听器；随后通过真实按钮打开 Dice，原开关仍启用。`dice-startup-generate.cli.js` 退出并重新进入聊天后，不重开 Dice、不重置开关，实际完成 2 次本地供应商请求、1 条检定记录和 1 张静止卡片，Dice APP 错误与未捕获页面异常为 0。仍阻断外网并对 `/node_modules/` 返回 404。

`dice-delayed-binding.cli.js` 仅在隔离浏览器响应中把最后一条已存骰点模拟为中止续写的记录，将 OS 文件响应延迟 1.5 秒。仅删除读取时，文件到达后恢复按钮仍不出现；显示层订阅分区变化后，按钮自动出现，无需打开 Dice 或触发额外消息更新。未修改真实用户聊天。
