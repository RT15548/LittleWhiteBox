# 余火：世界与战役设计

当前可玩范围是游戏入口里的第一章“哨站救援”，章末显示“第二章待续”。篇章页展示当前章节和第二章待续，没有未制作章节的可进入场景、随机房间旧入口或独立测试页。

## 世界与人物的唯一设定源

世界采用[赤炉城与檐下](expedition-cards/world.md)；人物采用[三娘](expedition-cards/sanniang.md)、[阿念](expedition-cards/anian.md)、[扣子](expedition-cards/kouzi.md)、[老白](expedition-cards/laobai.md)，三女一男，均为成年人。本文不另写人物小传或秘密总表。开场处境见[第一章开场](expedition-cards/openings.md)，资料分工见[接入约定](expedition-cards/README.md)。

玩家身份以 [玩家设定](expedition-cards/player.md) 为准。开始旅程时填写姓名、选择男或女，再选篇章和职业；欲望和关系意图由玩家表达。六职业只是玩家选择的作战方式，不是六套主角身份。探索、战斗、衣柜共用余火自己的轻量人形旅人模型，外观从存档性别与当前衣装派生，不增加独立外观存档。不导入酒馆的角色卡、用户人设或聊天记忆。

游戏的价值是探索、战斗和 AI 人物互相影响：玩家实际打开道路、带回人和物资；人物记得各自与玩家的共同经历，并按自己的性格回应。对话不替玩家决定行为，也不把一句口头声明当成已经完成的救援。

## 第一章的空间与进程

推荐主线闭环：在檐下了解扣人和扣货 → 岔口 → 从哨站正门或旧水道进入 → 打开牢门 → 阿念、扣子脱困返营 → 解除内堡门厅的物资封锁 → 核对归还药材、管件 → 与三娘收尾。撤离与接应遵循[第一章规划第五节](expedition-cards/chapter1-plan.md#五地图与移动)。门厅通行与挑战分区、提前挑战及不同完成顺序的目标规则见[第一章战斗编排](expedition-chapter1-combat.md#二路线与挑战边界)，不把推荐顺序当成任务门禁。

| 场景 | 在本章中的用途 |
| --- | --- |
| 檐下 | 三娘的诊棚、老白守的外门、休整、整备、接应与回访。 |
| 外墙岔口 | 初次遭遇，打通正门与水道分岔；后续可前往根庭。 |
| 哨站正门 | 突破盾卫封锁，前往烽火台。 |
| 烽火台 | 截断增援信号。 |
| 旧水道 | 操作水闸，绕至牢房；不是扣子私藏的深段通路。 |
| 牢房 | 打开牢门，见到两名被扣者，打开回檐下的小门。 |
| 内堡门厅 | 击败守卫，解除物资封锁。本章不进入内堡内部。 |
| 根庭 | 可选首领与构筑奖励，不阻断救援主线。 |

正门先熄烽火，能避免门厅增援；水道先救人更直接，但可能留下警报后果，玩家仍能回头截断信号。没有在读地图、等模型或离线时偷偷处决人质的倒计时。

场景之间通过真实出口连接；小门开启后成为可重复走的捷径。地图只展示已走过的地点与当前已开放的相邻方向，未抵达方向不提前标出地名。场景几何、碰撞、机关与地图使用同一组定义。

檐下生活空间的定义和移动边界见[第一章规划第五节](expedition-cards/chapter1-plan.md#生活空间)。工作点与住处分开，模型读取的房间事实与可行走地图一致。

第二章未开放。收尾后的自由活动、人物知情和阶段奖励遵循[第一章规划的收尾规则](expedition-cards/chapter1-plan.md#收尾与阶段奖励)，不出现指向空内容的任务。

## 人物与互动

三娘、老白从开场即可接触；阿念、扣子先在牢房，开门后可参与实际移动。人物位置归战役状态所有；人物只能通过游戏提供的移动行动移动，由游戏校验执行。跟随、独自赴约和留下的边界见 [第一章规划第五节](expedition-cards/chapter1-plan.md#五地图与移动)。

模型提出的剧情行动使用统一的前提和效果定义，包括接下救援、安排接应、整理诊棚、清点收尾。日常陪伴、玩闹和亲近由 AI 对话自然发展，不使用固定互动菜单或追加预写片段；不代表玩家同意某种感情关系。交谈好感结算遵循 [第一章规划第四节](expedition-cards/chapter1-plan.md#四好感)。

各人只收到自己的完整人物卡、私聊与按好感投影的阶段资料；秘密的开放、已披露事实和降好感后的保留规则以 [第一章规划第四节](expedition-cards/chapter1-plan.md#四好感) 为准。开放之后何时讲、怎样讲由人物性格和交谈决定，没有统一坦白轮数或强制暧昧路线。

游戏事实与人物知情分开：亲历的事件进入该人物的记录；玩家转述仍然是有来源的说法。当前公共处境与个人经历分开投影，回到檐下不会把全局事实复制给每个人。已发生的对白、互动结果按时间排列，不能在旧聊天上方不断插入新招呼。

原始记录长期保留在本次旅程中。模型上下文按 token 预算整理个人摘要，保留近期完整往返及当前问题；摘要保持承诺、关系经历、未完成话题和不确定性，不把猜测升级为事实。重开第一章同时清除这段旅程的交谈、知情与摘要。

重生成针对当前人物的最后一条聊天，不因关闭聊天或地图走动失效。末条是 AI 时立即移除回复，保留玩家消息并先存档，再请求生成；末条只有玩家消息时直接生成，不再删历史。失败或取消不会恢复已删除的 AI，重进仍可继续生成。未继续游戏时撤回本轮未确认效果；世界已经继续后保留实际位置、任务事实与奖励，只替换这条回复拥有的好感和衣物变化。存档确认只恢复已有候选，不自动购买新回复。

摘要阈值统一定义于 `narrative/memory.ts` 的 `MEMORY_POLICY`：触发线开始后台摘要，界面上限是发送等待线，不是报错线。摘要启动时固定旧记录边界，保留最近完整往返；生成期间新增的交谈全部留在边界之后。到等待线先等现有摘要、重新计量，仍有可整理的旧前缀才继续摘要；不裁近期原文。摘要输出继承用户 Agent API 的设置。每个人同一时间只有一个任务，任务及失败状态仅在本次运行内；失败在上下文浮层提供主动重试，不随每次发送重复购买。摘要只合并当前存档的个人记忆，不改变游戏操作版本，也不覆盖新交谈、好感或重生成检查点。离开游戏窗口不取消摘要，重开旅程或销毁运行时取消旧任务。

模型先输出 `<dialogue>` 包裹的纯文本正文，再输出 JSON 操作信息；正文内的正常引号、花括号、换行不参与 JSON 解析。解析允许标签外的说明文字及 Markdown 围栏，只接收正文闭标签后的一个完整操作对象；不修补损坏 JSON、不从数组中抽取操作、不在多个对象或多段正文之间猜选。完整正文不会因为附带信息缺失或损坏而丢失：标明未执行操作、保留对白进入后续上下文；无效行动与表演分别忽略并提示，不改写剧情。截断回复保留已收文字但不结算行动、好感或表演，也不作为完整对白进入上下文；没有可辨认正文的格式错误保留原文供查看。保存已经接收的结果不受随后取消等待影响；失败重试只恢复原结果，不重复调用模型。人物资料加载失败只影响对应的信息圈，不卸载正文与输入区；营地内的章节收尾不要求三娘站在初始位置。

## 战斗与探索的关系

六职业以自动普攻、手动走位、闪避和职业技能作战，战斗发生在真实探索场景中。统一的难度、敌人职责、遗物成长、重试与跨章规则见[战斗与成长设计](expedition-combat-design.md)；第一章逐场机制、路线奖励账本及验收见[第一章战斗编排](expedition-chapter1-combat.md)。独立战斗段、路线共享奖励及章节首领已接入；当前实现边界仍见对应工程文档，真人体验与真实手机表现另行验收。

范围预警对应实际危险区域；短暂格挡可以有头顶反馈，持续护盾只用脚下能量条。烽火已有 HUD，不在场景模型上再挂牌。人物近处显示名字与交互圈，不给整张地图堆常驻标签。

## 性能与交付边界

宿主是仍在运行的 SillyTavern。只加载当前场景；建筑按空间和材质合批，少量 NPC 单独合批并做轻量转身与待机动作。暂停与后台停止无意义绘制，衣柜静止时不维持绘制循环。限制像素比和阴影分辨率，不用持续后台模型调用维持 NPC。

纯前端只承诺页面仍存活时，切换 App 或收起窗口不会主动丢弃已发起的回复。刷新、关闭页面、浏览器进程被系统杀掉后，不保证请求能继续。本版不新增后端 LLM 服务，不自动重发结果未知的付费请求。

实现与验证边界见[第一章实现边界](expedition-game-target-design.md)。自动化能验证规则、数据、协议与界面行为，不能代替真人乐趣、真实手机性能或真实模型的人物表现验收。
