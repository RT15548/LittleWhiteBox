# 变量 2.0 使用说明

变量 2.0 让角色卡用一段 `<state>` 文本管理剧情状态：生命值、背包、好感度、地点……

- **有模板**：先说清楚变量长什么样，之后 AI 写错类型、多写字段、数值越界，会被挡下或自动修正。
- **跟着楼层走**：每条消息记下它对变量做了什么。删消息、切换候选回复（swipe）时按记录恢复；重新打开聊天不重复扣血。

本文先讲最常用的写法，再讲脚本接口和历史行为。内部实现见[执行与历史设计](<json-tool-design.md>)。

## 开始前：打开正确的开关

1. 在小白X设置的“变量控制”中勾选“变量管理”，旁边选择 **`2.0 (state)`**。`1.0 (plot-log)` 是另一种正文格式，不能用来自动处理本文的 `<state>`。
2. 可同时勾选“变量面板”，方便查看当前聊天的变量；它只是查看入口，不代替“变量管理”开关。
3. 本文用一个名叫 `数据` 的根变量存整份状态。`数据.角色.生命值` 表示从“数据”对象找到“角色”，再找到“生命值”。换名字时，初始化、读取宏和修改路径要一起换。
4. 先在新建的测试聊天里走通“初始化 → 读取 → 修改”。聊天至少要有一条消息，脚本写入才有归属楼层。

## 一、开局：在角色卡里初始化

打开要制作的角色卡，启用小白X的“循环任务”，新建任务：

- 任务类型选“角色任务”，勾选“启用任务”。
- 先将“楼层间隔”填为 `1`，再把触发时机选为“角色卡初始化”。如果间隔是 `0`，角色任务的时机下拉框会锁住；选好初始化后，间隔不参与判断。
- 将下面的**完整内容**粘进“脚本命令”，保存，然后为这张卡新建一个聊天。保存任务本身不会补跑初始化。

角色卡需要有开场白；任务在新聊天创建时执行，初始值记录在开场楼。任务的创建和调试入口见[循环任务指南](<../../scheduled-tasks/README.md>)。

```text
<<taskjs>>
const result = await LWB_StateV2.applyText(`
<state>
# 1. 模板：只规定结构和类型，不写入数据
$schema 数据
  角色:
    姓名: ""
    生命值: 0
    魔法值: 0
    金币: 0
    技能: []
    背包:
      "*": 0
  后宫:
    "*":
      生命值: 0
      好感度: 0
  当前地点: ""

# 2. 约束
$range=[0,999] 数据.角色.生命值
$range=[0,999] 数据.角色.魔法值
$step=50 数据.角色.生命值
$step=50 数据.角色.魔法值

# 3. 初始数据：真正写进去的值
数据:
  角色:
    姓名: "苏晚"
    生命值: 100
    魔法值: 50
    金币: 0
    技能: []
    背包: {}
  后宫: {}
  当前地点: "新手村"
</state>
`);
if (result.errors.length) console.warn('变量初始化提示，请核对实际值', result.errors);
<</taskjs>>
```

三段各管一件事：

| 段落 | 作用 | 会不会写入数据 |
| --- | --- | --- |
| `$schema` | 规定“数据”里有哪些字段、各是什么类型 | 不会 |
| `$range` / `$step` 等 | 给字段加限制 | 不会 |
| `数据:` | 写入初始值 | 会 |

> **最容易踩的坑：模板里有的字段，初始数据必须写全。**
> 上例模板有“后宫”，所以初始数据里要有 `后宫: {}`，哪怕现在一个人都没有。
> 少写一个字段，**整份 `数据` 都不会写入**——不是只缺后宫，苏晚、生命值、地点也全都没有。

### 怎么确认开局成功

在变量面板查看当前聊天的 `数据`：应有“角色”“后宫”“当前地点”，生命值是 `100`，当前地点是“新手村”。也可以在聊天输入框执行 `/getvar 数据 | /echo {{pipe}}`，把读取结果显示出来。

没有 `数据` 时，先确认“变量管理”已开启、任务已启用、是在保存任务后**新建**的聊天中测试。再看脚本返回值和浏览器控制台；诊断的含义与处理方式见[第五节](<#五写错了会怎样>)。

每个新聊天各初始化一次。重新打开已有聊天不会重跑任务；删除或切换消息会按保留下来的记录恢复，删除初始化记录本身也会撤销相应初值。修改初始化脚本后，建议另开测试聊天验证，别在已经推进的剧情上重跑整份初值。

### 角色卡有多条开场白时

开场白在酒馆里是第一楼的几个 swipe，变量记录也按 swipe 分开存。「角色卡初始化」只在新建聊天时跑一次，初值记在当时选中的那条开场白上。玩家在第一楼切到另一条开场白，那一页没有记录，`数据` 会消失；切回原来那条才恢复。

所以有备选开场白时，不用「角色卡初始化」，二选一：

**做法一：每条开场白正文里各写一份 `<state>`。** 插件在新建聊天时、以及切到一条还没有记录的开场白时，按这一页正文执行，各页记各页的初值。适合不在乎正文里带状态块的卡；状态块会原样显示在开场白里，要藏起来就给卡加一条酒馆正则，替换为空并只作用于显示。

**做法二：一个任务按所选开场白补写。** 触发时机选“切换聊天后”（`chat_changed`），不选「角色卡初始化」。聊天里只有开场白时写入当前开场白对应的初值，并在第一楼切换开场白时再写一次：

```text
<<taskjs>>
const SCHEMA = `$schema 数据
  当前地点: ""`;
// 下标与开场白一致：0 是主开场白，1 起是备选开场白
const INIT = [
  `数据:\n  当前地点: "新手村"`,
  `数据:\n  当前地点: "城镇"`,
];
async function initGreeting() {
  const { chat } = SillyTavern.getContext();
  if (chat.length !== 1) return;
  const data = INIT[chat[0].swipe_id ?? 0];
  if (!data) return;
  const result = await LWB_StateV2.applyText(`<state>\n${SCHEMA}\n${data}\n</state>`, { floor: 0 });
  if (result.errors.length) console.warn('变量初始化提示，请核对实际值', result.errors);
}
const tavern = SillyTavern.getContext();
const onSwiped = id => { if (Number(id) === 0) initGreeting(); };
tavern.eventSource.on(tavern.eventTypes.MESSAGE_SWIPED, onSwiped);
onCleanup(() => tavern.eventSource.removeListener(tavern.eventTypes.MESSAGE_SWIPED, onSwiped));
await initGreeting();
<</taskjs>>
```

- 只有开场白时才写，所以打开已推进的聊天不会重写；重开只有开场白的聊天、切回写过的开场白，相同文本的调用会跳过，不会叠加。
- 任务每次切聊天都会重跑，监听要用 `onCleanup` 撤掉，否则会越挂越多。
- 验证：新建聊天后在第一楼来回切开场白，每切一次都在变量面板确认 `数据` 是这一条的初值。

## 二、剧情中：让 AI 在回复里改变量

### 先让 AI 看到当前变量

把下面的宏放进会实际发送给模型的世界书条目或预设条目；世界书条目要处于启用状态，并设置为常驻或能被本次对话触发：

```text
<当前变量>
{{xbgetvar_yaml::数据}}
</当前变量>
```

`xbgetvar_yaml` 把对象、数组显示成多行 YAML，便于 AI 阅读；需要标出数组下标时用 `{{xbgetvar_yaml_idx::数据}}`。要把变量放进 JSON 参数模板时用另一种宏，见[第六节](#在工具参数里读取变量)。

### 在回复中提交修改

把[第九节的写作要点](<#九给-ai-的写作要点>)和读取宏放进同一份提示词，让 AI 知道既要读状态，也要提交修改。AI 在回复中输出 `<state>` 块，消息生成并渲染完后自动执行；开启模块本身不会自动教会模型这套写法：

```text
<state>
数据.角色.生命值: -10
数据.角色.背包.回血药: +1
数据.当前地点: "森林"
</state>
```

### 写法速查

| 想做的事 | 写法 | 说明 |
| --- | --- | --- |
| 改成某个值 | `数据.当前地点: "森林"` | 整体替换 |
| 改成某个数 | `数据.角色.金币: 30` | 不带正负号 = 赋值 |
| 加减 | `数据.角色.生命值: -10`<br>`数据.角色.金币: +5` | **带 `+` / `-` 号 = 加减** |
| 赋值成负数 | `数据.角色.金币: (-5)` | 加括号，否则 `-5` 会被当成“减 5”；此例表示欠款 |
| 数组追加一项 | `数据.角色.技能: +"火球术"` | |
| 数组追加多项 | `数据.角色.技能: +["火球术","冰箭"]` | |
| 数组按值移除 | `数据.角色.技能: -"火球术"` | 移除第一个相同的项 |
| 删除字段 | `数据.后宫.莉娜: null` | 模板规定的固定字段不能删 |
| 整块写入 | 见下 | |

整块写入用缩进。下面是**新增或替换莉娜这一名成员**，不会替换其他成员：

```text
数据.后宫.莉娜:
  生命值: 80
  好感度: 10
```

> **改一个字段，就写到这个字段为止。**
> 写 `数据.角色.生命值: 90` ✅
> 不要写成 `数据.角色:` 再只给一个 `生命值: 90` ❌——这是用不完整的对象替换整个“角色”，会被拒绝。

### 按变量切换世界书文本：`<varevent>`

同一个人物按好感分几档描写时，把各档写进一个 `<varevent>`，放在世界书或预设条目里。正式生成时整块只留下一档的 `display`，模型看不到其他档和条件：

```text
<varevent>
[event.冷淡]
display: "莉娜对你很冷淡。"
[event.亲近]
condition: var(`数据.后宫.莉娜.好感度`) >= val(`40`)
display: "莉娜愿意和你单独相处。"
</varevent>
```

- **请求定稿时从下往上选一次**：选中最后一个条件成立、且有显示内容或脚本的事件。没写 `condition` 的算成立；兜底档放最上面。
- ``var(`路径`)`` 支持点号与方括号路径，``val(`…`)`` 是常量。大小比较遇到不存在或 `null` 时为假，不当成零；两边都是有限数字或十进制、科学计数数字字符串时按数值比较，其他字符串保留字符串比较。空字符串与不存在不同。
- 条件可用括号、`&&`、`||`、`!`、相等和不等比较，也保留手写 JavaScript。复杂条件在编辑器中按原文编辑，不会删掉可视编辑器无法表达的部分。条件错误会指出事件，该事件不成立，其他规则继续处理。
- `display`、`js_execute` 可用原有的单引号和多行引号格式，代码里的反斜杠按原写法保留；编辑器修改后用 JSON 字符串转义保存，重开会还原换行、引号和反斜杠。未修改的字段与未打开的组保留原文。
- **显示与脚本固定同档**：请求时选中的 `display` 进入提示词，只有本轮 AI 回复成功完成后才执行同一事件的 `js_execute`。中途变量变化不重新选档；选中的事件没有脚本就不执行，不再寻找低档脚本。
- 普通回复、重新生成、新 swipe 和续写都遵循上述规则。预览、后台辅助请求不排脚本；失败、取消、切聊天、目标回复失效或关闭「启用小白X」会取消尚未开始的脚本。待执行内容只在当前生成的内存中，旧版残留队列在打开聊天时删除，不补执行。
- 脚本仍直接在页面运行，不是沙箱，已开始的任意 JavaScript 不会被强行终止。提供的 `getVar`、`setVar`、`STscript` 助手在本轮失效后会拒绝新操作。脚本不进变量 2.0 楼层记录，不要通过它直接改本文的受管变量。
- 原有 `STscript(...)` 动作不必重写：即使没有写 `await`，也会等它结束后再启动下一事件，返回值仍是酒馆原始结果。取消本轮运行时，也会取消该助手正在执行的酒馆命令链，等待中的命令返回后不再继续下一条。正常的回复变量宏替换不会中断事件；手动编辑、删除或切换目标回复仍会取消剩余事件。

## 三、模板 `$schema` 怎么写

模板用样例值表示类型：`""` 是文字，`0` 是数字，`[]` 是数组，`true` 是开关。

本节每小节是一个**独立模板片段**，供你设计自己的初始化脚本，不是要按顺序追加到第一节的 `数据` 模板。放进 `<state>`，为模板补齐初始数据后再用；最外层路径和 `$schema` 从行首写，成员统一用空格缩进。模板里的样例值不是默认数据。

### 固定字段

```text
$schema 数据
  名称: ""
  等级: 0
```

- “数据”只能有 `名称`、`等级` 两个字段，不能多写别的字段。
- 整体写入“数据”时，两个都要有。
- 不能删除；想清空就写空值：`数据.名称: ""`、`数据.等级: 0`。

### 自由对象：`{}`

```text
$schema 数据
  固定: ""
  自由: {}
```

`数据.自由.任意名字: 123` 可以；`数据.额外: x` 不行——只有“自由”里面能随便加。

### 名字不固定的成员：`"*"`

后宫、同伴、背包物品这种“有几个、叫什么都不确定”的，用 `"*"`：

```text
$schema 数据
  同行者:
    "*":
      HP: 0
      状态: ""
```

- 新成员整个写入：`数据.同行者.莉娜: {"HP":8,"状态":"同行"}`，多字段或少字段都会被拒绝。
- 已有成员改单个字段：`数据.同行者.莉娜.HP: -3`。
- 成员可以删除：`数据.同行者.莉娜: null`。
- 一开始没有成员，初始数据写 `同行者: {}`。

### 数组

```text
$schema 数据
  背包:
    - 名称: ""
      数量: 0
```

第一项就是每一项的样板：每个物品都必须有 `名称`（文字）和 `数量`（数字）。整体写入、追加时都会逐项检查。

数字写成字符串会自动转换：`数量: "3"` 存为 `3`；`数量: abc` 会被拒绝。

## 四、约束

写在 `$schema` 之后、从行首开始，每行一条。指令内部不要插空格，例如 `$range=[0,999]`；路径里的 `[*]` 表示数组每一项。

| 约束 | 写法 | 生效方式 |
| --- | --- | --- |
| 范围 | `$range=[0,999] 数据.角色.生命值` | 自动截到边界，例如直接赋值 `1200` 存为 `999` |
| 单次增减上限 | `$step=50 数据.角色.生命值` | 自动截断，`-1000` 先限制为 `-50`，结果还会受到范围约束 |
| 枚举 | `$enum={平静,警觉,交战} 数据.角色.状态` | 给该字段赋其他值时拒绝 |
| 只读赋值 | `$ro 数据.角色.姓名` | 阻止该路径的直接赋值、加减，也阻止整体赋值改掉这个字段 |

- `$range` 对整块赋值里的嵌套字段同样生效。
- `$step` 只限制“加减”，不限制赋值：初始化写 `生命值: 100` 不会被截成 `50`。
- 多个约束可写在一行，例如 `$range=[0,999] $step=50 数据.角色.生命值`。
- `$enum` 适合文字枚举。当前实现的数值加减不检查枚举，同一路径的数值范围检查也会优先返回；不要把“数值范围 + 枚举”当成两个都会执行的数值限制。
- `$enum` 只用于取值真的有限的字段（阶段、状态、等级）。地点、称呼这类会随剧情出现新值的字段别加：AI 写出表外的值，这一条修改会被整条拒绝，变量停在旧值。
- `$ro` 不是对象或数组的通用冻结：它不阻止 `push`、按值移除和删除，也不自动把子路径都设为只读。固定字段不能删除是 `$schema` 的规则，不是 `$ro` 的保证。

### 初值与只读要分两次提交

同一次提交会先登记所有规则，再写入数据；把 `$ro` 写到数据后面也不能绕开初始化检查。需要固定姓名时，在第一节脚本的 `await LWB_StateV2.applyText(...)` 完成后、同一个 `<<taskjs>>` 块结束前，加入第二次调用：

```js
await LWB_StateV2.applyText('<state>$ro 数据.角色.姓名</state>');
```

这次只登记规则，不重写姓名。该规则只能用于你确实不再需要改名的设计。

## 五、写错了会怎样

- **单条赋值不写**：赋值不符合模板时，这条赋值完全不生效，不会只写进去一半。
- **执行阶段可部分成功**：一条修改被规则拒绝，不妨碍其他有效操作执行；已经登记的规则也不会因此撤回。
- **解析阶段另算**：JSON 格式或批次冲突会在执行前拒绝整次提交，不适用“其他行照常”。纯文本格式有些错误会被忽略或作为文字解析，不保证每个拼写错误都会报错，所以必须核对实际值。
- **截断不等于失败**：被 `$range` / `$step` 截断后仍会写入修正值；文本接口把这类提示也放在 `errors` 里，结构化接口用 `corrections` 区分。
- **查原因与是否成功**：脚本优先看本次返回值；正文处理看控制台，并用变量面板辅助确认。输入 `/getvar LWB_STATE_ERRORS | /echo {{pipe}}` 可显示最近一次执行诊断；解析失败或跳过时可能没更新它，因此它不是所有失败的总日志。

| 常见原因 | 怎么改 |
| --- | --- |
| 缺少模板字段：xxx | 整体写入时把模板字段写全，没内容就写空值，如 `{}`、`""`、`0` |
| 字段不在结构模板中 | 删掉多写的字段，或在模板里加上 |
| 类型不匹配 | 按模板类型写，例如数字不要写成文字 |
| 父层结构已锁定 | 这个对象不能加新字段，改模板为 `{}` 或 `"*"` |
| 模板定义的字段不能删除 | 改为写空值 |
| 只读字段 / 枚举不匹配 | 去掉这次修改，或使用允许的值 |

## 六、在脚本里直接改变量

启用“变量管理”后，酒馆宿主页面上有全局对象 `LWB_StateV2`，循环任务和运行在宿主页面的工具适配器可以调用，不用往聊天里插消息。本文以 `2.0 (state)` 模式为前提。

这是宿主页面的对象，不是自动注入到任意前端卡 iframe 的变量。以下 JavaScript 示例可放进循环任务的 `<<taskjs>>…<</taskjs>>` 中运行；聊天输入框则只执行斜杠命令。

### `applyText`：用和正文一样的文字写法

```js
const result = await LWB_StateV2.applyText(`<state>数据.角色.金币: +10</state>`);
```

- 参数需要完整的 `<state>…</state>` 标签；没有完整块会跳过，不执行裸路径文本。
- 可以声明模板和约束。初始化通过它或正文文本完成；`apply()` 的 JSON 不能创建新的受管根变量。
- 返回 `{ atoms, errors, skipped }`：`atoms` 是已执行操作的明细，含路径和前后值；`errors` 是诊断文字，包含拒绝、修正提示和通知失败，非空不代表完全没写；`skipped` 表示本次没有执行。
- 默认记到调用时的最后一条消息上。第二个参数是 `{ floor, silent }`：`floor` 是从 `0` 开始的消息索引，`silent: true` 只关闭通知，不关闭写入或保存。
- 当前楼的当前 swipe 中，完全相同的文本调用，或与完整正文记录一致的状态块序列，会跳过；这不代表上一次所有操作都成功。它不是“每行防重”：更改这份提交里的任何一行后再调用，整份文本都可能重新执行。需要重复加减用 `apply()`；需要纠错只提交要改的内容。
- 返回值描述内存中的执行结果，不是保存回执。意外运行错误仍可能抛出异常，调用方可用 `try/catch` 处理。

### `apply`：结构化写法，适合程序和工具调用

```js
const result = LWB_StateV2.apply({
  ops: [
    { op: "inc", path: "数据.角色.生命值", delta: -10 },
    { op: "push", path: "数据.角色.技能", value: "火球术" }
  ]
});
```

| `op` | 需要的字段 | 作用 |
| --- | --- | --- |
| `set` | `path`、`value` | 整体替换；`value: null` 是写入 null，不是删除 |
| `inc` | `path`、`delta` | 加减；`delta` 必须是数字，`-10` 可用，`"-10"` 不可用 |
| `push` | `path`、`value` | 数组追加；`value` 是数组时逐项追加，`[[3,4]]` 追加一个坐标 |
| `remove` | `path`、`value` | 按值移除第一个相同项；数组值表示依次移除多项。对象按 JSON 序列化内容匹配，键顺序也影响匹配 |
| `del` | `path` | 删除，不带 `value` |

- 顶层只接受 `{ ops: [...] }`，也接受这一对象的 JSON 字符串。每个操作只带表中规定的字段和 `op`；路径可写 `数据.角色.金币` 或 `数据.角色.技能[0]`，数组下标从 `0` 开始。
- 只能操作已经由文本入口纳管的根变量（本例为 `数据`），不能新增受管根或声明模板。先初始化根，再按模板允许的范围新增成员；不是要求每个末端字段都已存在。
- 每次调用都会执行，内容一样也执行两次。
- 记在调用时的最后一条消息上，不等 AI 下一次回复。没有任何消息时返回 `no_chat`。
- 通过 JSON 接口提交过的操作，不要再让 AI 写进正文，否则会改两次。

返回值（立即返回，也可以 `await`）：

| 字段 | 含义 |
| --- | --- |
| `status` | `success` 有变化且无操作错误；`partial` 有变化也有错误；`noop` 无变化、无错误；`failed` 有错误且没有实际变化 |
| `changes` | 实际变化：`index`（从 `0` 开始的原操作索引）、`op`、`path`、`oldValue`、`newValue`；加减另有实际的 `delta`。缺失值可为 `undefined` |
| `corrections` | 修正记录：`index`、`path`、`requested`、`value`、`note`。加减时 `requested` 是请求增量，`value` 是修正后的最终值；实际增量看 `changes[].delta` |
| `errors` | 错误列表：`code` 用于程序判断，`message` 给人看；具体操作错误还带 `index`，并可能带 `path` 或 `pointer` 等位置 |
| `warnings` | 提交后的附带问题，含 `code`、`message`、`detail`（如通知失败），不要因此重试 |

常见格式和操作错误会通过返回值报告；意外运行错误仍可抛出。格式错误（缺字段、路径非法等）时整批都不执行，改好后可整批重发。格式没问题、但个别操作被规则拒绝时，其余操作照常完成，此时只重发失败项，不要整批重发，否则会重复扣减。守卫拒绝的请求仍会记入历史；改动前文规则后重建时，会按新前文重新判定。

`noop` 不是错误；`failed` 也不是保存状态，不能据此判断聊天有没有落盘。

### 同一批里删数组项要小心

同一批里，按下标删除会先执行，而且从后往前删；其他操作再按顺序执行。所以删除下标 1、2 不会错删。

会让下标错位的组合，会整批拒绝（`conflicting_operations`），例如：

- 删除下标 0，同时修改下标 1——删完后原来的 1 变成 0 了；
- 同一个下标删两次；
- 删除数组项，同时整体替换这个数组。

需要“先改 B 再删 A”时，分两次调用；或者用 `remove` 按值删除 A，不受下标影响。

### 正文里也可以写 JSON

`<state>` 内以 `{` 开头时按 JSON 处理，格式同 `apply()`。正文仍按状态块记录防重，不会因为多次渲染同一块就重复执行：

```html
<state>
{"ops":[{"op":"inc","path":"数据.角色.生命值","delta":-10}]}
</state>
```

限制与 `apply()` 相同：先初始化受管根，JSON 只提交操作，不声明模板。正文中的多个状态块会一起解析；其中一个 JSON 块格式错误时，这次正文同步整批不执行，保留原状态和记录，不会把坏 JSON 改当文字写法。

### 在工具参数里读取变量

工具调用的参数是 JSON。要把变量放进 JSON 参数模板，用不带 `_yaml` 的 `{{xbgetvar::…}}`，它把对象、数组输出为 JSON（假设 `数据` 已初始化）：

```text
"value": {{xbgetvar::数据}}
```

展开后会得到完整 JSON 值，而不是 YAML。注意三点：

- 不要用 YAML 宏，也不要给整个宏再套引号，否则得到的不是 JSON 对象。
- 对字符串，`xbgetvar` 返回原文，**不会自动加 JSON 引号或转义**。字符串参数应由脚本读取后用 `JSON.stringify` 序列化，不要把任意字符串宏直接拼进 JSON。
- 宏只在支持宏展开的提示词文本中替换，不会在 JavaScript 或工具参数对象里自行执行。

读取宏不改变提交方式：工具的 `state` 参数仍使用上面的 `apply` 格式，不要把多行 YAML 拼进去。

### `beginTurn`：补写或重写最后一楼的变量

这是给预设/工具适配器使用的入口，不负责发起模型请求。自动更新和手动按钮应调用同一个适配函数。

1. 记录最后一条 AI 回复的楼号和当前 `swipe_id`。
2. 调用 `LWB_StateV2.beginTurn({ floor, swipeId })`。它立即撤销**这楼当前 swipe 通过本接口提交的旧 state**。没有旧提交就完全不回滚，不向前找，也不撤销本楼初始化、正文状态块或普通 `apply/applyText` 调用。
3. 再通过宿主正常流程组装世界书、宏和聊天历史。此时读取到的就是真实回滚后的变量；变量如何展示由角色卡/世界书决定。
4. 模型结果到达后调用返回句柄的 `commit({ ops })`，把新 state 放回本楼原来的记录位置。参数格式与上面的 `apply` 相同。

`beginTurn` 只接受最后一条非用户、非系统的 AI 回复及其当前 swipe。宿主没有 `swipe_id` 字段时传 `0`。下面只演示替换提交，不会调用模型，可在初始化后的 AI 末楼试运行：

```js
const tavern = SillyTavern.getContext();
const floor = tavern.chat.length - 1;
const turn = LWB_StateV2.beginTurn({ floor, swipeId: tavern.chat[floor].swipe_id ?? 0 });
const result = turn.commit({ ops: [{ op: 'inc', path: '数据.角色.金币', delta: 5 }] });
console.log(result);
```

这段运行两遍，本楼通过它带来的金币仍只增加 `5`，不是增加 `10`。接入模型时，把“组装提示词并请求模型”放在 `beginTurn` 之后、`commit` 之前。`beginTurn` 本身就会撤销并安排保存旧提交；网络失败、取消或未调用 `commit`，都不会自动把旧提交恢复回来。

`commit` 前可调用 `turn.assertCurrent()` 检查目标是否仍有效；成功时无返回值，过期时抛出带 `code` 的异常。切聊天、增删消息、改正文、换 swipe 或变量值/记录变化后，旧句柄不能写回。一次成功提交后句柄也失效，重试需重新调用 `beginTurn`。句柄只活在当前页面调用中，不保存。

新提交有操作错误时整批不发布，返回 `status: "failed"` 和 `errors`；格式错误和过期句柄抛出异常。旧 state 已撤销，不会恢复成请求前的值。`{ ops: [] }` 表示本楼无需修改。

普通 `apply()` 仍然是追加调用，不是替换。工具 schema 可从 `LWB_StateV2.getInputSchema()` 获取，避免预设各自维护一份操作协议。

模型工具并不会因为调用 `getInputSchema()` 就自动注册。适配器负责注册工具、发送请求、取回模型给出的 `{ ops }`，再选择追加调用 `apply()`，或替换本楼调用 `turn.commit()`。工具名和外层参数名由适配器决定，变量模块本身不提供 `write`、不发起模型请求。

## 七、删消息、切 swipe、重开聊天

每条消息记的是“做了什么”（比如“生命值 −10”），不是结果。变量 2.0 随时可以按这些记录重算。

| 操作 | 变量怎么变 |
| --- | --- |
| 删除消息 | 撤销被删消息的修改，例如删掉扣 10 血的那条，生命值回到 100 |
| 切换 swipe | 用选中的那条回复的修改；新生成的 swipe 不继承旧 swipe 的修改 |
| 继续生成（continue） | 只执行新增的状态块，原有的不重复执行 |
| 编辑消息 | 只改普通文字：变量不变。改了状态块：按改后的内容重算。把状态块全删光：保留原来的修改 |
| 重开聊天 / 刷新页面 | 不重复执行任何修改 |

- 只有通过变量 2.0 写入的变量（例如“数据”）参与恢复，其他普通变量不受影响。
- 用宿主自带命令（如 `/setvar`）直接修改“数据”，不会留下记录，之后重算时可能被覆盖。要改请通过本模块。
- 每满 50 条消息可缓存一个重放结果，最多保留两个有效缓存。前文被编辑、删除或切换后，旧缓存可能失效，需要从更早处重算；并非所有长聊天操作都能跳过前文。
- 修改后约 1 秒防抖调用酒馆聊天保存，消息记录和变量一起保存。接口返回不代表服务器已写入成功；保存异常要看提示和控制台，别靠重发增量来“重试保存”。
- 从历史楼层开分支时，暂不自动回到那一楼的状态，见[分支说明](<branch-state.md>)。

## 八、从旧版本更新

正式版已有的旧变量 2.0 聊天记录会在打开时自动转换，当前变量值保持不变，无需手工迁移。这里说的是变量 **2.0 的旧存档**，不是把 `1.0 (plot-log)` 卡自动转换成 `<state>` 卡。

- 旧版 `applyText` 写入并保留下来的记录继续使用，重新打开不会再执行一遍。
- 旧版初始化记录或受支持的首楼初始化存档点仍在时，可以用于后续重建；没有留下的初始值不会凭空补造。
- 转换失败时旧数据保留，写入会报转换错误；`apply()` 的错误码为 `legacy_conversion_failed`，文本接口返回诊断文字。先备份聊天、查错误，不要在当前剧情上反复运行整份初始化。

若旧脚本缺少模板要求的初始字段（例如有“后宫”模板却没写 `后宫: {}`），升级不会替你修正它。补全初始化脚本，在新测试聊天中确认初值正确；已有聊天需要按其实际状态修复，不能把重置初值当成恢复历史。

## 九、给 AI 的写作要点

下面这段配合第一节的模板和第二节的读取宏使用，可放进同一个会发送给模型的世界书/预设条目。改了自己的字段名，也要改这里的路径和成员结构：

```text
当前变量由上方的“当前变量”块提供。回复末尾用 <state>…</state> 提交本次剧情造成的变化；没有变化时省略状态块。

这张卡的结构：
- 数据.角色：姓名（文字）、生命值/魔法值/金币（数字）、技能（数组）、背包（物品名到数量的对象）。
- 数据.后宫：成员名到成员对象；每个成员包含生命值、好感度两个数字字段。
- 数据.当前地点：文字。模板和初值由角色卡初始化负责。

修改路径写到需要改的字段；整体赋值会替换整个对象。新成员要写全两个字段。
带符号的数字表示加减；赋负数用括号，例如 数据.角色.金币: (-5)。
技能追加用 +"技能名"，按值移除用 -"技能名"。背包数量按数字加减。

以下仅演示格式，实际路径和值按本次剧情选择，不照抄事件：
<state>
数据.角色.生命值: -10
数据.角色.背包.回血药: +1
数据.角色.技能: +"火球术"
数据.后宫.莉娜: {"生命值":100,"好感度":0}
数据.当前地点: "森林"
</state>
```
