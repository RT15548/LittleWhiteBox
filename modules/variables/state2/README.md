# 变量 2.0 使用说明

变量 2.0 让角色卡用一段 `<state>` 文本管理剧情状态：生命值、背包、好感度、地点……

- **有模板**：先说清楚变量长什么样，之后 AI 写错类型、多写字段、数值越界，会被挡下或自动修正。
- **跟着楼层走**：每条消息记下它对变量做了什么。删消息、切 swipe、重开聊天，变量会回到对应的样子，不会重复扣血。

本文先讲最常用的写法，再讲脚本接口和历史行为。

---

## 一、开局：在角色卡里初始化

推荐用小白X的“循环任务”：新建一个角色任务，**触发时机选“角色卡初始化”**，内容如下。角色卡需要有开场白，新建聊天时任务会自动执行一次。

```text
<<taskjs>>
const result = await LWB_StateV2.applyText(`
<state>
# 1. 模板：只规定结构和类型，不写入数据
$schema 数据
  角色:
    姓名: ""
    生命值: 0
    魔法值: 0
    金币: 0
    技能: []
    背包:
      "*": 0
  后宫:
    "*":
      生命值: 0
      好感度: 0
  当前地点: ""

# 2. 约束
$range=[0,999] 数据.角色.生命值
$range=[0,999] 数据.角色.魔法值
$step=50 数据.角色.生命值
$step=50 数据.角色.魔法值

# 3. 初始数据：真正写进去的值
数据:
  角色:
    姓名: "苏晚"
    生命值: 100
    魔法值: 50
    金币: 0
    技能: []
    背包: {}
  后宫: {}
  当前地点: "新手村"
</state>
`);
if (result.errors.length) console.warn('变量初始化失败', result.errors);
<</taskjs>>
```

三段各管一件事：

| 段落 | 作用 | 会不会写入数据 |
| --- | --- | --- |
| `$schema` | 规定“数据”里有哪些字段、各是什么类型 | 不会 |
| `$range` / `$step` 等 | 给字段加限制 | 不会 |
| `数据:` | 写入初始值 | 会 |

> **最容易踩的坑：模板里有的字段，初始数据必须写全。**
> 上例模板有“后宫”，所以初始数据里要有 `后宫: {}`，哪怕现在一个人都没有。
> 少写一个字段，**整份 `数据` 都不会写入**——不是只缺后宫，苏晚、生命值、地点也全都没有。

初始化只需要执行一次。之后重开聊天、删消息、切 swipe，变量都由记录恢复，不会重跑这段脚本。

脚本正常结束不代表写入成功，要看返回的 `errors`；失败原因也会写在变量 `LWB_STATE_ERRORS` 里。上例会把失败原因打印到浏览器控制台，不会自动弹窗。

## 二、剧情中：让 AI 在回复里改变量

AI 在回复中输出 `<state>` 块，消息生成完后自动执行：

```text
<state>
数据.角色.生命值: -10
数据.角色.背包.回血药: +1
数据.当前地点: "森林"
</state>
```

### 写法速查

| 想做的事 | 写法 | 说明 |
| --- | --- | --- |
| 改成某个值 | `数据.当前地点: "森林"` | 整体替换 |
| 改成某个数 | `数据.角色.金币: 30` | 不带正负号 = 赋值 |
| 加减 | `数据.角色.生命值: -10`<br>`数据.角色.金币: +5` | **带 `+` / `-` 号 = 加减** |
| 赋值成负数 | `数据.温度: (-5)` | 加括号，否则 `-5` 会被当成“减 5” |
| 数组追加一项 | `数据.角色.技能: +"火球术"`<br>`数据.队伍: +{"名字":"莉娜","HP":8}` | |
| 数组追加多项 | `数据.角色.技能: +["火球术","冰箭"]` | |
| 数组按值移除 | `数据.角色.技能: -"火球术"` | 移除第一个相同的项 |
| 删除字段 | `数据.后宫.莉娜: null` | 模板规定的固定字段不能删 |
| 整块写入 | 见下 | |

整块写入用缩进：

```text
数据.后宫:
  莉娜:
    生命值: 80
    好感度: 10
```

> **改一个字段，就写到这个字段为止。**
> 写 `数据.角色.生命值: 90` ✅
> 不要写成 `数据.角色:` 再只给一个 `生命值: 90` ❌——这是用不完整的对象替换整个“角色”，会被拒绝。

## 三、模板 `$schema` 怎么写

模板用样例值表示类型：`""` 是文字，`0` 是数字，`[]` 是数组，`true` 是开关。

### 固定字段

```text
$schema 数据
  名称: ""
  等级: 0
```

- “数据”只能有 `名称`、`等级` 两个字段，不能多写别的字段。
- 整体写入“数据”时，两个都要有。
- 不能删除；想清空就写空值：`数据.名称: ""`、`数据.等级: 0`。

### 自由对象：`{}`

```text
$schema 数据
  固定: ""
  自由: {}
```

`数据.自由.任意名字: 123` 可以；`数据.额外: x` 不行——只有“自由”里面能随便加。

### 名字不固定的成员：`"*"`

后宫、同伴、背包物品这种“有几个、叫什么都不确定”的，用 `"*"`：

```text
$schema 数据
  同行者:
    "*":
      HP: 0
      状态: ""
```

- 新成员整个写入：`数据.同行者.莉娜: {"HP":8,"状态":"同行"}`，多字段或少字段都会被拒绝。
- 已有成员改单个字段：`数据.同行者.莉娜.HP: -3`。
- 成员可以删除：`数据.同行者.莉娜: null`。
- 一开始没有成员，初始数据写 `同行者: {}`。

### 数组

```text
$schema 数据
  背包:
    - 名称: ""
      数量: 0
```

第一项就是每一项的样板：每个物品都必须有 `名称`（文字）和 `数量`（数字）。整体写入、追加时都会逐项检查。

数字写成字符串会自动转换：`数量: "3"` 存为 `3`；`数量: abc` 会被拒绝。

## 四、约束

写在 `$schema` 后面，每行一条；路径里的 `[*]` 表示数组每一项。

| 约束 | 写法 | 超出时 |
| --- | --- | --- |
| 范围 | `$range=[0,999] 数据.角色.生命值` | **自动截到边界**，比如加到 1200 存为 999 |
| 单次增减上限 | `$step=50 数据.角色.生命值` | **自动截断**，比如 `-1000` 实际只扣 50 |
| 只能取这些值 | `$enum={白天,黄昏,夜晚} 数据.时段` | 拒绝 |
| 只读 | `$ro 数据.角色.姓名` | 拒绝修改 |

- `$range` 对整块写入里的嵌套字段同样生效。
- `$step` 只限制“加减”，不限制赋值：初始化写 `生命值: 100` 不会被截成 50。
- 多个约束可以写在一行：`$range=[0,100] $step=10 数据.好感度`。

## 五、写错了会怎样

- **整笔不写**：一次赋值不符合模板，这次赋值完全不生效，不会写进去一半。
- **其他行照常**：同一个 `<state>` 里别的行不受影响。
- **截断不算错**：被 `$range` / `$step` 截断的写入算成功，只是数值变了。
- **哪里看原因**：变量 `LWB_STATE_ERRORS`；脚本调用看返回值。

| 常见原因 | 怎么改 |
| --- | --- |
| 缺少模板字段：xxx | 整体写入时把模板字段写全，没内容就写空值，如 `{}`、`""`、`0` |
| 字段不在结构模板中 | 删掉多写的字段，或在模板里加上 |
| 类型不匹配 | 按模板类型写，例如数字不要写成文字 |
| 父层结构已锁定 | 这个对象不能加新字段，改模板为 `{}` 或 `"*"` |
| 模板定义的字段不能删除 | 改为写空值 |
| 只读字段 / 枚举不匹配 | 去掉这次修改，或使用允许的值 |

## 六、在脚本里直接改变量

变量 2.0 开启时，页面上有全局对象 `LWB_StateV2`，循环任务、前端界面或工具函数都可以调用，不用往聊天里插消息。

### `applyText`：用和正文一样的文字写法

```js
const result = await LWB_StateV2.applyText(`<state>数据.角色.金币: +10</state>`);
```

- 可以声明模板和约束，**初始化必须用它**（或写在正文里）。
- 返回 `{ atoms, errors, skipped }`。`errors` 是文字列表，为空表示全部成功。
- 默认记到最后一条消息上；`floor` 可指定楼层。
- 同一楼已经执行过完全相同的内容会跳过（`skipped`），防止重复执行。真的要再执行一次，用 `apply()`。

### `apply`：结构化写法，适合程序和工具调用

```js
const result = LWB_StateV2.apply({
  ops: [
    { op: "inc", path: "数据.角色.生命值", delta: -10 },
    { op: "push", path: "数据.角色.技能", value: "火球术" }
  ]
});
```

| `op` | 需要的字段 | 作用 |
| --- | --- | --- |
| `set` | `path`、`value` | 整体替换 |
| `inc` | `path`、`delta` | 加减 |
| `push` | `path`、`value` | 数组追加；`value` 是数组时逐项追加，`[[3,4]]` 追加一个坐标 |
| `remove` | `path`、`value` | 数组按值移除，对象要完整匹配 |
| `del` | `path` | 删除 |

- 只能修改已经初始化过的变量（例如上面的“数据”），**不能新建变量，也不能声明模板**。
- 每次调用都会执行，内容一样也执行两次。
- 记在调用时的最后一条消息上，不等 AI 下一次回复。
- 已经通过接口改过的，不要再写进正文，否则会改两次。

返回值（立即返回，也可以 `await`）：

| 字段 | 含义 |
| --- | --- |
| `status` | `success` 全部成功 · `partial` 部分成功 · `noop` 没变化 · `failed` 全部失败 |
| `changes` | 实际改了什么：`index`（第几个操作）、`path`、`oldValue`、`newValue`，加减另有实际的 `delta` |
| `corrections` | 被约束修正的操作，例如请求扣 200、实际只扣 10 |
| `errors` | 失败项，`code` 用于程序判断，`message` 给人看 |
| `warnings` | 修改已完成后的附带问题（如通知失败），**不要因此重试** |

格式错误（缺字段、路径非法等）时**整批都不执行**，改好后可整批重发。格式没问题、但个别操作被规则拒绝时，其余操作照常完成，此时**只重发失败的那几项**，不要整批重发，否则会重复扣减。

### 同一批里删数组项要小心

同一批里，按下标删除会先执行，而且从后往前删；其他操作再按顺序执行。所以删除下标 1、2 不会错删。

会让下标错位的组合，会整批拒绝（`conflicting_operations`），例如：

- 删除下标 0，同时修改下标 1——删完后原来的 1 变成 0 了；
- 同一个下标删两次；
- 删除数组项，同时整体替换这个数组。

需要“先改 B 再删 A”时，分两次调用；或者用 `remove` 按值删除 A，不受下标影响。

### 正文里也可以写 JSON

`<state>` 内以 `{` 开头时按 JSON 处理，格式同 `apply()`：

```html
<state>
{"ops":[{"op":"inc","path":"数据.角色.生命值","delta":-10}]}
</state>
```

限制与 `apply()` 相同：只能改已初始化的变量，不能声明模板。JSON 写坏了就整块不执行，不会当成文字写法处理。

## 七、删消息、切 swipe、重开聊天

每条消息记的是“做了什么”（比如“生命值 −10”），不是结果。变量 2.0 随时可以按这些记录重算。

| 操作 | 变量怎么变 |
| --- | --- |
| 删除消息 | 撤销被删消息的修改，例如删掉扣 10 血的那条，生命值回到 100 |
| 切换 swipe | 用选中的那条回复的修改；新生成的 swipe 不继承旧 swipe 的修改 |
| 继续生成（continue） | 只执行新增的状态块，原有的不重复执行 |
| 编辑消息 | 只改普通文字：变量不变。改了状态块：按改后的内容重算。把状态块全删光：保留原来的修改 |
| 重开聊天 / 刷新页面 | 不重复执行任何修改 |

- 只有通过变量 2.0 写入的变量（例如“数据”）参与恢复，其他普通变量不受影响。
- 用宿主自带命令（如 `/setvar`）直接修改“数据”，不会留下记录，之后重算时可能被覆盖。要改请通过本模块。
- 每 50 楼留一份存档点，长聊天重算不必从头开始；最多保留两份。
- 修改会自动随聊天保存。
- 从历史楼层开分支时，暂不自动回到那一楼的状态，见[分支说明](<branch-state.md>)。

## 八、从旧版本更新

不需要任何操作。第一次打开旧聊天时会自动转换，当前变量值保持不变：

- 旧版按 `applyText` 写的记录照常保留，重开不会再执行一遍。
- 用旧版“角色卡初始化”建立的变量，删消息后也能回到初始值。
- 转换失败时原数据原样保留，此聊天的变量 2.0 写入会报 `legacy_conversion_failed`。

之前写过的初始化脚本，如果模板里有字段在初始数据中没写（比如有“后宫”模板却没写 `后宫: {}`），**旧版本里这份初始数据就没写进去过**，只是当时没有提示。补上缺的字段即可。

## 九、给 AI 的写作要点

把下面这段放进提示词，可减少写错：

```text
需要改变量时，在回复末尾输出 <state>…</state>：
- 加减用带符号的数：数据.角色.生命值: -10
- 赋值用不带符号的值：数据.当前地点: "森林"；要赋负数写 (-5)
- 只改需要改的字段，路径写到最底层，不要重写整个对象
- 数组追加：数据.角色.技能: +"火球术"；移除：数据.角色.技能: -"火球术"
- 新成员按模板写全字段：数据.后宫.莉娜: {"生命值":100,"好感度":0}
- 不要新增模板之外的字段，不要声明 $schema
```
