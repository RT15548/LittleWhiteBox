# 向量缓存包的边界

聊天正文、`stateAtoms`、`l0Index` 和总结属于酒馆聊天 metadata/聊天记录。向量包不是记忆备份，所有导入结果（成功、失败、取消）都不能修改这些数据。

## 当前格式：ZIP v3

包只包含 `manifest.json` 及 `chunks.bin`、`states.bin`、`relations.bin`、`events.bin`。manifest 保存聊天标识、模型指纹、维度、记录标识/楼层和输入摘要，不保存 L0、L1 或事件原文。数值采用 little-endian float32，关系向量仅为实际存在的记录打包，不补零。

来源摘要是 `SHA-256(JSON.stringify([kind, embeddingInput]))`，在实际向量请求的输入确定后记录。它用于检测来源错配，不是签名或可信来源认证。不能在导出时根据最新文本给旧向量补摘要。

SHA-256 由插件自带的 `libs/js-sha256.mjs` 提供，不依赖宿主 `lib.js` 的导出或 Web Crypto。它由既有 `js-sha256` 依赖通过 `npm run build:sha256:vendor` 生成，并随插件发布代码与许可证；无需用户安装 npm 依赖。宿主旧版缺少该导出不会阻止加载，摘要值及数据格式不变，不需要迁移或重建向量。

现有向量表中的 `sourceHash`、L0 的 `relationHash` 与向量一起持久化：它们描述生成该向量的输入，需要跨重启保留；所有者是对应向量记录，替换或清理向量时一并删除。不新增表、schema 索引、持久化导入快照、锁或缓存。

旧浏览器缓存没有摘要时仍可供现有检索使用，但不能导出为有来源证明的新包。导出明确要求完整重建向量；不会重新提取 L0，也不会静默产生 API 请求。向量重新生成后该限制自然解除。

导入导出不读取或比对当前 Embedding 模型配置；未配置或配置了不同模型都不阻止缓存搬运，也不自动修改配置、调用模型。导出从向量记录保留其生成模型指纹，导入原样保存包内指纹。当前格式一包声明一个来源模型，不能把混合来源的记录伪标为同一个模型；维度、数值及包内来源信息仍需自洽。检索和补算时才检查当前模型能否使用该缓存，同维度不代表同向量空间。

L1 的 `meta` 是增量构建进度，不是各层向量的模型事实来源：L1 失败而 L0 成功时，可以没有 `meta`，但仍能导出合法的 L0 缓存。

## 恢复流程

`storage/package` 拥有格式、来源校验和存储事务；`vector-io.js` 仅负责本地文件或酒馆服务器 ZIP 的取放，两个入口共用同一套实现。

1. 捕获当前聊天的只读内容和文本过滤规则；不使用会初始化或迁移 metadata 的 getter。
2. 校验包结构、唯一标识、数值和当前聊天 ID；模型指纹来自包内，不与当前配置比较。
3. 用现有 `chunkMessage` 从当前正文重建 L1，并核对每条向量的实际输入摘要。L0 关系输入和事件输入与生成入口共享定义。
4. 以一笔 IndexedDB 事务替换当前聊天的检索缓存。每个异步写入后检查取消、切聊天及来源变化；失败则整笔回滚。不触碰其他聊天。
5. 提交后失效检索运行时和词法索引。L1 完成楼层从实际恢复覆盖范围派生，不相信包内宣称的完成位置。

完成边界之前连续，不代表之后没有可用缓存。后续 L1 增量补算将片段、向量与完成边界一起提交；Embedding 失败不写库，写入失败或取消则由事务恢复原记录，不按楼层范围删除已恢复的缓存。

这不是换卡导入入口。跨聊天 ID、修改过的正文/锚点/事件或不同过滤结果都会被拒绝；先打开原聊天并使用匹配的文本过滤规则。源设备已有旧片段且当前过滤结果不同，也不能将其导出为新来源的向量。

## 日常检查与补齐不是备份来源校验

日常 L1 的事实来源是已保存片段及其向量的输入摘要；不要求旧片段等于当前聊天重新切分的结果。其他插件事后追加标记、展示内容，或清洗规则变化，不会让一套配套的旧材料失效，也不触发静默重算。新输入仍使用当前清洗规则。

功能标记投影只移除已识别的生图、骰子和 TTS 控制标记，保留语音正文及其余文本的空白。原有过滤、首尾处理和切分规则不变；不因空行、连续空格或换行符规范化使普通旧片段失配。

日常检查、自动维护和手动补齐共用 `pipeline/chunk-materials.js` 选择材料：

- 有片段、缺向量：使用已保存片段补算。
- 整楼没有片段：从该楼当前正文构建，包括新楼层和整楼缺失。
- 楼层已有片段，但某个向量缺对应材料：仅从正文找回该 ID；检查时仍须核对原向量摘要，不能给旧向量补造新来源证明。
- 已有材料的楼层，不把当前正文多切出的 ID 当作缺口。不新增持久化的片段总数或正文快照来猜测缺口。

补齐先一次性保存全部新发现的文字材料，再串行分批生成和保存向量。单楼超过一批时，后批失败也保留其材料，下次按“有材料、缺向量”续补；完成进度只在全部成功后推进。正常增量构建仍在全部请求成功后原子提交，不改变其事务语义。

日常检查保留保存片段与已有摘要不符、孤立向量、混合模型等真实不一致的诊断；仅缺来源摘要不是检索损坏，不触发日常重建要求，也不伪造摘要。导出仍按前述严格契约拒绝缺少证明的缓存。

后台巡检和预热不弹全局警告：向量诊断显示在「向量数据」，连接状态显示在 Embedding 测试入口，原始失败保留日志。打开面板只读取状态，不为显示诊断请求模型。当前发送确实失败、手动操作失败或保存状态不确定时，仍即时通知；向量请求长时间重试只报告等待，不提前宣告失败。

面板完整性读取有独立的临时请求身份，不创建、替换或取消自动维护定时器。维护失败后的只读复查不恢复付费重试权限。只有实际扫描才显示检查中；空聊天、未选聊天、向量关闭、等待维护及取消都有终态，过期结果不得更新当前面板。L0 与 Rerank 测试分别持有请求身份及取消控制器，切聊、停用、卸载、配置变更或新测试会释放旧状态；旧请求迟到不能覆盖或解锁新测试。

延迟维护先完成待办处置并释放任务锁，再刷新面板统计和只读完整性状态；不能把持锁时的“等待”当作完成状态。该收尾不新增修复权限，读取失败显示不可用，切聊后的旧任务不更新新面板。

显式编辑先核对运行时记录的正文、说话人和角色；未改变输入的保存不取消召回、不失效缓存。普通编辑仅失效该楼 L1，以及该楼和直接依赖其 USER 输入的下一层 AI 的 L0。片段与向量原子删除，连续完成边界回退，后续健康缓存保留并由已有缺口维护补齐；清理失败时旧来源不可继续消费。对象顺序变化从首个变位楼层失效，swipe、删除维持原有回滚规则。quiet 或重复生成结束没有改变原文时不启动维护。不新增持久化正文快照或故障状态。

手动锚点提取、向量重建与补齐的取消身份覆盖来源准备阶段；准备在串行写队列之外等待，一致性写入仍排队完成。准备期间停止、切聊、配置变化或卸载后，不得再进入模型生成。准备成功或失败后均释放请求身份，不新增取消标记或第二条写队列。

ZIP v3 不携带 L1 原文，恢复必须从目标聊天重建材料。因此导出、上传与导入仍执行前述严格来源匹配；日常缓存有效，不等于在当前正文上一定能导出或恢复。这里不改变包格式或放宽备份契约。

## 旧文件兼容

只在解析入口支持正式线真实导出的 ZIP v2；转换后只保留当前缓存模型。`tests/fixtures/vector-package-v2.json` 是运行其记录的 upstream 提交中的真实 `exportVectors` 所得 ZIP，输入是虚构数据。

- v2 的 L1 文本及 L0 原文只用于核对输入，绝不回写聊天。
- v2 事件仅带 ID，无法证明来源：不恢复这部分，并返回 `legacy_events_omitted`，界面提示使用“补齐缺漏”。如果整个包都无可验证向量，则拒绝整次恢复，保留当前缓存。
- 原解析器虽然放行过版本号 1，但没有可核实的 v1 导出格式/真实样本；不再猜测其布局。未知版本明确拒绝。
- 只有明确停止支持已有 v2 备份后才能删除 `legacy-v2.js` 和对应 fixture；历史语义不进入日常生成或检索。

服务器备份仍使用原文件名规则和酒馆文件 API，不自动同步，也不改变聊天文件。删除本功能只需删除包模块、传输入口及注册，并清理其服务器备份文件；保留聊天记忆和正常检索缓存。

## 验证

`npm run test:story-summary:vectors` 先核对发布依赖与生成结果一致，再覆盖无宿主哈希导出时的加载、无 Node／Web Crypto 的浏览器式执行、摘要协议一致性，以及真实 ZIP、内存 IndexedDB 事务、跨入口一致性、模型配置独立性、来源错配、未知来源、取消/失败/切聊天、旧包转换和 metadata 不变性。不调用真实模型或读写真实聊天。
