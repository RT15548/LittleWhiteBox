# 同轮记忆复用

总结模块在当前页面保留一份已提交的召回结果，来源可以是 USER 或 AI。先核对当前消息来源并完成必要的缓存失效，再决定是否命中；命中后跳过分词预热、检索读取和召回。不新增配置、消息字段或持久化；未改来源时不增加保存请求。

## 回合与失效

正常生成产生新来源时替换缓存。当前回复的续写、swipe、原生重生成复用正文、角色与原边界，注入深度按当前聊天楼数重算。首次无缓存续写绑定实际参与查询的 AI；之后普通回复该 AI 开始新回合。quiet 和 impersonate 不消费或替换缓存，正常空结果也可复用。

显式正文编辑、来源删除或替换、较早历史 swipe、手动总结变更、影响证据装配的配置变化、切聊、禁用与缓存清理使缓存失效。删除当前回复而保留来源时可复用；后台总结、补向量及普通隐藏开关不改变本轮已采用的结果。修改保留可见楼数会失效。

群聊普通成员回复各自建立来源；末尾续写复用。整轮重生成删掉来源后重新召回。停止未完成召回不安装缓存，旧请求迟到不能覆盖新聊天的缓存。

## 生成前的失败处理

首轮查询 Embedding 在同一个宿主生成轮内循环：每次请求限时 3 秒，超时、网络错误、HTTP 408 或 5xx 失败后等待 1 秒，再发起一次限时 3 秒的请求。等待从失败返回后起算，快速失败与超时均等待完整 1 秒。没有尝试次数上限；成功前拦截器持续等待，不能带失败的空记忆进入主模型。429、配置错误、其他 4xx、无效响应及未知错误当场停止并报告，不参与循环。召回算法的第二轮 hints 向量请求与后台补齐策略不变。

循环只持有本次召回的临时态。每次请求使用新的超时信号，外层取消信号贯穿所有请求和间隔等待。用户停止、切聊、编辑或停用立即取消，迟到结果不能提交。等待查询向量期间暂停召回的 30 秒计算预算，结束后恢复剩余预算；等待 USER 入楼和其他准备步骤仍受原有截止控制。

每次 Embedding 请求用独立控制器接收外部取消与请求超时；无论成功、失败还是取消，都释放本次的超时计时和外部取消监听。连续重试不依赖 `AbortSignal.any`，旧浏览器不会积累已结束请求的监听器。

提前召回保留。宿主发出生成结束或群聊外层结束通知时，读取原生单聊／群聊忙碌标记；宿主已空闲就取消尚未被拦截器接管的预取，包括请求、重试等待和提醒。回收不保留取消占位，也不清除已提交记忆；原来的宿主流程若随后仍进入拦截器，会正常重新准备召回，而不是重新启动宿主或重发用户消息。并发 quiet 可能修改共享忙碌标记，因此存在预取被回收后多做一次召回的代价。已被拦截器接管的召回不因这种无身份的结束通知而取消；真实停止、发起方信号、切聊及停用仍按原有生命周期取消。

当前实现中，非向量的召回失败也停止本次生成，不自动重跑。每次因失败阻止发送都刷新原因提示与召回日志，不使用告警冷却隐藏重复发送的失败；前台失败提示只保留最新一条，不清除其他功能的提示。成功准备时的非阻断提醒和后台维护仍保留各自的冷却策略。

查询等待持续 30 秒时，只显示一次 `feedback-copy.js` 定义的短提醒，不自动停止。成功或取消清理计时和自有提示；关闭提示不会在下一次尝试重新弹出。外部失败诊断最多保留最近 100 条收据，查询尝试序号持续累计，避免无限循环积累无界日志。

循环不调用宿主停止或生成入口，不发出生成开始、结束、停止或消息完成事件，不修改草稿或模拟忙碌状态。地图投影、绘图与其他插件继续观察真实的宿主生命周期；生成状态追踪在同一个召回阶段累计等待时间。真正停止、切聊及正常回复仍结束追踪，不为其他后台自动生成开启追踪。

普通对话、重生成、群聊与骰子续写均保留原有宿主调用，不重复发送前剧情规划、入楼、删楼或检定。quiet（包括 `/gen`）跳过自动召回；impersonate 保留召回。

记忆维护的多次失效通知合并到同一个准备任务，等当前保存结束后读取最新记忆，不逐条取消发送。显式正文、设置或记忆数据修改打断实际进行中的准备时说明原因；已取消、已完成的召回不算被打断，停止后的取消占位仅防止迟到请求重新召回。用户停止、切聊和停用不额外提醒。

quiet 在总结拦截器入口直接跳过，不召回、不写入，也不清除记忆位置。`GENERATION_ENDED` 除上述预取回收外仅通知后续维护，不清除记忆，避免 quiet 结束时误清前台已提交、尚未组装的内容。下一次正常召回入口仍先清旧记忆再写新记忆；明确停止、切聊、停用等原有清理点保留。宿主的 `extension_prompts` 仍是全局槽位，quiet 可能带上前台当前或上一轮留下的记忆，但不保证来自同一轮。不新增 filter、排队或请求结束归属机制，不承诺 quiet 的记忆隔离。

## 保存与生命周期

消息完成去重和缓存来源确认是两个独立的运行态。quiet、渲染、发送通知均不能确认缓存来源；只有已有一致性写队列成功完成失效、保存确认，且消息对象顺序和正文仍匹配时，才能推进来源基线。失败、取消、过期和空返回均不确认；聊天初始化只在实际切换归属时建立基线。

未完成的一致性任务暂时保留原基线及回滚边界，离开后返回原聊天也不能重新确认它。成功同步或聊天删除时释放；这不是聊天历史缓存，不持久化，不为已完成任务保留副本。

来源包含宿主当前选择的 swipe 分支。后台先看到分支替换时也承担 L2 回滚，不能等迟到的 `MESSAGE_SWIPED` 才判断；后续 swipe 通知不重复回滚。`MESSAGE_SWIPE_DELETED` 按实际删除位置校正运行态分支编号，不确认正文、不释放旧缓存清理责任。删除后仍选中原分支时不失效缓存、不启动一致性写入，紧接着的普通编辑也不因此回滚 L2；删除当前分支或宿主改选其他分支仍按来源替换处理，不按宿主版本号分流。打开候选列表、取消删除不会触发这条处理。

宿主同聊重载会重新反序列化消息。加载边界只把同位置、同输入的新对象重新绑定到原来源，不把对象重建当作重排，也不推进正文确认。已有对象真实换位仍按结构变化处理；未完成的局部或结构失效范围独立保留，不能因重载后文字相同而消失。旧异步结果不得跨重载提交。

明确导入或清空 L2 经保存确认后，待完成任务以该次来源作为新的 L2 回滚依据，仍保留旧 L0/L1 的清理范围；不能再用删除前的缓存长度重建已解除的回滚。替换期间来源发生变化、切聊或保存失败时不得解除；替换后新的删除或 swipe 仍产生新责任。两种依据只在任务未完成时分开保留，完成后一起释放。

每次准备绑定本次消息对象顺序、正文、角色和说话人，最终注入前再次校验。期间编辑或切聊就丢弃旧结果；来源不安全明确阻止本次生成，不把失败表示成空召回。当前回复续写与 swipe 仍可复用已采用回合，历史变化必须失效。普通正文编辑只退休对应 L0/L1，不自动改写 L2；剧情改写仍由用户显式回滚总结。

缓存最多一份，只保留采用正文及必要边界，不保留向量、候选池或活跃检索会话。刷新后为空，不跨进程恢复。

手动总结成功保存后先使匹配原聊天及执行身份的缓存失效，再处理取消收尾；保存失败保留旧结果。切聊或同聊重载后的旧回调不能清掉新缓存。复用不增加聊天保存请求。

## 检查

稳定行为测试见 `tests/recall-reuse.test.js` 和 `tests/recall-diagnostics.test.js`。可运行 `npm run test:story-summary:runtime`、`npm run test:story-summary:alignment`及现有总结测试。

最终请求、群聊归属和宿主事件顺序需在真实宿主检查。固定接口响应只证明协议与次数，不证明召回质量或用户设备耗时。
